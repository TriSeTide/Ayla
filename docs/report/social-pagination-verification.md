# 社交目录分页验收记录

日期：2026-09-08。范围：P01–P10、P31 中的群/私聊目录、群成员、子群、搜索用户、好友与申请/邀请/退群通知；包含首页、三种消息面板、群创建、可见性选择和 @ 成员入口。

## 变更和边界

旧实现中的全量数组、先拉全量再切片、全量群成员和管理群逐个取申请，已替换为服务端过滤后的游标页。旧数组接口继续兼容，页面使用显式分页契约。群目录使用 SQL 置顶和最近活动排序，子群按默认、最近消息、稳定 ID 排序，均在 LIMIT 前完成。完整接口与排序定义见 [社交目录分页](../architecture/social-pagination.md)。

会话目录不再随每行返回完整群成员与全部未读序号。聊天打开时单独获取未读元数据。实时订阅使用独立的授权群 ID/续传头分页，只有传输注册自动遍历此轻量列表；可见目录和成员页不会为了订阅而自动耗尽。群的直播/语音/桌游标记由独立批量聚合接口刷新，不用已加载的目录页推断全局状态。

网络错误保留已加载数据，显示明确重试入口；首屏错误不会冒充空列表。选择器中的已选用户、群和转让对象不因搜索或翻页消失。失效游标、账号切换、查询变更及并发旧响应受到代次检查和删除墓碑保护。

## 群主管理与直接私聊补验 V13/V21–V23

两宽4个场景、64个状态通过：建群弹窗内直接私聊pending禁钮与成功导航；群资料校验/提交/失败/成功；头像类型校验、预览、上传失败保留与成功；加入方式及表情上传策略；成员管理员角色与移除；非默认子群保存及删除；解散、转让和转让后成员退出。最终聚合证据为`ayla-social-actions-complete/control-states-report.json`，运行异常、未知API及选中状态失败均为零。

本次真实发现并修复了子群删除失败反馈被第二层确认框遮住的问题：原先catch只更新下层编辑表单错误，确认框仍在上面，用户取消确认又会清掉该错误。现在删除请求期间确认框传入busy、禁止重复操作和关闭；失败后关闭确认层并在保留草稿的子群编辑框显示错误，允许重试；成功才移除子群。375错误界面和1440pending界面已目视检查。`group-info`新增定向测试覆盖pending/Escape/失败保留/成功，当前19项通过。

私聊撤回失败后的再次尝试会先清除该次操作旧notice，避免随后成功仍显示“撤回失败”；`private-chat-pane`新增失败→等待→成功回归，当前7项通过。两份文件同批26项通过，未与前文205项相加。`ayla-chat-recall-cancel-states-final/control-states-report.json`的两宽8状态亦通过，其中撤回失败/成功各2状态，并明确记录成功后notice为空，其余4状态属于Motion负责的上传取消验证。上述修改只涉及前端状态，可按文件差异恢复，不修改正式消息或子群数据；浏览器操作均由合成API承接。

`verificationRuns`明确保留验证脚本的替代关系：宽屏部分pending响应在固定850ms后已返回，采集时只剩结果页，因此旧尝试失败。脚本改为完成pending采集后才释放对应合成响应，并整例重跑1440群主操作；最终64个状态只采用两宽私聊、375群主原通过场景及1440群主重跑，没有把旧失败当产品缺陷或累计为通过。
