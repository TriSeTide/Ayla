## 2. 存储机制总览（已验证）

### 2.1 部署形态

- MinIO 单节点单盘，容器 `ayla-minio`，`minio/minio:latest`，数据卷 `ayla-deploy_minio_data`
- 端口：S3 API `127.0.0.1:9000`、Console `127.0.0.1:9001`（均仅本机，公网走 frp 穿透 nginx）
- 后端凭据环境变量：`S3_ENDPOINT_URL=http://127.0.0.1:9000`、`S3_BUCKET=elysia-media`、`S3_PUBLIC=false`
- 本地开发 compose（`Ayla/docker-compose.yml`）同为该镜像，端口对宿主 9000/9001 全开

### 2.2 对象布局（`apps/media/storage.py:338-351`）

| key 形态 | 用途 |
|---|---|
| `tmp/{upload_id}` | 未 complete 的临时对象 |
| `media/{kind}/{media_id}/original` | 正式原对象 |
| `media/{kind}/{media_id}/thumbnail` | 缩略图 / 视频海报帧 |
| `media/{kind}/{media_id}/waveform` | 语音波形图 |

`kind` ∈ {image, voice, file, emoji, video}。私密桶：派生对象一律 `ACL: private`，只经预签名 URL 访问；DB 只存对象 key，不存绝对路径/宿主路径。

### 2.3 上传链路（三步受控上传 + 预签名直传）

1. `POST /api/v1/media/uploads` → 建 `MediaUploadSession`（TTL `MEDIA_TMP_TTL_SECONDS`，默认 600s），返回 `presigned_url`（`presign_put`，有效期 ≥600s）
2. 浏览器 XHR **PUT 直打 MinIO** `tmp/{upload_id}`，数据面完全旁路 Django
3. `POST /api/v1/media/uploads/{id}:complete` → `head` 校验 size、Range 读 64 字节做魔数嗅探、ETag 当 `content_hash` 去重、**服务端 `copy_object`** tmp→正式 key、删 tmp、派生缩略图/波形
4. 幂等：`session.media_id` 作锚点，重复 complete 返回同一 media_id

派生上限：≤64 MiB 走内存；大图走临时文件（`MEDIA_TMP_DIR`，数据盘）；音频超限跳过波形。

### 2.4 访问链路

- `:sign`（`POST /api/v1/media/{id}:sign`）：鉴权后签 **预签名 GET URL**，TTL `MEDIA_VIEW_URL_TTL_SECONDS = 600`（`services.py:35` 硬编码，非 settings）
- `/content`：Bearer 或 HMAC 票据（`uid/exp/sig`，绑定 user+media+exp）双通道，流式转发（Range 原样透传 MinIO）
- 前端 `toSameOriginMinio()`（`web/src/api/media.ts:337-339`）把预签名绝对 URL 的 host 换成 `/minio` 同源路径
- dev：`vite.config.ts:38-42` → `127.0.0.1:9000` + `changeOrigin`；生产：`nginx.conf` `location /minio/` 显式 `Host 127.0.0.1:9000`（与签名 Host 一致，已验证生产容器内配置）

## 3. 过期机制（设计与实现）

### 3.1 方案（`docs/architecture/media-storage-expiration.md`，2026-09-10 定稿）

| 类别 | 策略 |
|---|---|
| 帖子配图 `PostImage` / 表情 `EmojiItem` / 评论 `Comment`（两种形态）/ 群头像 `Conversation.avatar` | **永久保留** |
| 聊天图片 | 两级：7 天删原图留缩略图 → 30 天完全过期 |
| 聊天语音 / 文件 / 视频 | 单级：7 天直接删 |
| 直播弹幕 `Danmaku` / 语音房消息 `VoiceChatMessage` | 归可过期类，单级 7 天 |
| 无引用孤儿 | 按 kind 对应策略 |

设计原则：**云端回收 ≠ 数据销毁**；DB 记录**永不删行**（只打标记），便于前端区分"已过期"与"不存在"。不设 bucket quota 硬上限。不引入后台调度。

TTL 配置（`settings.py:206-210`，均可 env 覆盖，`<=0` 禁用）：

```
MEDIA_CHAT_IMAGE_ORIGINAL_TTL_DAYS = 7    MEDIA_CHAT_IMAGE_FULL_TTL_DAYS = 30
MEDIA_CHAT_VOICE_TTL_DAYS = 7             MEDIA_CHAT_FILE_TTL_DAYS = 7
MEDIA_CHAT_VIDEO_TTL_DAYS = 7
```

### 3.2 实现

- 模型加两列：`original_expired_at`（阶段 1 完成）、`expired_at`（完全过期），均 `db_index=True`（迁移 `0004`，纯 AddField、无回填）
- 命令：`manage.py cleanup_media --expire-chat-media [--no-delete]`
- 判定：候选 = `created_at < now - min(有效TTL)` 且 `status=ready` 且 `expired_at is null`；保护集合 = 5 类引用全量扫描；可过期 = 候选 − 保护
- 图片阶段 2 会补打 `original_expired_at`（文档未写，代码更严谨）
- 幂等：已标记不再处理；`--no-delete` 只预览不删不标记

## 4. 实测发现（生产运行时）

> 全部为只读或可逆探针操作，探针桶已删除，生产桶 `elysia-media` 前后一致（3.8 MiB / 12 objects / 11 版本条目）。

### 4.1 P0-1：生产桶启用版本化 → 过期机制回收不到磁盘

**证据（`mc stat`）**

```
Properties: Versioning: Enabled | Anonymous: Disabled | ILM: Disabled
```

对照：**本地开发 MinIO 同桶为 `Versioning: Un-versioned`**——环境不一致。

**删除语义实测（两次独立验证）**

用 10 MiB 对象在隔离桶复现：

```
== after 10MiB upload ==        11M  /data/probe-disk      mc du: 10MiB 1 object
== after DELETE ==              11M  /data/probe-disk      mc du: 0B 0 objects
  [v2] 0B    DEL  big.bin
  [v1] 10MiB PUT  big.bin        ← 旧版本仍在磁盘
```

再用**后端真实代码路径**（`S3Storage.put()` + `S3Storage.delete()`）在 5 MiB 对象上复现：

```
after put    exists = True
after delete exists = False     ← 应用语义正确（后续 GET 404）
disk: 5.1M /data/probe-app-delete   ← 但字节完全没释放
```

**根因**

`storage.py:218-222` 的 `delete()` 调用 `delete_object(Bucket, Key)` **不带 `VersionId`**。在启用版本化的桶上，这只会插入 delete marker，历史版本永久保留，直到被显式清除。代码库**零处** lifecycle / versioning 相关逻辑（全仓 grep 空），桶上**也无任何 lifecycle 规则**（`ILM: Disabled`）。

**后果**

过期机制的唯一工程目的（回收磁盘）被完全击穿：

- 语义层"生效"：`expired_at` 打标 → `/content` 404 → 前端显示占用位
- 存储层"失效"：对象字节永久累积，且每次删除**额外增加 delete marker**（元数据膨胀）
- 换言之：跑得越勤，元数据越多，磁盘一分不少

**版本化来源不明**：仓库/部署脚本/compose 均无开启版本化的代码（grep 0 命中），`ayerelysia` 用户 `.bash_history` 也无 `mc version` 记录。推测经 Console(9001) 手动开启，无法确证。

### 4.5 前端降级链路（审计结果）

**已确认可用**

- 签名层 410 降级逻辑真实实现：`web/src/api/media.ts:79-101`；Flutter 对齐：`media_signer.dart:96-180`
- 完全过期占位：图片/表情 ✅、视频 ✅、文件 ✅
- 410 结果不写缓存，过期状态不会被缓存住

**缺口**

- ❌ **语音（web + Flutter）无「已过期」占位**：web `MediaContent.tsx:526` 走 `apiRequestBlob`（content 端点），过期只落到"语音播放失败+重试"(656-668)；Flutter `media_content.dart:1207-1210` 同样走 content+Bearer，无 410 分支
- ❌ **常规图片气泡不走 original 签名**：`MediaContent.tsx:112-136` 直接走 `thumbnail` + `variant=thumb`，故「原图已过期」角标只在查看器（`ImageViewer.tsx:441-448`）出现，与方案 §8.1「气泡显示原图已过期提示」不符
- ❌ **视频预热池不重签**：`media.ts:144-178` 缓存 detached `<video>` 元素及其 src，`ImageViewer.tsx:170-172` 直接接管；超 600s 后播放失败且不降级
- ⚠️ 弹幕与语音房图片未传 `expiredBadge`
- ⚠️ `Ayla/web/nginx.conf`、`Ayla/nginx/nginx.conf` 均无 `/minio` 段；`docs/服务器半容器化部署方案.md:258` 的 `S3_ENDPOINT_URL=http://minio:9000` 与 nginx 固定 `Host 127.0.0.1:9000` 冲突（签名校验会失败），而文档里 `MINIO_PUBLIC_ENDPOINT` 标注"待实现"、全仓代码 0 命中

### 4.6 后端代码缺陷

`apps/media/views.py:338-341`（`MediaContentView.get`）：

```python
store = storage.get_storage()
key = media.storage_path
size = store.head(key)          # ← 无 try/except
```

`S3Storage.head()`（`storage.py:160-162`）直接调 `head_object`，对象不存在抛 `ClientError`，**未捕获 → HTTP 500**。同一文件里 Range 分支(`:371-376`)和无 Range 分支(`:385-390`)都有 try/except，只有 `head` 这行裸奔。前端语音正好走这个端点，所以语音过期的实际表现是 **500** 而不是 404/410。

## 6. 根因归纳

1. **存储层配置无版本控制**：MinIO 桶属性（versioning / lifecycle）不在 compose、不在部署脚本、不在文档，纯靠手工操作，导致生产与开发环境不一致且无人知晓。
2. **"可访问"与"受保护"两套判定不一致**：`can_access_media` 与 `_protected_media_ids` 各自演进，新增引用类型（头像/封面/弹幕/语音房）时只改了前者。
3. **调度依赖人工承诺**：方案 §7 写"运维手动/计划任务执行"，但从未落到任何部署工件，属于"设计上依赖一个不存在的人"。
4. **测试用内存假存储**：FakeStorage 与真实 S3 语义（版本化、多版本删除）不等价，无法验证"回收"这一核心目标。
