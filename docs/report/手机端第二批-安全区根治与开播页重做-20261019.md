## 0. 本轮最重要的一条：逐页补安全区是一次注定失败的打法

**上一轮我的做法**：按用户截图逐个补了 4 处（窄屏顶栏 / 群顶栏 / 直播头部 / 登录注册页）。

**结果**：用户又发来 6 张截图，还有 6+ 页面漏着；而且**新增页面还会继续漏**。

**根因**：原生窗口是**边到边**的（整棵 UI 从 `y=0` 开始画），而「哪些页面自己让位」是一个
**跨全站的横切关注点**——用「逐页打补丁」处理横切关注点，必然漏。

**正确做法**：壳层（`AppShell`）作为**唯一 owner** 统一兜底。

### 判定逻辑（`lib/layout/app_shell.dart`）

```dart
final bool shellTopInset = isNarrow &&
    topBar == null &&                 // 有顶栏 ⇒ 顶栏自己已让位
    !aylaIsLiveRoomRoute(pathname);   // 直播间/开播台 ⇒ 视频要顶边，自己处理

Column(children: <Widget>[
  if (topBar != null) topBar,
  if (shellTopInset)
    SizedBox(height: MediaQuery.viewPaddingOf(context).top),
  Expanded(child: ClipRect(child: shellContent)),
])
```

### 三条实现纪律

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | 用 `viewPaddingOf(context).top`，**不要** `paddingOf` | 后者被键盘 `viewInsets` 联动，弹键盘时顶栏会跳动 |
| 2 | 留白放在 `Expanded` **之前** | 放进去会让页面以为视口变矮却不知道原因，滚动位置算错 |
| 3 | 凡「排除出统一兜底」的分支，**逐个检查它的子分支有没有自己补** | 本轮实机复验就发现开播控制台漏补（观看态补过、控制台分支没补）⇒ 返回键被状态栏时间压住 |

### 怎么列出「所有需要检查的页面」（不靠猜）

看 `aylaIsNarrowTopBarRoute` 的白名单：

- **在名单里**（`/group` `/voice` `/live` `/posts` `/posts/mine` `/games` `/messages` `/search` `/favorites`）
  ⇒ 有壳层顶栏，顶栏自己让位；

  `/posts/:id`（帖子详情）、`/chat/:id`（私聊）、`/voice/:id`（语音房）、`/games/:id`（桌游房）、
  `/profile`（个人主页）、`/user/:id`（他人主页）、`/group/:id*`（群聊五条）、
  `/live/start/:id`（开播控制台）、`/live/:id`（直播间）。

## 1. 窄屏开播页布局（用户原话「大量布局错误」）

### 根因：把窄屏当成宽屏三列渲染

```dart
// 旧实现：Row[ Expanded(主区), _side() ]
// 而 _side() 是**固定 340 宽**的弹幕卡
// ⇒ 420 逻辑宽的屏上：340 + 主区 ⇒ 必然挤压 / 溢出 / 裁切
```

### web 的真实结构（`live.css`）

| 维度 | web 做法 | 出处 |
|---|---|---|
| 整体 | 整页纵向滚动（`overflow-y: auto`） | `live.css:243` |
| 主区 | `flex: none; min-height: 0; overflow: visible` | `live.css:244` |
| 侧栏 | `position: static`，**落进内容流底部**；固定 `240` 高、方角、无阴影、无边距 | `live.css:245` + **`545–551` 覆写** |
| 头部 | `position: sticky; top: 0; z-index: 20` | `live.css:665–670` |
| 资料栏 | `flex-wrap: wrap`；封面 **88**；按钮组 `flex-basis: 100%` 独占整行、两键 `flex: 1` 等分 | `live.css:247–253` |

⚠️ **侧栏那两条是「后者赢」**：245 行先写 `min-height: min(38vh,280px)` + 圆角 + 阴影，
545–551 行同一选择器、更靠后的 `@media` 块又覆写成固定 240 / 方角 / 无阴影。
**只读第一条会做错**（本轮我先按 245 实现了一版，随后按 545 订正）。

### Flutter 实现（`lib/widgets/live/live_room_body.dart`）

```dart
if (_isNarrow && widget.showOwnerPanel) {
  return _shell(children: [
    Expanded(child: Column(children: [
      SizedBox(height: viewPaddingOf(context).top),  // 开播台自行补状态栏
      _headerSwap(narrow: true),                     // 固定头部 = sticky 等价
      Expanded(child: SingleChildScrollView(child: Column([
        资料栏 AylaLiveOwnerPanel,   // 内部已按 web 换行
        视频 stage, 观众条, 推流地址卡,
        SizedBox(height: 240, child: 弹幕卡),   // 落进流底
      ]))),
    ])),
  ]);
}
```

**用「外层 Column 固定头 + Expanded 滚动体」表达 sticky**：比把整页改成 sliver 结构改动面小，
视觉与滚动行为等价。⚠️ 头部**不要**参与 `_replay` 入场动画（吸顶层带位移会在滚动中抖动）。

### 资料栏（`lib/widgets/live/live_owner_panel.dart`）窄屏档按 web 重做

```dart
// 旧：Row[封面 128, 字段列, 按钮列 96] —— 三列平铺，按钮挤在第三列
```

## 2. 加载转圈只转一圈就停

### 根因

```dart
// lib/widgets/base/loading.dart（修复前）
TweenAnimationBuilder<double>(
  tween: Tween<double>(begin: 0, end: 1),
  duration: AylaDurations.spin,   // 800ms
  ...
)
// TweenAnimationBuilder **只播一次**，播完停在 end。
// end=1 与 begin=0 在画面上是同一个位置（整圈）⇒ 表现为「转一圈后冻住」。
```

### 修复

改用 `AnimationController` + `..repeat()`，对应 CSS 的 `animation: spin 800ms linear infinite`。
`vsync` 走 `SingleTickerProviderStateMixin` ⇒ 页面不在前台时自动暂停，不白烧帧。
`reduced-motion` 档保持静态标识（不旋转），语义不变。

### 为什么这个 bug 长期没被发现

- `dart analyze` 不报；
- 既有测试都是单帧断言（只看某一帧画对了没有），**测不到「会不会继续转」**。

### 可稳定断言的判据（新增回归锁用的）

```dart
// 循环动画每帧结束后都会排下一帧；单次动画播完就不再排帧。
for (int i = 0; i < 30; i++) {
  await tester.pump(const Duration(milliseconds: 100));
  expect(tester.binding.hasScheduledFrame, isTrue);  // 跨 3 秒（>3 圈）持续为真
}
```

## 6. 流程教训（写给下一个 agent）

1. **横切关注点不要逐页打补丁** —— 找唯一 owner（壳层/中间件/基类）。
2. **改行为时连测试一起订正**，并在测试里写清「旧断言为什么是错的」，否则下一个人会以为是他改坏了。
3. **跑全量测试前先冻结代码**：本轮两次全量报 `Failed to load ... Compilation failed`，
   都是因为我边跑边改 `lib/`（不是断言失败）。看到 `loading ... [E]` 先确认是不是编译错。
4. **CSS 同一选择器可能被后面的 @media 块覆写** —— 拿到全部命中后按「生效值」实现。
