# 客户端登录后不检查更新（电脑端 + 手机端）—— 根因与修复

> 日期：2026-11-05 · 范围：`Ayla/flutter`（Windows / Android）
> 需求原文：「添加 Ayla Flutter 的电脑端 + 手机端的登录自动检查更新并弹窗」

## 1. 结论先行

更新链路的**组件全都在**（`core/update/*` + `AylaUpdateDialog` + `AylaUpdateHost` +
顶栏「检查更新」入口），真正坏的是**接线**：

1. **冷启动主路径从不检查**（决定性根因）；
2. 按**进程**而不是按**登录会话**计次；
3. 手机端返回键可以**绕过强制更新**；
4. Windows 自绘标题栏的关闭键可以**绕过强制更新**；
5. 版本读不到时会把「读失败」放大成「每次登录都被强制更新锁死」。

## 2. 根因链（逐条，含证据）

### 2.1 冷启动主路径漏了 `checkOnLogin()`（决定性）

`state/auth_bootstrap.dart` 里有**两条**登录成功路径：

| 路径 | 何时走 | 原实现 |
| --- | --- | --- |
| `aylaApplyLoginSession()` | 表单登录 / 注册 / 冷启动自动登录 | ✅ 调了 `checkOnLogin()` |
| `_restoreSessionWithToken()` | 冷启动 **refresh 静默续期** | ❌ **手写了一份收尾**，只做未读 + 预加载门 |

而 refresh 令牌是**无条件落盘**的（`aylaApplyLoginSession` 里写，不依赖任何用户开关），
⇒ 只要用户成功登录过一次，**之后每次启动都走静默续期**：

- 电脑端：每次打开 App；
- 手机端：切后台被系统回收后回来（Android 内存紧张时是常态）。

⇒ 也就是说，**更新弹窗几乎永远不会出现**。而那条路径的注释里还写着
「与手动登录**完全相同**的副作用链（WS / 预加载门 / 未读 / 更新检查）」——
注释与实现不符，属静默缺口（`auth_bootstrap.dart` 文件头「复制一份必然漂移」
那句话说的就是它）。

同一处还漏了 `_restartRealtimeBridges()`（帧桥重装）⇒ 静默续期后 WS 帧无人消费。

**修复**：抽出 `_finishSignIn(container, userId:)` 作为**唯一收尾实现**，两条路径都调它。

### 2.2 按进程计次 ⇒ 换号登录不再弹

`AylaUpdateController._loginCheckDone` 从不清零 ⇒ 「登出 → 换号登录」之后再也不会弹更新。

**修复**：新增 `resetForNewSession()`（登出 / 401 时由 `aylaLogout*` 调用），
并同时复位 `_checking`、丢弃旧 session、自增会话代号。

### 2.3 手机端返回键可绕过强制更新

更新弹窗**不是路由**（它是壳层里的一层浮层）⇒ 页面级 `PopScope` 到不了
（机制链见 `layout/app_back.dart` 文件头）⇒ 返回键一路落到 `homeExit` 档，
在主页连按两次就 `SystemNavigator.pop` **退出 App** —— 强制更新被绕过。

**修复**：`aylaBackActionFor` 新增**最高优先级**档 `updateDialog`；
`AylaUpdateHost` 在弹窗打开时登记处理器（`aylaUpdateDialogBackHandler`），
关闭时注销。强制更新 / 下载中时返回键被吞掉（弹窗不关、App 不退）。

### 2.4 Windows 自绘标题栏的关闭键可绕过强制更新

`main.dart` 的装配是 `Column[ if(自定义标题栏) AylaTitleBar, Expanded(Stack[Navigator]) ]`：
标题栏是 Navigator 的**兄弟且在上方**，而所有根 Overlay 都在 Navigator 里
⇒ **任何弹窗都盖不住那 32px**（`create_sheet.dart:60–66` 早就记着同一条实测结论）。

⇒ 强制更新弹窗开着时，右上角的最小化/关闭键仍可点，用户点 X 直接关掉 App。

**修复**：新增 `aylaWindowChromeLock`（ValueNotifier），`AylaUpdateHost` 在
「mandatory 或 downloading/applying」时置真，`AylaTitleBar.windowKeysLocked` 据此
禁用三键（拖拽与边缘缩放不受影响 —— 它们不构成逃逸）。

### 2.5 版本读失败 ⇒ 每次登录都被强制更新锁死

`loadAppVersion()` 失败回退 `0.0.0+0`（那是对的：更新不是启动硬依赖），
但服务端按 `build` 比大小 ⇒ `0` 恒小于任何已发布版本 ⇒ **永远 update_available**。
若该版本带 `--mandatory`，用户会陷入「每次登录被强制更新锁死 → 装上同一版本 → 再弹」。

**修复**：`build <= 0` 时自动检查**放弃本轮**（不弹），手动检查如实报
「无法读取当前安装包版本，暂时无法判断更新」。

## 3. 同轮修掉的相邻缺口（审计发现）

| # | 缺口 | 修法 |
| --- | --- | --- |
| 1 | 强制更新 + 下载失败时，「关闭」键**可点但毫无反应**（`requestClose` 对 mandatory 直接 return） | failed 档的关闭键按 mandatory 置灰，并补一句「必须更新才能继续使用」 |
| 2 | `postpone()` 无 mandatory 守卫（当前 UI 没接线，属潜伏雷） | 收敛成 `requestClose()` 同一判据 |
| 3 | 预加载门（`Offstage`）期间登记了返回键 ⇒ 用户按返回**完全没反应**（最长 20s） | 门 `loading` 时不登记；同时订阅 `AppInit` 以便 ready 后补登记 |
| 4 | 手动检查把 `no_release_for_platform` 说成「已是最新」 | 按 `reason` 分档文案 |
| 5 | Android 缺「安装未知应用」权限时无引导入口 | 原生通道改回 `{launched, reason, permissionRequired}` + 新增 `canInstallPackages` / `openInstallPermissionSettings`；弹窗给「去设置」 |
| 6 | 跨登出才返回的检查结果会在新会话里弹窗（旧 session 成孤儿） | 加会话代号 `_sessionEpoch`，代号不符丢弃结果 |
| 7 | `resetForNewSession` 不复位 `_checking` ⇒ 卡住的在途检查挡住下次手动检查 | 一并复位 |
| 8 | 关闭弹窗时在途下载继续跑 | `AylaUpdateDialogSession` 持有 `CancelToken`，`_close` 时取消 |
| 9 | 测试夹具 `_availableCheck({mandatory})` 把形参写死成 `false` | 修正（否则所有「强制更新」用例其实测的是普通更新） |

```bash
/e/flutter-3.47.4/bin/flutter.bat test                            # 3308 通过 · 2 跳过 · 0 失败
cd android && ./gradlew :app:compileDebugKotlin -PskipDependencyChecks=true   # BUILD SUCCESSFUL
```

### 回归锁（新增 3 个文件）

| 文件 | 锁什么 |
| --- | --- |
| `test/update_login_autocheck_test.dart` | 会话恢复路径**真的**发起检查（有更新/已最新/失败/无令牌四种）；换会话复位；返回键分档；接线点存在 |
| `test/update_dialog_back_key_test.dart` | 真 `GoRouter` + 真 `AylaBackButtonHost`：可关弹窗按返回只关弹窗；**强制更新按返回弹窗仍在且不退出 App** |
| `test/title_bar_window_lock_test.dart` | 锁定期间三键全部失效（点关闭不调 `controller.close`） |

两个关键锁都做过**变异验证**：把修复摘掉后用例变红并停在准确断言行。

## 5. 已知未做（如实登记）

- `AylaUpdateApplyResult.scriptPath` / `fallbackUrl`、`releaseId`、`minSupportedBuild`、
  `AylaUpdateController.checking`、`AylaUpdateDialogSession.closed` 仍无消费者 ——
  其中 `scriptPath`（Windows 安装失败时的日志路径）值得后续补进失败文案；
- 顶栏「检查更新」不按 `checking` 禁用 ⇒ 连点两次第二次会弹「已有更新检查在进行中」；
- `publish_release.py` 没有 `--build` 上界校验（Windows VERSIONINFO 第 4 段 > 2^31-1 会溢出）；
- 客户端 `arch` 在 Android 上恒为空串，靠后端 `universal` 匹配；将来若拆 ABI 分包需让客户端上报真实 ABI。

## 6. 复核方法（不依赖本机调试实例）

```bash
# ① 公网接口：旧版本应得 update_available=true
curl -sk 'https://s.ayla.trise.top:26211/api/v1/updates/check/?channel=stable&platform=windows&arch=x64&version=1.0.0&build=1'
# ② 同版本应得 up_to_date
curl -sk 'https://s.ayla.trise.top:26211/api/v1/updates/check/?channel=stable&platform=windows&arch=x64&version=1.1.2&build=56'
```

真机验收（用户自行执行）：装旧版 → 冷启动（不点登录，靠已存的 refresh 静默续期）→
应看到更新弹窗；Android 上按返回键应只关弹窗、不退出 App。
