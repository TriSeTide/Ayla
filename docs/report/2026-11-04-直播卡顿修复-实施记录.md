## 2. 已实施改动

### 2.1 P0-1 缓冲目标 2 → 4（Web）

**文件**：`Ayla/web/src/player/hls.ts`

- 新增导出常量 `LIVE_SYNC_DURATION_COUNT = 4`（附实测依据注释）
- `new Hls({ liveSyncDurationCount: LIVE_SYNC_DURATION_COUNT })`
- 该值同时是 `refreshToLiveEdge()` seekable 兜底的回退量，语义一致

**依据**：同机同时刻 A/B（旧流）：sync=2 累计卡顿 17.5s / 3 次 bufferStalledError；
sync=4 累计卡顿 1.0s / 0 次。端到端延时仍 4~5s（需求 G5 目标 4~6s）。

### 2.2 P0-2 Flutter mpv 缓存对齐

**文件**：`Ayla/flutter/lib/player/platforms/media_kit_impl.dart`

- `cache-secs`：2 → **4**
- `demuxer-max-bytes`：8388608(8MB) → **12582912(12MB)**

**依据**：与 Web 端 sync=4 对齐；2s 缓存撑不过实测分片下载 p95=1.48s / max=6.69s。

### 2.3 P1-1 watchdog 出帧后永久失效（本次最关键 bug）

**文件**：`Ayla/web/src/runtime/liveSessionRuntime.ts`

- `clearStallTimer()` 现在**只清定时器**，不再拆监听器
- 新增 `detachWatchdog()`，只在 `destroyPlayer()` 与会话 `leave()` 调用
- 新增回归测试「出帧一次后 watchdog 仍然有效：后续卡死仍会自愈重建」
- **已做变异验证**：把旧行为（clearStallTimer 内调 detachWatchdog）塞回去，新测试立刻失败 ⇒ 测试确实锁住了该 bug

**依据**：旧实现下 armWatchdog 只在 rebuildPlayer 调用，而 onResume 出帧会触发
clearStallTimer 拆掉 5 个监听器 ⇒ 死锁。服务端日志印证：上游停摆 151s 期间重建 0 次、fatal 0 次。

### 2.4 P1-2 自愈参数与 Flutter 对齐

**文件**：`Ayla/web/src/runtime/liveSessionRuntime.ts`

- `STALL_TIMEOUT_MS`：2000 → **6000**（对齐 Flutter kStallTimeoutMs）
- `REBUILD_COOLDOWN_MS`：4000 → **8000**（对齐 Flutter kRebuildCooldownMs）
- 四个常量改为 `export`，测试直接引用，**避免改常量时测试静默失效**
- 测试里 20 处硬编码 `2_000/4_000/5_000` 改为引用常量 / `PAST_COOLDOWN`

### 2.5 P1-3 hls_dispose 120s → 0（服务端）

**线上文件**：`/home/ayerelysia/Elysia/ayla-deploy/srs.conf`（bind mount 成容器内 conf/docker.conf）

- 新增 `hls_dispose 0;`（不自动销毁；分片回收仍由 `hls_cleanup` 按窗口滚动）
- 备份：`srs.conf.bak-20261105-090204`
- **同时修正了 2 处误导性注释**（原注释写「窗口 10s / gop_cache off」，实际是 20s / on）

**仓库同步**：`Ayla/srs.conf`、`Ayla/deploy/examples/srs.conf.example` 已同步为生产实际值
（原两处写 `hls_window 10` / `gop_cache off`，与线上不符）。

**已重启并验证**：容器 `Up (healthy)`，API 200，配置 md5 一致，nginx -t 通过，网页 200。

### 2.6 P1-4 分片错误不再被静默丢弃

**文件**：`Ayla/web/src/player/hls.ts`

- `HlsPlayerCallbacks` 新增 `onFragmentError`：非 fatal 且带 `data.frag` 的分片级故障上报
- fatal NETWORK_ERROR 的重试改为 `startLoad(video.currentTime > 0 ? video.currentTime : -1)`
  （原来无参 `startLoad()` 等价 -1，而 hls.js 会用 lastCurrentTime 覆盖，语义不稳定）

### 2.7 P2-1 上游停摆判定（新增能力）

**文件**：`Ayla/web/src/player/hls.ts` + `liveSessionRuntime.ts`

- hls.ts 新增 `onPlaylistLevelUpdated`（`LEVEL_UPDATED` → 上报 MEDIA-SEQUENCE/startSN）
- runtime 新增 `UPSTREAM_STALL_WINDOW_MS = 12_000` 与 `noteMediaSequence / reportUpstreamStall /
  clearUpstreamStallTimer / resetUpstreamStallWatch`
- 序号停滞超窗口 ⇒ `currentPlayerError = "直播流已中断（上游停止推送），恢复后自动继续"`
- 恢复前进 ⇒ 自动清除；**不触发重建**（停摆期间重建也拉不到数据）
- 新增 2 条测试：停摆上报 / 停摆不重建

### 2.8 P2-5 Flutter 死代码清理

**文件**：`Ayla/flutter/lib/player/platforms/media_kit_impl.dart`
