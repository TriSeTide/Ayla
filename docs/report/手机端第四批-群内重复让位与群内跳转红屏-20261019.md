# 第四批手机端实报：群内重复让位与群内跳转红屏（2026-10-19 深夜）

> 用户实报（4 张截图，红框圈出群内一条空白带）：「**群内不需要这个**」

## 1. 群内场景不应重复让出状态栏

### 根因

第三批我给 4 个房间/详情组件在**玻璃材质内部**加了状态栏占位（一级沉浸路由的正确做法），
但**没意识到它们也被群内场景复用**：

| 路径 | 状态栏由谁着色 | 组件该不该自己让位 |
|---|---|---|
| 一级沉浸路由（`/live/:id` `/voice/:id` `/posts/:id` `/games/:id`） | 没有顶栏 ⇒ 组件自己让 | ✅ `topInset: true`（默认） |
| **群内场景**（`/group/:id/live/:cid` 等） | **群顶栏 `AylaGroupTopTabs` 已覆盖着色** | ❌ 必须 `topInset: false` |

⇒ 群顶栏之下又多出一条空白带：

```text
❌ 群内多一条空白带                   ✅ 正确
┌──────────────┐                  ┌──────────────┐
│ 23:12  5G ▮ │ ← 群顶栏玻璃      │ 23:12  5G ▮ │ ← 群顶栏玻璃
│ 语音 直播 主页│                  │ 语音 直播 主页│
├──────────────┤                  ├──────────────┤
│              │ ← 空白带（多余）    │ ← 直播头部    │
├──────────────┤                  └──────────────┘
│ ← 直播头部    │
└──────────────┘
```

### 修法：组件加 `topInset` 开关，群内显式关掉

| 组件 | 群内调用点 | 开关 |
|---|---|---|
| `AylaLiveRoomBody` | `pages/group_live_page.dart` | `topInset: false` |
| `AylaVoiceRoomHost` → `AylaVoiceRoomBody` | `pages/group_voice_page.dart` | `inGroup: true` → `topInset` |
| `AylaPostDetailChrome` ← `PostDetailPage` | `pages/group_posts_page.dart` | `inGroup: true` → `topInset` |
| `AylaGameRoomPlaceholder` ← `AylaGameRoomHost` | `pages/group_games_page.dart` | `inGroup: true` → `topInset` |

### 判定口诀

> **一个「页面组件」是否自己让状态栏，取决于它被谁渲染，不取决于它自己。**
>
> 凡**被群内场景复用**的房间/详情组件，都必须有 `topInset` / `inGroup` 开关，
> 且群内调用点**必须显式传 false** —— 群顶栏已经覆盖着色，再让一次就是空白带。

## 2. 群内跳转红屏（同一缺陷的 2 处遗漏）

### 现象

实机复验：点「加入」进群内语音房 ⇒ 整屏红：

```text
'package:flutter/src/widgets/navigator.dart': Failed assertion: line 4096 pos 18:
'!keyReservation.contains(key)': is not true.
```

### 为什么上一批没修干净

第三批我修了 3 处群路由 push，但用的是**单行 grep**：

```bash
grep -rn "context.push('/group" lib    # ← 只能匹配单行字面量
```

而下面两处是**多行字符串拼接**，grep 匹配不到：

```dart
context.push(
  '/group/${Uri.encodeComponent(widget.groupId)}/voice/'
  '${Uri.encodeComponent(channelId)}',
);
```

### 修复

- `pages/group_voice_page.dart`：进群内语音房（`onJoin`）→ `go`
- `pages/group_posts_page.dart`：群帖列表 → 帖子详情（`_openPost`）→ `go`

### 新增回归锁：`test/no_group_push_test.dart`

**静态扫描 `lib/` 全部源码**：逐个定位 `context.push(`，做**括号配对**取出完整实参文本，
只要实参里出现 `/group` 即判失败。

为什么必须用静态扫描而不是普通测试：
| 手段 | 为什么抓不到 |
|---|---|
| `dart analyze` | `push` / `go` 签名相同，不报错 |
| 常规 widget 测试 | 只有恰好点到那条路径才会炸 |
| 单行 grep | 漏多行拼接（**本轮就是这样漏的**） |

## 6. 流程教训

1. **改一个组件的「环境假设」时，必须先查它被几处复用** —— 尤其是「被群内复用」这个模式，
   本项目有 4 处（直播/语音/帖子/桌游）。
2. **grep 排查多行代码不可靠** —— 多行字符串拼接会漏。要么用括号配对扫描，要么写测试。
3. **同一天内同一个缺陷漏两次**，说明排查手段本身有问题（我第一次用单行 grep）。
   ⇒ 改用**可重复执行的静态检查**（`test/no_group_push_test.dart`），而不是人工 grep。
4. **共享工作区里的 `tmp_*_test.dart` 不是你的** —— 不要删、不要改，用定向测试集验收。
