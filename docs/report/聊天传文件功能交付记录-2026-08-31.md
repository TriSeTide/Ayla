# 聊天传文件（file 消息）功能交付记录 — 2026-08-31

> 任务来源：`.workbuddy/prompts/ayla/02-聊天传文件.md`（群聊/私信新增消息类型：文件，单文件任意格式，气泡显示文件名+可下载，列表预览显示文件名）。

## 1. 需求本质

新增消息类型 `file`（单文件传输）：

- **入口**：composer 新增「文件」按钮，与图片/视频、语音按钮并列；`<input type="file">` 不设 `accept`（任意格式）、不 `multiple`（单文件）；
- **气泡**：显示文件名 + 大小 + 下载按钮（复用既有 `FileMedia`，无需重做，但本次补齐上传/发送/预览前半段并实测下载链路）；
- **列表预览**：会话列表/消息中心/宽屏左侧栏/群活跃度预览显示**文件名**（非 `[文件]` 占位）；
- **单文件互斥**：一条文件消息只传一个文件，不与图片/视频混排（`file` 是单媒体消息类型，不走 mixed 段）。

## 2. 契约

### 2.1 消息类型（已存在，本次未新增迁移）

- `Message.TYPE_FILE = "file"`（`backend/apps/chat/models.py` L108，choices 早已含）——无需迁移；
- `MediaObject.KIND_FILE = "file"`（`backend/apps/media/models.py` L29）——上传 API 已支持 file kind；
- 文件消息契约：`content` 存**文件名**（前端发送时写入，气泡 `caption(msg)` 读取），`media_id` 指向 file kind 媒体。

### 2.2 任意格式与安全边界（本次后端改动）

- 原 `ALLOWED_MIME["file"]` 是有限白名单，不满足「任意格式」；改为**黑名单模式**（`_mime_allowed` 对 `KIND_FILE` 除可执行文档外一律放行）：
  - 新增 `_FILE_BLOCKED_MIMES` = `{text/html, application/xhtml+xml, image/svg+xml, application/javascript, text/javascript, application/x-javascript, application/xml, text/xml}`；
  - 魔数嗅探 `_sniff_kind` 对 file 本已只要求非空（`len(data) > 0`），不再收紧；
  - 大小上限仍为 `MEDIA_MAX_FILE_BYTES = 50MB`（未改）。
- 安全依据：下载走 `<a download>` + 签名 URL（MinIO 直连），content 端点已有 `X-Content-Type-Options: nosniff` + CSP；黑名单双保险排除浏览器可直接打开执行脚本的文档类型。

### 2.3 列表预览（本次后端改动）

- `message_preview` 对 `TYPE_FILE` 取 `content`（文件名），非 `[文件]` 占位；`content` 为空才回退 `[文件]`；
- 前端 `ConversationList.previewLabel` / `groupActivity.messageEvent` 均以 `preview || content || 占位` 顺序渲染，后端 preview 生效即透传文件名；WS `message.new` 帧 `d.content`（=文件名）已天然覆盖。

### 2.4 发送链路（本次前端改动）

- `validateMediaFile` 三分类：image/video 白名单 → file（任意格式，排除可执行文档，`>50MB` 报错）；
- 文件按钮 → 入队（`kind=file`）→ 乐观 `type=file` 气泡（`content=文件名`，`localMedia` 单 file 项）→ 上传（`uploadMediaFile(file, "file")`）→ `POST messages/` `{type:"file", content:文件名, media_id}`；
- 重试 `retryOptimistic` 对 file 走同契约（复用幂等键）；file 项不构造 mixed segments。

## 5. 已知基线问题（与本次改动无关，任务 01 已记录，此处复述）

- **Django 5.2 SQLite 测试环境不支持 JSON contains**：`segments__contains`（@ 未读查询）在 SQLite 抛 `NotSupportedError`，`test_message_api.py`/`test_conv_api.py` 等任何触发会话序列化的用例全量失败（生产/开发用 MySQL 不受影响）。本次 file preview 测试改为函数级 `message_preview` 单测避开。
- **`conversation-list.test.tsx` 删除用例**：`ConversationMoreMenu` 已从 `window.confirm` 换成自定义 `ConfirmDialog`（commit eca5dec），旧测试仍 `spyOn(window, "confirm")`，点「删除会话」后不弹 confirm → 超时失败（与本次改动无关，未在本任务修）。
