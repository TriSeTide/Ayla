# 在线状态「自动」改造交付记录（任务 06）

> 日期：2026-09-01 ｜ 状态：代码 + 契约测试 + Playwright 局域网 https 实测验收通过

## 1. 需求

在线状态四选项「在线/勿扰/离开/隐身」中，「在线」改为「自动」（auto），并实现在线状态显示：

- auto → 按实时 presence 显示「在线」或「离线」；
- dnd → 显示「勿扰」；
- away → 显示「离开」；
- invisible → 显示「离线」（对外完全离线，不暴露在线痕迹）。

「显示状态」（User.status 用户选择的模式）与「实时在线」（Redis presence）是两层，显示规则 = f(status, 实时在线)。

## 3. 关键设计

1. **后端权威文案**：`display_status` 由 `UserPublicSerializer` 按 `User.status` + Redis presence 计算，所有 REST 消费方统一；
2. **前端两层合并**：presence WS 增量（实时）优先，REST 快照兜底，规则只写在一处工具函数，所有显示点统一消费；
3. **presence 语义收敛**：Redis presence 只表达「连接存在」（值恒 online），隐身（invisible）是对外可见性语义、由 `User.status`（DB 实时）承载——`get_online`/`display_status`/前端 `presenceOnline` 三方一致，运行中切换隐身/恢复 auto 立即生效、无需重连；
4. **隐身边界三层**：REST（get_online 查 status）＋ WS（隐身不广播上线）＋ 前端（presenceOnline 对 invisible 强制离线），保证光环/文案双通道零泄漏；
5. **广播组修复**：`presence_<id>` 个人组无人消费，在线/离线广播从未投递（历史 F2「在线状态显示矛盾」的根因之一）；本次让客户端加入全局 `"presence"` 组，WS 实时更新全链路打通；
6. **迁移**：存量 `online` 值 → `auto`；presence 不迁移。
