# 戳一戳（poke）功能交付记录 — 2026-08-31

> 任务来源：`.workbuddy/prompts/ayla/01-戳一戳.md`（新消息类型：双击头像触发、居中提示、置顶但不打扰）。

## 1. 需求本质

新增消息类型 `poke`（戳一戳）：

- **触发**：双击消息头像（自己的头像也触发）→ 发送 poke；
- **展示**：聊天界面居中提示（非气泡，玻璃胶囊式样）文案 `xx戳了戳xx`；
- **列表预览**：会话列表/消息中心/宽屏侧栏/群列表预览统一为 `xx戳了戳xx`；
- **置顶但不打扰**：收到 poke → 会话按「最近活跃」往前排；**不产生红点、不增加未读数、无已读/未读属性**；
- 群聊与私信都支持；poke 落库进会话历史（刷新/重进后可见）。

## 2. 契约

### 2.1 消息类型

- `Message.TYPE_POKE = "poke"`（`backend/apps/chat/models.py` + 迁移 `0010_message_alter_type_poke.py`）；
- `content` 字段存**目标用户 id**（轻量、不随昵称变化）；
- poke 不携带媒体、不支持引用；发送校验：目标必须是会话成员（`CreateMessageSerializer.validate`）；
- 私聊发 poke 仍受好友校验（与普通消息一致）；禁言成员不可发。

### 2.2 未读/已读语义（刻意排除）

- `ConversationSerializer._unread_queryset` 增加 `.exclude(type=Message.TYPE_POKE)`：
  未读数、未读序号、@我、回复未读、mention_unread_count 全部不含 poke；
- poke 不写 `MessageRead`（无已读回执），`MessageList` 视口已读 observer 跳过 poke。

### 2.3 WS 帧（独立事件，不混入 message.new）

`message.poke`：

```json
{
  "type": "message.poke",
  "data": {
    "conversation_id": "1",
    "message_id": "42",
    "sender_id": "u1",
    "sender_name": "小乙",
    "target_user_id": "u2",
    "target_name": "小甲",
    "seq": 5,
    "ts": "2026-08-31T00:00:00Z"
  }
}
```

- 发送：`POST /api/v1/chat/conversations/<id>/messages/` body `{type: "poke", content: <target_user_id>, idempotency_key}`；
- 后端落库后广播 `message.poke`（`services.broadcast_message_poke`），**不**广播 `message.new`，**不** inject 爱莉主链；
- `resume` 补发：poke 消息走 `message.poke` 帧（绝不走 `message.new`，否则前端会进未读路径）；
- 前端收到 `message.poke`：消息进会话流 + 预览更新 + 群 `bumpGroupActivity` / 私信 `bumpConversationActivity`；**不** bumpUnread、**不**拉 badges、**不**弹红点。

### 2.4 预览文案

- 后端 `message_preview`：`"发送者戳了戳目标"`（昵称缺失回退「有人/对方」）；
- 前端群聊列表/群活跃描述不加「发送者:」前缀（poke preview 已含发送者名，避免 `A：A戳了戳B`）。

## 5. 已知基线问题（与本次改动无关，如实记录）

**Django 5.2 SQLite 测试环境不支持 JSON contains**：`django.db.backends.sqlite3.features.supports_json_field_contains = False`（硬编码），
M8（@ 能力，commit d2bf087）引入的 `segments__contains` 查询在 SQLite 测试环境必然抛
`NotSupportedError: contains lookup is not supported`。受影响：`test_conv_api.py`、`test_message_api.py`、
`test_friend_private_send.py` 中**任何序列化会话**（触发 get_mention_unread_count/get_mention_unread_seqs）的用例，
以及 `conversation-list.test.tsx` 的删除用例（eca5dec 将 window.confirm 换成 ConfirmDialog 后测试未同步，
spy window.confirm 已无效）。

- 本任务 poke 测试刻意绕开会话序列化路径（未读排除用 DB 级断言 + message_preview 单测）；
- 生产/开发环境使用 MySQL，不受影响；
- 待办归属：建议在 MySQL 测试库跑全量契约测试，或为 SQLite 测试提供 contains 等价实现。
