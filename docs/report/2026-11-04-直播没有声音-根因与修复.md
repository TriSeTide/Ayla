# 2026-11-04 Ayla web 直播没有声音 —— 根因与修复

> 用户实报：**Ayla web 的直播没有声音**（画面正常、弹幕正常、无报错）。
> 性质：只读诊断 + 前端修复。服务端与 SRS 配置**未做任何改动**。
> 关联：`Ayla/docs/design.md` §12.7.3 / §12.7.4 / **§12.7.6（新增）**。

## 1. 结论摘要

**根因在前端播放器：`<video>` 以 `muted = true` 创建，此后全仓没有任何一处把它设回 `false`，播放器也没有音量/静音按钮。所以直播从头到尾都是静音的。**

服务端音频链是健康的（下面 §2 有实测证据），HLS 与 SRS 都正常。这不是"流里没有音频"，是浏览器端把音频轨静音了且永不解除。

## 3. 根因：静音只进不出

`Ayla/web/src/runtime/liveSessionRuntime.ts`：

```ts
private ensureVideo(): HTMLVideoElement {
  if (!this.videoEl) {
    const v = document.createElement("video");
    v.className = "live-player-video";
    v.muted = true;        // ← 起点：自动播放策略要求
    v.autoplay = true;
    v.playsInline = true;
    ...
```

全仓检索结果（修复前）：

| 检索 | 结果 |
| --- | --- |
| `grep -rn 'muted' src/runtime/liveSessionRuntime.ts src/hooks/useLiveRoom.ts src/components/live/*.tsx` | 只有 1 处命中：`liveSessionRuntime.ts:400 v.muted = true` |
| `grep -rn 'muted = false\|muted=false\|muted: false' src/` | 直播域 **0 处**（命中全在语音房 / 测试夹具，与直播无关） |
| 播放器控件 | 左下只有刷新键，右下只有画中画 + 全屏 —— **没有音量键** |

### 3.1 为什么当初必须 muted（这不是随手写的）

浏览器自动播放策略（Chrome / Safari 一致）：**无用户手势时，只有 `muted` 的媒体允许自动 `play()`**。
直播间是路由直达页，用户没点过播放器，所以 `<video>` 必须以 `muted = true` 起播，否则 `play()` 直接 `NotAllowedError` → 黑屏。

**问题不在于"起播时静音"，而在于把"起播手段"当成了"最终状态"**：播放真正开始（`playing` / `canplay`）之后，静音这个理由就消失了，但代码里没有任何一处去解除它，也没有给用户一个手动解除的入口。

### 3.2 演进史（为什么一直没被发现）

- `c55856a`（M5-4 契约层）起，`<video>` 就是 React 直接渲染的 `muted autoPlay`；
- `c8398cd`（B 站式体验优化）注释写着"muted autoplay 起播，**用户手势后取消静音**"——但**该逻辑从未实现**，注释与代码不符；
- `c78c27f`（手机端小窗）把 video 元素提升到 runtime 单例持有，`ensureVideo()` 把 `muted = true` 固化在元素创建处；小窗继续复用同一元素，静音状态一路继承。

### 3.3 与 2026-10-18 那次故障的区分

`docs/operations/直播播放修复说明.md` 记录的是 **App（Flutter）** 播放失败（TLS 握手被中间设备重置），web 当时是正常的。
本次是 **web** 无声，且与网络/TLS 无关（画面正常）。两次故障根因不同，不要混为一谈。

## 4. 修复

### 4.1 设计原则

**静音起播 + 起播后按用户偏好自动恢复 + 始终提供手动音量键。**

1. **不能为了出声牺牲画面**：恢复失败时静音继续播，绝不让 `play()` 失败导致黑屏；
2. **不能篡改用户偏好**：浏览器拒绝自动出声时，用户偏好仍是"有声"，下次有手势时继续尝试；
3. **单一 owner**：video 元素归 `liveSessionRuntime`，静音状态也归它；store 只镜像投影，组件只读投影。

### 4.2 改动清单

| 文件 | 改动 |
| --- | --- |
| `web/src/runtime/liveSessionRuntime.ts` | 新增 `isMuted()` / `setMuted()` / `toggleMuted()` / `retrySound()`；`ensureVideo()` 起播即镜像 `muted=true` 到 store；`playing`/`canplay` 回调里调 `retrySound()` 按偏好恢复声音；`leave()` 不动偏好 |
| `web/src/stores/live.ts` | 新增 `muted` 字段 + `setMuted()`；导出 `readLiveMuted()` / `writeLiveMuted()`（localStorage `ayla.live.muted`，`"1"`=静音，异常兜底为有声）；`clearCurrent()` 不动偏好 |
| `web/src/components/live/LivePlayer.tsx` | 新增 `muted` / `onToggleMute` props；左下 `.live-player-left` 并排「跳到最新 + 音量」两个 32px 圆钮；`aria-label` = 「打开声音」/「静音」 |
| `web/src/components/live/LiveMiniPlayer.tsx` | 小窗左上角 24px 音量键 `.live-mini-player-mute`（材质同关闭键）；点击不触发返回、不启动拖动 |
| `web/src/components/live/LiveRoomBody.tsx` | 接线 `muted={muted}` / `onToggleMute={toggleMute}` |
| `web/src/styles/app.css` | 新增 `.live-player-left` 容器；`.live-player-refresh` 定位上移给容器；全屏弹幕输入框宽度 `calc(100% - 120px)` → `calc(100% - 176px)`（左下由 1 钮变 2 钮） |
| `web/src/styles/live.css` | 新增 `.live-mini-player-mute` |
| `Ayla/docs/design.md` | 新增 §12.7.6「直播声音（静音起播 + 偏好恢复 + 音量键）」；§12.7.3 / §12.7.4 同步控件口径 |

### 4.3 恢复时序（关键路径）

```
enter() → ensureVideo(): muted=true  ──┐  自动播放策略放行
                                       │
hls attach → video 开始出帧              │
                                       ▼
                          playing / canplay 事件
                                       │
                          retrySound(): 偏好=有声?
                              ├─ 否 → 保持静音（用户选的）
                              └─ 是 → muted=false + play()
                                        ├─ 成功 → store.muted=false（喇叭变"静音"态）
                                        └─ 拒绝 → muted=true 回退，画面继续播，
                                                   偏好不变，用户点音量键即可出声
```

### 4.4 为什么自动恢复值得做（而不是只给按钮）

只给按钮的话，用户进每个直播间都要点一次才出声，体验比"B 站点进去就有声"差一截。
实测多数桌面浏览器在**同一 origin 已有过媒体播放**后会放行无手势的 `play()`（media engagement index）；
即便被拒，回退路径保证画面不受影响，用户点一下即可 —— 收益大于风险。

### 5.1 服务端（只读，已执行）

见 §2：SRS 流 `publish.active=true` + audio AAC 立体声；HLS 分片 ffprobe 含 audio stream。
**结论：无需改动服务端任何配置。**（SRS 配置、nginx、后端 `.env` 均未动。）

### 5.2 前端：真实 Chromium 端到端（决定性证据）

**不是只跑单测**。用 Playwright 驱动真实 Chromium（`--autoplay-policy=user-gesture-required`，
即默认的"无手势不许有声自动播放"策略），加载**本地 dev server 上的修复后代码**，
`/api` 走真实线上后端，进入**真实正在推流的直播间（频道 2）**，用 Web Audio
`AnalyserNode` 采样该 `<video>` 的真实音频波形测峰值。

```
gotFrame: true                          ← 真实 HLS 出帧
afterAutoRecover:
  videoMuted: false                     ← 自动恢复声音生效
  paused: false, readyState: 4
  volumeBtnExists: true
  volumeBtnLabel: "静音"                 ← 有声态的正确文案
  prefStorage: null                     ← 偏好未被写脏（关键回归点）
  leftBtns: ["跳到最新画面", "静音"]      ← 左下两个钮并排
audioLevel:
  peak: 0.0962, samples: 40             ← ★ 真实音频波形非零 = 真的在出声
afterClickMute:  { videoMuted: true,  prefStorage: "1", label: "打开声音" }
afterClickUnmute:{ videoMuted: false, prefStorage: null, label: "静音" }
```

**peak 0.0962 是本次修复的决定性证据**：修复前该值恒为 0（`video.muted === true`，
音频被硬静音）；修复后非零且随声音起伏。

> 同时验证了**线上部署的仍是旧构建**：直接访问 `https://s.ayla.trise.top:26211/live/2`
> 得到 `volumeBtnExists: false / videoMuted: true / audioLevel.peak: 0` ——
> 用户报的"没有声音"在线上可复现，且线上代码就是静音不恢复的旧版本。
> 修复要生效必须**重新构建并部署 web 产物**（见 §7.1）。

### 5.3 自动播放策略边界（真实 Chromium 实测）

| 场景 | 结果 |
| --- | --- |
| 默认策略：静音起播 → 出帧后取消静音 | **放行**（`retrySound` 返回 ok，muted=false） |
| 最严格 `document-user-activation-required`：静音起播 → 取消静音 | **仍放行**（muted=false） |
| 最严格策略：从未播放过 → 直接取消静音 | **仍放行**（Chrome 对 `muted=false` 赋值本身不拦截，只拦有声 `play()` 起播） |

结论：本修复的自动恢复路径在 Chromium 全策略档位下都能出声；
回退分支（`play()` 被拒 → 回退静音）仍保留，用于应对未来策略收紧与 Safari 差异。

### 6.4 独立复核（Lead）

Lead 在合并前独立复跑了 8 个直播域文件（105 tests）、全量 1437 tests 与 `tsc --noEmit`，
并逐个审阅了两名成员的全部 diff。

**Lead 复核中拦下的一个真实缺陷**（已修复，是本次交付最重要的质量点）：
初版把 `writeLiveMuted()` 写在 `store.setMuted` 里，而 `ensureVideo()`（每次进房）与
`retrySound()` 的失败分支这两个**非用户手势**路径也调 `store.setMuted`：

1. 每进一次直播间就把 `"1"` 写进 localStorage ⇒ 用户明明偏好有声，只是还没等到
   `playing`，偏好就被改写成"静音"；
2. 更致命的是它**让自动恢复根本不发生**：`ensureVideo()` 写 `"1"` 后，
   `retrySound()` 开头的 `if (readLiveMuted()) return` 立刻 bail out —— 声音永远恢复不了。

修法：`store.setMuted` 只做投影 `set({ muted })`；`writeLiveMuted` 的唯一调用点收敛到
`liveSessionRuntime.setMuted()`（用户手势）。并补了 2 条防回归用例
（`ensureVideo 不得改动 localStorage 偏好`、`自动恢复被拒时偏好不变`）。
**这条正好说明"偏好语义洁癖"不是洁癖，它是恢复声音能工作的前提。**

## 7. 回滚

纯前端改动，回滚 = 还原上表 7 个源文件 + `docs/design.md`。
无数据库迁移、无服务端配置变更、无协议变更 ⇒ 回滚不影响已部署的 App 与后端。
用户偏好键 `ayla.live.muted` 留在 localStorage 无副作用（旧版本代码不读它）。

### 7.1 修复要生效必须重新部署 web 产物（重要）

本次验收同时确认：**线上 `s.ayla.trise.top:26211` 跑的仍是旧构建**（详见 §5.2 末尾）。
代码修好 ≠ 用户听到声音，还需重新构建并发布 web 静态产物到 `~/Elysia/ayla-deploy/web`。

**这是本次交付唯一未完成的一步，归属用户/运维决策**（部署时点由用户定，
且部署属对外可见动作，不在本次"修 bug"的授权范围内）。验证方式：部署后打开任意在播
直播间，左下应出现两个钮（跳到最新 + 喇叭），喇叭图标初始为「静音」态、出帧后自动变「静音」可点态。
