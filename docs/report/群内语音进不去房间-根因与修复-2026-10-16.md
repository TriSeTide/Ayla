# 群内语音「进不去房间」+ 侧栏语音行消失 —— 根因与修复（2026-10-16）

## 现象（用户实报）

Flutter（Ayla/flutter，Windows）群聊宽屏第 2 列点语音房行 / 群内语音场景点卡片：

1. **进不去语音房** —— 停在「正在加载语音房…」骨架，永远不渲染房内界面；
2. **侧栏语音房行整批消失** —— 语音帧（有人进出）到达后，第 2 列的语音房行从列表里被摘掉；
3. **群不往前排** —— 新建语音房 / 群里有人开语音，群列表（服务器栏）顺序不动；
4. **侧栏语音人数不对** —— 「语音」场景项右侧的裸数字偏小。

web 同场景一切正常。

## 根因

### 主因：目录取页落地钩子丢了 `allowed_group_ids`（一处缺列，三条链路同时受损）

web 的目录条目**就是**域 store 的描述符本身（同一个对象），字段不存在搬运损失：

| 环节 | web 事实源 |
|---|---|
| 目录缓存条目 = `useVoiceStore.channels` 的**同一批对象** | `stores/directory.ts:143–146` |
| 取页结果逐条 `upsertChannel(item)` —— 传的是**原对象** | `stores/directory.ts:310–320` |
| 目录条目类型 = 完整 `VoiceChannelDescriptor`（含 `allowed_group_ids`） | `api/types.ts:863–885` |

Flutter 侧的目录条目是**卡投影 + 活动事实**（`AylaDirectoryVoiceEntry`），域 store 存的是
`AylaVoiceChannelSnapshot`，两者之间**必须有一次逐字段搬运**，落点是
`flutter/lib/state/room_providers.dart` 的 `_onVoiceDirectoryItem`。

该搬运漏传 `allowedGroupIds`（对照同文件的 `_onLiveDirectoryItem` —— 直播侧一直有传），
于是域 store 里的语音房的 `allowedGroupIds` **恒为空列表**，而它是三处判据的唯一来源：

| # | 判据 | web | 漏列后的表现 |
|---|---|---|---|
| ① | 群内房内命中：本地列表里白名单含本群才渲染房内界面 | `GroupVoice.tsx:121–129` | `_roomChannel()` 恒 null ⇒ 落到骨架 = **进不去房间** |
| ② | 群活跃度 `visibleInGroup`：白名单含本群才计入「新内容」事件 | `groupActivity.ts:70–76` | 事件恒缺席 ⇒ `sortGroupsByActivity`（tsx 205–209）不把它往前排 |
| ③ | 目录 `matchesQuery`：`groupId` 档复查每行白名单 | `stores/directory.ts:110–113` | 投影回目录缓存的行被判「不属于本群」⇒ 从群桶 record 里**整批移出** = **侧栏行消失** |

三条链路都指向同一行缺失，只是表现面不同（房内 / 群列表 / 侧栏）。

### 次因 1：补拉跳过条件比 web 宽（把「存在」当成了「本群可见」）

`flutter/lib/pages/group_voice_page.dart` 的 `_ensureRouteChannel()` 原写
`if (channelOf(id) != null) return;` —— 只要本地有该 id 就跳过补拉。

web（`GroupVoice.tsx:88–90`）是：

```tsx
if (!routeChannelId || channels.some((item) => item.id === routeChannelId
  && (fromShare || (item.allowed_group_ids ?? []).some((id) => String(id) === String(groupId))))) return;
```

⇒ 跳过的前提是「**本地已有 且 本群可见**」。只判存在时，「存在但白名单不含本群」的频道
会**永远停在骨架**：补拉被跳过（不进域 store 纠正）、房内命中判据又为假 —— 这是「进不去」的第二条独立路径。

### 次因 2：侧栏语音人数取错了来源

`flutter/lib/pages/group_page.dart` 原用 `_voiceMemberCount(voice)` —— 把**域 store 快照**里
本群房间的 `member_count` 求和。

web（`ChannelSidebar.tsx:126–127`）用的是**目录响应的 `total_member_count`**：

```tsx
const voiceCount = voiceDirectory.totalMemberCount ?? 0;
```

后端 `apps/voice/views.py:141–144` 的原话解释了为什么必须用它：

> 侧栏人数是完整可见目录的成员数，不能把首屏成员和冒充总数。

即：分页只返回前 20 条，域 store 里也只有「用户进过 / 有过帧」的房间，
两者都会让求和结果偏小。`total_member_count` 为 `null`（presence 存储不可用）时按 0 —— 裸文本不渲染（不伪造「0 人在聊」）。

### 附带：目录条目缺 `group` 列（分享载荷退化）

`AylaDirectoryVoiceEntry` 没有 `group` 字段 ⇒ 快照搬运时该列恒 null ⇒ 房内分享载荷的
`extra.group_id` 恒为 null（web `VoiceRoomBody.tsx:281–287` 的 `group_id: channel.group`
→ `sharePayload.ts:56`）。与主因同源（同一处搬运），一并补齐。

⚠️ 注意 `group` 与 `allowed_group_ids` **不是同一列**：前者是「本房归属哪个群」（单一 FK），
后者是「哪些群可见」（多对多白名单）；`is_owner` 也不搬 —— 语音快照承载「我是否在其中」的列是
`mine`，与直播 descriptor 的 `is_owner`（我是否房主）语义不同。

## 修复（`Ayla/flutter/lib/`）

| 文件 | 改动 |
|---|---|
| `state/room_providers.dart` | `_onVoiceDirectoryItem` 补齐 `allowedGroupIds` / `group` 两列（**根因修复**） |
| `core/api/voice_api.dart` | `AylaDirectoryVoiceEntry` 增加 `group` 列（构造 + `fromJson`） |
| `pages/group_voice_page.dart` | `_ensureRouteChannel()` 跳过条件对齐 web「已有且本群可见」 |
| `pages/group_page.dart` | 侧栏语音人数改读 `_voice?.totalMemberCount ?? 0`（删掉旧的求和函数） |
| `pages/hub_support.dart` / `state/directory_tracking.dart` | 两处条目搬运点同步带上 `group`（保持「逐字段搬运、零丢失」不变量） |

## 未做 / 待决

- **真机音频联测未做**：本轮修的是「进房判定与列表投影」，进房后的音频中继本身未改动；
  音频需用户在自己的调试实例里实测（agent 不代起预览）。
  本条是当前唯一的验收缺口：自动化已覆盖「进得去」，未覆盖「听得见」。
- **`fromShare` 分支仍未接**（`group_voice_page.dart` 文件头「机制差异 2」的既有登记）：
  web 从分享消息进房时免白名单校验，Flutter 侧路由不带 state ⇒ 一律走严格白名单档。
  本轮**未扩大**该偏离，但它意味着「从分享消息点进他群语音房」在 Flutter 侧仍会停在骨架（不伪造可见）。
- **直播侧同类缺口已核**：`_onLiveDirectoryItem` 一直有传 `allowedGroupIds`（未受影响）；
  直播条目缺 `group` 列（分享载荷同源问题）**本轮未改** —— 它不在用户实报范围内，
  留作独立小改（涉及 3 个页面调用点，见下）。
