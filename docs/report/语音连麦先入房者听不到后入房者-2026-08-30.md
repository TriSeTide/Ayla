# 语音连麦「先入房者听不到后入房开麦者」修复（2026-08-30）

## 1. 问题现象（用户报告）

语音功能连麦体验不连贯：

1. 账号 A 先进入语音房；
2. 账号 B 后进入语音房并开麦；
3. A 听不见 B 说话；
4. A 返回重新进入语音房，才听见 B 说话。

用户定性为「有状态没有热更新」——已在线客户端没有对后加入者做实时订阅。

> 镜像场景（同一根因，用户二次报告）：账号 A 先进房**不开麦**，账号 B 后进房；随后 A 开麦，
> B 听不见 A；B 重进后才听见 A。此处 B 进房时 A 尚未开麦，`attachExistingRemoteAudio()` 对 A
> 无可 attach；A 开麦属于「听者连接稳定后新发布的轨道」，依赖 `TrackSubscribed` 事件 attach，
> 与场景 1 完全同源——事件名修对后两个场景一并恢复。

## 2. 根因

`Ayla/web/src/livekit/client.ts` 中，`createLiveKitRoom()` 用 `room.on(...)` 注册的
**所有媒体层事件名写成了 PascalCase**（`"TrackSubscribed"`、`"ParticipantConnected"`、
`"Disconnected"` 等），而 livekit-client 2.21 的 `RoomEvent` 枚举值实际是
**camelCase**（`"trackSubscribed"`、`"participantConnected"`、`"disconnected"` 等）。

livekit-client 的事件名是大小写敏感的字符串匹配，因此这 10 个监听器**全部静默失效**，
没有任何报错。

### 与现象逐条对应

- A 先进房：`connect()` 成功后 `attachExistingRemoteAudio()` 遍历 `room.remoteParticipants`
  补齐已有轨道，但此刻房间只有 A 自己，遍历为空，什么都没 attach；同时 `connect()` 末尾
  手动 `onStateChange("connected")`，所以 UI 显示连接正常。
- B 后进房开麦：B 的音频轨对 A 是「连接后新订阅」，本应触发 `TrackSubscribed` → attach；
  但监听器因事件名错误未挂上，B 的音频轨**从未被 attach** → A 听不见 B。
- A 重进：`connect()` 时 B 已在房间，`attachExistingRemoteAudio()` 遍历到 B 的轨道并
  attach → A 听见 B。

### 连带影响（同一根因，本次一并修复）

| 失效事件 | 后果 |
| --- | --- |
| `TrackSubscribed` / `TrackUnsubscribed` | 新入房/开麦者的音频轨不 attach / 不 detach（本次主症状） |
| `Disconnected` / `Reconnecting` / `Reconnected` | 媒体断线/重连时 `onStateChange` 不更新，`livekit="failed"/"reconnecting"` 状态与「重新加入」入口失效（隐藏 bug） |
| `TrackMuted` / `TrackUnmuted` | 远端静音事实不同步到 UI |
| `ActiveSpeakersChanged` | 说话指示事件失效 |
| `ParticipantConnected` / `ParticipantDisconnected` | 远端参与者进出事件失效（成员表以 voice.state 为准，影响较小） |

### 为何测试没拦住

`Ayla/web/src/vitest/create-livekit-room.test.ts` 的 RoomMock 用
`h.emit("TrackSubscribed", ...)` / `h.emit("TrackMuted", ...)` 等 **PascalCase** 事件名，
与 client.ts 的错误写法一致，mock 自洽通过，但脱离了真实 SDK 的 camelCase 枚举值。
即：测试验证了「client 在收到 `"TrackSubscribed"` 时 attach」，却没验证「真实 livekit-client
发出的事件名是 `"trackSubscribed"`」。

## 3. 证据来源

- `Ayla/web/src/livekit/client.ts`（修复前）：`room.on("TrackSubscribed", ...)` 等 10 处 PascalCase。
- `Ayla/web/node_modules/livekit-client/src/room/events.ts`（只读核对）：
  `RoomEvent.TrackSubscribed = 'trackSubscribed'`、`ParticipantConnected = 'participantConnected'`、
  `Disconnected = 'disconnected'`、`ActiveSpeakersChanged = 'activeSpeakersChanged'` 等，全部 camelCase。
- `Ayla/web/src/vitest/create-livekit-room.test.ts`：`h.emit("TrackSubscribed", ...)` 等 PascalCase mock。

## 4. 已执行操作（均可逆，纯字符串修正）

- `Ayla/web/src/livekit/client.ts`：
  - `RoomEventName` 类型 10 个字符串字面量改为 camelCase，并在类型注释处记录本事故，防止回归；
  - 10 处 `room.on("PascalCase")` 改为 `room.on("camelCase")`，并在注册处加注释强调「事件名必须与
    RoomEvent 枚举值逐字一致，改前先核对 events.ts」。
- `Ayla/web/src/vitest/create-livekit-room.test.ts`：3 处 mock `h.emit("TrackSubscribed"/"TrackUnsubscribed"/"TrackMuted")`
  改为 camelCase，使测试与真实 SDK 对齐。

## 5. 验证

- 静态核对：grep `client.ts` 确认 10 处 `room.on(...)` 全部为 camelCase、无遗留 PascalCase；grep 测试文件确认 3 处 `h.emit(...)` 已对齐。
- 单元/类型检查与真实双账号 E2E 由用户执行（用户明示「测试我来测试」）。
