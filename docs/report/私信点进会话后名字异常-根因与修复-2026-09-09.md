# 私信点进会话后左侧栏/顶栏名字异常 —— 根因与修复（2026-09-09）

## 现象

宽屏下点进一个私信会话（/messages → /chat/:id）后：左侧栏（WideMessagesSidebar）当前会话显示"未命名会话"，顶栏（PrivateChatPane 头部）名字变"私聊"。

## 根因

`PrivateChatPane` 挂载时调用 `getConversationMetadata(conversationId)`（`GET /chat/conversations/<id>/?metadata=1`），返回 `ConversationDetail`——**该序列化器没有 `peer` 字段**（`ConversationMetadataSerializer` 继承 `ConversationSerializer`，fields 不含 peer；只有列表用的 `ConversationListSerializer` 有 peer）。

`useChatStore.upsertConversation` 的归一函数 `toSummary` 把缺失的 peer 补成 `null`，合并时 `{ ...c, ...normalized }` 用 `peer: null` **覆盖了已有会话的 peer**：

1. chat store 里该会话 peer 变 null → `PrivateChatPane` 顶栏 `peer?.nickname || peer?.username || "私聊"` → 显示"私聊"；
2. `ensureSocialTracking` 的 `reconcileCached` 用 chat store 会话替换 social store 同 id 会话 → 左侧栏 `conv.peer?.nickname || ... || "未命名会话"` → 显示"未命名会话"。

## 修复（`web/src/stores/chat.ts` upsertConversation）

1. **保护已有 peer**：incoming 的 peer 为 null 且已有会话 peer 非 null 时，合并保留已有 peer（防恶化）；
2. **从 members 推导对端**：incoming 无 peer 且为私聊时，从 `members` 推导对端（`ConversationMetadataSerializer` 对私聊返回 `members[:2]` 含对端，排除自己取另一人）——已损坏的数据（peer 已被覆盖）也能在下次 metadata upsert 时恢复，新建私聊（`openPrivateConversation` 同样返回无 peer 的 detail）顶栏也直接正常。
