# 搜索与收藏筛选布局验收

日期：2026-09-08。范围：搜索分类、收藏筛选、两页的独立结果滚动容器，以及宽窄屏搜索入口的 URL 同步。

## 问题与原因

此前搜索页只有「全部」的分组结果，没有可独立分页、返回和重试的分类入口；收藏筛选与结果共用页面滚动区域。页面滚动时筛选离开视口，宽屏的居中最大宽度与两侧留白也限制了实际结果区域。

筛选新增后，搜索表单原有导航只拼接 `q`，会在提交或清空关键词时丢失已选分类。宽屏搜索框的本地初始状态为空，也不能准确表达直达 `/search?q=...` 的 URL。因此本次一并修复入口同步，避免页面筛选与实际查询分离。

## 最终行为

- 搜索提供「全部、用户、群聊、帖子、直播间、桌游室」六项筛选。URL 的 `type` 接受 `user/group/post/live/game`；省略或非法值按全部处理。全部保留原来的分组展示与每组首批 3 条；单类使用 `types: [type]` 和每页 20 条，结果区只展示该类。
- 搜索缓存以账号、裁剪空白后的关键词、分类共同区分。首次进入新分类从顶部开始；返回已有分类恢复已加载分页、游标和滚动位置。旧分类的迟到响应不能覆盖当前分类，错误和重试也归属于各自查询。群成员变化继续使当前账号的相关搜索缓存失效，并沿用已有自动刷新逻辑。
- 收藏保留原有七类、分页、缓存、WebSocket 更新和自动刷新契约。结果组件拥有实际滚动节点，使恢复时 ref 已绑定；切换分类的首次位置与返回位置分别处理。
- 宽屏筛选为左侧 176px 面板，页面外侧间距为 12px。窄屏筛选位于顶部，是结果滚动容器的兄弟节点，所以滚动结果不会带走筛选，也不需要覆盖内容的浮层。窄屏搜索按三列换行，收藏按四列换行，按钮保持至少 44px 高。
- 收藏在 1024px 及以下以单列保持阅读空间，1025px 起使用已有两列瀑布流；搜索「全部」保留原分组响应式布局，单类只显示一个结果组。
- 筛选复用现有玻璃材质、Ayla 配色和选中指示动画。宽屏上下箭头、窄屏左右箭头以及 Home/End 可以选择并聚焦分类；Tab 只进入当前选项，`aria-selected`、`aria-controls` 与结果面板对应。降低动态效果设置继续关闭位移与缩放。
- 宽屏与窄屏搜索入口在搜索页提交或清空关键词时保留合法 `type`；从其他页面发起的新搜索默认全部。输入框从 URL 的 `q` 初始化，只有 `q` 改变时同步，因此仅切换分类不会覆盖尚未提交的草稿。预填 URL 不会在输入框未聚焦时自动打开宽屏下拉结果。

## 操作与范围

实现直接位于原共享工作区。新增 `DirectoryFilters`、其局部样式和 `searchLocation` URL 构造函数；修改 SearchPage、FavoritesPage、TopNav、NarrowTopBar 以及对应局部样式、定向测试。`profile.css` 仅移除被新收藏布局取代的旧收藏页面宽度、滚动和筛选规则，个人资料区域由并行任务维护。

本次不涉及服务启动、数据库、迁移或数据修复。浏览器请求和 WebSocket 全部使用合成夹具，没有向正式服务写入收藏、群成员或其他业务数据。产品变更均为可通过版本差异复核和撤销的工程文件修改。

没有新增认知裁决、主体身份、私有记忆或外部写入路径；既有权限、业务动作和数据来源保持其原有契约。结果缓存仍是可替换的前端投影。当前模块没有需要用户决定的未决实现选择；真实账号环境与最终整体验收归属主任务。
