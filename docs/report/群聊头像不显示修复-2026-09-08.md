# 群内聊天发送者头像不显示 事故记录

日期：2026-09-08
影响：群内聊天（`/group/:id`，GroupChat）所有发送者头像不显示（发送者昵称同样缺失）；私聊不受影响。

## 现象（用户报告）

- 群内聊天消息气泡旁的头像不显示。
- 用户肉眼验收确认：修复前无头像，修复后有头像且交互（戳一戳/长按 @）正常。

## 根因（确凿，代码链验证）

**回归提交 `6fc9142`（feat(social): 完成社交目录分页与群订阅隔离，2026-09-08）引入 metadata/目录 serializer 排除群 members，前端 GroupChat 没有把成员分页结果合并进 `conversation.members`，导致 MessageList 的发送者头像/昵称数据源恒空。**

数据链：

1. 后端新增 `ConversationMetadataSerializer`（`backend/apps/chat/serializers.py`）：群聊 `get_members` 返回 `[]`（有意设计，注释 "Group metadata explicitly excludes its independently paged members"），`members_complete=false`；成员走独立分页接口 `GET /chat/conversations/<id>/members/?pagination=cursor`。
2. 会话列表分页改用 `ConversationDirectorySerializer`（同样 `members=[]`）。
3. 前端 `GroupChat` 只调 `getConversationMetadata`（`?metadata=1`）→ `conversation.members` 恒空；前端没有任何路径把 `listConversationMembersPage` 的结果合并进 `conversation.members`。
4. `MessageList` 的 `memberAvatars`/`memberNames` 从 `conversation.members` 构建（`web/src/components/chat/MessageList.tsx`）→ 空 map → `MessageBubble` 的 `senderAvatar`/`senderAvatarLabel` 为 null → `showSenderHalo=false` → 头像（和昵称）不渲染。

为什么 6fc9142 之前正常：此前会话列表用 `ConversationListSerializer`（继承 `ConversationSerializer`，members 完整），GroupChat 从 store 的 conversations 直接拿到完整 members。

为什么私聊不受影响：`ConversationMetadataSerializer.get_members` 对私聊返回前 2 个成员（私聊恰好 2 人），数据源完整。

## 修复（前端，`web/src/pages/group/GroupChat.tsx`）

GroupChat 挂载后全量拉取成员分页并合并进 `conversation.members`：

- 循环调用 `listConversationMembersPage(groupId, { limit: 100, cursor })` 直到 `has_more=false`；
- 合并后置 `members_complete=true`（此后不再重复拉取）；
- 拉取失败静默（只缺头像/昵称，不阻断聊天、不弹错误）；
- 组件卸载取消（cancelled flag）。

时序安全：`stores/chat.ts` 的 `upsertConversation` 兼容逻辑（`members_complete===false && 已有完整 members` 时保留旧 members）保证「members 拉取完成」与「metadata upsert 返回」两种先后顺序都安全；直接 URL 刷新（conversations 尚未加载该群）时跳过合并，等 metadata upsert 后 `members_complete` 变化触发 effect 重跑补拉。

## 验证

- `tsc -b --noEmit` 通过；
- 新增定向测试 `web/src/vitest/group-chat-members.test.tsx`（3 用例：分页全量合并 / members_complete 后不重复拉取 / 失败不阻断）；
- 既有群聊相关测试补 `listConversationMembersPage` mock 后全绿：group-chat-members / subgroup / group-subgroup-motion / conversation-transition / group-page 共 5 文件 55 用例；
- 用户浏览器肉眼验收：头像显示且交互正常。

## 经验

- **metadata/目录 serializer 排除 members 后，任何依赖 `conversation.members` 的渲染路径都会断**。群聊发送者头像/昵称的唯一数据源是成员分页接口，必须显式合并进 conversation（`members_complete=true` 标记完整性）。
- 回归点特征：后端为性能把大数组（members/unread_seqs）移出列表/元数据响应时，前端消费方（头像、@ 选择器、成员名）必须同步切换数据源，否则静默丢功能。
- 测试盲区：既有测试的 conversation fixture `members: []` 恰好掩盖了「members 恒空」的缺陷——渲染路径不校验 members 完整性时，空 members 与「未加载」无法区分。
