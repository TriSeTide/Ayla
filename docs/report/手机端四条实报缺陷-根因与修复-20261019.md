> 用户实报（原文）：
> 1. 修复手机端直播无法全屏的问题
> 2. 修复手机端返回键直接退出应用而不是返回的问题
> 3. 修复手机端切后台重登的问题
> 4. 修复手机端顶部没有避开手机顶部任务栏的问题

## 0. 一条必须记住的订正：不要用「平台差异」给缺失开脱

**我的错误判断**：最初把这四条归因为「移动端平台限制、web 没有对应能力」，
依据是「web 是浏览器，没有原生全屏 API / 没有 Android 返回键 / 刷新就丢会话」。

**用户当场推翻**：web 做了窄屏适配，有的是有的。

**回查 web 源码后确认用户是对的**：这四条 **web 侧全都有窄屏实现**，Flutter 是漏对齐。
我当时连 web 代码都还没读就下了结论 —— 这是本轮的流程性错误，记在此处以儆效尤。

| 能力 | web 的真实实现（含行号） | 我错误的假设 |
|---|---|---|
| 全屏 | `components/live/LivePlayer.tsx:377` 全屏键**窄屏照常渲染**（只有画中画受 `hidePipButton:388` 控制）；`components/live/LiveRoomBody.tsx:96–111` 全屏期间冻结 `isNarrow`，防锁横屏导致窄↔宽切换重建黑屏 | 「web 没有原生全屏 API」 |
| 返回 | `navigate()` = **push** 语义（全仓 112 处，其中显式 `replace: true` 仅 25 处）；`navigate(-1)` = pop（22 处） | 「web 没有 Android 返回键」 |

| 顶部安全区 | `styles/auth.css:217` `padding: max(var(--sp-4), env(safe-area-inset-top))`；`styles/shell.css:653` 顶栏 `top` 已加安全区；底部共 13 处 `env(safe-area-inset-bottom)` | 「web 有浏览器外壳代劳」← **这条半对**，见 §4 |

## 1. 直播无法全屏

### 根因（两个，且第一个是致命的）

**① 函数签名误用 ⇒ 点击全屏键必抛异常（真根因）**

`lib/widgets/live/live_player.dart:199`（修复前）：

```dart
final OverlayEntry entry = (widget.overlayHostBuilder ?? aylaOverlayEntry)(
  _buildFullscreen(),
);
```

`aylaOverlayEntry` 的真实签名（`lib/widgets/base/overlays.dart:22`）是**具名参数**：

```dart
OverlayEntry aylaOverlayEntry({required WidgetBuilder builder})
```

⇒ 传位置参数在运行期抛：

```text
NoSuchMethodError: Closure call with mismatched arguments: function 'aylaOverlayEntry'
Found: aylaOverlayEntry({required (BuildContext) => Widget builder}) => OverlayEntry
Tried calling: aylaOverlayEntry(Instance of '_LivePlayerFullscreenHost')
```

**为什么长期没被发现**：
- 异常在 `GestureDetector.onTap` 回调里抛出 ⇒ 只有 debug 控制台一行红字，**UI 完全无反馈**
  （全屏层根本没插入），用户看到的是「点了没反应」；
- `dart analyze` 不报错（`Function` 类型擦除后，位置/具名两种调用都能编过）；
- 既有测试 `test/live_player_test.dart:214` 传了 `overlayHostBuilder` 替身 ⇒ **绕开了默认分支**，
  恰好把这条坏路径屏蔽掉了。

**② videoView 双挂**（次要，但同样会导致黑屏）

`_content({required bool fullscreen})` 里的条件写作 `(!fullscreen || _fullscreen == fullscreen)`：
inline 调用（形参 `false`）时 `!fullscreen` 恒真 ⇒ 全屏期间 inline 侧仍挂同一份视频，
与 overlay 里那份**重复 attach 同一平台视图**。
web 无此问题：它的 `<video>` 由 `liveSessionRuntime` 唯一持有、原子迁移，DOM 里永远只有一个 video。

### 修复

`lib/widgets/live/live_player.dart`：
- 两条 overlay 构造路径按各自签名分支（注入的走 `custom(fullscreen)`，默认走 `aylaOverlayEntry(builder: ...)`）；
- 挂载判据改为 `fullscreen == _fullscreen`（同一时刻只挂一处）。

### 回归锁

`test/mobile_reported_fixes_test.dart` →「全屏期间视频只挂一份」：断言进全屏后
`find.byType(_VideoProbe)` 仍为 **1**（修复前会因 inline 侧残留而错乱，且点全屏会抛上面那个异常）。

## 2. 返回键直接退出应用

### 根因

go_router 的 `context.go()` 是**替换当前页**，不建历史栈；而 web 的 `navigate()` 是 **push**。

| | web | Flutter（修复前） |
|---|---|---|
| 列表 → 详情 | `navigate('/group/:id')` = push | `context.go('/group/:id')` = 替换 |
| 系统返回键 | pop 历史，逐级回退 | 栈里没有上一页 ⇒ **系统直接销毁 Activity** |

实测（Android 模拟器）：进群 → 按返回 → **直接回桌面**。修复前全仓 `context.push` **0 处**、`context.go` 108 处。

补充：群页虽有 `PopScope` + 场景历史栈（处理群内场景逐级回退），但**栈空时 `canPop: true` 放行给系统**，
冷启动 deep-link 直达 `/group/:id` 时同样会退出应用。

### 修复（三层）

1. **列表→详情类导航改 push**（本轮 40+ 处）：进群、进直播间、进语音房、进桌游房、帖子详情、
   他人主页、私聊、开播控制台、收藏进帖等；
2. **页面返回键统一**：`context.canPop() ? context.pop() : context.go(兜底)`；
3. **群页 `PopScope` 恒 `canPop: false`**，三级兜底：`_popScene()` → `context.canPop()` → `context.go('/group')`。

### 刻意保留 `context.go` 的场景（不要无脑全改）

- 一级 tab 切换（切换模块应当复位，而不是无限堆栈）；
- 切台 / 切筛选 tab（web 明写 `navigate(..., { replace: true })`，共 25 处）；
- 群内场景切换（5 条路由共用 `kAylaGroupShellPageKey`，`push` 会抛 `!keyReservation.contains(key)` 断言）；
- 登录/注册落点、登出、非法 id 兜底。

### 回归锁

- `test/nav_push_semantics_probe_test.dart`：锁住「push 保留壳层且可逐级 pop」「go 不建栈（`canPop()==false`）」；
- `test/group_page_shell_test.dart` E3：断言栈空时 `canPop` 仍为 `false`（旧断言是 `true`，已按新语义订正并写明理由）。

## 3. 切后台重登

### 根因

Android 在内存紧张时会杀掉进程，回前台是**冷启动**。修复前 App 只有「自动登录」一条冷启动路径 ——
而它是用**明文口令**重放 `POST /auth/login/`（`state/auth_bootstrap.dart` 的 `aylaRunAutoLogin`）。
⇒ 没勾「自动登录」的用户，即使 refresh 令牌还完全有效（后端默认 7 天），也必然被踢回登录页。

对照 web：`main.tsx:36` 无条件 `await restoreSession()` —— 有 refresh 就续期进应用，与该开关无关。

### 修复

| 件 | 内容 |
|---|---|
| `state/auth_prefs.dart` | 新增 `AylaSessionTokenStore`：refresh 令牌落平台安全存储（`flutter_secure_storage`），与「记住密码」的明文口令**分开**存储 |
| `state/auth_bootstrap.dart` | 新增 `aylaRestoreSession`：读 refresh → 续期 → 拉 `/me/` → 建四通道 WS → 预加载门；失败清令牌并返回 `failed` |
| `state/auth_bootstrap.dart` | 新增 `aylaBootstrapSession`：把「静默续期」与「自动登录」**串行化**（先续期，失败才自动登录）。并行会发两次登录链 |
| `main.dart` | 启动期改为调用 `aylaBootstrapSession(container)` |
| `state/auth_bootstrap.dart` | `aylaApplyLoginSession` 登录成功后落盘 refresh；两个登出函数登出时清除 |
| `aylaInitialLocation` | 增加 `sessionRestoreInFlight` 参数：有令牌时首屏落 `/login` 但**渲染启动态而非表单**（否则表单闪一下、用户误以为被登出） |
| `pages/login_route.dart` | `_restoring` 档渲染 `AylaFullScreenLoader` |

⚠️ 关键点：`ROTATE_REFRESH_TOKENS=True` ⇒ 续期后**必须把轮换后的新 refresh 写回存储**，
否则下次启动拿旧（已作废）令牌必然 401（web `stores/auth.ts:113` 有同款注释）。

**与 web 的有意差异（登记）**：web 存 `sessionStorage`（关标签页即失效，是浏览器限制下的妥协）；
Flutter 存平台安全存储、跨进程存活 —— 原生 App 用户对「切回来还在」的预期强于网页。

### 验收证据（模拟器实测）

修复前：杀进程重启 → 回登录页，账号密码空白。
修复后：杀进程重启 → **直接进主页**，日志 `[AylaAuth] 冷启动引导完成：restore=success`。

## 4. 顶部没避开手机任务栏

### 根因

**这条是四条里唯一「web 确实没有对应 CSS」的** —— 但原因不是它不需要：

- `web/index.html:5` 的 viewport 是 `width=device-width, initial-scale=1.0`，**没有** `viewport-fit=cover`；
- ⇒ `env(safe-area-inset-top)` 在 web 上**恒为 0**；
- ⇒ 浏览器把整个页面排在状态栏/地址栏**之下**，安全区由浏览器外壳代劳
  （这也解释了为什么 `auth.css:217` 那行 `max(sp4, env(safe-area-inset-top))` 在网页上永远取 `sp4`）。

Flutter 的窗口是**边到边**的（Android edge-to-edge / iOS 全屏），没有那层外壳 ⇒ 必须 App 自己让。

修复前实测症状：状态栏的 `7:34`、`5G`、信号图标直接压在顶栏头像/标题上（群页压在「群聊」上、
直播间压在房间标题上）。

### 修复（四处）

| 位置 | 文件 | 修法 |
|---|---|---|
| 窄屏顶栏 | `widgets/shell/top_nav.dart` `_narrowBar` | `AylaGlassSurface` 的 child 改为 `Column[ if(vp>0) SizedBox(vp), SizedBox(height:56, ...) ]` |
| 群顶栏 | `widgets/shell/group_top_tabs.dart` | 同上（群页是沉浸路由，壳层不出 TopBar） |
| 直播间头部 | `widgets/live/live_room_body.dart`（窄屏分支） | Column 顶部插 `if(vp>0) SizedBox(vp)` |
| 登录/注册页 | `pages/login_page.dart` / `pages/register_page.dart` | 对齐 web `auth.css:217` 的 `max(设计值, 安全区)` 语义 |

### 两条实现纪律

1. 用 `MediaQuery.viewPaddingOf(context).top`，**不要**用 `paddingOf` —— 后者被键盘 `viewInsets` 联动，
   顶栏会因弹键盘而跳动；
2. 状态栏占位**放在玻璃材质内部**（与顶栏共用同一块磨砂底），否则会出现「透明横带 + 玻璃条」的断色。

### 验收证据（模拟器实测）

登录页 / 主页 / 群聊页 / 直播间：状态栏图标均位于顶栏**上方**的独立区域，不再压字。

### 测试环境的两个坑（记下来）

1. **Gradle 版本**：本机 wrapper 是 Gradle 8.12，Flutter 3.47.4 要求 ≥8.14 ⇒ `flutter run` 直接构建失败
   （`Your project's Gradle version (8.12.0) is lower than Flutter's minimum supported version of 8.14.0`）。
   加 `--android-skip-build-dependency-validation` 即可，**不要升级 wrapper**（会动用户的既有构建环境）。
2. **全屏控件只在有流时渲染**：`_showVideo = srsStatus == live && playerError == null`（web 同），
   无推流时点不出全屏键。验证全屏要么开真实推流，要么走 widget 测试。
