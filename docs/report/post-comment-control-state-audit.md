# 帖子评论与图片失败状态验收（2026-09-08）

## 对象与边界

本次验收覆盖群内帖子旧刷新与实时事件的合并、详情评论分页、评论输入/附件/删除、帖子编辑/删除，以及 ResourceImage 在帖子/评论/查看器中的失败重试。所有浏览器 HTTP 写入和 WebSocket 都终止于合成夹具；未启动或重启 Elysium，未操作真实数据或麦克风。

## 发现与修复

1. 原群帖刷新响应能够覆盖请求期间到达的新帖、编辑和可见范围变更。GroupPosts 现按请求起点和本地变更 revision 合并，并保留删除标记；同帖逆序详情读取不能覆盖较新的对账结果。
2. 原详情一次读取完整评论。现使用按读者/帖子绑定的签名 cursor，每页 20 条；首页/续页错误保留工作，WS/本地创建和删除有独立版本边界。接口、兼容数组读取和权限约束见 `../architecture/post-comment-pagination.md`。
3. 首轮真实浏览器在 375px 与 1440px 复现：返回详情时已加载 47 条仍在，但滚动位置从 680px 归零。读取 scrollTop 写入与 scroll 事件可见，退出旧 DOM 归零事件覆盖了位置；修复在返回前显式保存，并在 Presence 退出时移除旧视图的监听。复测均为 680px → 680px。
4. 浏览器复现帖子保存期间标题/正文仍可编辑，成功回执关闭编辑页并丢弃新输入。保存期间现由原生 disabled fieldset 冻结表单，忙锁拒绝重复提交；失败恢复原草稿。评论输入允许继续写下一条，但只清空已提交且未被再次修改的草稿。
5. 评论附件移除原先先从 UI 消失、再忽略服务器删除失败。现在只有删除成功才移除；部分上传失败必须重试或显式移除，不能随文本发送静默丢弃。评论和帖子删除各自具有可见忙态与防重复请求。
6. ResourceImage 的失败重试按钮在已有图片按钮内产生嵌套原生 button；自定义占位还会隐藏失败。内容图片现复用最近外层原生按钮/链接完成失败重试，阻止同时打开查看器；成功恢复原标签及打开动作。独立内容图片保持独立重试按钮。组合回归发现空 alt 的装饰头像不应接管父行，已改为保留 fallback 和原行操作，搜索加群回归通过。签名变体变化重新读取对应变体，未用缩略图结果冒充原图。
7. “我的帖子”原有尾页失败隐藏于已有列表、滚动反复请求且缺少同步锁。现保留卡片与 cursor，显示明确重试入口，错误后停止滚动重试，并拒绝连续请求和失去 owner 的响应。
8. 最终目视随后发现全页编辑的字段间隙透出原详情和评论。追加两宽有界复核在编辑与媒体完成后再等待 1600ms：编辑外壳/正文背景均为透明、backdrop 为 none、opacity 为 1、运行中动画为空；同一 PostDetailContent 下的正常详情与 20 条评论仍作为可见 sibling 保留，并非退出中的旧 DOM。原证据为 `ayla-post-edit-settled/control-states-report.json` 的 editSettle。此前 V37 自动状态通过只证明交互/请求/溢出检查，不代表全页编辑视觉通过。最终最小修复在编辑时给原顶栏、详情滚动区和评论输入添加隐藏/inert/aria-hidden，保留其 DOM 和状态，编辑层本身不受影响；进入/退出编辑恢复正确焦点，不增加白底或修改配色。修复后两宽 `ayla-post-edit-settled-fixed/` 的稳定截图不再透出底层内容，该证据替代旧 V37 编辑截图的视觉结论。

所有修改是网页/后端工程代码与测试，回滚代码即可撤回行为；没有数据迁移或主体语义修改。
