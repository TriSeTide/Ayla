# 个人页与群详情连续滚动验收

记录日期：2026-09-08。范围为 ProfilePage、UserProfilePage 和 GroupInfo 的布局与可达性；稳定设计规则同步在 `docs/design.md` §5。

## 问题与原因

原个人页在宽屏把 `.profile-side`、`.profile-main` 都设为 `overflow-y:auto`，页面本身禁止滚动，并用负边距、透明容器不接收指针的方式补偿阴影空间。滚轮落在不同区域时会改变滚动对象，左右列的阅读位置彼此分离。

原群详情也采用两列独立滚动。每列各有 24px 左右内边距，实际卡片之间累计出 48px 空隙；1200px 的居中限宽在较宽屏幕上继续增加页面左右留白。上述规则已由本次整页连续滚动规则替换，旧的独立列滚动要求不再适用。

## 实现边界

- 个人页由 `.profile-page`、群详情由 `.group-info` 各自持有页面竖向滚动。两列保持自然高度，取消列内滚动、固定列高及个人页负边距/指针穿透补丁。
- 宽屏两栏卡片净间隔为 16px，页面外沿预留 24px、底部 32px 的阴影空间。个人页和群详情取消 1200px 居中限宽，使用可用内容区域。
- 个人页大于 768px 保持左资料、右内容；左轨道为 280–340px，资料卡内边距和主要间距为 16px，表单间距为 12px。未公开内容、加载和错误分支继续使用单列。窄屏保留原有连续阅读顺序。
- 群详情大于 1000px 使用两栏，左轨道为 `clamp(280px, 32%, 340px)`。769–1000px 时，服务器栏和频道栏压缩了可用正文宽度，因此详情继续使用单列；小于等于 768px 保持窄屏布局。
- 群详情右栏以 `container-type:inline-size` 提供实际宽度依据。右栏小于等于 420px 时，成员操作按钮独占下一行并常显，避免原来透明按钮仍占据行宽、把成员名压成单字。名字保留省略和完整 `title` 提示；角色、权限与操作条件保持原有实现。
- 左侧没有强制吸顶或固定高度。长简介、编辑表单、入群审批和管理操作随整页连续到达；文本框自身的原生文字滚动不属于第二个页面滚动区。

```powershell

```

结果为 3 个文件、30 个测试通过，覆盖资料保存/草稿与头像、内容分页和群角色管理。输出包含既有 React Router future flag 和 `act(...)` 警告；没有测试失败。本次布局验收使用真实浏览器几何和输入，不新增仅比对 CSS 字符串的测试。

浏览器复用已运行的 Vite，独立 Chromium context 拦截全部 API、WebSocket、媒体和外部请求，使用合成资料；没有向真实后端写入，也没有启动、停止或替换任何服务。每个场景使用 600px 高度，分别展示本人 20 条长标题内容、他人超长简介及公开内容、群长简介及 20 名成员。

上述 18 个场景均获得通过证据：滚轮分别落在左卡和右卡，每次推动所属页面 280px，而左右列 `scrollTop` 始终为 0。页面末端的本人表单按钮、他人资料操作和群管理按钮可完整滚入视窗并获得焦点。每种宽度另外检查未公开内容的用户页，没有空的右栏。分栏净间隔按有限入场动画结束后的几何测量确认；滚轮结果等待实际 `scrollTop` 变化，避免固定延迟采样误判。

证据分为全宽矩阵与单独宽屏复验：全宽首轮有一次 1920px 群页的间隔采样报警；该场景及 1920px 两种个人页单独复验通过。随后对 1001px、1920px 群页等待有限动画 `finished` 后再次测量，同时检查窄成员行布局与完整名称提示。最终采用已完成动画的几何结果，不把过渡中的位置当成静态布局。浏览器证据没有 runtime error 或未知 API。

最终定向测量中，1001px 群右栏为 289px、成员名可用宽度为 174px，操作行位于名字下方且不透明；1920px 群右栏为 1148px，操作保留原有同行 hover/focus 显示。两种宽度的列间隔均精确为 16px，左右滚轮各推动页面 280px。
