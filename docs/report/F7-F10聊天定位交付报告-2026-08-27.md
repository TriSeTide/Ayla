# F7/F10 聊天定位交付报告（2026-08-27）

## 1. 范围与最终语义

本次仅实施功能层 F7 未读跳转与 F10 回复跳转；窗口化基础复用 M6a 的消息 store、DOM 窗口与 `before_seq` 分页链路。

按用户最终确认的 QQ 式语义落地：

- 新消息到达先判断当前是否已读：正在看这个会话（活跃）时，他人消息直接标已读，不弹未读/@/回复标签；被 @/回复的只给泛光圈并滚底。
- 非活跃会话的新消息才进入未读投影，普通未读/@我/回复分别进入各自标签。
- 自己发送消息无条件回到底部，即使此前向上翻阅过历史。
- 进入群聊/打开私聊仍然滚到底部，不自动定位、不自动清除未读。
- 普通未读显示一个带全部未读数量的定位标签；点击后跳转到第一条未读，并批量标记跳转位置以下的普通消息为已读。
- 普通未读批量已读会排除 `@我` 与“回复我”的特殊消息；特殊标签继续保留。
- `@我` 与回复分别显示独立定位标签；对应消息未读时标签存在，真实进入视口或点击标签定位后才精确标记该消息已读。
- 标签目标在当前消息区上方时显示在顶部，下方时显示在底部；多个标签按上下位置分组堆叠。
- 引用块为可访问按钮；点击后定位被引用原消息，窗口外目标沿 M6a `before_seq` 逐页扩窗。
- 原消息已撤回时保留消息位置并显示“该消息已撤回”，同时执行定位辉光。
- 定位辉光使用现有 token 与 `prefers-reduced-motion` 降级规则。

## 2. 改动文件

  - 消息增加只读 `reply_to_seq`、`read_by_me`。
