# 聊天已读判定修复（2026-08-29）

## 1. 问题现象

群聊与私信界面存在已读误判：会话有未读消息时，进入界面（或刷新后进入）会瞬间把未读消息全部标为已读，未读标签（「N 条新消息」「@我」「回复」）直接消失，用户无法点击标签跳转到未读位置。

## 2. 根因

已读判定被实现为「物理滚到底部 → 全清未读」：

- `MessageList.handleScroll` 在 `physicallyAtBottom` 时调用 `onMarkAllRead`（→ `markConversationAllRead` → `markConversationRead` 不带 `through_seq` → 后端把「对方发、非撤回」的最新一条之前的全部消息标已读），视口内外的未读一次性清空。
- 进入会话时的「自动贴底」（`useLayoutEffect` 里 `scrollToBottom`）会触发浏览器 scroll 事件，误触发上述 `onMarkAllRead`，在用户尚未看到任何未读消息时就全标已读。

这违背了《F7-F10 聊天定位交付报告》第 12 行的设计意图：「进入群聊/打开私聊仍然滚到底部，不自动定位、不自动清除未读。」

## 3. 修复

- 移除「回底 → `onMarkAllRead`」的粗粒度全清逻辑（`MessageList.handleScroll`）。
- 把 IntersectionObserver 从「只观察特殊消息（@我/回复）」扩展为「观察所有未读消息（普通 + 特殊）」：消息真正进入视口（可见比例 ≥ 0.6）才精确标已读（`markMessageRead(..., exact=true)` 单条，不连带视口外更早的未读）；视口外的未读保留标签，供用户跳转后逐条已读。
- 删除不再使用的 `markConversationAllRead`；`PrivateChatPane` / `GroupChat` 移除 `onMarkAllRead` 传入。

## 8. 附：对方消息气泡长度不一致修复

- 现象：群聊/私信对方发的短消息气泡长度不一且偏宽（如内容都是 "1"，气泡却有 39px / 56px 等不同宽度）；自己的气泡正常。
- 根因：`.msg-body` 默认 `align-items: stretch`，把 `.msg-bubble-wrap`（气泡容器）拉伸到 `.msg-body` 宽度；而 `.msg-body` 宽度 = 内部最宽子元素——`.bubble-meta` 的时间文本（"X 分钟前" 比 "HH:mm" 宽）或 `.msg-sender` 昵称。于是短消息气泡被时间/昵称撑宽，且随时间文本变化导致长度不一；自己消息因 `.msg-row.self .msg-body { align-items: flex-end }` 不被拉伸，故只有对方气泡异常。
- 修复：`.msg-body` 增加 `align-items: flex-start`（`web/src/styles/app.css`），气泡容器按自身内容宽度收缩，不再被 meta/昵称撑宽；self 的 `flex-end` 规则不变。
- 验证：Playwright 实测（dev server + 真实数据）：短消息「1」气泡 37–39px、「213」57px（均等于内容宽度）、长文本气泡 498px（正确收缩到 70% 上限内）；`npx tsc -b --noEmit` 通过；`message-list` + `private-chat-pane` 定向 18 项通过。

## 9. 附：群内非聊天场景消息被自动已读修复

- 现象：宽屏下在群内但不在聊天子界面（帖子/语音/直播/桌游）时，该群新消息被自动已读；窄屏不易察觉（默认停在聊天场景）。
- 根因：`GroupPage` 的 effect（依赖含 `effectiveScene`）在任意子场景都调用 `openConversation(id)`；宽屏切换子场景时 GroupChat 卸载并 `closeConversation()`，但 GroupPage effect 随即又 `openConversation(id)`，`activeConversationId` 残留为当前群 id → WS `message.new` 判定 `isActive` 为 true（`viewerAtBottom ?? true` 默认 true）→ 自动已读。
- 修复（`web/src/pages/GroupPage.tsx`）：只在 `effectiveScene === "chat"` 时 `openConversation(id)`，其他子场景显式 `closeConversation()`——非聊天界面不持有 activeId，新消息进未读投影。
- 验证：Playwright 实测（dev server + 真实 store）：posts 场景 `activeConversationId=null`（群 42 的 8 条未读保留）、回到 chat 场景恢复 `"43"`；`npx tsc -b --noEmit` 通过；`group-page`（新增 1 项契约测试「非 chat 子场景不持有 activeConversationId」）+ `ws-chat` 32 项通过。
