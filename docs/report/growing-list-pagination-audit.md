# 可增长列表分页核对与补齐

2026-09-08，用户明确将本轮范围扩为所有可增长业务列表。基线为 Ayla `26e6e85`；此前12个模块及其父仓库指针已提交。下表记录新增分页实现与增量复验；代码和证据完成、按模块提交及父指针复核以前不执行关机。

分页验收同时检查后端有界查询与前端继续读取入口。只有前端 slice、只返回最近若干条、接口有 cursor 但页面丢弃它、首页后自动无界拉完，均不能算完成可见列表分页。旧数组接口可以为既有非展示消费者兼容保留，但不得用它绕过新页面的分页契约。

## 必须保持的跨模块契约

- 每一页按账号、资源、查询、筛选、父对象和排序绑定cursor；错误scope、损坏cursor与越权请求显式失败。
- 服务端执行limit+1或等价有界查询。返回完整total及必要摘要时使用独立受权限过滤的计数，不能从一页数量推算全量。
- 前端重复触底共用忙锁；下一页失败保留旧列表/cursor并提供明确重试；旧账号、旧查询和旧父对象的迟到响应不能覆盖当前页。
- 同ID去重；请求期间新增/修改/删除的实时结果不能被旧页覆盖或复活。旧DOM和滚动位置保持，仅新项进入。
- 聊天的群订阅、重连seq基线、未读和私信提醒必须与可见分页分离。首连不能通过resume从0重放全部历史。
- 成员页不能替代完整成员事实源；权限依据使用服务端角色/归属字段。@与转让等选择器需要服务端搜索或继续加载，并保留已选对象。
- 历史消息/弹幕向上分页必须能读到被内存窗口省略的原文，分页插入时保留可见锚点；实时消息继续按原授权路由进入。
- 所有旧无分页调用点逐一分类为兼容消费者、固定预览加明确续读入口，或待迁移的可见列表；最终不得留下未说明的硬截断入口。
