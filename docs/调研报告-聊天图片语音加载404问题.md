# 调研报告：聊天图片和语音加载 404 问题

**调研时间**：2026-08-17  
**问题描述**：群聊中的聊天图片和语音消息无法加载，浏览器显示 404 错误  
**影响范围**：所有媒体资源（图片、语音、文件）的详情接口  

---

## 一、问题现象

### 1.1 用户报告
- 群聊里的聊天图片加载不出来
- 语音消息加载失败
- 浏览器 Network 面板显示 404 错误

### 1.2 实际请求
```
请求 URL: http://localhost:5173/api/v1/media/4eb5e4ff3ce347aa98c522e7cecfa1ac/
请求方法: GET
状态代码: 404 Not Found
```

### 1.3 数据库验证
查询 MySQL `ayla.media_objects` 表，该 `media_id` 存在且状态正常：
```sql
SELECT media_id, kind, status, storage_path 
FROM ayla.media_objects 
WHERE media_id = '4eb5e4ff3ce347aa98c522e7cecfa1ac';
```
结果：
- `media_id`: 4eb5e4ff3ce347aa98c522e7cecfa1ac
- `kind`: image
- `status`: ready
- `storage_path`: media/image/4eb5e4ff3ce347aa98c522e7cecfa1ac/original

**结论**：数据存在，不是数据丢失问题。

---

## 二、根本原因

### 2.1 路由不匹配

**后端路由定义**（`Ayla/backend/apps/media/urls.py:23`）：
```python
path("<str:media_id>", views.MediaDetailView.as_view(), name="media-detail"),
```
- 路由模式：`/api/v1/media/<media_id>`（**无尾部斜杠**）

**前端 API 调用**（`Ayla/web/src/api/media.ts:22`）：
```typescript
export function fetchMediaDescriptor(mediaId: string) {
  return apiRequest<MediaDescriptor>(`/media/${seg(mediaId)}/`);
}
```
- 实际请求：`/api/v1/media/<media_id>/`（**带尾部斜杠**）

### 2.2 验证测试

**测试 1：带尾部斜杠**
```bash
curl http://127.0.0.1:8100/api/v1/media/4eb5e4ff3ce347aa98c522e7cecfa1ac/
# 结果：404 Not Found（Django 标准 404 页面）
```

**测试 2：不带尾部斜杠**
```bash
curl http://127.0.0.1:8100/api/v1/media/4eb5e4ff3ce347aa98c522e7cecfa1ac
# 结果：401 Unauthorized（路由匹配成功，需要登录）
```

### 2.3 为什么前端要加尾部斜杠？

**历史原因**：`ResourceImage.tsx:17` 的正则表达式要求尾部斜杠
```typescript
// 匹配 /media/{media_id}/ 模式
const match = src.match(/\/media\/([^/]+)\//);
```
这个正则用于从 URL 提取 `media_id` 作为缓存 key，**要求 media_id 后面必须有斜杠**。

为了配合这个正则，前端所有媒体 URL 构造都加了尾部斜杠，导致：
- `/media/${mediaId}/` ✅ 能被正则匹配
- `/media/${mediaId}` ❌ 无法提取 media_id

但后端路由定义时**没有加尾部斜杠**，导致前后端不一致。

---

## 三、解决方案

### 方案 A：修改后端路由（推荐）✅

**修改文件**：`Ayla/backend/apps/media/urls.py`

**变更**：在 `media_id` 路由后添加尾部斜杠
```python
# 修改前
path("<str:media_id>", views.MediaDetailView.as_view(), name="media-detail"),

# 修改后
path("<str:media_id>/", views.MediaDetailView.as_view(), name="media-detail"),
```

**优点**：
- ✅ 符合 Django REST framework 惯例（资源详情接口通常带尾部斜杠）
- ✅ 前端无需修改，历史 URL 缓存仍然有效
- ✅ 不影响其他子路径（`/content`、`/thumbnail` 等已正确定义）

**风险**：
- ⚠️ 需要验证是否有其他地方硬编码了不带斜杠的 URL

---

### 方案 B：修改前端 API 调用（备选）

**修改文件**：`Ayla/web/src/api/media.ts`

**变更**：移除 `fetchMediaDescriptor` 的尾部斜杠
```typescript
// 修改前
export function fetchMediaDescriptor(mediaId: string) {
  return apiRequest<MediaDescriptor>(`/media/${seg(mediaId)}/`);
}

// 修改后
export function fetchMediaDescriptor(mediaId: string) {
  return apiRequest<MediaDescriptor>(`/media/${seg(mediaId)}`);
}
```

**同时修改**：`ResourceImage.tsx` 的正则表达式
```typescript
// 修改前
const match = src.match(/\/media\/([^/]+)\//);

// 修改后（允许可选的尾部斜杠）
const match = src.match(/\/media\/([^/]+)\/?/);
```

**优点**：
- ✅ 符合后端现有路由定义
- ✅ 不影响后端代码

**缺点**：
- ❌ 需要修改多处前端代码
- ❌ 可能导致浏览器缓存的旧 URL 失效
- ❌ 不符合 DRF 惯例

## 五、影响范围评估

### 5.1 受影响的接口
仅 `GET /api/v1/media/{media_id}/` 媒体详情接口

### 5.2 不受影响的接口
以下接口路由定义已正确，无需修改：
- ✅ `GET /api/v1/media/{media_id}/content` - 下载原文件
- ✅ `GET /api/v1/media/{media_id}/thumbnail` - 缩略图
- ✅ `GET /api/v1/media/{media_id}/waveform` - 波形图
- ✅ `POST /api/v1/media/uploads` - 创建上传会话
- ✅ `PUT /api/v1/media/uploads/{upload_id}` - 上传二进制
- ✅ `POST /api/v1/media/uploads/{upload_id}:complete` - 完成上传

### 5.3 兼容性
- **向后兼容**：Django 默认 `APPEND_SLASH=True`，访问不带斜杠的 URL 会自动 301 重定向到带斜杠版本
- **前端缓存**：修改后端路由不影响前端已缓存的 blob URL
- **移动端**：如有原生客户端，需同步检查媒体 URL 构造逻辑

## 六、总结

### 6.1 问题本质
前后端 URL 约定不一致：
- 前端构造：`/api/v1/media/{media_id}/`（带斜杠）
- 后端路由：`/api/v1/media/{media_id}`（无斜杠）

### 6.2 推荐方案
**修改后端路由添加尾部斜杠**，原因：
1. 符合 Django REST framework 惯例
2. 前端无需修改，风险最小
3. 向后兼容性好
