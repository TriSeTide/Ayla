# Ayla 客户端发布与服务端热更新

> 本文是 2026-10-18 交付的「发布更新」功能的操作手册。
> 事实源：`Ayla/scripts/publish_release.py`、`Ayla/backend/apps/releases/`、
> `Ayla/flutter/lib/core/update/`、`Ayla/flutter/lib/widgets/base/update_dialog.dart`。
> 本机专有值（SSH 别名、端口、证书、密码）只写在运行环境里，**不进仓库**。

---

## 1. 目标与边界

需求原文：**实现发布更新功能。Ayla Flutter 在远端 SSH 有部署。制作 Ayla Flutter 的更新功能，
更新流程：使用脚本把各个端 release 构建产物（构建的 release 使用远端的 ayla 后端）发布至
SSH 服务器指定文件夹，git 更新 SSH 服务器后端，然后在各个端 app 登录时能收到更新弹窗，
各个端覆盖重启更新或下载安装更新。**

交付拆成四段，每段都可单独执行、单独失败、单独回滚：

| 段 | 入口 | 结果 |
| --- | --- | --- |
| ① 构建 | `publish_release.py build` | `flutter build {windows,apk,ipa} --release --build-name/--build-number --dart-define=AYLA_API_BASE=<远端>` |
| ② 发布产物 | `publish_release.py publish` | `~/Elysia/ayla-deploy/releases/<channel>/...` + 原子替换 `manifest-<channel>.json` |
| ③ 更新后端 | `publish_release.py deploy-backend` | 本地 commit 打包成 git bundle → 服务器 `git merge --ff-only` → `docker build` + `docker compose up -d backend` |
| ④ 客户端 | 登录成功钩子 + 顶栏「检查更新」 | `GET /api/v1/updates/check/` → 弹窗 → 下载校验 → Windows 覆盖重启 / Android 下载安装 |

**不做的事**：
- 不做热补丁/代码签名绕过（iOS 不允许自装；Android 仍走系统安装器；Windows 覆盖脚本不要求管理员）；
- 不建数据库表、不做灰度百分比（渠道即灰度：`stable` / `beta` 各自一份清单）；
- 不把发布目录放进后端镜像（后端只读 manifest，二进制由 nginx `/releases/` 直出）。

## 2. 一次性准备

### 2.1 服务器发布目录

```bash
ssh ayerelysia
mkdir -p ~/Elysia/ayla-deploy/releases/{stable,beta}
chmod -R u+rwX,go+rX ~/Elysia/ayla-deploy/releases
```

> **离线构建兜底（2026-10-18 实测）**：服务器 Docker daemon 配置了
> `HTTP_PROXY=127.0.0.1:7890`，代理未运行时 `docker build` 拉不到基础镜像。
> `backend/Dockerfile` 提供 `--build-arg BASE_IMAGE=ayla-backend:pre-20260916`，
> 并配合 `docker build --network=host` 让容器内 pip 走宿主机网络；两条合起来可在
> 代理不可用时完成镜像重建。命令见 §7。

### 2.2 后端挂载与清单路径

`ayla-deploy/docker-compose.yml` 的 backend 服务增加只读挂载（compose 变量文件同目录）：

```yaml
  backend:
    volumes:
      - backend_runtime:/app/runtime
      - ./releases:/app/releases:ro          # 只读：后端不会写发布目录
    environment:
      AYLA_RELEASES_DIR: /app/releases        # 可选；也是 settings.py 的默认之外的显式值
      AYLA_RELEASES_PUBLIC_BASE: /releases
```

> `AYLA_RELEASES_DIR` 未设置时默认 `BASE_DIR/runtime/releases`（容器内 `/app/runtime/releases`），
> 生产建议显式指向挂载目录，避免与 `backend_runtime` 卷混在一起。

### 2.3 nginx 直出 `/releases/`

在 `ayla-deploy/nginx/nginx.conf` 的 **443 / 8080 两个 server 块**里加（放在 `location /` 之前）：

```nginx
    location /releases/ {
        alias /usr/share/nginx/releases/;
        autoindex off;
        add_header Cache-Control "public, max-age=300";
        types { application/zip zip; application/vnd.android.package-archive apk; }
    }
```

并给 nginx 容器挂载发布目录（`docker-compose.yml` 的 nginx 服务）：

```yaml
    volumes:
      - ./releases:/usr/share/nginx/releases:ro
```

改完执行：

```bash
cd ~/Elysia/ayla-deploy
docker compose up -d --no-deps nginx
docker exec ayla-nginx nginx -t
curl -sI https://127.0.0.1/releases/manifest-stable.json | head -3   # 404 也可以，说明路由通了
```

### 2.4 构建环境（本机）

- Flutter 3.47.4（`flutter --version` 自检）；
- Android：SDK 36 + JDK 17；release 目前沿用 debug 签名（`android/app/build.gradle.kts`
  的 TODO 未完成），分发前如要正式签名，先在本地配置 `key.properties` 并改 signingConfig；
- iOS：仅 macOS + Xcode 可构建；
- SSH：`ssh ayerelysia` 免交互可用（BatchMode 验证：`ssh -o BatchMode=yes ayerelysia true`）。

## 3. 发版流程

### 3.1 一条命令全流程

```bash
cd E:/Elysium-AyerElysia/Elysium/Ayla
python scripts/publish_release.py all \
    --version 1.0.1 --build 2 \
    --notes-file docs/releases/1.0.1.md \
    --platforms windows,android
```

- `--api-base` 默认 `https://s.ayla.trise.top:26211`，会被写进
  `--dart-define=AYLA_API_BASE=...`，**所有 release 产物都连远端后端**；
- `--channel` 默认 `stable`，同时写入 `--dart-define=AYLA_UPDATE_CHANNEL=...`；
- `--mandatory` / `--min-supported-build N` 控制强制更新；
- 同名 build 已存在会拒绝；确需覆盖加 `--allow-replace`。

### 3.2 分步执行

```bash
# 只构建（产物在 flutter/dist/release/<version>+<build>/）
python scripts/publish_release.py build --version 1.0.1 --build 2

# 只发布（用已有产物；也可以 --artifacts-dir 指向别处）
python scripts/publish_release.py publish --version 1.0.1 --build 2 \
    --notes-file docs/releases/1.0.1.md

# 只更新后端（git bundle 推送 + 重建容器）
python scripts/publish_release.py deploy-backend
```

`deploy-backend` 的安全约束（脚本内实现）：

1. `git merge-base --is-ancestor <server HEAD> <local HEAD>` 必须成立，否则拒绝（防覆盖服务器独有提交）；
2. 只打 `<server HEAD>..<local HEAD>` 的 bundle，不传整个仓库；
3. 服务器 `git bundle verify` → `git fetch` 到 `refs/ayla/incoming` → `git merge --ff-only`；
4. 重建镜像并 `docker compose up -d --no-deps backend`（Dockerfile 的 CMD 会自动 `migrate`）。

### 3.3 发布后自检

```bash
ssh ayerelysia 'cd ~/Elysia/Elysium/Ayla/backend && docker exec ayla-backend python manage.py release_manifest_check --channel stable --platform windows --arch x64'
curl -s 'https://s.ayla.trise.top:26211/api/v1/updates/check/?channel=stable&platform=windows&arch=x64&version=1.0.0&build=1' | python -m json.tool
```

期望第二个命令返回 `update_available=true` 且 `download.sha256` 与清单一致。

## 4. 客户端行为

### 4.1 登录后自动检查

`state/auth_bootstrap.dart:aylaApplyLoginSession()` 在登录副作用链末尾调用
`updateControllerProvider.checkOnLogin()`（**不 await**）。约束：

- 每个 App 进程只自动检查一次（controller 内 `_loginCheckDone` 单飞）；
- 检查失败/清单缺失只 `debugPrint`，**不弹错误**，不影响登录；
- 有更新才打开弹窗；`mandatory=true` 时弹窗不可关闭、只有「立即更新」。

### 4.2 手动检查

顶栏「更多」菜单新增「检查更新」项（宽窄屏同菜单）→ `checkManually()` →
有更新弹窗；已是最新/服务不可用/失败时用 SnackBar 明确反馈。

### 4.3 弹窗状态机

`available → downloading → ready → applying`，失败进入 `failed`（可重试，不重复下载）：

| 平台 | 产物 | 行为 |
| --- | --- | --- |
| Windows | `.zip` | 解包 → 生成 `%TEMP%\updates\<sha>\apply-update.cmd` → `taskkill` 旧 PID → `robocopy /E` 覆盖安装目录 → `start` 新 exe；日志 `apply-update.log` |
| Android | `.apk` | 先尝试用系统打开 apk（`file://`），失败则打开下载页由用户安装 |
| iOS | `.ipa` | 只打开 `install_url`（`itms-services://`）；iOS 不允许应用自装 |

> Windows 覆盖脚本由应用在**用户态**生成并启动，不写系统目录、不注册服务、不改 PATH。
> 安装目录需要当前用户有写权限（便携版解压目录默认满足）。

### 4.4 下载与校验

`core/update/update_downloader.dart`：

- 先写 `<name>.part`，`size` 与 `sha256` **都**匹配后才原子改名；
- 失败删除临时文件；单包上限 2 GiB；
- 文件名净化（去路径分隔符 / Windows 非法字符 / 控制字符），目标目录固定在应用缓存 `updates/`。

## 5. manifest 契约

```json
{
  "schema_version": 1,
  "channel": "stable",
  "generated_at": "2026-10-18T12:00:00+00:00",
  "releases": [
    {
      "release_id": "stable-1.0.1-2",
      "version": "1.0.1",
      "build": 2,
      "published_at": "2026-10-18T12:00:00+00:00",
      "notes": "修复若干问题",
      "mandatory": false,
      "min_supported_build": 0,
      "artifacts": [
        {
          "platform": "windows",
          "arch": "x64",
          "kind": "zip",
          "path": "stable/windows/1.0.1+2/ayla-windows-x64-1.0.1+2.zip",
          "file_name": "ayla-windows-x64-1.0.1+2.zip",
          "size": 40092299,
          "sha256": "…64 hex…",
          "install_url": null
        }
      ]
    }
  ]
}
```

后端校验（`apps/releases/services.py`）是 fail-closed 的：

- 字段类型/范围、`build` 唯一、`path` 必须是 `<channel>/` 开头且不含 `..`/反斜杠/绝对路径；
- `sha256` 必须 64 位小写十六进制、`size > 0`、`install_url` 只允许 http/https/itms-services；
- 清单文件缺失 → `200 + degraded=true + reason=manifest_unavailable`（**不冒充已是最新**）；
- 清单损坏 → `503 + code=release_manifest_invalid`（客户端保留旧版）。

API 响应**不包含**服务器文件系统路径；`download.url` 由 `AYLA_RELEASES_PUBLIC_BASE` 生成。

## 5.1 服务器离线重建（代理不可用）

```bash
ssh ayerelysia
cd ~/Elysia/ayla-deploy
docker build --network=host     --build-arg BASE_IMAGE=ayla-backend:pre-20260916     -f ~/Elysia/Elysium/Ayla/backend/Dockerfile     -t ayla-backend:latest ~/Elysia/Elysium/Ayla/backend
docker compose up -d --no-deps backend
docker exec ayla-backend python manage.py release_manifest_check --channel stable
```

注意：`--network=host` 只用于构建阶段（容器内 pip 需要访问清华 PyPI）；
镜像运行时仍是 `network_mode: host` 的既有部署形态。

## 6. 回滚

| 场景 | 操作 |
| --- | --- |
| 新版本有严重问题 | 用 `--allow-replace` 重新发布**更高 build**并置 `--mandatory`；或从 manifest 删除该 release（手工编辑后 `mv` 原子替换）再 `release_manifest_check` |
| 只有某个平台回滚 | 把该平台 artifact 指向上一版文件（同 channel 下路径可复用），重算 `size/sha256` |
| 后端回滚 | 服务器 `git revert` 或 `git reset` 到上一个提交后重建镜像；**禁止**在本地 `force push` |
| 更新服务整体停用 | 服务器移除 `manifest-<channel>.json` → 客户端收到 `degraded`，不弹窗、不影响登录 |

回滚必须留档：记录 release_id、commit、manifest 新旧哈希与执行时间。

## 7. 已知限制（交付时如实登记）

1. **Android release 仍用 debug 签名**（`android/app/build.gradle.kts` 的 TODO）；
   分发前需要正式 keystore，否则系统安装器可能拒绝覆盖安装不同签名的版本。
2. **iOS 未在真实设备验收**（需要 macOS + 开发者签名 + `itms-services` 托管页）；
   代码路径与契约测试已就绪，`install_url` 需发布时填写。
3. **Windows 覆盖脚本会显示一个控制台窗口**（失败时 `pause` 保留日志）；
   当前不重命名/不删除目标目录中的多余旧文件（`robocopy /E` 只覆盖并新增）。
4. 服务器上 `~/Elysia/Elysium/Ayla` 是 `git@github.com:AyerElysia/Elysium.git` 的**子模块**，
   而本地父仓库的 Ayla 子模块指向 `TriSeTide/Ayla`；`deploy-backend` 以**本地 Ayla 工作树**的 HEAD
   打包（快进校验基于服务器当前 HEAD），不依赖 GitHub 连通性 —— 服务器 `ls-remote` 已验证可访问，
   但此流程刻意不要求它联网。
