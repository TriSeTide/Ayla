**硬约束（继承 AGENTS.md + M4-5 契约）**：
- 前端**永不直连 Elysium `/api/v1`**；爱莉语音交互（创建通话/文本注入/结束/轮询转写）一律走应用后端 `/api/v1/elysia/voice-calls/*` 代理。
- **主体性铁律（AGENTS.md §4.1 / M4-5 §3.3）**：前端绝不生成爱莉的第一人称内容；爱莉在语音频道的"发言"只渲染后端投影到聊天链里的爱莉消息（来自 `voice_call.transcript.final` 投影），`voice.state` 里爱莉的状态（connected/speaking 等）是**技术状态**，UI 只能中性表达（如"通话中"），禁止写成"爱莉正在说话/很开心"一类主观描述。
- **LiveKit token 是媒体凭据**：只从 `POST /voice/channels/<id>/join/` 获取，绑定本人 + 本房间；前端不得缓存/复用他房间的 token，不得把 token 打进日志。
- **幂等是工程硬约束**：离开频道、结束爱莉通话、文本注入重试都必须可安全重复（服务端幂等/单并发复用）；文本注入失败重试不制造重复语义（后端带 `Idempotency-Key`，前端重试走同一请求即可，服务端已兜底）。
- LiveKit 未配置时 `join` 返回 503——前端要显式提示"语音服务未配置"，不得静默失败或伪造"已加入"。
- 断线重连是双层：应用 WS（voice.state 订阅）走指数退避重连；LiveKit 媒体连接由 `livekit-client` 自带重连，前端监听其 `Disconnected/Reconnected` 事件更新 UI，**不得把媒体断连伪装成已离开频道**。
- 每次改动要有与风险相称的测试（Vitest 单测 + mock WS/LiveKit 契约测试）。
- 只写 `web/` 相关代码；不动 backend 已有代码（除非公共契约确有缺陷，先说明再动）。

## 1. 目标（M5-3 验收定义）

完成**语音界面**的完整闭环（开发文档 §8 M5-3：语音频道 + 通话控制）：

- **频道列表**：语音频道卡片（名称/人数/我是否在其中）；建频道；爱莉语音频道入口（M5-6 预留，本期按编排端点接入）
- **加入/离开**：`POST join/` 拿 LiveKit token → `livekit-client` 连房间；`POST leave/` 离开并断开媒体连接
- **通话控制（元数据 + 媒体双层）**：
  - 静音/取消静音：`localParticipant.setMicrophoneEnabled(false/true)`（媒体层，LiveKit 客户端完成）
  - 成员音量：每个远端参与者独立音量滑条（`RemoteAudioTrack.setVolume()` 或 audio 元素 `volume`）
  - 成员列表实时更新：订阅 `voice.state`（joined/left/heartbeat/muted）
- **presence 心跳**：在频道期间按固定间隔 `POST heartbeat/`（刷新 `last_seen_at`，防被超时清理）；离开/断线停止
- **断线恢复**：应用 WS 断线自动重连并重新 `subscribe`；LiveKit 媒体断线由 SDK 重连，UI 显示"媒体重连中"而非"已离开"
- **爱莉语音（控制面闭环，对齐 M4-5 §5.2）**：爱莉频道面板——创建/复用 Voice Live 通话（`POST /elysia/voice-calls/`）、文本注入（`POST .../text/`）、结束（`POST .../end/`）、轮询投影（`POST .../poll/` 触发增量转写投影，爱莉发言出现在关联聊天链）；爱莉通话状态以 `GET .../<call_id>/` 为准渲染
- **契约测试**：REST 调用、WS 协议、LiveKit 交互（mock `livekit-client`）、心跳节奏、越权/503 提示

**不包含（本里程碑边界，显式声明）**：
- **真人 ↔ 爱莉实时双向音频互通**（M4-5 §5.3 最大未决点：WebRTC vs WS+PCM16 两套媒体传输）：前端本期不做；爱莉语音只到「控制面 + 文本注入 + 转写投影」闭环
- **屏幕共享**（FR-14 可选）：LiveKit 支持但本期不做
- 直播（M5-4）、桌游（M5-5）：不在本期
- 完整视觉系统：沿用 M5-1/M5-2 最小样式 + 本次补齐语音组件样式

## 3. 后端契约（M5-3 直接对接，按真实代码为准）

### 3.1 语音频道 REST（挂 `/api/v1/voice/`）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| GET | `/voice/channels/` | - | 频道列表：`{id, name, room_name, owner_id, member_count, mine, created_at}[]` |
| POST | `/voice/channels/` | `{name}` | 201 频道 descriptor |
| GET | `/voice/channels/<id>/` | - | 详情（含 `member_count`、`mine`） |
| PATCH | `/voice/channels/<id>/` | `{name}` | 改名（仅 owner，403 文案"仅频道创建者可改名称"） |
| POST | `/voice/channels/<id>/join/` | - | `{channel_id, room_name, token, ws_url, ttl, joined:true}`；**LiveKit 未配置 → 503** `{detail:"LiveKit 未配置，无法加入语音频道"}` |
| POST | `/voice/channels/<id>/leave/` | - | `{left:true}`（幂等：重复离开返回同样结果） |
| POST | `/voice/channels/<id>/heartbeat/` | - | `{ok:true}`；**非成员 → 403** |
| GET | `/voice/channels/<id>/members/` | - | `[{id, user_id, joined_at, last_seen_at}]` |

### 3.2 Voice WebSocket（`/ws/voice/?token=<jwt>`）

**客户端 → 服务端帧**：

```json
{"type": "subscribe", "channel_ids": ["1", "2"]}
{"type": "ping", "ts": 123456}
```

**服务端 → 客户端帧**：

```json
{"type": "voice.subscribed", "data": {"channel_id": "1"}}
{"type": "voice.state", "data": {"channel_id": "1", "user_id": "a5bdf...", "state": "joined", "ts": "2026-08-13T00:00:00Z"}}
{"type": "pong", "ts": 123456}
{"type": "error", "detail": "..."}
```

**协议要点（按 consumers.py 真实实现）**：
- 未认证 → `close(4401)`。
- `subscribe`：逐个校验频道存在 + **我是成员**；不存在或非成员**静默忽略**（不回 `voice.subscribed`，不 group_add）。**因此必须先 REST join 成功再 subscribe**；join 后 subscribe 才会收到 `voice.subscribed`。
- `voice.state` 的 `state` 枚举：`joined / left / heartbeat / muted / unmuted`；爱莉频道的爱莉条目 `user_id` 是爱莉 profile 绑定的应用内 user，`state` 来自 Voice Live 技术状态映射——**UI 中性表达**（见硬约束）。
- 心跳：30s `ping` 保活（对齐 chat WS 节奏）。

### 3.3 爱莉语音编排 REST（挂 `/api/v1/elysia/`，真实契约以 `elysia_bridge/views.py` 为准）

| 方法 | 路径 | 说明 | 返回要点 |
|---|---|---|---|
| POST | `/elysia/voice-calls/` | 创建/复用爱莉 Voice Live 通话（**单并发**：活跃通话未结束则复用） | `{call: {call_id, state, mode, resumable, connected, ...}, connection: {...}|null, reused: bool}` |
| GET | `/elysia/voice-calls/<call_id>/` | 通话状态 | `{call: {...}}` |
| POST | `/elysia/voice-calls/<call_id>/text/` | 文本注入（真人想对爱莉说的话） `{text}`；空 → 400 | `{command_id, status, accepted}` |
| POST | `/elysia/voice-calls/<call_id>/end/` | 结束通话（幂等） | `{command_id, status, accepted}` |
| POST | `/elysia/voice-calls/<call_id>/poll/` | 增量转写投影（把 final transcript 投影为爱莉消息） | `{projected: [...], total: n}` |

**错误语义**：profile 未初始化/禁用 → 503；未登录 → 401；Elysium 侧错误 → 502 `{detail, code}`。前端按 status 分别提示，不静默吞掉。

### 3.4 LiveKit（前端媒体面）

- `join` 返回的 `token` + `ws_url` 交给 `livekit-client`：`room = new Room(); await room.connect(ws_url, token)`。
- 静音：`room.localParticipant.setMicrophoneEnabled(bool)`（SDK 自动 publish/unpublish 麦克风轨）。
- 音量：遍历 `room.remoteParticipants` → `participant.audioTrackPublications` → 取 `RemoteAudioTrack`，`track.setVolume(0~1)`（或挂到 `<audio>` 元素调 `volume`）。**音量是本地播放偏好，不落库、不上报**。
- 事件：`RoomEvent.Disconnected / Reconnecting / Reconnected / ParticipantConnected / ParticipantDisconnected / TrackSubscribed / TrackUnsubscribed` → 归一到 voice store。
- token TTL（默认 600s）到期前：`livekit-client` 不断线则无需主动续签；若 SDK 报 token 过期断线，重新走 `join` 拿新 token 再连（成员幂等，`join_channel` 重复调用安全）。

## 4. 关键实现要点

### 4.1 voice store（成员表 + 当前频道）

```ts
// voice store 形态
{
  channels: VoiceChannelDescriptor[];   // 频道列表
  currentChannelId: string | null;      // 我正在的频道
  members: Record<string, VoiceMemberState>;  // user_id → { user_id, joined_at, muted, speaking, volume }
  livekit: "idle" | "connecting" | "connected" | "reconnecting" | "failed";
  wsConnection: "connecting" | "online" | "offline";
}
```

- `voice.state` 合并：`joined` → 写入成员；`left` → 移除；`muted/unmuted` → 更新标记；`heartbeat` → 只刷新 `last_seen`（UI 可不展示）。
- 成员基础信息（昵称/头像）复用 M5-2 已有的用户缓存（或按 `user_id` 懒拉 `users/search`）；**不要**在 voice store 里复制一份用户资料源。
- 离开频道 / 切换频道：清空 `members` + `currentChannelId`，断开 LiveKit 连接，停止心跳定时器。

### 4.2 加入/离开编排（useVoiceChannel）

1. `POST join/` → 成功拿 `{token, ws_url, room_name}`；**503 → 提示"语音服务未配置"并终止**（不进入媒体连接）。
2. `livekit/client.ts` 连接房间；`connected` 后：
   - 默认开麦与否按用户选择（UI 提供"加入时静音"勾选项；默认关麦加入更安全，见已知取舍）；
   - 启动 presence 心跳定时器（间隔取 `VOICE_MEMBER_TIMEOUT_SECONDS` 的 1/3 量级，如后端默认 90s 则 30s 一次；读不到配置时前端常量 30s）；
   - Voice WS `subscribe [channel_id]`（WS 单例已在登录后连上；未连则先连）。
3. 离开：`POST leave/` → 断开 LiveKit → 停止心跳 → `unsubscribe`（WS 侧无退订帧，本地清集合即可，对齐 chat WS 模式）。
4. **异常路径**：join 成功但 LiveKit 连接失败 → 调 `leave/` 回滚成员状态并提示；心跳 403（被超时清理后仍尝试心跳）→ 视为已被移出，本地重置到未加入态。

### 4.3 静音与音量

- 静音切换：本地立即更新 UI 图标（乐观），调 `setMicrophoneEnabled`；SDK 抛错则回滚 UI 并提示。
- `muted/unmuted` 上报：本期后端接受客户端静音态经 `voice.state` 广播（元数据层，不落库强制）——**本期前端不主动上报**（后端 REST 无对应端点，广播来自后端服务路径）；自己的静音态只影响本地 LiveKit 发布，他人从 LiveKit `TrackMuted` 事件感知（SDK 层），应用层 `voice.state` 只处理 `joined/left/heartbeat`。**两者不要混用**：LiveKit 的轨道 mute 是媒体事实，`voice.state` 是应用层成员事实。
- 音量滑条：每个远端成员 0~100，默认 100；只影响本地播放，不持久化（刷新重置，可接受，README 注明）。

### 4.4 断线恢复（双层）

- **应用 WS（voice.state）**：对齐 chat WS 单例——指数退避重连，重连成功后对 `subscribed` 集合重发 `subscribe`；voice WS 无 resume/补发语义（状态是即时的），重连后**主动拉一次 `GET members/` 对账**，避免漏掉断线窗口内的成员变化（`voice.state` 不落库、无补发）。
- **LiveKit 媒体**：监听 `Reconnecting` → UI 显示"媒体重连中"（保持成员面板不清空）；`Reconnected` → 恢复；`Disconnected`（最终失败）→ 提示并给出"重新加入"按钮（走 join 幂等路径）。**媒体断线 ≠ 离开频道**：不自动调 `leave/`，由用户决定。
- 心跳定时器在媒体重连期间继续（应用层成员身份不因媒体抖动丢失）。

### 4.5 爱莉语音面板（useElysiaVoice）

- 进入爱莉频道（或爱莉面板）时：`POST /elysia/voice-calls/` 创建/复用通话。返回 `reused:true` 说明已有活跃通话（Voice Live 单并发），直接接入展示，**不提示错误**。
- 状态轮询：`GET .../<call_id>/` 每 5s 刷新（仅在面板打开时）；`state=ended/failed` 时停止轮询并允许重新创建。
- 文本注入：输入框提交 `POST .../text/`；400（空文本）前端拦截不发；502 提示"爱莉侧不可用"。
- 转写投影：面板打开期间每 10s `POST .../poll/` 触发增量投影；**爱莉发言的渲染不在语音页做**——投影落在聊天链（爱莉会话），用户在聊天页可见（与 M5-2 爱莉会话复用）。语音页只显示"已投影 N 条"中性计数。
- 结束：`POST .../end/`（幂等，重复点击安全）；结束后 `call` 状态置 ended，UI 允许重新创建。
- **不伪造**：没有 final transcript 就没有爱莉发言——前端绝不本地生成"爱莉说：..."占位。

### 4.6 爱莉频道成员的特殊渲染

- 成员列表里爱莉条目（`user_id` = 爱莉 profile 的 user）：头像/昵称用 profile `display_name`；`voice.state` 的爱莉技术状态映射为中性标签：`connected/active` → "通话中"、`speaking` → "输出中"、`listening` → "接收中"、其他 → 不显示。**禁止**主观化文案（"爱莉正在思考"这类是 Provider 技术状态，不是她的主观意图——M4-5 §3.3）。

## 9. 已知取舍与待确认（遇到先记录，不阻塞）

- **加入默认关麦**：进频道默认 `setMicrophoneEnabled(false)`，用户手动开麦——避免误入频道即广播环境音；如汐汐偏好默认开麦再调整（UI 保留"加入时静音"勾选）。
- **音量不落库**：远端成员音量是本地播放偏好，刷新重置；持久化属后续体验优化。
- **mute 状态双通道**：应用层 `voice.state` 的 `muted/unmuted` 本期前端不上报（后端无 REST 入口）；他人静音态经 LiveKit SDK `TrackMuted` 事件感知——两套通道语义不同（媒体事实 vs 应用层成员事实），UI 以 LiveKit 为准显示静音图标。
- **voice.state 无补发**：WS 重连后必须 `GET members/` 对账（断线窗口的成员变化无补偿机制），已在 4.4 固化。
- **Voice Live 单并发**：爱莉语音同一时刻一个活跃通话；`reused:true` 是正常路径不是冲突；多人同时要与爱莉语音需排队——本期 UI 不做排队，先到先得（M4-5 §12 取舍继承）。
- **真人 ↔ 爱莉实时双向音频互通不做**（M4-5 §5.3 未决点继承）：爱莉语音只到控制面 + 文本注入 + 转写投影；音频互通需 Elysium 侧媒体网关契约，属公共契约缺陷，先说明再动。
- **爱莉发言渲染在聊天页**：语音页只显示投影计数；爱莉的"话"全部走聊天链（M5-2 爱莉会话），保持单一渲染源，不双写。
- **token 日志纪律**：LiveKit token 与 JWT 不得打进 console/日志；调试输出只打 call_id/channel_id 级别标识。
