## 1. 动画基座决策

**引入 `framer-motion`（包名 `motion` 亦可，下文统一称 framer-motion）作为动画基座**，理由：

- 本轮大量需求是**跟手转场**（群内横滑、直播间上下滑、侧滑返回、下拉刷新）：需要 motion value 逐帧驱动 transform、速度判定、弹簧吸附——纯 CSS 做不了跟手，自研 rAF + 手写 transform 管理在多手势场景下复杂易碎。
- 需要**进出协同**（旧场景滑出 + 新场景滑入）：`AnimatePresence` 是现成方案；纯 CSS 需要双元素自管理卸载时序。
- 需要**编排**（进群动画：底栏上移 + 内容浮入 + 输入框延迟滑入的时间线）。
- 体量可接受（core ~18KB gzip），React 18 兼容，无其他 runtime 依赖。
- 现状基线：`web/package.json` 无任何动画库；现有动画全部为 CSS keyframes（`frost-rise`/`halo-breathe`/`reveal-item-in`/`group-scene-fade`/`create-sheet-slide-in` 等），**全部保留**，framer-motion 只接管「跟手 + 进出协同 + 编排」三类 CSS 做不到的事。

**纪律**：时长/缓动仍遵守 design.md §7（150–300ms、ease-out 进 / ease-in 出、`prefers-reduced-motion` 全部降级为直切或纯淡入）；framer-motion 的 spring 只用于 ♡ 微反馈与跟手回弹，其余统一用 tween + 现有 `--ease-*` 变量对应的曲线。

**回退路径**：若某项 framer-motion 与现有 CSS 动画冲突，以 CSS 版本为准删 motion 版本，不双轨并存。

## 2. 转场体系

### 2.1 全局路由切换动画（A3，用户要求「所有界面切换都有动画」）

- **现状**：路由切换硬切；仅群内场景有 `group-scene-fade` 淡入、进房/进群有局部编排。
- **目标**：所有一级路由（/group /voice /live /posts /games /messages /chat/:id /search /profile /posts/:id /live/:id …）切换时：新页浮入（`opacity 0→1 + translateY(8px)→0，200ms ease-out`），旧页快速淡出（`150ms ease-in`，退出快于进入，§7）。
- **方案**：`AppShell` 内容区包 `AnimatePresence mode="popLayout"` + `useLocation()` key；页面根元素统一 `motion.div`（封装为 `PageTransition` 组件，避免每页手写）。`prefers-reduced-motion` 只留透明度。
- **注意**：群页（GroupPage）有自己的进群/退场编排，挂载 `PageTransition` 时其进入动画与 `useEnterGroupAnimation` 时间线合并，避免双重位移——群页进入用现有编排，退出走全局淡出。
- **落点**：`src/layout/AppShell.tsx`、新增 `src/components/motion/PageTransition.tsx`。

### 2.2 群内五子场景横滑跟手重做（用户拍板 3）

- **现状**：`GroupPage.tsx` `useSwipe` 只在 `onEnd` 判方向后 `goScene`；`group-scene-inner` 以 `key={activeScene}` 重挂载 + CSS 淡入。**无跟手位移、无退场**。
- **目标**：拖动时当前场景**跟手 translateX**（1:1，边缘阻尼）；松手按位移（>1/3 宽）+ 速度判定切换或回弹；切换时旧场景向对应方向滑出、新场景从对应方向滑入（250ms ease-out）；回弹 200ms ease-out。方向锁保持（垂直滚动优先）。
- **方案**：
  - `group-scene` 容器内当前场景包 `motion.div`，`drag="x"` + `dragConstraints={0}` + `dragElastic`（边缘阻尼）；`onDragEnd` 按 offset/velocity 调 `goScene(prev/next)`。
  - 场景切换动画：`AnimatePresence custom={direction}` + `variants`（enter: `x: ±40% → 0`，exit: `x: ∓30% → 透明`），`direction` 由切换前后 scene 索引差计算（`GROUP_SCENE_ORDER` 已有）。
  - **保持单场景挂载**（语音房/直播间是重组件有 WS 副作用，禁止五面板并排常挂）；滑出的是卸载中的旧场景实例（AnimatePresence 保管），滑入的是新场景。
  - PostEditor 等已有 `stopPropagation` 手势孤岛，天然不冲突；聊天列表垂直滚动由方向锁保护。
- **落点**：`GroupPage.tsx`、`group.css`（`group-scene-fade` 退役或降级为 reduced-motion fallback）、新增 `src/hooks/useSceneSwipeDirection.ts`（方向计算复用）。

### 2.3 下拉返回主页：内容协同（用户拍板 4）

- **现状**：`pullOffset` 只驱动 `GroupTopTabs` 的 transform，内容区纹丝不动。
- **目标**：下拉时**顶栏下移回底部 + 内容区同步跟手**（内容 `translateY(dy)` 全程 1:1，附轻微 `scale(1→0.98)` 与 `opacity(1→0.6)` 视差）；过阈值（80px，已有）松手：内容下滑出屏 + 顶栏落回底部（250ms ease-in），随后 `navigate("/group")`；不过阈值整体回弹（200ms ease-out）。
- **方案**：`pullOffset` 同时喂给内容容器 motion value；退场改为 AnimatePresence exit variant（替换现有 `setTimeout 250ms` 手工时序，语义不变）。
- **落点**：`GroupPage.tsx`（pullSwipe 分支 + 内容容器）、`group.css`。

### 2.4 进群动画编排补全（现状缺陷：只有导航栏动）

- **现状**：`useEnterGroupAnimation` 的 `entered` 只控制 GroupTopTabs 上移；群场景内容无入场。
- **目标**（对齐 design.md §12.12 已有定义，补齐实现）：时间线 = 底栏上移 250ms ease-out → 群场景内容自下方 24px 浮入 + 淡化（180ms，延迟 80ms）→ 输入框滑入（250ms，延迟 100ms，已有）。中央槽位「主页→群头像」交叉淡化已有则保留。
- **方案**：内容容器接 `entered`：`motion.div initial={{y:24, opacity:0}} animate={entered ? {y:0, opacity:1} : ...}` transition delay 0.08；`prefers-reduced-motion` 全部直切。
- **落点**：`GroupPage.tsx`、`useEnterGroupAnimation.ts`（如需导出时间线常量）。

### 2.5 直播间上下滑切换（G3，用户拍板 5：群内外都要）

- **现状**：`LiveRoomPage`（全站）与 `GroupLive`（群内）均无上下滑；`useSwipe.ts` 文档提到 F4 但未接线。
- **目标**（对齐 §12.12 F4）：直播播放区**跟手 translateY**；拖动中上/下边缘露出相邻直播间**封面预览 ≥20%**（轻量封面卡：封面图 + 标题 + 主播，不挂载真实播放组件）；松手过半（或速度达标）切换：旧直播间滑出、新直播间滑入（250ms ease-out），预览位替换为真实组件；不过半回弹。到列表端头时边缘阻尼+端头提示。
- **方案**：
  - 数据源：live store 已有直播间列表（全站 / 群内过滤），当前 index ±1 即相邻项。
  - 结构：垂直三槽容器（prev 预览 / 当前 / next 预览），当前槽为真实 `LiveRoomBody`，预览槽为 `LivePeerPreview`（新组件，纯展示）；拖动用 motion value 驱动三槽整体位移。
  - 切换 = 变更当前 live id（路由 `/live/:id` 已支持，群内走 GroupLive 内部状态），配合 AnimatePresence 滑动过渡。
  - 群内 `GroupLive` 复用同一组件（传入群内直播列表）。
- **落点**：`LiveRoomPage.tsx`、`GroupLive`（`components/group/` 下）、新增 `LivePeerPreview.tsx`、`live.css`。

### 2.6 私信侧滑返回（G6，用户拍板 7：仅 /chat/:id）

- **现状**：无私聊返回手势。
- **目标**：`/chat/:id` 页面**左边缘 24px 起手**右滑：整页跟手右移（1:1，附视差：底层消息中心列表以 0.3 倍速右移营造层次）；松手 >120px 或速度达标：页面滑出右屏（200ms ease-out）→ `navigate(-1)`（回消息中心）；否则回弹。
- **边界**：仅窄屏；群聊页不接（保持下拉返回）；聊天输入框区域滑动不触发（起手判定限定边缘带）。
- **落点**：`PrivateChatPane` 挂载页（`/chat/:id` 对应页面组件）、新增 `useEdgeSwipeBack.ts`（边缘起手判定封装 useSwipe）。

## 3. 手势与浮层体系

### 3.1 一级五 tab 横滑切换（G1）

- **现状**：一级页（/voice /live /group /posts /games）之间只能点底栏，无滑动。
- **目标**：窄屏一级页内容区左右滑切换相邻一级页，交互与 2.2 同款（跟手 + 方向判定 + 滑动过渡）；BottomTabs 选中态同步。顺序即 tab 顺序：语音 → 直播 → 主页 → 帖子 → 桌游。
- **方案**：与 2.2 共用「跟手 + AnimatePresence 方向变体」实现（抽 `useHorizontalScenePager` 或等价封装，群内/一级两处复用）；`AppShell` 一级页容器接线。**保持单页挂载**；`/group` 在宽屏是三栏布局，本手势仅窄屏。
- **注意**：08-25 已确认组件级 `stopPropagation` 手势孤岛方案对弹层/输入面板生效，横滑不会误触。
- **落点**：`AppShell.tsx`、`BottomTabs`（选中态联动已有路由驱动，无需改）。

### 3.2 图片查看器横滑切图（G2）

- **现状**：`ImageViewer.tsx` 无 touch 处理，多图仅左右按钮 + 键盘。
- **目标**：多条目时内容区横滑切上一张/下一张：跟手位移 + 边缘阻尼 + 松手吸附（过 1/3 或速度达标切换）；单条目时横滑 = 关闭（下滑关闭已有则保留）。
- **落点**：`ImageViewer.tsx`（条目容器 motion 化）。

### 3.3 下拉刷新（G5，移动端）

- **现状**：无任何刷新手势。
- **目标**：列表页顶部下拉触发刷新：跟手下拉（阻尼递增）→ 过阈值松手触发刷新（指示器：玻璃圆点 + 旋转 spinner，`frost-pulse` 同族语言）→ 完成后收起；不足阈值回弹。仅当列表已在顶部时响应（方向锁天然满足）。
- **接入范围**：主页群列表、消息中心会话列表、帖子流、直播列表（四处）。
- **方案**：封装 `PullToRefresh` 组件（children + onRefresh），内部 motion value + 状态机（idle/pulling/refreshing/done）；接入处包列表容器。
- **落点**：新增 `src/components/motion/PullToRefresh.tsx`；`GroupList`（主页）、`ConversationList`、`PostsHubPage`、`LiveHubPage`。

### 3.4 右下角浮层按钮组（G5 桌面端 + 回到顶部）

- **目标**：右下角垂直堆叠（自下而上）：`CreateFAB`（56px，已有）→ `ScrollTopFAB`（44px 玻璃圆钮，↑ 图标；页面滚动超过一屏才出现，点击平滑回顶）→ `RefreshFAB`（44px 玻璃圆钮，⟳ 图标；**仅桌面（>768px）显示**，点击触发当前页刷新）。出现/消失均带 200ms 浮入/淡出。
- **方案**：`ScrollTopFAB` 监听滚动容器（AppShell 主滚动区）；`RefreshFAB` 复用 PullToRefresh 的 onRefresh 通道（各页注册刷新回调，或由页面自行实现 onClick 刷新——取简单方案：各页自行传刷新函数，浮层组件只管外观与位置）。
- **落点**：新增 `ScrollTopFAB.tsx`、`RefreshFAB.tsx`（或合并 `CornerFabStack.tsx`）；`AppShell.tsx` 挂载；`app.css` 堆叠样式（间距 12px，避让 CreateFAB）。

### 4.1 U16 聊天窗口化细化

- **初始加载**：`loadHistory` limit 50 → 20（后端游标分页已支持，无需后端改动）。
- **向上翻页**：复用 `loadMoreHistory`；触发阈值 = 滚动距顶 < 400px 预加载；顶部加载指示（玻璃 spinner 条）。
- **渲染窗口**：消息 store 全量保留（权威缓存），`MessageList` 渲染窗口化——窗口外消息以「加载更早消息」占位行表示；窗口上限 200 条，超限从顶部收缩（收缩边界对齐翻页批次，避免半批渲染）。
- **滚动锚定**：向上插入历史消息时按插入前 `scrollHeight` 差值补偿 `scrollTop`（现有实现若已锚定则保留并补测试断言）。
- **新消息到达**：窗口化不影响底部实时追加；「回到底部」浮动钮（距底 >一屏时出现，点击回底并恢复实时跟随）一并实现——与 §3.4 CornerFabStack 语言一致，但挂聊天容器内右下。
- **验收**：500 条消息会话首屏只渲染 20 条（DOM 计数断言）；向上翻 3 页视口不跳；回复跳转跨窗口定位正确。

## 8. 风险与纪律

- **重组件挂载**：群内横滑、直播间上下滑严格保持「单真实实例 + 轻量预览」，禁止为动画把语音房/直播间多实例常挂（WS 副作用、内存）。
- **手势冲突**：所有新手势必须过方向锁（useSwipe 既有 lockSlop）；聊天列表滚动、PostEditor、输入框等已有孤岛保持 stopPropagation 链路；新增手势逐一与既有手势矩阵核对（群内：横滑切场景 + 下拉返回 + 编辑器孤岛；直播间：上下滑 + 弹幕列表滚动 + 输入框）。
- **性能**：跟手位移只动 `transform/opacity`（合成层）；列表 reveal stagger 封顶 300ms（§7.1 既有）；瀑布流量高用 ResizeObserver 节流。
- **回退**：每批独立可回退；framer-motion 若引发不可接受包体/兼容问题，仅 2.2/2.5/2.6/3.1/3.3 需要它，其余项均可用纯 CSS 独立回退。
- 验收结论区分「已验收/暂不验收/已回退」；涉及启动的验收由用户手动进行。
