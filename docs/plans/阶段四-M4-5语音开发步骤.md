**硬约束（继承 AGENTS.md + 阶段三决策 + 阶段四方案 §6/§7.4）**：
- **主体性铁律**（阶段四 §6.5 / 需求 NFR-6）：爱莉的"说过的话"以 Elysium 侧**真实 transcript / 发送回执**为准。应用侧**绝不伪造爱莉发言**：Voice Live 的转写文本只能来自阶段三 `transcripts` / observer 事件的投影，不能由应用侧生成；爱莉在语音频道里的"发言"必须可追溯到 Elysium `voice_call.transcript.final` 事件。
- **前端永不直连 Elysium**（阶段三决策 1 / 需求 §1.3）：一切爱莉语音交互（创建通话、ticket、转写、文本注入）经应用后端 `elysia_bridge` / `apps/voice` 代理。**真人用户之间的语音走 LiveKit（应用自己的 SFU）**，与爱莉无关。
- **爱莉 Voice Live 与 LiveKit 是两套媒体传输**（开发文档 §11 风险表第三行）：LiveKit 是 WebRTC SFU（真人多人频道），Voice Live 是浏览器 ↔ Elysium 的 WebSocket + PCM16 二进制协议（一对一意识实例，`max_concurrent_sessions=1`）。**本期不实现双向实时音频互通**（那需要与阶段三协调新契约，属公共契约缺陷，先说明再动）；本期以「控制面桥接 + 转写/状态投影 + 文本双向注入」打通爱莉入会闭环，见第 5 节与第 10 节。
- **幂等是工程硬约束**：向 Elysium 的 voice-call 命令（`:resume/:interrupt/:end/text`）必须带 `Idempotency-Key`（阶段三 `voice_call_*` 命令同 chat 命令的幂等语义）；应用内 `voice_channels` 落库复用 M4-2 `idempotency_key` 语义（如 `elysia-voice-<event_id>`）。
- **不扩张阶段三公共契约**：Voice Live 侧 `voice_call:operate` 只授权调用者被授权参与的通话；应用侧 credential 只申请所需最小 scope（见第 4.5 节），**不授 `admin:*`**。
- 每个订阅、后台任务、WS 连接与临时对象必须有明确 owner、超时、取消与关闭路径（AGENTS.md §7 / 阶段三决策 6）。
- LiveKit key/secret、Elysium voice-call 相关连接信息走本机配置，**不提交仓库**（开发文档 §10 / 部署纪律）。
- 每次改动要有与风险相称的契约测试（生命周期、鉴权、token 签发、幂等、断线恢复、主体性边界）。
- Elysium 必须由用户手动启动；LiveKit 属基础设施服务，可在 docker-compose 编排（不违背 Elysium 手工启动禁令）。

## 1. 目标（M4-5 验收定义）

完成**语音频道（真人多人）**与**爱莉 Voice Live 接入**两件事（开发文档 §8 M4-5 定义 + 需求 §3.4）：

### 1.1 真人语音频道（LiveKit，FR-13/14/16）

- **语音频道**：基于频道的多人语音（Discord 风格）；用户可加入/离开频道；`voice_channels` 表维护频道元数据（name/room_name/owner）。
- **LiveKit 集成**：自托管 LiveKit SFU；Django 用 LiveKit 官方 `livekit-api` 签发访问 token（绑定用户 identity + 房间 + publish/subscribe grants）。
- **通话控制（元数据层）**：静音/闭麦、音量由 LiveKit 客户端完成；**应用层只维护「谁在哪个频道」状态**，经 Chat WS 广播 `voice.state`。
- **断线恢复**：LiveKit 客户端自动重连；应用侧 `voice.state` 以 presence 心跳更新频道成员，成员表持久化。
- **验收**：2~8 人语音频道实时通话（P95<500ms，LiveKit 达标）；加入/离开状态广播正确；断线重连恢复。

### 1.2 爱莉 Voice Live 接入（FR-15）

- **控制面桥接**：应用后端经 `elysia_bridge` 调阶段三 `/voice-calls` 全套 REST——创建通话、查状态、`:resume`、`:interrupt`、`:end`、`/text`（文本注入）、`/transcripts`（转写历史）、`/tickets`（参与者/观察者 WS ticket）。
- **转写/状态投影**：应用后端以 **observer** 身份订阅该通话的 `voice_call.*` 事件（SSE `events/stream` 的事件类型过滤 `voice_call.`）或 `/observe` WS，把爱莉**真实 final transcript** 投影为语音频道内的"爱莉发言"（可追溯，不伪造），并广播 `voice.state` 更新爱莉在场/说话状态。
- **文本双向注入**：真人把想对爱莉说的话以文本提交给应用后端 → `POST /voice-calls/{id}/text` 注入 Voice Live（爱莉侧可听可说路径由 Elysium 管理）。
- **验收**：爱莉在应用内"入会"语音频道；真人通过文本/转写与爱莉语音对话闭环（至少一条真实路径可演示，见第 8.2 节端到端状态）。

**不包含（本里程碑边界，显式声明）**：
- **真人 ↔ 爱莉的实时双向音频互通**（把真人 WebRTC 音频实时送进 Voice Live、把爱莉 PCM16 音频实时播进 LiveKit Room）：协议不同（WebRTC vs WS+PCM16）、Voice Live `max_concurrent_sessions=1`、且需要 Elysium 侧新增媒体网关契约——属**未决点**（第 10 节），本期不做，先记录。
- 屏幕共享（FR-14 可选）：本期不做，LiveKit 本身支持，后续按需开启。
- 直播（M4-6）、桌游（M4-7）：不在本期。
- 不改造 Elysium 阶段三 voice-calls 代码（除非公共契约确有缺陷，先说明再动）。
