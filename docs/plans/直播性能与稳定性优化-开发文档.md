## 1. 现状架构（双端对照）

### 1.1 Web 端

```
LiveRoomBody.tsx (视图)
   └─ useLiveRoom.ts → liveSessionRuntime.ts (全局单例，唯一 owner)
        ├─ HlsPlayer (player/hls.ts, 基于 hls.js ^1.7.0)
        ├─ video 元素（全局唯一，通过 attachVideoTo / stashVideo 在容器间原子迁移）
        └─ miniPlayer 投影 → AppShell.tsx 渲染 LiveMiniPlayer 浮层
```

**关键事实**：
| 项 | 值 | 位置 |
|---|---|---|
| 低延时参数 | `lowLatencyMode: true` + `liveSyncDurationCount: 2` + `startLoad(-1)` | `hls.ts:43-46,68` |
| 跳边实现 | `hls.liveSyncPosition` → `seekable.end()` → `reload+play` 三级兜底 | `hls.ts:120-148` |
| 自愈参数 | `STALL_TIMEOUT_MS=2000` / `REBUILD_COOLDOWN_MS=4000` | `liveSessionRuntime.ts:30,32` |
| video 迁移 | 同一元素 appendChild 到不同容器，**不脱离文档 ⇒ 不暂停** | `liveSessionRuntime.ts:100-136` |

### 1.2 Flutter 端

```
LiveRoomPage (每页 new 一个 session)
   └─ AylaLiveRoomSession (pages/live_support.dart)
        ├─ HlsPlaybackController (player/hls_player.dart)
        │    ├─ MediaKitHls   (Windows, libmpv)   player/platforms/media_kit_impl.dart
        │    └─ VideoPlayerHls (Android/iOS)      player/platforms/video_player_impl.dart
        ├─ videoView 注入 AylaLivePlayer（widgets/live/live_player.dart）
        └─ miniPlayer 投影 → AppShell._LiveMiniPlayerHost → 第二引擎窗口
```

**关键事实**：
| 项 | 值 | 位置 |
|---|---|---|
| 播放器创建 | `Player()` **无参**，全用 media_kit 默认 mpv 参数 | `media_kit_impl.dart:45-47` |
| 起播 | `p.open(Media(url), play: true)`，无任何贴边参数 | `media_kit_impl.dart:67` |
| 跳边 | `seek(duration)` ← **语义错误** | `media_kit_impl.dart:76-89` |
| 自愈 | `kStallTimeoutMs=2000` / `kRebuildCooldownMs=4000` / `kMaxAutoRebuilds=2` | `hls_player.dart:20-30` |
| 平台视图 | 不可跨树迁移，只能「这边卸、那边挂」 | `live_player.dart` 文件头 |
| 小窗 | 第二 Flutter engine + 第二窗口 + 第二播放器 | `core/platform/detached_live.dart` |

### 1.3 双端核心差异

| 维度 | Web | Flutter | 影响 |
|---|---|---|---|
| video 迁移 | **同一元素原子迁移** | 平台视图不能迁移，只能重建 | Flutter 切形态必然重建播放器 ⇒ 更依赖自愈 |
| 会话归属 | 全局单例 | 页面级（每页 new） | Flutter 切台 = 整页重建 = 重新握手 |
| 低延时参数 | **已配** | **完全未配** | Flutter 是延时主要来源 |
| 跳边实现 | liveSyncPosition（正确） | seek(duration)（错误） | 刷新键无效的根因 |

## 2. 总体方案

### 2.1 分层策略

```
层 1  推流端（OBS）      GOP 8.33s → 1s（★ 唯一需改项，其余保持 1080p30/3000kbps/NVENC）
层 2  服务器（SRS）      hls_fragment 2 / hls_window 15 / gop_cache off
层 3  拉流入口           裸 IP 直连 volx（去掉樱花回退）
层 4  播放器参数         Flutter 补 mpv 贴边参数；Web 已达标
层 5  自愈状态机         双端重写为「有界 + 可恢复 + 语义化」
层 6  渲染/生命周期      纹理固定尺寸、后台恢复、全屏层动态刷新
```

**层 1~3 是配置，层 4~6 是代码。** 层 1 未做则层 2 无效（GOP 决定分片下限）。

### 2.2 实施顺序（不可颠倒）

| 阶段 | 内容 | 依赖 | 预计 |
|---|---|---|---|
| **P0** | 层 1（GOP）+ 层 2（SRS 配置） | 用户操作 OBS + 批准重启 SRS | 0.5 天 |
| **P1** | 层 3（裸 IP 直连） | 无 | 0.5 天 |
| **P2** | 层 6 的 B4/B5（纹理固定、后台恢复） | 无 | 1 天 |
| **P3** | 层 5（自愈状态机重写） | 无 | 2 天 |
| **P4** | 层 6 的 B1/B6 + 层 4（mpv 参数） | 无 | 2 天 |
| **P5** | 刷新键贴边 + 反馈（双端） | 无 | 1 天 |
| **P6** | 单观众长时实测（1080p30@3000kbps 连续 30 分钟） | P0~P5 完成 | 0.5 天 |

> ⚠️ **P0 必须先做**：不改 GOP，SRS 分片永远是 16.67s，后面所有优化收益都被吃掉。

## 3. 缺陷修复方案（逐条）

### B1 全屏层冻结

**根因**：`live_player.dart:491-498` 把 `_buildFullscreen()` 的结果（一个已构建的 Widget 实例）塞进 OverlayEntry 的 builder 闭包里。OverlayEntry 子树不会因 `setState` 重建，播放器自愈重建后 `videoView` 变了，全屏层仍持有旧引用。

**修复**：
```dart
// 改前（live_player.dart:491-498）
final Widget fullscreen = _buildFullscreen();
final OverlayEntry entry = aylaOverlayEntry(builder: (ctx) => fullscreen);

// 改后：builder 内动态取，并在播放器状态变化时 markNeedsBuild
final OverlayEntry entry = aylaOverlayEntry(
  builder: (BuildContext ctx) => _buildFullscreen(),  // 每次重建都取最新
);
// 并在 _onPlayerState 变化处：
_fsEntry?.markNeedsBuild();
```

**Web 对照**：web 无此问题（video 元素是同一 DOM 节点，`requestFullscreen` 只改容器，元素本身不变）。**登记为 Flutter 独有缺陷。**

**测试**：`test/live_fullscreen_rebuild_test.dart` — 全屏中替换 videoView，断言全屏层渲染的是新视图。

### B2 自愈封顶后永久放弃

**根因**：`hls_player.dart:203-212` 的 `_autoRebuild` 在 `_autoRebuilds >= maxAutoRebuilds` 时只调 `onError` 后 return，**没有任何后续重试路径**。`_autoRebuilds` 只在 `_markStarted()`（position > 0）时清零。

**修复**：引入**时间窗重置**。
```dart
// 新增：连续失败超过该时长后自动重置计数（不是永久封顶）
const Duration kRebuildCountResetWindow = Duration(seconds: 60);

DateTime _lastFailureAt = DateTime.fromMillisecondsSinceEpoch(0);

Future<void> _autoRebuild(String url, String reason) async {
  // 时间窗重置：距上次失败超过 60s ⇒ 视为新一轮，计数归零
  if (DateTime.now().difference(_lastFailureAt) >= kRebuildCountResetWindow) {
    _autoRebuilds = 0;
  }
  _lastFailureAt = DateTime.now();
  if (_autoRebuilds >= maxAutoRebuilds) {
    _log('本次失败已达上限（$maxAutoRebuilds），$reason');
    _events.onError?.call(reason);
    // ★ 关键：不再永久放弃，排一个延迟重试
    _scheduleRetryAfterCooldown(url);
    return;
  }
  ...
}

void _scheduleRetryAfterCooldown(String url) {
  _retryTimer?.cancel();
  _retryTimer = Timer(kRebuildCountResetWindow, () {
    if (_currentUrl != url) return;
    _autoRebuilds = 0;
    unawaited(_autoRebuild(url, '时间窗后自动重试'));
  });
}
```

**Web 对照**：`liveSessionRuntime.ts:407` 有 `REBUILD_COOLDOWN_MS` 但同样缺少时间窗重置 ⇒ **双端同改**。

**测试**：`test/hls_player_rebuild_window_test.dart` — 连续触发 3 次失败后，推进 fake time 60s，断言第 4 次重建被触发。

### B4 窗口缩放触发纹理重建（Flutter 独有）

**根因**：`media_kit_video` 的 `VideoOutput::CheckAndResize()`（`windows/video_output.cc:241-265`）在 `GetVideoWidth() != surface_manager_->width()` 时调 `Resize()`，而 `Resize()` 会 `UnregisterTexture(旧id)` + 新建纹理 + 通过 `VideoOutput.Resize` 方法调用把新 id 传给 Dart。

`GetVideoWidth()`（`video_output.cc:366-413`）在 `width_` 为空时读 **`video-out-params` 的 dw/dh（视频自身分辨率）**；只有 `SetSize()` 被显式调用才会固定。

**Ayla 从未调用过 `VideoController.setSize()`**（全仓 grep 0 命中）⇒ 纹理尺寸完全跟随视频分辨率，任何导致 mpv 重算输出尺寸的事件都可能触发重建。

**修复**：在 `MediaKitHls.attach` 后固定纹理尺寸。
```dart
// media_kit_impl.dart
final p = Player();
_player = p;
_videoController = VideoController(p);
// ★ 固定纹理尺寸为视频原生分辨率，避免窗口尺寸变化驱动纹理重建
// 1080p 直播固定 1920x1080；未知时保持 null（跟随视频）
unawaited(_videoController!.setSize(width: 1920, height: 1080));
```

**更稳妥的做法**：监听 `player.stream.width/height`，在**视频分辨率真的变化时**才调 `setSize`，窗口尺寸变化不触发。
```dart
_subs.add(p.stream.width.listen((w) {
  if (w != null && w > 0) _applySize(w, p.state.height);
}));
```

**验证**：`flutter run` 后反复拖动窗口尺寸 20 次，观察日志中是否出现 `VideoOutput.Resize`。**修复后不应出现。**

### B5 后台暂停后不自动恢复

**根因**：`media_kit_video` 的 `Video` widget 参数默认值（`video_texture.dart:132-133`）：
```dart
this.pauseUponEnteringBackgroundMode = true,    // 默认暂停
this.resumeUponEnteringForegroundMode = false,  // 默认不恢复 ★
```

Ayla 在 `media_kit_impl.dart:104-108` 创建 `Video` 时**没有传这两个参数** ⇒ 进后台暂停、回前台不播。

**修复**：
```dart
return Video(
  key: ObjectKey(vc),
  controller: vc,
  controls: NoVideoControls,
  pauseUponEnteringBackgroundMode: false,   // ★ 由会话层统一管理生命周期
  resumeUponEnteringForegroundMode: true,   // ★ 双保险
);
```

**注意**：直播场景不建议用 `pauseUponEnteringBackgroundMode: false`（后台继续解码耗电），推荐组合是：**保持 pause=true，但 resume=true**。具体取哪个由 §3.6 的画面槽位状态机统一决策。

**Web 对照**：web 无此问题（浏览器 video 元素生命周期由浏览器管）。**登记为 Flutter 独有缺陷。**

### R1~R3 刷新键

**R1 修复（Flutter）**：
```dart
// media_kit_impl.dart:76-89 改前
final dur = p.state.duration;
if (dur > Duration.zero) { await p.seek(dur); return true; }

// 改后：用 mpv 的 seekable-ranges 取真实边缘
@override
Future<bool> seekToLiveEdge() async {
  final p = _player;
  if (p == null) return false;
  try {
    // mpv 暴露 seekable-ranges；取最后一段的末尾
    final String ranges = await (p.platform as dynamic).getProperty('seekable-ranges');
    final Duration? edge = _parseSeekableEnd(ranges);
    if (edge != null && edge > Duration.zero) {
      // 回退 1 个分片时长（2s），避免 seek 到尚未写完的边缘
      final Duration target = edge - const Duration(seconds: 2);
      await p.seek(target > Duration.zero ? target : edge);
      return true;
    }
    // 兜底：duration - 2s
    final Duration dur = p.state.duration;
    if (dur > const Duration(seconds: 4)) {
      await p.seek(dur - const Duration(seconds: 2));
      return true;
    }
    return false;
  } catch (_) { return false; }
}
```

**R1 修复（Web）**：web 已有 `liveSyncPosition`（`hls.ts:125`），但 `seekable.end()` 分支（`hls.ts:134-137`）直接 seek 到 end，**没有回退 1 分片** ⇒ 改为 `end - segmentDuration`。

**R2 修复（双端）**：刷新后显示状态。
| 端 | 实现 |
|---|---|
| Flutter | `AylaLivePlayer` 增加 `refreshFeedback` 参数，会话层在 seek 完成后置「已贴边」，2s 后清除 |
| Web | `LivePlayer.tsx` 增加同语义的 toast/文案，复用既有 `.live-player-status` 样式 |

**R3 修复（双端）**：状态非 playing 时不再整条重建，改为「先尝试 seek，失败才重建」。

## 4. 延时优化（层 1~4）

### 4.1 层 1：推流端 GOP（用户操作）

> **目标配置：1080p30 @ 3000kbps / NVENC，只改 GOP。**
> 分辨率、帧率、码率、编码器、预设**全部保持现状**，唯一必须改的是关键帧间隔。

**OBS 设置（只需改一项）**：
```
设置 → 输出 → 输出模式「高级」
  编码器：NVENC H.264        ← 保持
  码率控制：CBR              ← 保持
  码率：3000 Kbps            ← 保持
  关键帧间隔：1 秒            ← ★ 唯一必须改（当前 8.33s，这是延时总根源）
  预设：P5 或 P6             ← 保持
设置 → 视频
  基础/输出分辨率：1920x1080  ← 保持
  FPS：30                    ← 保持
```

**为什么必须是 1s 而不是 2s**：
- 目标延时 4~5s，需要 SRS 分片 ≤1s 才能把起播落后控制在 2 片以内；
- GOP=2s 时分片 2s，起播落后 2 片 = 4s，加上网络与解码开销会顶到 5~6s 上限；
- GOP=1s 时分片 1s，起播落后 2 片 = 2s，留出 2~3s 余量吸收抖动。

**代价**（可接受）：
| 项 | 影响 |
|---|---|
| 码率 | 关键帧密度 ×8，1080p 下约 +10~25%（3000 → 3300~3700 kbps 实际） |
| 推流 CPU | NVENC 硬件编码，影响 <5% |
| 画质 | 同码率下略降（关键帧占更多比特），1080p30@3000kbps 可接受 |

**验证**：推流后看 SRS 日志分片时长。
```bash
docker logs --tail 20 ayla-srs 2>&1 | grep 'HLS time'
# 期望：dur=1000ms 左右（而不是现在的 16667ms）
```

### 4.2 层 2：SRS 配置

**当前**（`~/Elysia/ayla-deploy/srs.conf`）：
```nginx
vhost __defaultVhost__ {
    hls {
        enabled         on;      # ← 只有这一行，走默认 10s/60s
    }
    http_remux {
        enabled         on;
        mount       [vhost]/[app]/[stream].flv;
    }
}
```

**目标**：
```nginx
vhost __defaultVhost__ {
    hls {
        enabled         on;
        hls_fragment    1;        # 分片 1s（需 GOP=1s 才生效）
        hls_window      10;       # 窗口 10s（保留 ~10 片）
    }
    http_remux {
        enabled         on;
        mount       [vhost]/[app]/[stream].flv;
    }
    play {
        gop_cache       off;      # ★ 关 GOP 缓存，避免新观众吃积压
        queue_length    5;        # 队列收紧
        mw_latency      200;      # 最小延迟模式（ms）
    }
}
```

> ⚠️ **风险**：`gop_cache off` 意味着新观众要等下一个 I 帧才能出画。GOP 1~2s 时最多等 2s，可接受；GOP 8.33s 时会等 8s，**所以必须先做层 1**。

**生效**：需重启 SRS 容器（`docker compose restart srs`），**会中断当前推流，需用户批准**。

**同步更新**：`Ayla/srs.conf`（仓库版）与 `Ayla/deploy/examples/srs.conf.example`（部署模板）**都必须改**，否则新部署会退回默认值。

### 4.3 层 3：拉流入口裸 IP 直连

**背景**：`live.trise.top:7882` 的 HTTPS 被阿里云备案拦截（SNI 含 trise.top 即 RST，实测确认）。必须用裸 IP。

**Flutter 修改**：`lib/core/net/live_play_url.dart`
```dart
/// 拉流入口（volx，裸 IP 直连）。
/// 为什么用 IP 而不是域名：见需求文档 §4.2 约束 C3。
const String kAylaVolxPullHost = '47.108.85.223';
const int kAylaVolxPullPort = 7882;

String aylaNormalizeLivePlayUrl(String url, {String? apiBase, bool? configured}) {
  // ... 既有逻辑保留 ...
  // 改为：直播流路径 → 重写到 volx 裸 IP
  return Uri(
    scheme: 'https',
    host: kAylaVolxPullHost,
    port: kAylaVolxPullPort,
    path: parsed.path,
    query: parsed.hasQuery ? parsed.query : null,
  ).toString();
}
```

**证书处理**：volx 的证书 SAN 是 `*.trise.top`，用 IP 连接会 hostname mismatch。两个方案：
| 方案 | 做法 | 评价 |
|---|---|---|
| A1 | nginx 换一张带 `IP:47.108.85.223` 的自签证书 | ✅ 推荐，客户端保持正常校验 |
| A2 | 客户端对该 IP 显式信任（mpv `--tls-verify=no` 等价） | ⚠️ 降级，仅作过渡 |

**去掉樱花回退**（用户明确要求）：删除 `live_play_url.dart` 中重写到 API 同源的逻辑，改为固定 volx 裸 IP。

**Web 修改**：`Ayla/web/src/` 中若有同类归一逻辑，同步改为裸 IP。

### 4.4 层 4：播放器参数（Flutter）

**media_kit 注入 mpv 参数**（`media_kit_impl.dart`）：
```dart
final p = Player();
final np = p.platform;
if (np is NativePlayer) {
  await np.setProperty('demuxer-lavf-o',
      'live_start_index=-1,seg_max_retry=5,http_persistent=1,reconnect=1');
  await np.setProperty('cache-secs', '2');
  await np.setProperty('demuxer-max-bytes', '8388608');   // 8MiB
  await np.setProperty('demuxer-readahead-secs', '1');
  await np.setProperty('cache-pause-initial', 'no');
  await np.setProperty('hls-bitrate', 'max');
}
```

| 参数 | 默认 | 目标 | 作用 |
|---|---|---|---|
| `live_start_index` | -3（ffmpeg 默认） | **-1** | 从最后一个分片起播，而不是边缘前 3 片 |
| `cache-secs` | 极高 | **2** | 限制预读时长 |
| `demuxer-max-bytes` | 32MiB（media_kit 默认） | **8MiB** | 限制缓冲大小 |
| `demuxer-readahead-secs` | 默认 | **1** | 减少预读 |

**移动端（ExoPlayer）**：`video_player` 插件锁死了 `LoadControl`（`TextureVideoPlayer.java:60-81`），**不 fork 插件无法调**。本期策略：
| 方案 | 可行性 | 结论 |
|---|---|---|
| fork `video_player_android` 设 `LoadControl(3000, 15000, 500, 1000)` + `targetOffsetMs 2000` | 可行但工作量大 | **本期不做**，登记为后续项 |
| 保持默认 | 延时较高（约 10~20s） | 可接受（仍在 10s 目标边缘） |

> **移动端延时不达标时的补救**：改用 HTTP-FLV（后端已下发 `flv_url`，但 `video_player` 的 ExoPlayer 对 FLV 支持需实测）。

## 5. 自愈状态机重写（层 5）

### 5.1 设计目标

| 目标 | 说明 |
|---|---|
| **有界** | 任何情况下都有上限，不会无限重建 |
| **可恢复** | 封顶后不是永久放弃，而是延迟重试 |
| **语义化** | 区分「等缓冲」（等待）vs「真卡死」（重建），不一律 2s 判死 |
| **双端一致** | Web 与 Flutter 使用同一套参数与状态转移 |

### 5.2 状态机

```
                    ┌──────────────┐
                    │    idle      │
                    └──────┬───────┘
                           │ attach(url)
                           ▼
                    ┌──────────────┐
              ┌─────│   loading    │─────┐
              │     └──────┬───────┘     │
              │            │ 首帧          │ fatal
              │            ▼              ▼
              │     ┌──────────────┐  ┌────────┐
              │     │   playing    │  │ error  │
              │     └──────┬───────┘  └───┬────┘
              │            │ stall         │
              │            ▼               │
              │     ┌──────────────┐       │
              └────►│  buffering   │       │
                    └──────┬───────┘       │
                           │               │
              ┌────────────┴────┐          │
              │                 │          │
         (等 3s)           (等 8s)         │
              │                 │          │
              ▼                 ▼          │
        ┌──────────┐     ┌────────────┐    │
        │ 轻量重连  │     │  重建播放器 │◄───┘
        └──────────┘     └─────┬──────┘
              │                 │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │ 连续失败计数 +1  │
              │ ≥3 次 ⇒ 报错    │
              │ 60s 窗口后重置   │
              └─────────────────┘
```

### 5.3 参数（双端统一）

```dart
// Flutter: hls_player.dart
const Duration kBufferingGraceMs = Duration(seconds: 3);    // 缓冲宽限（原 2s → 3s）
const Duration kHardStallTimeoutMs = Duration(seconds: 8);  // 真卡死判定（新增）
const Duration kRebuildCooldownMs = Duration(seconds: 4);   // 重建冷却（不变）
const int kMaxConsecutiveRebuilds = 3;                      // 上限（原 2 → 3）
const Duration kRebuildCountResetWindow = Duration(seconds: 60); // 时间窗重置（新增）
```

**关键改进**：
| 改进 | 原 | 新 | 理由 |
|---|---|---|---|
| 缓冲宽限 | 2s 判死 | **3s 宽限 + 8s 真卡死** | 网络抖动时 2s 太激进，会误杀正常缓冲 |
| 重建上限 | 2 次 | **3 次** | 给弱网多一次机会 |
| 封顶后 | **永久放弃** | **60s 后重试** | 消除「永久黑屏」 |
| 恢复判据 | 仅 position 前进 | position 前进 **或** `buffering=false && playing=true` | mpv 的 playing 不可靠，但结合 buffering 可以更准 |

| Flutter | `lib/player/hls_player.dart` | 状态机主体 |
| Flutter | `lib/player/platforms/*.dart` | 平台信号映射 |
| Web | `src/runtime/liveSessionRuntime.ts` | 状态机主体 |

## 7. 端差异登记表

> 任何有意的端差异必须登记在此，否则视为缺陷。

| # | 差异 | Web | Flutter | 理由 |
|---|---|---|---|---|
