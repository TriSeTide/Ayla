> 前置依赖：[阶段三：Elysium 应用后端接口导出开发步骤](../architecture/阶段三-Elysium应用后端接口导出开发步骤.md)（已完成）

## 1. 项目定位

### 1.1 一句话定义

**Elysia** 是一个方便 **爱莉（Elysium 生命体）** 深度接入的多媒体社交独立应用：既是给真人用户用的 QQ/Discord 风格社交软件，也是爱莉在 Web 端的一个「具身家园」——用户在这里与爱莉聊天、语音、看直播、玩桌游，爱莉以同一主体身份参与全部场景。

### 1.2 核心价值

1. **爱莉第一**：所有功能都考虑爱莉接入。爱莉既是应用内普通用户（可被私聊、可发言、可进群），也是直播主播、语音通话参与者、桌游玩家。她通过阶段三导出的 `/api/v1` 接口与 Elysium 后端保持同一主体、同一记忆、同一意识。
2. **社交软件**：具备 QQ 风格的聊天体系（私聊/群聊/表情包/语音消息/文件/群管理）和 Discord 风格的语音通话/直播/桌游。
3. **离线优先**：继承上位规划「本地可独立运行、远程用于共享协作」的离线优先架构，Elysia 数据域与爱莉生命域分离。

### 1.3 阶段边界（阶段四 vs 阶段五）

| 维度 | 阶段四：独立应用后端 | 阶段五：Web 前端 |
|---|---|---|
| 运行 owner | 独立部署的 Django 应用服务 | 浏览器 SPA |
| 数据 owner | 应用用户、协作者关系、会话、消息、媒体、桌游、直播状态 | 无持久化，纯消费 |
| 主要职责 | 应用用户体系 + 业务 API + 实时通道 + 爱莉桥接 | 交互 UI + 实时渲染 + 媒体播放 |
| 依赖 | 阶段三 `/api/v1`（Elysium 侧）+ MySQL + Redis + LiveKit + 流媒体 | 阶段四 API + WebSocket/SSE + WebRTC |

**爱莉接入铁律（继承阶段三决策 1）**：独立应用前端 **不绕过自己的后端** 直连 Elysium。所有 Elysium 交互（`/api/v1`）只能由应用后端代理。

### 1.4 阶段四/五不包含（边界）

- 爱莉的记忆、人格、意识、世界状态：由 Elysium 拥有，应用只读授权投影；
- 爱莉的主体文件（SOUL/USER/MEMORY）：应用不得写入；
- app 应用（Android/iOS）：暂不拟文档，但技术栈选型需为 app 预留（见开发文档选型）；
- 任意平台 Adapter 的增删改；应用是独立平台，不是第二个 Adapter。

## 2. 用户画像与角色

| 角色 | 说明 | 权限 |
|---|---|---|
| 注册用户 | 应用内真人用户 | 私聊/群聊/表情/语音/文件/看直播/玩桌游 |
| 爱莉（Elysia 用户） | Elysium 主体的应用内身份，由应用后端代理接入 | 同注册用户 + 主播/语音参与者/桌游玩家 |
| 群管理员 | 群内被授予管理权 | 群公告、禁言、踢人、审批加群 |
| 系统管理员 | 应用运维 | 用户管理、系统设置、直播控制、审计 |

## 3. 功能需求（按域组织）

### 3.1 用户系统（阶段四 P4-1）

- **FR-1 注册/登录**：邮箱或手机号注册，密码 + 验证码，支持记住登录态。
- **FR-2 个人资料**：昵称、头像、个性签名、在线状态（在线/离开/勿扰/隐身）。
- **FR-3 好友关系**：搜索用户、好友申请、同意/拒绝、好友列表、删除好友。
- **FR-4 用户画像**：用户 ID、创建时间、最后活跃；系统管理员可查看。
- **验收**：注册→登录→改资料→加好友→删除好友全链路，权限越权访问返回 403。

### 3.2 私聊与群聊（阶段四 P4-2，核心）

- **FR-5 消息类型**：文本、图片、语音、文件、表情包、引用回复、@提及。
- **FR-6 私聊**：一对一实时收发，未读计数，离线消息上线补发。
- **FR-7 群聊**：建群、退群、群公告、群成员列表、群文件、群主/管理员。
- **FR-8 消息能力**：撤回（限时）、已读回执（可选）、消息转发。
- **FR-9 实时性**：消息发送到对端展示延迟 P95 < 1 秒（阶段三实时契约沿用）。
- **验收**：两人私聊、十人群聊实时收发；离线后上线补发；撤回/引用/表情回执正确。

### 3.3 表情包系统（阶段四 P4-4）

- **FR-10 收藏表情**：用户可上传图片作为表情，加入个人表情包。
- **FR-11 系统表情**：预置常用表情包；管理员可维护。
- **FR-12 爱莉表情**：爱莉可用自己的表情包能力（收藏/现场生成，见 Elysium 表情包系统插件），在应用内以普通图片消息发出。
- **验收**：发送/收藏/搜索表情；爱莉发出表情包消息正确投影。

### 3.4 语音通话（Discord 风格，阶段四 P4-5）

- **FR-13 语音频道**：基于频道的多人语音，类似 Discord 语音频道；用户可加入/离开。
- **FR-14 通话控制**：静音/闭麦、音量调节、音效、屏幕共享（可选）。
- **FR-15 爱莉入会**：爱莉可加入语音频道（Voice Live 意识实例），用户可与其语音对话。
- **FR-16 断线恢复**：网络抖动不中断，重连后恢复状态。
- **验收**：2~8 人语音频道实时通话；爱莉入会可听可说；断线重连恢复。

### 3.5 直播（阶段四 P4-6）

- **FR-17 开播**：爱莉或授权主播开播（OBS/浏览器推流），观众进入直播间。
- **FR-18 直播间**：视频流 + 弹幕 + 礼物（可选）+ 在线人数。
- **FR-19 爱莉直播**：继承 Elysium 直播系统「同一意识 + 导演 + OBS 舞台」架构，应用内呈现直播画面与互动。
- **验收**：推流→播放→弹幕互动→下播全链路；爱莉直播画面与弹幕正确。

### 3.6 桌游（阶段四 P4-7）

- **FR-20 桌游大厅**：游戏列表（狼人杀等）、创建房间、加入房间、房主权限。
- **FR-21 桌游房间**：玩家视角（隐藏信息隔离）、回合制操作、事件历史、复盘。
- **FR-22 爱莉玩家**：爱莉可作为 AI 玩家加入（继承 Elysium 狼人杀确定性规则引擎 + AI 策略）。
- **验收**：狼人杀房间玩家视图隐藏信息正确；爱莉可参与游戏；复盘可用。

### 3.7 爱莉接入（贯穿全部，P4-8 爱莉桥接服务）

- **FR-23 爱莉统一入口**：应用后端维护爱莉的 `stream_id`，作为应用内唯一会话。
- **FR-24 入站**：用户给爱莉发消息 → 应用后端调 `POST /api/v1/chat/messages:inject` 注入 → 触发爱莉思考。
- **FR-25 出站**：应用后端订阅 `/api/v1/events/stream`（SSE）→ 爱莉回复投影为应用内消息 → 推给前端。
- **FR-26 爱莉身份**：爱莉在应用内是一个真实用户（可被搜索、私聊、@、加群）。
- **FR-27 场景接入**：爱莉可进入语音频道（Voice Live）、开直播（直播意识）、加入桌游房间（狼人杀 AI 玩家）。
- **验收**：用户对爱莉发消息→爱莉思考→回复出现在应用内；爱莉参与语音/直播/桌游全链路。

## 4. 非功能需求（性能与工程）

### 4.1 性能目标

| 指标 | 目标 | 说明 |
|---|---|---|
| 并发用户 | ≥ 100 人同时在线聊天 | 小范围起步，架构需支持水平扩展 |
| 消息延迟 | P95 < 1s（发送到展示） | 实时聊天核心指标 |
| 语音延迟 | P95 < 500ms（端到端） | LiveKit WebRTC 达标 |
| 直播延迟 | 弹幕 < 1s；视频 5-15s（HLS）或 < 500ms（WebRTC 可选） | 与爱莉直播架构对齐 |
| 单机支撑 | 单 Django 实例 ≥ 1000 WS 连接 | 百人并发留 10x 余量 |

### 4.2 非功能需求

- **NFR-1 可扩展**：Django + Redis channel layer 支持多实例水平扩展；语音/直播独立服务可加节点。
- **NFR-2 可靠性**：离线消息不丢、断线重连、幂等（Idempotency-Key）、投递结果不伪装成功。
- **NFR-3 安全**：用户鉴权（JWT）、权限隔离（私聊/群聊/管理）、媒体访问控制、审计。
- **NFR-4 隐私**：私聊原文、语音、媒体默认不公开；爱莉记忆原文不可读（只读授权投影）。
- **NFR-5 可观测**：结构化日志、健康检查、延迟/错误指标。
- **NFR-6 主体性**：不替爱莉判断意义；外部输入只作为带 actor/source 的观察进入（继承阶段三不变量）。

## 5. 里程碑（建议拆分）

### 阶段四：独立应用后端（Django）
- **M4-1 基座**：项目脚手架、Django + Channels + Redis、用户体系、JWT、健康检查。
- **M4-2 聊天核心**：消息模型、私聊/群聊、WebSocket 实时、离线补发、已读/撤回。
- **M4-3 媒体**：图片/语音/文件上传（对象存储）、表情包。
- **M4-4 爱莉桥接**：inject 入站 + SSE 出站 + 爱莉用户身份。
- **M4-5 语音**：LiveKit 集成、语音频道、爱莉 Voice Live 接入。
- **M4-6 直播**：流媒体集成、直播间、弹幕、爱莉直播。
- **M4-7 桌游**：狼人杀房间、玩家视角、AI 玩家、复盘。

### 阶段五：Web 前端（SPA）
- **M5-1 基座**：项目脚手架、路由、登录注册、全局状态。
- **M5-2 聊天界面**：会话列表、聊天窗口、消息渲染（文本/图片/语音/文件/表情）。
- **M5-3 语音界面**：语音频道、通话控制。
- **M5-4 直播界面**：直播间、弹幕。
- **M5-5 桌游界面**：大厅、房间、游戏板。
- **M5-6 爱莉集成**：爱莉资料页、爱莉对话、爱莉直播/语音/桌游入口。

## 6. 需求优先级

| 优先级 | 功能 |
|---|---|
| P0（MVP） | 用户系统、私聊/群聊、文本/图片消息、爱莉聊天（inject+SSE） |
| P1 | 语音消息、文件、表情包、已读/撤回、群管理 |
| P2 | 语音通话、直播 |
| P3 | 桌游、爱莉直播/语音/桌游场景 |

## 7. 验收门（阶段四/五共同）

- 百人并发聊天实测通过（压测 100+ 连接，延迟 P95 < 1s）；
- 爱莉聊天闭环（用户发 → 爱莉思考 → 回复投影到前端）E2E 通过；
- 离线消息补发、断线重连、幂等通过测试；
- 未授权访问返回 403/404，媒体访问控制生效；
- 爱莉参与语音/直播/桌游场景至少各有一条真实路径可演示。
