**硬约束（继承 AGENTS.md）**：
- 前端**永不直连 Elysium `/api/v1`**；爱莉的一切交互经应用后端代理（阶段三决策 1）。
- **主体性铁律（AGENTS.md §4.1）**：前端绝不生成、改写爱莉的第一人称内容；爱莉消息文本只能来自服务端投影（`message.new` / `elysia.reply` 帧的内容），前端只渲染。`display_name` 只用于 UI 展示，绝不写回 Elysium 主体文件。
- 发送消息必须带 `idempotency_key`（前端生成 uuid），服务端幂等；同 key 冲突（409）要按用户可见的"重复提交"处理，不静默丢弃。
- 已读/撤回/引用都是消息事件，前端不得伪造投递回执（撤回只能点自己的、限时窗口内）。
- 断线重连按 `seq` 幂等补发，客户端以 `seq` 去重，禁止跳尾部伪装连续。
- 每次改动要有与风险相称的测试（Vitest 单测 + WS 契约测试）。
- 只写 `web/` 相关代码；不动 backend 已有代码（除非公共契约确有缺陷，先说明再动）。

## 1. 目标（M5-2 验收定义）

完成**聊天界面**的完整闭环：

- **会话列表**：私聊（展示对方昵称/头像/在线状态）+ 群聊（群名/公告）；未读数徽标
- **聊天窗口**：消息渲染（文本/图片/语音/文件/表情占位）、气泡区分自己/他人、时间分组
- **发送**：文本输入 + 发送（幂等）；回车发送、输入中（typing）提示
- **已读/撤回/引用**：标已读；撤回（限时 120s、仅自己）；引用回复（点击消息 → 引用 → 发送）
- **历史分页**：`before_seq` 游标上拉加载更早消息
- **实时**：Chat WebSocket 订阅/补发/重连；`message.new` 实时到达、`message.recall`/`message.read`/`typing` 实时生效
- **爱莉对话入口（M5-6 预留）**：把爱莉会话当作一个普通会话渲染；爱莉消息来自 `elysia.reply` 帧（或 `message.new` 里 sender 为爱莉 profile user），前端只渲染不生成
- **契约测试**：WS 收发、补发、幂等发送、撤回、越权（403）提示

**不包含（本里程碑边界）**：
- 媒体上传/缩略图/表情包资产（M4-3 后端未做，本期 `image/voice/file/emoji` 消息**只渲染占位**，发送按钮禁用或仅存文本描述）
- 语音（M5-3）、直播（M5-4）、桌游（M5-5）
- 完整视觉系统（沿用 M5-1 最小样式 + 本次补齐聊天组件样式）

## 3. 后端契约（M5-2 直接对接，按真实代码为准）

### 3.1 Chat REST（挂 `/api/v1/chat/`）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| GET | `/conversations/` | - | 会话列表（`ConversationListSerializer`：`id/type/title/announcement/owner_id/members[]/my_role/member_count/unread_count/created_at/peer`） |
| POST | `/conversations/private/` | `{user_id}` | 私聊会话（幂等：同两人复用已有会话） |
| POST | `/conversations/group/` | `{title, member_ids[]}` | 建群（owner=当前用户，201） |
| GET | `/conversations/<id>/` | - | 会话详情（`ConversationSerializer`） |
| GET | `/conversations/<id>/messages/?before_seq=&limit=` | `before_seq`（整型）、`limit`（默认50，max200） | 历史消息（按 `seq` 倒序取，接口内已倒回升序返回） |
| POST | `/conversations/<id>/messages/` | `{type, content, reply_to?, idempotency_key?, media_id?}` | 发消息；幂等返回 200+原消息 / 409 冲突 |
| POST | `/conversations/<id>/messages/<mid>/read/` | - | 标已读（`{"detail":"已读"}`） |
| POST | `/conversations/<id>/messages/<mid>/recall/` | - | 撤回（限时 120s、仅发送者；越权 403、超时 400） |
| POST | `/conversations/<id>/typing/` | `{is_typing: bool}` | 声明输入中（触发 `typing` 广播） |
| POST | `/conversations/<id>/members/` | `{user_ids[]}` | 加人（群管理员） |
| DELETE | `/conversations/<id>/members/<user_id>/` | - | 踢人（群管理员；群主不能踢自己） |
| POST | `/conversations/<id>/members/<user_id>/mute/` | `{muted: bool}` | 禁言/解除 |
| PATCH | `/conversations/<id>/` | `{title?, announcement?}` | 改群标题/公告（群管理员） |

**消息序列化字段**（`MessageSerializer`）：
`id(str), conversation_id(str), sender_id(str), type, content, media_id, reply_to(id|null), status(sent/delivered/read/recalled), seq, created_at`

**消息类型**：`text / image / voice / file / emoji / system`
- M4-3 未做：`image/voice/file/emoji` 发送时后端只存文本引用，**前端本期不启用这些类型的真实发送**（按钮置灰），但**渲染占位要做**（后端可能回放这类历史消息）。

**幂等语义（严格按 M4-2 验收）**：
- 同 `idempotency_key` + 同 `conversation` + 同 `sender` 重复 POST：返回 200 + 原消息（不重复落库）。
- 同 key 但内容/type 不同：返回 409，`detail` 说明冲突。
- key 被其他会话使用：返回 409。

### 3.2 Chat WebSocket（`/ws/chat/?token=<jwt>`）

**客户端 → 服务端帧**：

```json
{"type": "subscribe", "conversation_ids": ["1", "2"]}
{"type": "resume", "conversation_id": "1", "last_message_seq": 5}
{"type": "ping", "ts": 123456}
```

**服务端 → 客户端帧**：

```json
{"type": "chat.subscribed", "data": {"conversation_id": "1", "last_seq": 5}}
{"type": "message.new", "data": {"conversation_id":"1","message_id":"42","sender_id":"a5bdf...","content":"你好","type":"text","media":null,"reply_to":null,"seq":3,"ts":"2026-08-10T00:00:00Z"}}
{"type": "message.recall", "data": {"conversation_id":"1","message_id":"42","seq":3}}
{"type": "message.read", "data": {"conversation_id":"1","message_id":"42","user_id":"...","seq":3}}
{"type": "typing", "data": {"conversation_id":"1","user_id":"...","is_typing":true}}
{"type": "history.sync", "data": {"conversation_id":"1","last_seq":7}}
{"type": "elysia.reply", "data": {"conversation_id":"1","message_id":"99","sender_id":"<爱莉user>","content":"...","type":"text","seq":8,"event_id":"...","ts":"..."}}
{"type": "error", "detail": "..."}
{"type": "pong", "ts": 123456}
```

**协议要点（按 consumers.py 真实实现）**：
- 未认证连接 → 服务端 `close(4401)`。
- `subscribe`：逐个 `conversation_ids` 校验成员，非成员**忽略**（不报错、不 group_add）；成功订阅回 `chat.subscribed`（含该会话当前 `last_seq`，作为补发基线）。
- `resume`：带 `last_message_seq`，服务端补发 `seq > last_message_seq` 的消息（升序，`message.new` 逐条），最后发 `history.sync` 表示补发完成。**补发依据 `seq`，客户端以 `seq` 去重（幂等恢复）**。
- 心跳：客户端可发 `ping`，服务端回 `pong`（保活）。
- `message.new` 的 `sender_id` 用于前端区分"自己发的 vs 别人发的"（服务端不回环过滤）。
- `elysia.reply`：爱莉回复投影，`sender_id` 即爱莉 profile 绑定的应用内 user；前端**只渲染** `content`，绝不生成。

## 4. 关键实现要点

### 4.1 消息 store（按 conversation_id 分桶，seq 有序）

```ts
// message store 形态
{
  [conversationId: string]: {
    messages: Message[];   // 按 seq 升序
    lastSeq: number;       // 已收到的最新 seq
    hasMore: boolean;      // 还有更早历史
    loading: boolean;
  }
}
```

- 写入统一走 `upsertMessage(convId, msg)`：按 `seq` 去重（服务端补发/重连可能重复投递），重复则忽略。
- 撤回/已读/typing 是"元事件"：只改对应消息的 `status`（recalled）或渲染对端已读状态，不新增消息。
- `history.sync` 只作为补发完成信号，不改变消息集合。

### 4.2 幂等发送（关键）

- 前端生成 `idempotency_key`（`crypto.randomUUID()`），每条消息唯一。
- 发送失败重试（网络抖动）时**复用同一 key**，服务端幂等返回原消息，不会重复落库。
- 收到 409：说明同 key 内容冲突（极端情况下 key 碰撞或服务端已有同 key 不同内容），按用户可见错误提示，不静默丢弃。
- 发送成功（201）后：本地乐观插入 + 等待 WS `message.new` 到达（以 `seq` 去重）；**不要**因为本地已插入就忽略服务端回放（seq 幂等去重保证一致）。

### 4.3 撤回

- 仅自己发的、`status != recalled`、`created_at` 在 120s 窗口内才显示"撤回"按钮。
- 点击 → `POST .../recall/`；成功本地置 `recalled`；同时服务端广播 `message.recall`，其他端同步。
- 超时（400）→ 提示"超过撤回时限"；越权（403）→ 提示"只有发送者本人可撤回"。

### 4.4 标已读

- 打开会话 / 收到新消息时，把"当前会话中对方发且我未读"的消息批量 `POST .../read/`（可只标最新一条，服务端 `mark_read` 幂等）。
- 对端通过 `message.read` 帧看到已读状态（私聊必做）。

### 4.5 历史分页

- 打开会话：`GET .../messages/`（无 `before_seq` → 最新 50 条）。
- 上拉加载：取当前缓存最小 `seq` 作为 `before_seq`，请求更早 50 条，**前插**到消息列表。
- `hasMore`：返回条数 < limit 视为到底。

### 4.6 Chat WS 管理（复用 M5-1 presence 的重连模式）

- 单例连接，`subscribe` 当前会话列表（打开会话时增量 `subscribe` 单个 conv_id）。
- 断开重连：指数退避（1s→2s→...→30s 上限）；重连成功后对每个已订阅会话发 `resume {last_message_seq: <该会话 lastSeq>}`。
- 心跳：每 30s 发 `ping`（保活，Redis TTL）。
- 事件分发：`message.new/recall/read/typing/elysia.reply/history.sync` → 对应 store/handler。
- 前端按 `conversation_id` 路由事件到对应会话（未打开的会话只更新未读数，不缓存整段消息——避免内存膨胀）。

### 4.7 typing 声明

- 用户输入时以节流（如 2s 一次）`POST .../typing/ {is_typing:true}`，停止输入 3s 后 `{is_typing:false}`。
- 对端收到 `typing` 帧 → `TypingIndicator` 显示"对方正在输入…"。

### 4.8 爱莉对话（M5-6 入口占位）

- 会话列表顶部"爱莉"卡：`GET /elysia/profile/` 找到 `enabled` 的 profile，展示 `display_name`。
- 点击 → `POST /conversations/private/ {user_id: profile.user.id}` → 进入该会话。
- 渲染：普通消息走 `message.new`；爱莉回复走 `elysia.reply` 帧（`sender_id` 匹配爱莉 user 即视为爱莉消息）。**前端不生成爱莉第一人称内容**（AGENTS.md §4.1），`display_name` 仅 UI 展示。

## 9. 已知取舍与待确认（遇到先记录，不阻塞）

- **媒体消息占位**：M4-3 后端未做，`image/voice/file/emoji` 发送按钮本期置灰，只渲染历史消息占位（图标 + 文本描述）；M4-3 完成后启用。

- **离线补发上限**：后端 `_messages_after` 一次最多补 200 条，超出部分需后续分页（本期接受，README 注明）。
