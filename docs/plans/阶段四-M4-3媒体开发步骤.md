**硬约束（继承 AGENTS.md + 阶段三 §10 + 阶段四方案）**：
- **媒体访问控制是工程硬约束（NFR-3/NFR-4）**：图片/语音/文件/表情访问均需鉴权；未授权返回 403/404，绝不静默放行；私密媒体不得进入共享缓存（`Cache-Control: private`）。
- **媒体安全（阶段三 §10.3）**：MIME allowlist 与文件头嗅探同时检查；分类型大小/像素上限；压缩炸弹防护；只允许已登记 `media_id` 下载，禁止 path traversal；事件/序列化只带 descriptor 不暴露绝对路径。
- **完整性（阶段三 §10.2）**：`content_hash`（sha256）上传时校验，媒体去重 + 完整性保证；命令成功至少证明"有权读取 + 内容已进受管对象存储 + hash/size/MIME 已验证 + 元数据已耐久记录 + 生成稳定 `media_id`"。
- **派生与 ready 分离（阶段三 §10.2）**：元数据已提交但派生（缩略图/波形）失败时，媒体保持 `ready`，派生单独 `failed`；禁止把派生失败伪装成媒体失败或空结果。
- **幂等**：同一 `upload_id` 重复 `:complete` 必须返回同一 `media_id`，不重复建对象/不重复派生。
- **主体性铁律（AGENTS.md §4.1 / 需求 FR-12）**：爱莉表情是"以普通图片消息发出"，应用只渲染/投影，绝不生成爱莉第一人称内容、不做 VLM 决策（那是 Elysium 表情包插件的事）。
- 每次改动要有与风险相称的契约测试（上传/下载/权限/MIME/派生/表情包/越权）。
- 只写 `apps/media/`、`apps/emoji/` 相关代码与必要配置接线；不动 accounts/chat/elysia_bridge 已有模型与接口（除非公共契约确有缺陷，先说明再动）。

## 1. 目标（M4-3 验收定义）

完成**媒体闭环**：对象存储上传 + 缩略图/波形派生 + 表情包 + 文件，并接入 M4-2 消息链。

- **对象存储（MinIO/S3 兼容）**：受控上传三步（创建会话 → 传二进制 → complete 校验生成 `media_id`），`content_hash` 完整性校验，下载鉴权 + Range 支持。
- **缩略图 / 波形**：图片消息生成缩略图派生资源；语音消息生成波形图派生资源（并记录 `duration`）；派生失败媒体仍 `ready`。
- **文件**：任意合法 MIME 文件消息上传/下载，大小上限，MIME allowlist + 文件头嗅探。
- **表情包**：系统预置包（管理员维护）+ 用户收藏表情（上传图片加入个人表情包）；`type=emoji` 消息引用表情媒体。
- **接入消息链（M4-2 复用）**：`CreateMessageSerializer` 已收 `media_id`；M4-3 补齐校验——`type=image/voice/file/emoji` 时 `media_id` 必须存在、`status=ready`、类型匹配、且调用方有权访问该媒体；消息序列化返回媒体 descriptor。
- **契约测试**：上传-完成-下载闭环、幂等、越权 403/404、MIME/大小校验、缩略图/波形派生、表情包 CRUD、系统包权限、爱莉表情投影（通道预留）。

**不包含（本里程碑边界）**：
- **爱莉媒体/表情的真实投影**（M4-4 已交付文本 `elysia.reply`）：爱莉发出图片/语音/表情时，媒体如何从 Elysium 侧（阶段三 `/media/*`）进入应用侧对象存储，属**待协调的未决点**（第 6.3/10 节）；本期只保证应用内消息链支持媒体渲染，爱莉媒体消息真实 E2E 不验收。
- **视频**：消息类型无 video（M4-2 模型即无），直播归 M4-6；不做视频转码/播放。
- **预签名 URL / CDN**：下载走应用内鉴权流式端点（Range），不签 URL、不上 CDN（后续按需）。
- **TTS 合成**（归属爱莉能力，非应用内用户媒体）；语音消息仅指用户上传的语音文件 + 波形。
- **VLM 表情决策 / 现场生成**（Elysium 表情包插件 `plugins/emoji/` 的能力）：应用侧只做收藏/系统包/发送引用，不做 AI 决策。

## 3. 数据模型（严格按开发文档第 4 节 + 注明补充字段）

开发文档 §4 媒体域定义：
```text
media_objects         id, media_id(稳定uuid), owner_id, content_hash, mime_type,
                      size, storage_path, status(processing/ready), created_at
emoji_packs           id, owner_id, name, is_system, created_at
emoji_items           id, pack_id, media_id, tag, created_at
```

### 3.1 MediaObject（媒体对象）

| 字段 | 类型 | 约束/说明 | 来源 |
|---|---|---|---|
| `id` | AutoField | | 开发文档 |
| `media_id` | CharField(64) | **稳定 uuid（`uuid4().hex`，32 字符）**，对外唯一标识；**唯一索引**。与 M4-2 `Message.media_id`(CharField 64) 兼容 | 开发文档 `media_id` |
| `owner` | FK → accounts.User | 上传者；`related_name="media_objects"` | 开发文档 `owner_id` |
| `kind` | CharField(16) | `image`/`voice`/`file`/`emoji`，choices。**补充字段**（开发文档无，消息类型驱动，见下） | 补充 |
| `content_hash` | CharField(64) | **sha256 hex**；上传 complete 时校验，媒体去重 + 完整性 | 开发文档 `content_hash` |
| `mime_type` | CharField(128) | 上传声明 MIME，complete 时**文件头嗅探比对** | 开发文档 `mime_type` |
| `size` | PositiveBigIntegerField | 字节数 | 开发文档 `size` |
| `storage_path` | CharField(256) | 对象存储 key（如 `images/{media_id}/original`）；**对外序列化只给 descriptor，不暴露此路径** | 开发文档 `storage_path` |
| `status` | CharField(16, default="processing") | `processing`/`ready`/`failed`，choices（开发文档 processing/ready；补 `failed` 表示派生失败但元数据已提交，见派生语义） | 开发文档 `status` + 补充 |
| `width` | PositiveIntegerField(null) | **补充字段**：图片宽（缩略图/前端渲染用） | 补充 |
| `height` | PositiveIntegerField(null) | **补充字段**：图片高 | 补充 |
| `duration` | FloatField(null) | **补充字段**：语音时长（秒） | 补充 |
| `thumbnail_path` | CharField(256, blank) | **补充字段**：缩略图对象存储 key（派生产物） | 补充 |
| `waveform_path` | CharField(256, blank) | **补充字段**：波形图对象存储 key（派生产物） | 补充 |
| `created_at` | DateTimeField(auto_now_add) | | 开发文档 |

Meta：`db_table="media_objects"`；`unique(media_id)`；`db_index`：`owner`、`kind`、`created_at`。

**补充字段的理由**（写进 README 已知取舍）：`kind`/`width`/`height`/`duration`/`thumbnail_path`/`waveform_path` 是媒体 descriptor 的必要组成（阶段三 §10 的 descriptor 含 MIME/size/width/height/duration），开发文档表未列，属"接口驱动"补充；核心字段（media_id/owner/content_hash/mime_type/size/storage_path/status）与开发文档一致。
