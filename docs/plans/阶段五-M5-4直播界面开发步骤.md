**硬约束（继承 AGENTS.md + M4-6 契约）**：
- **状态真实性（AGENTS.md §8 / M4-6 §4.2）**：`GET /status/` 返回 `live/idle/degraded` 三态——`degraded`（SRS 不可用）UI 必须中性提示"直播服务状态未知"，**禁止把 degraded 渲染成"未开播"**；应用侧 `status` 字段是乐观标记，播放器区域的真实在播判定以 `/status/` 为准。
- **stream_key 最小权限**：`stream_key`/`rtmp_url` 仅 owner 的详情响应可见；前端不得把推流指纹写进日志/复制给观众侧组件；非 owner 收到 `null` 是正常契约不是缺陷。
- **主体性铁律（AGENTS.md §4.1 / M4-6 §6）**：爱莉直播 = 应用内普通 User 开播；前端绝不生成、改写爱莉的直播内容/第一人称叙事/弹幕；弹幕内容原样渲染，应用不代判内容意义（无敏感词过滤，审核属 Elysium 侧能力）。

- **弹幕幂等与顺序**：弹幕以 WS 实时帧为主、REST 历史为补；重连后拉一次历史对账（WS 无补发语义），按 `id` 去重，禁止跳尾部伪装连续。
- **工程纪律**：视频播放失败要区分"未开播"（idle）与"播放器/网络错误"（error 事件），不得混淆；每个定时器/播放器实例/WS 连接有明确 owner 与销毁路径（离开直播间页面必须销毁 hls 实例、断 WS、停轮询）。

- 只写 `web/` 相关代码；不动 backend 已有代码（除非公共契约确有缺陷，先说明再动）。

## 1. 目标（M5-4 验收定义）

完成**直播界面**的完整闭环（开发文档 §8 M5-4：直播间 + 弹幕 + 播放器）：

- **直播大厅**：频道列表（标题/主播/状态徽章：直播中/未开播）；`?only_live=1` 只看在播；爱莉直播间入口（M5-6 预留，按 owner 是爱莉 user 的普通频道渲染）
- **开播（主播侧）**：建频道 → 创建响应一次性回显 `stream_key`/`rtmp_url`（复制进 OBS 的指引 UI）→ `:start` 开播 / `:stop` 下播；详情页 owner 可见推流地址面板
- **播放器**：HLS 播放（`hls.js`，Safari 走原生 HLS）；`flv_url` 作为备选展示（HTTP-FLV 播放可选，见已知取舍）；播放区域按 `/status/` 三态渲染：live→播放器、idle→"未开播"占位、degraded→"服务状态未知"中性提示
- **弹幕**：实时弹幕（WS `danmaku` 帧）+ 历史弹幕（进房间拉最近 50 条）+ 发送（REST POST，落库后服务端广播，**自己发的也等 WS 回帧渲染**，保持单一数据流）；弹幕列表自动滚动 + 新弹幕提示
- **状态轮询**：直播间页面打开期间每 15s 轮询 `/status/`（视频流状态以 SRS 为准；乐观标记与 SRS 不一致时以 SRS 为准更新徽章）
- **断线恢复**：弹幕 WS 断线指数退避重连，重连成功拉历史对账去重
- **契约测试**：REST 调用、WS 协议、HLS 播放（mock hls.js）、状态三态渲染、越权/错误路径

**不包含（本里程碑边界，显式声明）**：
- **礼物系统**（FR-18 可选）：本期不做。
- **WebRTC 低延迟播放**（<500ms）：SRS 支持但本期播放器只验 HLS（5-15s 可接受，需求 §4.1），WebRTC 标注可选。
- **在线人数精确计数**（FR-18 可选）：本期不做（WS group 连接数可选，不做 UI 计数）。
- **爱莉直播真实对接**（FR-19）：Elysium 直播意识接入是 Elysium 侧工作（M4-6 §6.3 未决点继承）；本期爱莉直播间只是"owner 为爱莉 user 的普通频道"渲染，订阅阶段三 `/livestream/*` 状态投影不做，不验收。
- **录制/回放**：SRS 不落盘录制，本期不做。
- 语音（M5-3）、桌游（M5-5）：不在本期。

## 3. 后端契约（M5-4 直接对接，按真实代码为准）

### 3.1 直播频道 REST（挂 `/api/v1/live/`）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/live/channels/` | `{title}` | 201 descriptor（**创建响应回显 `stream_key`/`rtmp_url`**，创建者即 owner，供复制进 OBS） |
| GET | `/live/channels/` | `?only_live=1` 可选 | descriptor 列表 |
| GET | `/live/channels/<id>/` | - | descriptor；owner 可见 `stream_key`/`rtmp_url`，**他人为 null** |
| POST | `/live/channels/<id>:start/` | - | 开播（乐观标记；**不校验 SRS 真实流**）；非 owner → 403 |
| POST | `/live/channels/<id>:stop/` | - | 下播；非 owner → 403 |
| GET | `/live/channels/<id>/status/` | - | **SRS 实时判定**：`{status: live\|idle\|degraded, ...}`（degraded = SRS 不可用，**不是未在播**） |
| DELETE | `/live/channels/<id>/` | - | 删频道；非 owner → 403；**直播中（乐观 live）→ 400** |

**descriptor 字段（`LiveChannelSerializer`）**：
`id, title, status(乐观标记), owner_id, is_owner, stream_key(owner 可见，否则 null), rtmp_url(owner), hls_url(全员), flv_url(全员), started_at, ended_at, created_at`

### 3.2 弹幕 REST

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/live/channels/<id>/danmaku/` | 发弹幕 `{content}` → 201 `{id, channel_id, sender:{...}, content, created_at}`；空/超长（>200）→ 400 |
| GET | `/live/channels/<id>/danmaku/?limit=` | 最近历史（默认 50，上限 200），升序返回 |

### 3.3 弹幕 WebSocket（`/ws/live/<channel_id>/?token=<jwt>`）

**服务端 → 客户端帧**：

```json
{"type": "danmaku", "id": "12", "sender": {"id":"...","nickname":"..."}, "content": "来了", "created_at": "2026-08-13T00:00:00Z"}
{"type": "pong", "ts": 123456}
{"type": "error", "detail": "unknown type ..."}
```

**协议要点（按 consumers.py 真实实现）**：
- 未认证 → `close(4401)`；频道不存在 → `close(4404)`。
- 客户端可发 `ping` 保活；**不能发弹幕**（WS 只收，发送走 REST——落库与广播分离，M4-6 §5.2）。
- 弹幕广播帧带 `sender` 序列化（昵称/头像）；内容原样，应用不代判。
- **发送回环**：REST POST 成功后服务端广播 `live_{id}` 组，**发送者自己的 WS 也收到回帧**——前端发送后不做乐观插入，统一等回帧渲染（单一数据流，避免双份）。

### 3.4 SRS 播放地址（后端生成，前端只消费）

- HLS：`hls_url`（`http://<host>:8080/live/{stream_key}.m3u8`）——**浏览器播放主路径**。
- HTTP-FLV：`flv_url`（`.flv`）——备选，低延迟略好但需 flv.js（本期可选，见已知取舍）。
- 前端**不得**自行拼接 stream_key 生成地址（播放地址从 descriptor 取，stream_key 对观众本就不可见）。

## 4. 关键实现要点

### 4.1 live store（频道列表 + 当前直播间）

```ts
// live store 形态
{
  channels: LiveChannelDescriptor[];    // 大厅列表
  current: {
    channel: LiveChannelDescriptor | null;
    srsStatus: "live" | "idle" | "degraded" | null;  // /status/ 实时判定（权威）
    danmaku: DanmakuItem[];             // 升序，按 id 去重
  };
  wsConnection: "connecting" | "online" | "offline";
}
```

- 弹幕去重：WS 回帧与历史拉取按 `id` 去重（重连对账时窗口内弹幕可能重复到达）。
- 弹幕列表定长：内存保留最近 N 条（如 500），超出丢弃最旧（防内存膨胀；权威历史在后端，可随时再拉）。
- 徽章语义：`srsStatus=live` → "直播中"；`idle` → "未开播"；`degraded` → "状态未知"；`null`（未查询）→ 用乐观 `status` 兜底并标注。

### 4.2 进房/退房编排（useLiveRoom）

1. 进入 `/live/:channelId`：`GET /channels/<id>/` 拿详情 → `GET /status/` 拿实时判定 → `GET /danmaku/?limit=50` 拉历史 → 连弹幕 WS。
2. 状态轮询：每 15s `GET /status/`（组件卸载停止；页面隐藏时暂停轮询，`visibilitychange` 恢复——省电且防抖）。
3. 播放器：`srsStatus=live` 才 attach HLS；轮询发现 live→idle 切换时销毁播放器显示"未开播"占位；idle→live 重新 attach。
4. **退房销毁清单**（owner 语义，AGENTS.md §7）：销毁 hls 实例（`hls.destroy()`）、断 WS、停轮询定时器、清 store current。重复进房不叠加。

### 4.3 HLS 播放器（player/hls.ts）

- 分支：`Hls.isSupported()`（Chrome/Firefox/Edge）→ `new Hls()` + `attachMedia(video)` + `loadSource(hls_url)`；Safari（原生 HLS）→ `video.src = hls_url` 直接播。
- 错误恢复：`Hls.Events.ERROR` → `networkError` 调 `hls.startLoad()` 重试；`mediaError` 调 `hls.recoverMediaError()`；fatal 且不可恢复 → UI 显示"播放失败" + 重试按钮（重试 = 销毁重建实例）。
- **区分播放错误与未开播**：HLS 404/反复网络错误且 `/status/` 为 idle → 渲染"未开播"占位而不是播放器报错；`/status/` 为 live 但播放失败 → "播放失败，重试"。两者不得混淆（状态真实性以 SRS 为准）。
- 直播延迟：HLS 5-15s 属预期（需求 §4.1），UI 不做"低延迟"承诺文案。
- 禁止 `autoplay` 无声策略踩坑：`muted autoplay` 起播 + 用户手势后取消静音（浏览器自动播放策略）。

### 4.4 弹幕编排（useDanmaku）

- 发送：`POST danmaku/` `{content}`（前端拦截空文本与 >200 字符）；成功不乐观插入，等 WS 回帧（4.3 单一数据流）；400 显示后端 `detail`。
- 接收：WS `danmaku` 帧 → 按 `id` 去重 append → 自动滚动到底（若用户上翻查看历史则不强制滚动，显示"有新弹幕"浮动提示，点击跳底）。
- 重连对账：WS 断线重连成功后 `GET /danmaku/?limit=50` 拉最新历史，按 `id` 合并去重（断线窗口弹幕补偿）。
- 渲染：纯文本原样渲染（不做富文本/表情解析——后端不解析，前端不自作主张）；XSS 交给 React 默认转义，**禁止 `dangerouslySetInnerHTML`**。

### 4.5 开播流程（主播侧）

1. `LiveCreate`：输标题 → `POST /channels/` → **创建响应的 `stream_key`/`rtmp_url` 一次性展示**（弹窗/面板 + 复制按钮），文案明确"此信息仅本次显示，请立即复制到 OBS"（与后端契约一致：此后仅详情页 owner 可见）。
2. OBS 指引：服务器填 `rtmp_url` 去掉流名部分（或完整地址按 OBS 习惯拆分"服务器 + 串流密钥"），UI 提供两个复制框：服务器 `rtmp://<host>:1935/live`、串流密钥 `stream_key`。
3. `:start` 开播 → 轮询 `/status/` 直到 live（SRS 识别推流有秒级延迟，UI 显示"等待推流信号…"）；推流上来后播放器区对 owner 也可预览。
4. `:stop` 下播 → 状态回落；直播中禁止删除频道的 400 提示"请先下播"。
5. **stream_key 安全**：复制按钮用 clipboard API；不打日志；页面不持久化（刷新后从详情重新拉——详情对 owner 仍可见，符合契约）。

### 4.6 爱莉直播间（M5-6 入口占位）

- 大厅列表里 owner 是爱莉 profile user 的频道按普通频道渲染（可加"爱莉"角标，复用 M5-2 的 profile 判断）。
- **不订阅阶段三 `/livestream/*`**（M4-6 §6.3 未决点继承：Elysium 直播意识接入未完成，订阅通道预留不做）；爱莉直播画面 = 爱莉 user 的 OBS/推流与弹幕，前端不做任何爱莉内容生成。
- FR-19 验收（爱莉直播画面与弹幕正确）**不验收**，如实标注。

## 5. 实施顺序（建议按此推进，每步可独立验证）

1. **API 层**：`api/live.ts`（频道/状态/弹幕端点）+ types → 单测 mock（含 403/400/degraded 分支）。
2. **store**：`stores/live.ts`（列表/当前直播间/弹幕去重定长）→ 单测。
3. **WS 客户端**：`ws/live.ts`（连接/重连/事件分发，对齐 chat.ts 骨架）→ WS 契约测试（mock WS：4401/4404 关闭码、重连对账触发）。

## 9. 已知取舍与待确认（遇到先记录，不阻塞）

- **弹幕单一数据流**：发送不做乐观插入，统一等 WS 回帧渲染——牺牲 ~100ms 感知延迟换"绝不双份"；慢网络下输入框可加"发送中"态。
- **HLS 为主、FLV 可选**：flv.js 体积不小且 FLV 逐步退场，本期播放器只验 HLS；`flv_url` 在主播面板展示供外部播放器使用；如汐汐要低延迟播放再引入 flv.js 或评估 WebRTC。
- **状态轮询 15s**：平衡实时性与请求量；页面隐藏暂停；WS 频道级状态推送（`live.status` 事件）后端未实现（M4-6 未做），本期轮询兜底，后端补事件后切换。
- **弹幕不定长保存**：内存 500 条截断；权威历史在后端（`?limit=200` 可再拉）；不做本地持久化。
- **不做在线人数/礼物/录制**：FR-18 可选项本期全部不做（M4-6 边界继承）。
- **爱莉直播 = 普通频道**：owner 是爱莉 user 的频道无特殊数据通道；阶段三 livestream 订阅预留不做（M4-6 §6.3）；FR-19 不验收。
- **muted autoplay**：播放器默认静音起播（浏览器策略），用户点击取消静音；不绕过浏览器限制。
- **stream_key 不持久化**：一次性回显 + 详情 owner 可见；前端不写 localStorage；泄漏则重建频道（轮换 key 属后续能力，M4-6 §10 继承）。
