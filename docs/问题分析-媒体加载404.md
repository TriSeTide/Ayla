# 问题分析：聊天图片和语音消息加载 404

## 问题描述

用户反馈：群聊中的聊天图片和语音消息加载不出来，浏览器控制台显示 404 错误。

**错误请求示例**：
```
GET http://localhost:5173/api/v1/media/4eb5e4ff3ce347aa98c522e7cecfa1ac/
Status: 404 Not Found
```

## 根因分析

### 调查过程

1. **后端代码检查**
   - ✅ `apps/media/models.py` 定义了 `MediaObject` 模型
   - ✅ `apps/media/views.py` 实现了媒体内容和缩略图接口
   - ✅ `apps/media/urls.py` 注册了路由 `media/<str:media_id>/` 和 `media/<str:media_id>/thumbnail/`
   - ✅ `apps/chat/serializers.py` 的 `MessageSerializer.get_media()` 查询并序列化 `MediaObject`

2. **数据库检查**
   - ❌ `messages` 表有 `media_id` 字段，但**所有记录的 `media_id` 都为空**
   - ❌ 数据库中**不存在 `media_mediaobject` 表**
   - ❌ 没有任何媒体相关的表（`media_*` 或 `upload_*`）

3. **迁移检查**
   - ✅ `apps/media/migrations/` 目录存在，包含两个迁移文件：
     - `0001_initial.py`：创建 `MediaObject` 和 `MediaUploadSession` 表
     - `0002_mediauploadsession_media_id_and_more.py`：添加字段和索引
   - ✅ `apps.media` 已在 `config/settings.py` 的 `INSTALLED_APPS` 中注册
   - ❌ **`media` app 的迁移从未执行**，`django_migrations` 表中没有 `media` 相关记录

### 根本原因

**数据库迁移缺失**：`media` app 的迁移从未在当前数据库上执行，导致：

1. 数据库中不存在 `media_mediaobject` 表
2. 即使前端发送了包含 `media_id` 的消息，后端也无法存储 `MediaObject` 记录
3. 前端请求 `/api/v1/media/{id}/` 时，后端查询不到对应的 `MediaObject`，返回 404

### 为什么会这样？

可能的原因：
- 数据库是在 `media` app 添加之前创建的
- 添加 `media` app 后没有运行 `python manage.py migrate`
- 或者运行迁移时出错但被忽略了

## 解决方案

### 方案 A：执行缺失的迁移（推荐）

**操作步骤**：

1. 停止后端服务
2. 备份当前数据库：
   ```bash
   cd Ayla/backend
   cp db.sqlite3 db.sqlite3.backup
   ```

3. 检查待执行的迁移：
   ```bash
   python manage.py showmigrations
   ```

4. 执行迁移：
   ```bash
   python manage.py migrate
   ```

5. 验证 `media_mediaobject` 表已创建：
   ```python
   import sqlite3
   conn = sqlite3.connect('db.sqlite3')
   cursor = conn.cursor()
   cursor.execute("SELECT name FROM sqlite_master WHERE type='table' AND name LIKE 'media_%'")
   print(cursor.fetchall())
   conn.close()
   ```

6. 重启后端服务

**预期结果**：
- ✅ `media_mediaobject` 表已创建
- ✅ 后续上传的图片和语音可以正常保存和访问
- ⚠️ **历史消息的媒体仍然无法加载**（因为之前没有保存 `MediaObject` 记录）

### 方案 B：重建数据库（仅限测试环境）

如果当前数据库中的数据不重要，可以重建：

```bash
cd Ayla/backend
rm db.sqlite3
python manage.py migrate
python manage.py createsuperuser  # 如果需要
```

**警告**：⚠️ 所有现有数据将丢失！

### 方案 C：修复历史数据（如果需要）

如果历史消息中的媒体文件仍然存在于服务器上，可以：

1. 找到媒体文件存储位置（通常在 `MEDIA_ROOT` 配置的目录）
2. 为每个文件创建对应的 `MediaObject` 记录
3. 更新 `messages` 表中的 `media_id` 字段

这需要根据实际的文件存储结构编写数据迁移脚本。

```bash
#!/bin/bash
cd backend

if [ $? -eq 0 ]; then
    echo "警告：存在未执行的迁移！"
    exit 1
fi
echo "✓ 所有迁移已执行"
```

### 2. 启动时自动检查

在 `backend/config/wsgi.py` 或 `asgi.py` 中添加启动检查：

```python
import sys
from django.core.management import call_command
from django.db import connection

def check_migrations():
    """检查是否有未执行的迁移"""
    try:
        with connection.cursor() as cursor:
            cursor.execute("""
                SELECT COUNT(*) FROM django_migrations 
                WHERE app = 'media'
            """)
            count = cursor.fetchone()[0]
            if count == 0:
                print("错误：media app 迁移未执行！", file=sys.stderr)
                print("请运行：python manage.py migrate", file=sys.stderr)
                sys.exit(1)
    except Exception as e:
        print(f"迁移检查失败：{e}", file=sys.stderr)

check_migrations()
```

### 4. 监控告警

添加定期检查，确保媒体数据一致性：

```python
# apps/media/management/commands/check_media_integrity.py
from django.core.management.base import BaseCommand
from apps.chat.models import Message
from apps.media.models import MediaObject

class Command(BaseCommand):
    help = '检查媒体数据完整性'

    def handle(self, *args, **options):
        # 检查孤儿消息
        orphan_messages = Message.objects.filter(
            media_id__isnull=False
        ).exclude(
            media_id=''
        ).exclude(
            media_id__in=MediaObject.objects.values_list('media_id', flat=True)
        )
        
        count = orphan_messages.count()
        if count > 0:
            self.stdout.write(
                self.style.WARNING(
                    f'发现 {count} 条消息的 media_id 指向不存在的 MediaObject'
                )
            )
        else:
            self.stdout.write(
                self.style.SUCCESS('✓ 媒体数据完整性正常')
            )
```
