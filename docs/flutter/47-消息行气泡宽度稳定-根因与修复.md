# 消息行气泡宽度稳定（2026-11-12）—— 根因与修复

> 用户实报：屏幕较窄时，群聊/私信界面的聊天气泡被气泡左侧的「工具栏 + 发送转圈」挤压到很窄；
> 等 2 分钟撤回键消失、上传结束转圈消失后，气泡才变回正常比例 —— 也就是**宽度会跳变**。

## 一、用户裁决（本次实现的唯一口径）

1. 以**终态**（无撤回键、无加载态）为目标，消息刚发出时气泡就必须是这个宽度，**禁止出现变化**。
2. 空间不足时**不能用工具栏挤压气泡**（撤回消失后气泡变宽），而要**让气泡优先、工具栏让位**。
3. 加载态**不得挤压宽度**（web 端本就不挤压，Flutter 端要参考 web）。
4. 追加裁决（2026-11-12）：「**如果空间够显示文字，则显示文字；如果不够，则仅显示图标，不再出现竖排。**」

## 二、根因（两端各一处，互相独立）

### web 侧

`.msg-row` 是 flex 行，`.msg-actions`（工具栏）作为普通 flex item 参与布局，宽度 = **子键自然宽之和**：
- 自己行 3 键（收藏 + 引用 + 撤回）= 156px；
- 撤回键仅在 120s 内存在（`MessageBubble.tsx` 的 `canRecall`）⇒ 消失后工具栏变 98px，**这 58px 直接回流给气泡**。
- 实测（375 档）：3 键气泡 182 → 2 键气泡 220，**+38px 跳变**。

### Flutter 侧

同一问题（`AylaCssFlexRow` 按 CSS §9.7 收缩，把气泡压到 183），**外加一处独立缺陷**：
`_BubbleWrap` 把 `.msg-send-state` 放成 `Row` 的同级，并用 `Flexible(child: bubble)` 包住气泡
⇒ 上传进度 / 取消键**占用布局宽度**，一出现就把气泡再挤一次。
web 侧该状态是 `position:absolute`（`right: calc(100% + 8px)`），**本来就不占布局** —— 这就是两端观感不同的原因。

## 三、修复方案

核心思路：给工具栏一个**与键数量无关的固定槽位**，并把同一常量从气泡宽度上限里扣掉。

```
气泡宽 = min(比例上限, 行内宽 − reserve − 槽位)
  reserve = 头像 37 + 2×gap 8 = 53
  比例上限 = 75%（宽屏）/ 84%（窄屏 ≤768）
  槽位 = 文字档 155.2 / 图标档 78
```

这样行**永不溢出** ⇒ flex-shrink 分支永不触发 ⇒ 气泡宽度与键数量、发送态全部无关。
3 键时槽位刚好用完；2 键时剩余空间作为**透明留白**落在行的外缘（[`justify-content`] 让按钮组仍紧贴气泡）。

| 档位 | 生效条件 | 槽位 | 组成 |
|---|---|---|---|
| 文字档 | 行内宽 ≥ 832.8 | 155.2 | 收藏 32 + 4 + 引用 57.6 + 4 + 撤回 57.6 |
| 图标档 | 行内宽 < 832.8 | 78 | 收藏 26 + 4 + 22 + 4 + 22（方键，无文字） |

### 阈值为什么是 832.8（而不是某个视口宽）

文字档「不吃掉气泡」⇔ `rowInner − 53 − 155.2 ≥ 0.75 × rowInner` ⇔ `rowInner ≥ 832.8`。

⚠️ **判据必须是「气泡列/行内宽」，不是窗口宽**。桌面侧栏让同一 vw 下的列宽差 356px 以上：
宽屏私聊侧栏 356（`.wide-messages-sidebar` 332 + gutter 12×2）、群聊 380（ServerRail 96 + ChannelSidebar 284）。
**vw=1024 时真实 rowInner 只有 612**，远低于 832.8；若按窗口宽判会误判成文字档、把气泡压窄。

- web 实现：`.message-column { container-type: inline-size }` + `@container msg-column (max-width: 844px)`
  （844 = 列宽；列宽 = rowInner + 8，即 `padding: 0 var(--sp-1)`）。
- Flutter 实现：`LayoutBuilder` 的 `c.maxWidth − 2×sp1`（**不要**用 `MediaQuery.sizeOf(context).width`）。
  两端判的是同一层量，边界等价。

### 加载态（Flutter 特有取舍）

Flutter 不能照抄 web 的绝对定位：溢出父边界的部分会被祖先 `RenderBox.hitTest` 丢弃
（只在自身 size 内接受）⇒「取消 / 重试 / 删除」会变成看不见摸不着。

落地改为：**发送态占用工具栏的同一个固定槽位**（两者互斥）。槽位早已从气泡上限扣掉 ⇒ 气泡宽度零影响；
状态整体落在行内 ⇒ 按钮可点；视觉位置与 web 一致（右对齐到槽位靠气泡一侧 = 气泡左缘外那个 8px）。

## 六、容易再犯的三个坑

1. **不要把 scroll padding / 行 padding 混进 `reserve`**。`reserve` 只含行**内部**的固定占位
   （头像 + 两个 gap）；`100%` 的基数是 `.msg-row` 的 content box，scroll/column 的 padding 在它外面。
2. **不要用窗口宽判档位**（见上）。
3. **不要在 Flutter 用绝对定位做发送态**（命中测试会被祖先裁掉），要用固定槽位。
