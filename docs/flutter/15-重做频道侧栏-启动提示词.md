## 二、上一版为什么失败（**必读**：这些坑一个都别再踩）

上一版实现已被删除，失败点全在**交互时序与范本复用**。

### 坑 1：选项卡高亮自己拼，没照库内范本

用户原话：**「选项卡高亮、扫光、动画都应该参考组件库现有成功范例，或复用」**。

必须照范本（`lib/widgets/profile_and_filters.dart` 的 `AylaDirectoryFilters` **555–587** /
`lib/widgets/bottom_tabs.dart` **150–167**）：

| 要素 | 正确做法 |
|---|---|
| 共享高亮 | **容器级单实例** `AylaNavHighlight` + `AnimatedPositioned`（300ms）→ 等价 Framer `layoutId` 的**跨项迁移**（同一实体滑动，不是旧底消失/新底出现） |
| 定位 | `GlobalKey` **实测**选中项矩形（或「实测容器原点 + 实时计算」） |
| 按压 | `AylaPressScale.onPressChanged` → 容器级 `AnimatedScale(0.98, 200ms)` |
| hover 底 | 行自身 `AnimatedContainer(300ms --auroraqua-ease)` → `.18`；**选中时自身底取消**（auroraqua 194–197 / 288–291），底交给胶囊 |

### 坑 2：扫光的触发面搞错（用户第二次点名「扫光也要改」）

web 的选择器是 **`.has-auroraqua-highlight:hover > .auroraqua-nav-highlight::after`**（auroraqua **163**）
—— 只有**按钮本体**被命中才扫光；行级 `:has()`（**878–881**）**只管底色**。
⇒ 有浮层钮的行（右侧 ＋ / 笔 / 三角）必须把 hover 状态**拆成两套**：行级（底色）/ 按钮级（扫光）。

另外：胶囊扫光时长是 **700ms**（auroraqua 187 覆写 `::after` 的 600ms）；**点击选中时**要在回调里
`highlightKey.currentState?.setSweep(true, jump: true)`（范本 545–548 的「挂载即命中」），否则
「点击选中」那次扫光看不到。`sweepActive` 必须**每帧求值**（指针所在项 == 选中项），不能只在
`onEnter/onExit` 里记 bool。

### 坑 3：展开/收起没有带动父级选项卡（用户报「错位」）

web 里场景行在**正常流**中（只是 sticky），下拉高度变化时后续行的流位置随之变化。
Flutter 侧若用实测值定位浮层行，必须解决两件事：

1. **测量要开追踪窗口**：`AnimatedSize` 只重绘自身、**不触发父级 build** ⇒「点击 → build（布局还是旧的）
   → 不 setState → 不再测量」→ 动画期间几何停在旧值。做法：`_scheduleMeasure({int ticks = 0})` +
   `_measureTicks`，在展开/收起、展开更多/收起的 onTap 里开 30 帧窗口，测量末尾若窗口未耗尽就继续排队。
2. **定位必须同帧（paint 阶段）**：追踪窗口只保证「每帧都测」，而测量是 `postFrame`（layout **之后**）
   → 永远落后一帧 ⇒「子列表已到位、选项卡还在动」的穿透（用户第三次报）。
   正解：写 `SingleChildRenderObjectWidget` + `RenderProxyBox`，在 **`paint`** 里读占位相对视口的
   `localToGlobal`（本帧 layout 已完成）→ 算出 clamp 后的 y → `context.paintChild(child, offset + y)`。
   **三个必须一起做的细节（每个都实测踩过）**：
   - `performLayout` 要自己写：层用 `Positioned.fill` 铺满视口（命中测试要覆盖），但默认 ProxyBox 布局
     会把 40px 的行**拉伸到视口高**（实测 `child=Size(244,443)`）→ `size = constraints.biggest` +
     `child.layout(BoxConstraints.tightFor(width: size.width))`；
   - **必须覆盖 `applyPaintTransform`**（与 paint 同偏移），否则 `localToGlobal` / 命中 / 语义 / `getRect`
     读到的还是布局坐标（探针会误判「元素不动」）；
   - **每次 widget 重建无条件 `markNeedsPaint()`**（位置取决于**外部**占位的移动，外部移动不会让本层重绘
     → 「内容在动、行不动」）。

   **验收判据**：动画每一帧「行 ↔ 其下拉首行」的距离恒定（上一版实测全程 `gap=42` 才算对）。

### 坑 4：Flutter 没有 CSS `overflow: hidden` 的静默裁剪

语音房下拉「折叠高度 = `min(3, n) × 31 − 1`、行仍渲染但被裁」是 web 行为；Flutter 的 `RenderFlex` 会直接报
`A RenderFlex overflowed`。做法：`SizedBox(height:) + ClipRect + OverflowBox(maxHeight: double.infinity)`，
并把隐藏行的交互语义对齐 web（`disabled` / `tabIndex=-1` / `inert` → `IgnorePointer + ExcludeSemantics`）。

### 坑 5：三个下拉的「展开更多」**实现各不相同**（照抄 tsx，别统一）

- **子群**：前 3 条 + **条件渲染**追加段（编辑态直接全显）+ `DirectoryLoadMore`；
- **语音房**：**固定高度裁剪**（折叠时高度 = `min(3,n)×31−1`，行全渲染但禁用）+ 展开后才渲染页脚；
- **直播**：前 3 条 + **条件渲染**追加段（分开两个列表）+ 页脚。

三者展开/收起都用 `disclosureVariants` 语义（height auto ↔ 0，300ms `--auroraqua-ease-out`）。

### 坑 6：Dart `List.sort` **不稳定**

web `sortSubgroupsByActivity`（`stores/subgroup.ts` 19–23）依赖「默认组固定第一 + `last_message_seq` 降序 +
**并列保持原序**」。Dart 必须显式带原索引做二级比较（`return a - b`），否则顺序会漂移。

### 坑 7：语音房行的胶囊**不迁移**

web 对语音房行传 `sharedLayout={false}`（行有自己的排序位移，二次共享投影会互相取消）
⇒ 该行保持**行内独立胶囊**；扫光 / hover 底仍与其它行一致。子群、直播、场景项则都是**跨项迁移**。

### 坑 8：画布样张的长文本必须限宽

不限宽的 `Text` 会把 `Row` 撑出画布（实测画布 736 可用宽、溢出 5.2px、冒烟测试直接失败）
→ 样张说明文字包 `SizedBox(width: 组件宽 + margin)`。

### 坑 9：`find.ancestor(...).first` 取的是**最外层**祖先

断言尺寸/位置用 `find.byWidgetPredicate` 直接锁属性（如 `w is SizedBox && w.width == 64`）更稳；
拖动类测试的起点要落在**内容**上（吸附行浮层会吃掉指针，与 web 相同）。

1. **读全 web 源码链**：tsx 全文 → `group.css` 680–1370 逐条 → `auroraqua.css` 相关段落
   （**连带确认所属 @media**）→ `useSidebarContentClip.ts` → `auroraquaMotion.ts` → stores/hooks/types →

3. **列出推导表**（字段 / 尺寸 / 颜色 / 交互 / 动画 / 复用清单，**每条标 web 文件:行号**）→ **给用户过目**；
4. 用户点头后**才写代码**；
5. `dart analyze lib` 零告警 → 定向测试（**必须含**：sticky 吸顶/吸底边界、动态裁剪、三下拉差异、
   **同帧同步（gap 恒定）**、扫光触发面、按压同步、迁移、排序稳定性、编辑态、入场）→ `@Preview` +
   加入 `lib/preview/component_gallery.dart`；
6. `flutter test --concurrency 1` **全量全绿**（当前基线 **223/223**，新增条数往上加）；
7. **汇报**：逐条「web 行号 ↔ 实现」对照 + 未做项；等用户验收。

**定位纪律**（本件事故全部靠这个查出来）：

- 位置/交互类问题**先写临时探针**：分阶段 dump 几何（initial / tap / 150ms / settled / 操作后），
  一眼看出哪个方向失效；必要时在测量/绘制入口加临时 `debugPrint`，看「哪一帧开始没再测 / 没再画」；
- **渲染与坐标要验两样**：`tester.getRect` 读的是**布局**坐标（改了 paint 偏移就必须覆盖
  `applyPaintTransform`）；必要时验像素（`matchesGoldenFile` / 像素采样）；
- 探针**跑完即删**，别留在仓库里。
