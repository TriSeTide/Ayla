# 2026-11-02 Flutter 主页宽屏「第一列群头像侧栏滑入动画」—— 根因与修复

> 用户实报原话：「修复 Ayla Flutter-宽屏-主页群聊界面-第一列群头像侧栏的滑入动画，滑入行为要与
> web 端一致，在主页切换群聊时第一列侧栏不播放动画，只修进入和离开主页时的播放」。
>
> 本文件记录**根因、证据、修法、验收**。代码事实源在 `Ayla/flutter/lib`。
> 相邻但**不重叠**的历史记录：`43-2026-11-02-直播侧栏切台跳变`（同样是「页面/组件身份」问题，
> 但那个是**路由 page key**，本轮是**动画 owner 的生命周期边界**）。

## 一、web 端的正确行为（先读事实源，再看 Flutter）

web 有两层不同 owner，**缺一不可**：

| 层 | 位置 | 作用 |
|---|---|---|
| CSS 入场**关闭** | `auroraqua.css:293` 的 `@media (min-width:769px)` 内 `310–313` | `.server-rail, .channel-sidebar, .wide-messages-sidebar { animation: none }` —— 原文注释：「宽屏进入/切群由 React motion 按各自 owner 编排，避免叠加 CSS 整列入场」 |
| motion 入场 | `ServerRail.tsx:90–99` 的 `motion.nav`：`initial={reduced ? false : "enter"}` + `animate="center"` + `variants={panelVariants(reduced, "left")}` | 只在**它自己被挂载**时播 x −20 → 0 + opacity 0 → 1（300ms easeInOut） |
| 生命周期边界 | `PageTransition.tsx:56–60` 的 `resolvePageKey` | `/group/*` 全部归一成 **`wide-group-shell`** 作 page key ⇒ 切群 / 切场景**不换 key**、React 复用同一个 `GroupPage`；只有**离开主页再进来**才换 key ⇒ 重挂 ⇒ 重播 |

`docs/design.md` §12.3 把这条写成硬要求：

> 宽屏切换群时AppShell使用稳定的 `wide-group-shell`，ServerRail owner与共享指示条id不重挂…
> **首次进入主页的左移入场与同一主页内切群须由不同生命周期边界控制，避免第一列反复滑入。**

⇒ 正确行为矩阵：**进入主页播 / 切群不播 / 切场景不播 / 离开再回来又播**。

## 二、修前的 Flutter（两处都错，且方向相反）

### 2.1 组件层：模块级「只播一次」标记 —— 切走再回来也不播了

`server_rail.dart` 里有模块级布尔：

```dart
bool kAylaServerRailEntered = false;   // 每个 app 会话只播一次
...
if (widget.animateEntrance && !kAylaServerRailEntered) {
  kAylaServerRailEntered = true;
  _enter = true;
}
```

它是 2026-10-01 为修「每次进主页都滑入」加的，但把边界做成了**进程级**而不是
**页面生命周期级** —— 一旦播过，**离开主页再进来也不再播**（web 会播）。

### 2.2 页面层：根本没接 owner

`group_page.dart` 的宽屏三列里 `AylaServerRail(...)` **没传** `animateEntrance`
（用默认 `true`），于是「什么时候播」完全由组件自己那个错误的模块级标记决定。

### 2.3 冷启动：入场被全屏预加载门**吃掉**

`layout/app_gate.dart` 在 `AppInit.status == loading` 时把路由子树放进 `Offstage`。
`Offstage` 的官方文档原文：

> **Animations continue to run in offstage children**, and therefore use battery and CPU time,
> regardless of whether the animations end up being visible.

⇒ 冷启动时第一列的 300ms 入场在**门还盖着**的时候就跑完了，用户第一次看到主页时侧栏是静止的。

**实测证据**（临时 widget test，1440×900，真实路由 + 真实 `AylaAppGate`，
量的是第一列玻璃件的**全局左边距** `glassLeft`，终值 12、入场起笔 −8）：

```text
GATE-0:      reveal=1 glassLeft=-8.0    ← 门关着，入场已经在跑
GATE-640ms:  reveal=1 glassLeft=12.0    ← 门还关着，入场已跑完
OPEN-0..7:   reveal=1 glassLeft=12.0    ← 门打开，用户看到的是终态（没有动画）
```

## 三、修法

### 3.1 组件层：删掉模块级标记，改成「由调用方给的 replay 开关」

`server_rail.dart`：

- 删除 `kAylaServerRailEntered` 与 `_enter`；
- `animateEntrance` 的语义明确为 **「false → true 的那一刻播一次，true 期间不重播」**；
- 状态侧新增 `_enterPlayed` + `_enterTick`：`_syncEnter()` 在 `initState` 与
  `didUpdateWidget` 调用，抬旗时 `_enterTick += 1`；
- 入场层写成 `AylaRevealItem(key: ValueKey<int>(_enterTick), …)` ——
  `AylaRevealItem` **只在被新建时**播入场，复用同一实例时「再播一次」会被它静默忽略
  （这就是必须换 key 的原因；换 key 只重挂**入场层**，列本身、滚动位置、悬停面板、
  指示条测量全在 `State` 上，不受影响）；
- `reduced-motion`（`MediaQuery.disableAnimations`）时**不挂**入场层 =
  web 的 `initial={reduced ? false : "enter"}`。

### 3.2 页面层：owner 落到 GroupPage 的生命周期上

`group_page.dart`：

- 新增 `_railEntrance`，**只在 `initState` 判定一次**（`build` 一帧内可能跑多次，
  判定会被自己吃掉 —— 历史实现踩过，`server_rail_test` 的入场用例就是这么红的）；
- 判据 = 「本 State 挂载 = 一次『进入主页』」：5 条群路由共用 `kAylaGroupShellPageKey`
  ⇒ 切群 / 切场景复用同一个 State（不播），离开再回来 State 新建（播）；
- 传给 `AylaServerRail(animateEntrance: _railEntrance)`。

### 3.3 冷启动：门打开那一帧才抬起开关

`_armRailEntrance()`：`initState` 时若 `AppInit.status == loading`（门正盖着），
**先不抬起**，挂 `AppInit` 监听，等它离开 loading（门打开那一帧）再 `setState` 抬起
⇒ 入场与「用户第一次看见主页」同一帧开始。监听在 `dispose` 里注销。

修后实测（同一条探针）：

```text
GATE-CLOSED(480ms): reveal=0 left=12.0     ← 门关着：连入场层都不挂（开关还没抬）
GATE-OPEN0:         reveal=1 left=-8.0     ← 门一开：从起笔位开始
GATE-OPEN1..5:      reveal=1 left=-7.9 -7.5 -7.0 -6.1 -5.0
GATE-OPEN-END:      reveal=1 left=12.0
```

## 五、未自证项（按纪律交用户验收）

- **真机肉眼**：按 skill「预览职责边界」，agent 不代起/代看预览实例、不截图。
  用户自己 `flutter run`（debug 热加载）后看四处：
  ① 冷启动进入主页 → 第一列**从左侧滑入**（此前是静止出现）；
  ② 主页内点另一个群头像切群 → 第一列**不动**，只有粉色指示条迁移；
  ③ 切到语音/直播/帖子/桌游场景再回聊天 → 第一列**不动**；
  ④ 切到 /voice 等一级页再回主页 → 第一列**重新滑入**。
- **离开主页的退场**：本轮**只改「进入」**。web 侧离开时，第一列`motion.nav` **不播自己的 exit**
  —— 它随外层 `.page-transition` 一起淡出（`PageTransition.tsx:103` 的 exit 只有 `opacity: 0`，
  `ServerRail.tsx` 的 `variants` 里虽有 exit 分支但父级卸载即止，实测 rail 的 opacity/transform
  在 300ms 内**稳定为 1 / none**，淡的是外层）。

  Flutter 现状：`/group` 与离开目标（`/voice` `/live` `/posts` `/games` `/favorites` `/search`
  `/profile` …）**都**在 `aylaPanelOwnedPath` 里 ⇒ 走 `NoTransitionPage`（零时长）⇒ 旧页在切换那一帧
  就卸载，**没有**那 300ms 淡出。这是**库内既有的全局决策**（`app_router.dart:75–95` 的注释：只有
  `/group` 与 `/posts/mine` 用 `MaterialPage`；而 web 的 `/group` 同样在 `panelOwned` 名单里、
  `initial` 即终值 ⇒ *进入* 无动画），**不属于本轮「第一列滑入」的范畴**，也不建议为这一处
  单独给 `/group` 加 300ms route：那会让**整个主页**（含第二列、内容区、所有玻璃卡）在切换时
  多留一帧页面存活，与「panelOwned ⇒ 同屏只有一页」的防卡顿决策冲突（见该文件的长注释）。
  若用户验收后仍要「离开也淡出」，应作为**独立任务**按「整页转场总开关」重新评估，
  而不是在路由分档里为一条路径开特例。
- **窄屏**：第一列是宽屏专属（`_buildWide`），窄屏不受影响。

## 七、可复用教训（已同步进 skill）

1. **`Offstage` 不吃动画**：它只跳过绘制，`Ticker`/controller 照常推进
   （官方文档原话 “Animations continue to run in offstage children”）。
   凡「先挂载、后显示」的门/遮罩，都要问一句「入场是不是在看不见的时候跑完了」。
2. **`AylaRevealItem` 只在新建时播**：想让已存在的实例「再播一次」必须**换 key**
   （`ValueKey(nonce)`），改 prop 无效。库内已有 `AylaRevealScope(replayKey:)` 这一族能力。
3. **动画 owner 要落在「用户能感知的生命周期」上**：`/group/*` 共用一个 Page key
   ==> 组件 State 不重建 ==> 入场开关必须由**页面**在 `initState` 判定并下传，
   不能在组件里用进程级标记（那会把「离开再回来」也吃掉）。
4. **写「切换开关」类 widget 测试必须让 route 内部的有状态件 setState**：
   `pumpWidget` 对已挂载的同一个 `MaterialApp` 不会重建 `home:` 路由
   ==> 断言读到旧值、用例假绿。
5. **量动画要用「值集合」而不是单点**：切群用例里断言 `seen == {12}`，
   任何多出来的取值都等于「又滑入了一次」——比断言首帧/末帧都稳。
