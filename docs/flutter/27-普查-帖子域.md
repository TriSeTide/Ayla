## 3. 一级帖子页 `post.created` 不刷新 —— 完整根因链（用户实报第一条）

### 3.2 为什么「帧会到达」是确定的（不是「收不到帧」）

| 环节 | 证据 |

| 全局桥确实挂在 chat WS 上 | `room_providers.dart:451–453` → `posts_frames.dart:119–123`；启动 `main.dart:262`，登录后重装 `auth_bootstrap.dart:189–190` |

### 3.3 为什么「群内帖子页可以」——两处结构性差异（缺一不可）

| 差异 | web 群内页 | Flutter 群内页 | web 一级页 | Flutter 一级页（修前） |
|---|---|---|---|---|
| **① 发帖成功后是否卸载页面** | 不会：编辑器是列表下方常驻 input（`GroupPosts.tsx:493–502`） | 不会：`AylaGroupPostsComposer` 常驻（`group_posts_page.dart:1065–1066`） | **会**：`navigate('/posts/<id>')`（`CreateFab.tsx:97–100`） | **会**：`context.go('/posts/<id>')`（`create_sheet_forms.dart:682–686`） |
| **② 发帖成功后是否本地插入** | 会：`handleCreated → mergePosts(prev,[post],true)`（`:239–248`，挂载 `:494–501`） | 会：`_submit → _posts=[created,..._posts]`（`:846–852`） | **不会**（`PostEditor` 只回 `onCreated(post)`，`PostEditor.tsx:169–190`） | **不会**（`_submit` 只关浮层+跳转，`:673–687`） |
| **③ 返回时是否被 60s 窗口挡住** | 不涉及（没卸载过） | 不涉及 | 是（`PostsHubPage.tsx:224`） | 是（`posts_store.dart:320–327` + `posts_hub_page.dart:343`） |

⇒ 群内页靠 **②** 直接得到新卡（不依赖 WS、不依赖缓存窗口）；一级页 **②** 缺失，只能依赖 WS，而 WS 期间页面又因 **①** 被卸载、回来被 **③** 挡住。**三条同时成立才出现该症状。**

## 5. 详情页 / 评论实时性：逐项与竞态

1. **订阅完整**：Flutter 在 `initState` 挂 `chatWsProvider.onFrame(_onFrame)`（`post_detail_page.dart:217–218`），`dispose` 解绑（`:229–231`）；消费 `comment.created`（`:289–304`）、`comment.deleted`（`:307–324`）、`post.viewed`（`:333–348`），全部按 `data.post_id == _postId` 过滤（`:274–275`）。
   web 对应 `PostDetailPage.tsx:219–245` + `usePostComments.ts:129–133` —— web 是「页面 + hook 各挂一份」（双消费），Flutter 单份，净效果等价（计数覆盖同源）。
2. **评论创建/删除的跨端同步成立**：后端按帖子可见性广播（`services.py:459–510` / `:513–539` `_comment_audience`），consumer 透传（`consumers.py:659–665`）。
3. **竞态缺口（P2，静态可证）**：
   - **缺 deleted 墓碑**：web `upsert` 先查 `current.deleted.has(comment.id)`（`usePostComments.ts:111`）、`request` 也过滤（`:92`）；Flutter `_applyCommentCreated` 只查「是否已在 `_comments`」（`:300`），`_applyCommentDeleted` 不记墓碑（`:307–324`），`_loadComments` 不过滤（`:432–475`）⇒ WS 重连重放 / 广播顺序争用时**已删评论可复活**。
   - **计数算术不同**：`_deleteComment` 用 `commentCount - 1` 本地推算（`:518–522`）；web 用 `Math.max(0, total - 存在性)`（`usePostComments.ts:116–122`）+ 帧携带 `comment_count` 覆盖（`PostDetailPage.tsx:223`）。重复删除帧场景会差 1（低危）。
   - **在途分页 vs 帧**：web `request` 用 `mutationAtStart` 保留请求期间被帧改过的项（`usePostComments.ts:77/94`）；Flutter `_loadComments` 直接 `merged`（append 保 prev、首屏替换）⇒ 首屏在途期间新增的评论会被响应覆盖。
4. **web 有、Flutter 无的 affordance**：`commentPage.stale`（离开详情时把快照 `updatedAt` 归零，回来显示「刷新评论」，`usePostComments.ts:134–143` + `PostDetailPage.tsx:697–699`）。Flutter 无评论缓存 ⇒ 每次重进都真取，**反而没有「看起来新但其实旧」的风险** —— 判为可接受机制差异，「刷新评论」按钮缺席（低优先级）。
5. **两侧都缺**：正在看详情时他端 `post.deleted` / `post.updated` 不处理（web `:219–245` 无这两分支；Flutter `:268–286` 同）⇒ 帖子被删后详情仍显示、被编辑后正文不刷新。
