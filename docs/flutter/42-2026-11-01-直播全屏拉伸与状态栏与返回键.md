## 零、第二轮复报「还是有概率拉伸」的两个**代码级**根因

> 用户原话：「**还是有概率拉伸，你应该找到拉伸的代码级根因。直接把全屏播放器的
> 长宽比限死不就行了**」。这句话直接点破了两处 —— 一处是「比例来源不可靠」，
> 另一处是一个**确定性的**框架层缺陷（根本不是概率）。

### 根因 A：全屏 overlay 子树是**快照**（确定性，不是概率）

`_toggleFullscreen` 旧写法：

```dart
final Widget fullscreen = _buildFullscreen();          // ← 已经构建好的实例
aylaOverlayEntry(builder: (ctx) => fullscreen);        // ← 闭包 capture 这个实例
```

`OverlayEntry` 的 builder 只会被调用，返回的**永远是同一份 Widget 实例**
⇒ 全屏层渲染的是「进全屏那一刻的快照」：

| 冻结的东西 | 用户可见后果 |
|---|---|
| `widget.videoAspectRatio` | 进全屏时若还没上报 ⇒ **永远**停在「比例未知」⇒ 拉伸，换台/重连都不自愈 |
| `_controlsVisible` | 3s 自动隐藏在全屏里**从不生效** |
| `_spinning` | 全屏里点刷新不转圈 |

**修法**：builder 每次重建都重新求值（`_buildFullscreen()` 读当前 State/widget），
再由统一入口 `_setStateAndSync` / `_syncFullscreen`（帧末 `markNeedsBuild`）把
这棵独立子树拉进当前帧。

⚠️ `markNeedsBuild` **不能**在 `didUpdateWidget`（build 阶段）直接调 —— 会被框架
丢弃（实测：比例迟到时仍是旧快照）⇒ 必须用 `addPostFrameCallback` 排到帧末。

### 根因 B：比例来源不可靠 ⇒ 「有就用、没有就铺满」

第一版写成「平台上报比例、报不出来就**原样铺满**」。于是只要比例晚于进全屏
（刚好在刚进房 / 播放器自愈重建），那一次必然拉伸。

**修法（用户直接指出的解法）**：**把比例限死**。

```dart
// lib/widgets/live/video_contain.dart
const double kAylaLiveVideoAspectRatio = 16 / 9;   // 事实源 app.css:3521
```

| 注入值 | 用哪个比例 |
|---|---|
| null（默认 / 未上报 / media_kit 不报） | **16:9（锁死）** |
| 有效值 | 用它（真实流比例更准） |
| 非有限 / ≤0 | 16:9（绝不产出 NaN 尺寸） |

⇒ **任何时刻都有确定的等比盒**，最坏是「非 16:9 的流按 16:9 收盒」（画面略小 +
四周留黑），**永远不会是拉伸**。

### 这两处的回归锁与变异验证

`test/live_fullscreen_video_contain_test.dart`（7 条），并逐条做过「摘掉修复 ⇒ 变红」：

| 变异 | 摘掉什么 | 变红的用例 |
|---|---|---|
| A | builder 改回快照（值 capture 进闭包） | 「比例的迟到要能生效」 |
| C | 去掉 `_safeRatio` 的 16:9 兜底 | 「非法比例 ⇒ 退回 16:9」 |

### ⚠️ 验证这类缺陷时**宿主必须与生产同构**

用 `tester.pumpWidget` 整棵替换宿主来模拟「父级传新值」会假失败：`previewScope` 的
`Overlay(initialEntries:)` 在重建时忽略新 entries，量出来的永远是旧条目。
正确写法 = StatefulWidget 持字段 + `setState`（= 生产里页面拿到 session 通知后
重新 build `AylaLivePlayer` 的那条路径）。

## 一、画面被拉伸（「不要拉伸屏幕，要正常长宽比，多余的留黑」）

### 根因
全屏容器是**整块屏幕**（手机上全屏后逻辑尺寸约 844×390 = 2.16:1），
而视频视图是 `video_player` 交出的 `Texture`：

- `RenderTexture` 是 **RenderProxyBox**（`flutter/lib/src/rendering/texture.dart`）：
  尺寸 = 父约束，纹理按自身尺寸**拉伸**绘制；
- `video_player` **没有** `fit` 参数（与 web 的 `<video>` 不同）⇒ 16:9 的直播画面
  被拉成屏幕比例。

web 侧没有该缺陷：`object-fit: contain` 挂在 `<video>` **元素自身**
（`app.css:3528–3533`），元素铺满 100%×100%、由元素内部 letterbox。

另外，全屏档此前用的是 `AspectRatio(aspectRatio: 1)`（正方形占位）—— 在
`Stack(fit: expand)` 下被强行拉伸成整屏，语义错误且一旦父级不再强制 expand
就会退化成正方形黑块。web 的全屏档是 `aspect-ratio: auto`（`app.css:3639–3646`）。

### 修法
1. **新增 `lib/widgets/live/video_contain.dart` 的 `AylaVideoContain`**：
   `LayoutBuilder` 先算出**有界等比盒**（contain 的核心一步），再居中交给平台视图。
   - 为什么不直接用 `FittedBox`：既有结论（2026-10-01 直播黑屏）是
     「外层套 FittedBox 会把无界约束传给 media_kit 内部的 `Stack(fit: expand)` ⇒
     Infinity ⇒ 无效变换矩阵 ⇒ 黑屏」。本件用 LayoutBuilder 给出**确定尺寸**，
     不传导任何无界约束，因此对 `media_kit` 也是安全的。
   - 比例未知（`null` / 非有限 / ≤0）⇒ **原样铺满**，与 web 上 `<video>`
     尚无元数据时一致（不猜）。
2. **比例从播放器取**：
   - `HlsPlatformPlayer` 新增**可选能力接口** `HlsVideoMetrics`
     （`lib/player/hls_player.dart`）—— 不加进抽象类本体，避免 5 个测试替身
     全部编译失败；
   - `VideoPlayerHls` 实现它：`videoAspectRatio` = 渲染后的
     `size` 比例（**含** `rotationCorrection` 的 90° 交换，与
     `VideoPlayer` widget 自己的 `RotatedBox` 对齐）。
   - `MediaKitHls` **不实现**（它不报比例）：它的 `Video` widget 内部
     自带 `FittedBox(fit: BoxFit.contain)`，本身就是 `object-fit: contain`。
3. **全屏档不再套 16:9 / 正方形**：`_content(fullscreen: true)` 直接返回
   「黑底 + 铺满」，比例交给画面（`lib/widgets/live/live_player.dart`）。
4. **接线**（三层，缺一层就还是拉伸）：
   `HlsPlaybackController.videoAspectRatio` → `AylaLiveRoomSession.videoAspectRatio` →
   三个页面（`live_room_page` / `live_studio_page` / `group_live_page`）
   的 `AylaLiveRoomBody(videoAspectRatio:)` → `AylaLivePlayer(videoAspectRatio:)`。

### 验证
`test/live_fullscreen_video_contain_test.dart`（6 条）：量**实际渲染框**
（不是断言 widget 存在）—— 16:9 画面在 844×390 的屏上必须是 693.3×390 且水平居中；
4:3 画面反之；比例 null / 非法值必须原样铺满。

## 二、全屏时状态栏没隐藏

### 根因（两层）
1. **Flutter 侧从来没调过任何系统栏 API** —— 全屏只做了「插 root Overlay + 锁横屏」。
2. 补上 `SystemChrome.setEnabledSystemUIMode` 也**不生效**：本工程
   `targetSdk = 36`（Android 16；`flutter.targetSdkVersion` 在 Flutter 3.47 就是 36），
   Flutter 官方文档明写「If your app targets Android SDK 16 (API 36) or later, then the
   Android system will ignore this value」（`system_chrome.dart` 的 enum 注释）。
   引擎侧证据（反编译 `flutter.jar` 的
   `io/flutter/plugin/platform/PlatformPlugin.class`）：三种沉浸模式只换算 legacy
   flags（1798 / 3846 / 5894）并调用 `View.setSystemUiVisibility` ——
   而该 API 在 Android 16 上已失效。

### 修法
1. **新增原生通道 `ayla/system_ui`**（`android/.../MainActivity.kt` +
   `lib/core/platform/system_ui.dart`）：
   - API 30+：`WindowInsetsController.hide(WindowInsets.Type.systemBars())` +
     `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`（= 沉浸式粘性）；
   - API 24–29：`View.SYSTEM_UI_FLAG_IMMERSIVE_STICKY | HIDE_NAVIGATION | FULLSCREEN`；
   - **生命周期重放**：`onResume` / `onWindowFocusChanged` / `onConfigurationChanged`
     在「仍处于沉浸式」时重放一次 —— 否则旋转与切后台回来时系统栏会回弹。
2. **Android 上故意不调 `SystemChrome.setEnabledSystemUIMode`**：引擎在非
   EDGE_TO_EDGE 模式下会先 `disableEdgeToEdge()`（`WindowCompat.setDecorFitsSystemWindows(true)`），
   那会破坏本工程全站按 edge-to-edge 设计的 `AylaTopInsetGap` 语义 ⇒ 只有害处。
   iOS 仍走 `SystemChrome`（那里才是正解）。
3. 进出全屏成对：进 ⇒ `setImmersive(true)`；退 ⇒ `setImmersive(false)`；
   **全屏中直接离开页面（dispose）也必须恢复**，否则整个 App 都没有状态栏。
4. 控制器可注入（`AylaSystemUiController`）：测试用替身断言下发序列，
   不需要改 `defaultTargetPlatform`（改了会被 binding 的
   `debugAssertAllFoundationVarsUnset` 判为失败）。

### 验证
`test/live_fullscreen_back_and_status_bar_test.dart` 的 ④⑤ 三条；原生侧由
`./gradlew :app:compileDebugKotlin -PskipDependencyChecks=true` 通过编译验证
（Gradle 8.12 < Flutter 3.47 要求的 8.14，属既有环境约束，不改 wrapper）。

## 三、全屏时按返回键直接离开直播间

### 根因
全屏层只是**插进 root Overlay 的浮层**，路由仍在 `/live/:channelId` ⇒ 系统返回键走
`aylaBackActionFor(canPop: true)` = `popRoute` ⇒ `context.pop()`（进房是 push）
⇒ **直接退出直播间**。而用户预期是「先退出全屏、回到未全屏的直播间」。

页面级 `PopScope` 到不了（机制链见 `lib/layout/app_back.dart` 文件头：
`go_router` 的 `RootBackButtonDispatcher` 只问顶层 Navigator）⇒ 唯一入口是
`AylaBackButtonHost`（挂在 `AppShell` 根部）。

### 修法
1. `lib/layout/app_back.dart` 新增：
   - 档位 `AylaBackAction.liveFullscreen`（**排在所有档之前**：全屏是浮层，
     与「当前在哪个路由 / 能不能 pop」无关，群内直播同样适用）；
   - 模块级登记点 `aylaLiveFullscreenBackHandler`（typedef `AylaLiveFullscreenBackHandler`）；
   - `aylaBackActionFor(hasLiveFullscreen:)` 参与判档；`_handle` 命中该档时
     调用处理器并**返回 true**（不交回框架）。
2. `AylaLivePlayer`：进全屏登记、退全屏注销、dispose 注销；处理器用**字段稳定实例**
   （`late final _backHandler`）+ `identical` 判定注销，避免 tear-off 相等性歧义。

### 验证
`test/live_fullscreen_back_and_status_bar_test.dart` 的 ①②③：
③ 是**真实链路**（真 `GoRouter` + 真 `AylaBackButtonHost` +
`tester.binding.handlePopRoute()`），断言「全屏层消失 **且** 路由仍是 /live/7」。

## 七、待用户确认的两个取舍
1. **导航栏也隐藏**：需求只说「顶部状态栏」。实现顺带隐藏了底部导航栏
   （`systemBars()` = status + navigation），理由是 web 的 `requestFullscreen` 同样是
   全屏无导航栏，且底部手势条压在画面上更难看。若希望只藏状态栏，改
   `WindowInsets.Type.statusBars()` 即可（一处）。
2. **全屏仍锁横屏**：与 web 的 `lockLandscape()` 一致（沿用既有行为，未改）。
