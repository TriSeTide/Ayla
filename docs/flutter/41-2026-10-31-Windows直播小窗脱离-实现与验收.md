# 2026-10-31 Windows 直播小窗脱离应用（独立置顶窗口）—— 实现与验收

> 需求（用户原话）：「电脑端直播小窗，也要脱离应用，目前没能正常实现，在电脑端看不到小窗
> （实现时要注意跟手机一样，小窗观看直播时也算作观看人）」
>
> 契约（Lead 持有，勿改）：`Ayla/flutter/lib/core/platform/detached_live.dart`，通道

### 2. 原生（runner）

| 文件 | 改动 |
|---|---|
| `windows/runner/live_window.h` / `.cpp`（新） | `AylaLiveWindowHost`：开一个 `WS_POPUP \| WS_CLIPCHILDREN \| WS_CLIPSIBLINGS` + `WS_EX_TOPMOST \| WS_EX_TOOLWINDOW` 的顶层窗口，内嵌**第二个 Flutter engine**；`Show()/Close()/RequestClose()` |
| `windows/runner/CMakeLists.txt` | 加源文件 `live_window.cpp`；给 runner 加 vendored 插件头文件路径 |
| `windows/runner/flutter_window.h` / `.cpp` | 注册 `ayla/desktop_window` 通道（`openLiveWindow` / `closeLiveWindow` / `showBall`→`"unsupported"` / `hideBall`）；接 `WM_APP + 1` → 回调 `onLiveWindowClosed` + 把主窗口拉回前台；`OnDestroy` 里先关第二引擎 |

关键实现点（每一条都是踩过的坑）：

1. **第二个 engine 只注册 media_kit_video**：`MediaKitVideoPluginCApiRegisterWithRegistrar`，
   **不** `RegisterPlugins()`（否则 flutter_webrtc / livekit / record 会在第二引擎里各起一套）。
2. **每个顶层窗口都转发** `FlutterDesktopViewControllerHandleTopLevelWindowProc`
   —— 漏了第二个窗口的键盘/IME/lifecycle 全废；`WM_SIZE` 里 `MoveWindow` 子 view。
3. **销毁顺序**：`channel_` → `controller_`（messenger 随 engine 消亡）。
4. **不 `PostQuitMessage`**：主窗口 `SetQuitOnClose(true)` 自己管消息循环。
5. **`ShowWindow(SW_SHOWNOACTIVATE)`**：不抢焦点；`WS_EX_TOOLWINDOW` ⇒ 不进 Alt-Tab / 任务栏。
6. **播放地址的交给时机**：`Show()` 里**不**发 `play` —— 那会与 Dart 侧 handler 注册竞态
   （平台→Dart 消息在 handler 未挂时会被丢弃），而且在 channel 回调里等「引擎就绪」会把
   **主窗口 UI 卡住**整个第二引擎冷启动时间。现在改成：第二引擎首帧后回 `ready`，
   宿主**在 `ready` 的处理里**发 `play`{url,title}。
7. **关闭通知只有一个出口**：所有关闭路径都进 `WM_DESTROY`，在那里判断
   `suppress_closed_notification_`（Dart 主动关 = 不通知；用户点关闭 = 通知）。
   Dart 主动关走 `RequestClose()`（`PostMessage(WM_CLOSE)`，**同步销毁第二个引擎会重入当前引擎**）。
8. Win11 圆角用 `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_DONOTROUND)`
   关掉，否则无边框窗口四角露出桌面色。

### 3. Dart

| 文件 | 改动 |
|---|---|
| `lib/main.dart` | 只**追加**顶层 `@pragma('vm:entry-point') void aylaLiveWindowMain(List<String> args)`（与 `main()` 同一个库 —— 自定义 entrypoint 的硬要求）；**未改 `main()` 主体** |
| `lib/widgets/live/live_window_surface.dart`（新） | `AylaDetachedLiveWindowApp`（第二引擎根：自持 `Player`+`VideoController`）+ `AylaDetachedLiveWindowSurface`（纯视图）+ `AylaDetachedWindowChannel`（`ready`/`close`/`activateMain`/`play`）+ 画布样张 |
| `lib/pages/live_support.dart` | 只**新增** `AylaLiveRoomSession` 内的 Windows 交接逻辑：`_bindDetachedWindowLifecycle` / `_onDetachedWindowClosed` / `_suspendMainPlayerForDetached` / `_resumeMainPlayerAfterDetached`，并在 `enterDetachedPresentation` 成功分支里挂上 / `dispose` 里摘订阅 |

**「小窗观看也算观看人」怎么保证**：进入脱离态**只停 Windows 那一路播放器**
（`_player.destroy()`），`_alive` / 弹幕 WS / 观看心跳 / 在看名单**全都不动** ⇒ 后端看到观众仍在。

⚠️ **只在 Windows 停播放器**（2026-10-31 由 android-pip 复核修掉的真缺陷）：
`enterDetachedPresentation` 是 **Android / Windows 共用入口**。Android 的 PiP 显示的就是
**本 Activity 本 engine** 的那张画面，无条件 `_player.destroy()` 会让**画中画变成纯黑窗口**。
现在改成 `final bool secondWindow = defaultTargetPlatform == TargetPlatform.windows;`
后按平台分派：Windows 停主窗口那一路（第二引擎已经接管）、Android 什么都不停。

**挂起 / 恢复的配对（三条路径都必须收口，漏一条就黑屏）**：

| 路径 | 谁来恢复主窗口播放器 |
|---|---|
| 用户点独立窗口的关闭键 / 点画面回主窗口 | 原生 `WM_DESTROY` → `WM_APP + 1` → `onLiveWindowClosed` → `_resumeMainPlayerAfterDetached()` |
| **Dart 主动关**（`closeDetachedPresentation`，例如会话菜单/切台） | 原生**故意不回调** ⇒ 该方法里**自己**再调一次 `_resumeMainPlayerAfterDetached()` |
| 会话终止（`stop` / `dispose` → `clearDetachedPresentation`） | 不需要恢复播放器，但**必须** `_resetDetachedWindowBridge()` 复位「已挂起」标志与事件订阅，否则复用的会话下一次脱离会带着错的基线 |

这三条是复核时补上的：前两条漏掉会让**主窗口一直黑屏直到会话结束**，第三条漏掉会让
**会话重启后的第一次脱离不被恢复**。

**视觉事实源**（不自由发挥）：关闭键 = 24×24 玻璃圆钮、底色 `0x52465B92` / hover `0x85465B92`、
1px `0x47FFFFFF` 描边、`iconClose` 14px —— 逐条取自 `web/src/styles/live.css:1065–1090`
与 `lib/widgets/live/live_mini_player.dart` 的 `_AylaMiniCloseButton`。
**有意差异**：关闭键内缩 6（不是 web 的 -10），因为 `WS_POPUP` 没有外扩面积，放外侧会被窗口裁掉。

## 三、用户可执行的验证步骤（agent 无法替代）

1. `cd Ayla/flutter && flutter run -d windows`（debug 热加载；本任务只做 debug 验证）。
2. 登录后进任意**正在直播**的直播间 → 点小窗上的「脱离应用」键
   （`live_mini_player.dart` 里关闭键左侧那个 24×24 键）。
3. 预期：
   - 屏幕**右下角**出现 360×202 的无边框窗口（距工作区右/下各 24），
     播放同一路直播，右上角有 24×24 玻璃关闭键；
   - 主窗口 App 内小窗消失、主窗口这一路播放器停止（不会双声道重叠）；
   - 该窗口**不进 Alt-Tab、不进任务栏**；点其他程序让它失去焦点后**仍在最上层**；
   - 把主窗口最小化，小窗**仍然可见**（这是本需求的核心）；
   - 另一端账号看「在看名单」，本账号**仍在**名单里（= 小窗也算观看人）。
4. 交互：点小窗**画面** ⇒ 主窗口被拉回前台、小窗关闭、主窗口重新起播（回到 App 内小窗/页面）。
   点小窗**关闭键** ⇒ 小窗关闭 + 主窗口重新起播。
5. 若第 3 步没有出现小窗：`flutter run` 的控制台会打印第二引擎日志；
   常见失败面是 `media_kit_video_plugin.dll` 未被注册（第二引擎注册那一步）或 HLS 地址
   过期（重开一次直播间即可）。

## 四、已知限制 / 未做

- **拖动/缩放独立窗口**：未做（任务里标为可选）。窗口固定 360×202 @ 右下 24。
- **悬浮球（ball）在 Windows 上仍返回 `"unsupported"`**：归 task-5，本任务只预留通道分支（不抛异常）。
- **热重载**：第二个引擎不参与 `flutter run` 的热重载（改 UI 需重启 App）。
- **release 未验证**：本任务只跑 debug 构建；release 下 `aylaLiveWindowMain` 依赖
  `@pragma('vm:entry-point')` 防摇树（已加），但没有跑过 release 构建验证。
