## 二、`AylaDirectoryFilters` 为什么是「范本之王」

它把 CSS 的动态语义完整翻译成了 Flutter 写法，其余组件遇到同类问题**照抄即可**：

| 文件位置 | 解决的问题 | 抄什么 |
|---|---|---|
| `:344–354` | `:hover` 是**每帧求值**的谓词，而 `MouseRegion` 只在指针移动时触发 | 记**索引** + 在 `build` 里求值 `_hoveredIndex == 选中索引` |
| `:356–366` | 胶囊在容器级 → 不继承按钮的 `:active` 缩放 | `_pressedIndex` + `GlobalKey<AylaNavHighlightState>` |
| `:405–424` | 高亮尺寸 = 按钮实测矩形，不能按等分推算 | `GlobalKey` + `addPostFrameCallback` + `localToGlobal(ancestor:)` |
| `:555–587` | 共享胶囊迁移 | `AnimatedPositioned`（300ms `[0,0,.58,1]`）外包 `AnimatedScale`（同步 `.98`） |
| `:527–550` | 「挂载即命中」：点击时 `:hover` 首帧已匹配，**不产生 transition** | `setSweep(true, jump: true)` |
| `:737–802` | 零透明必须**同色相**（透明黑插值会闪灰） | `color.withValues(alpha: 0)` 而非 `Colors.transparent` |
| `:805–829` | hover 阴影**不能裸用 `boxShadow`**（会染进内部） | `AylaGlassShadow.ring` + `AnimatedOpacity` |
| `:880–898` | 按压态上报 | `Listener.onPointerDown/Up/Cancel` → `onPressedChanged` |

## 三、组件库纪律

1. **复用优先**（用户三次点名）：先看整个组件库；没有实现才新增。
2. **看起来像但不完全一样** → **先想加档位，再想新建**；档位保留并在注释写明「当前用哪档 + 另一档为何存在」。
3. **不要凭印象关闭库内默认样式**：改任何参数前先读该参数的**默认值**与 **web 规定**。
   事故：我曾在底栏/群顶栏/顶栏三处凭空传 `showBorder: false`，把 1px 白边全关了。
4. **不要写死库内已表达的属性**：如 `TextStyle.height`（会破坏行高继承）。
5. 新增基础件前，先 `grep` 这些关键词确认无现成实现：
   `sweep` / `setSweep` / `AnimatedScale` / `onPressChanged` / `AylaNavHighlight` / `MouseRegion` /
   `AylaGlassShadow` / `AylaGlassInset` / `cssLinearGradient` / `AylaRevealItem` / `aylaOverlayEntry`。

## 四、易错点速查（写代码前扫一眼）

- `AylaIconData` **不是常量表** → 用 `aylaIconByName('iconX')!`；
- `AylaIcon` 颜色解析：显式 `color` → 祖先 `IconTheme` → `textPrimary`；**主题必须显式设 `iconTheme`**
  （否则 SDK 注入 `Color(0xDD000000)` 纯黑）；
- `StackFit.expand` 在无界高度下崩（`BoxConstraints forces an infinite height`）；
- `Center` 在**无高度约束**下会撑满父级（顶栏模块项因此 44→64）；
- `BackdropFilter` 必须配 `ClipRRect`/`ClipRect`（否则糊掉整块画布）；
- `OverlayEntry` 是独立子树 → 文本必须走 `aylaOverlayEntry` 兜底；
- 换 `MaterialApp.home` 不重建子树（测试改参数用 `StatefulBuilder`）。
