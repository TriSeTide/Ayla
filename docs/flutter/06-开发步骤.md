## 1. 总目标与验收定义

**目标**：用 Flutter 一比一复刻 Ayla Web 全部功能域与视觉（Y2K Frost），打包 Windows / Android / iOS 三端。

**验收定义（全部满足才算完成）**：

- P1 功能域：认证 / 群聊 / 私聊 / 语音房 / 直播（含开播台）/ 帖子 / 桌游（占位）/ 消息中心 / 搜索 / 收藏 / 个人页，全部可跑通
- P2 实时链路：chat WS 41 事件响应、语音双端通话（PoC-A 通过的延迟内）、直播三端可看（PoC-B 选定播放器）、presence 在线状态、红点实时刷新
- P3 视觉：四视口（375/768/1024/1440）双形态布局、玻璃材料体系、动效时长表、流体极光背景、reduced-motion 降级
- P4 平台：Windows 桌面窗口 + hover、Android 返回/安全区/音频焦点、iOS 安全区/原生全屏/音频会话
- P5 质量：可访问性（对比度/焦点/触达目标 ≥40px）、无崩溃、性能帧率达标（毛玻璃降级链生效）

**不包含（边界）**：桌游玩法本体（web 同为占位）；移动端后台推送与前台保活（03 §5 范围决策点，需用户拍板）；Windows 端 HLS 弱环的降级方案（03 §5 决策点）。

## 2. 两个 PoC（开工后第一个任务！决定架构，不能后补）

> 为什么先做：05 文档热点 1/2 是全项目仅有的两个"平台无现成等价物"的链路；选型结论决定 `lib/audio/`、`lib/player/` 与 `lib/runtime/` 的架构，M5/M6 前必须落地。

### PoC-A 音频 echo（WS 音频中继整链）

**目标**：本机打通「录音 → Opus 编码 → WS 发送 → 服务端回环（或本端自收）→ 解码 → 播放」，延迟体感可接受（目标端到端 <300ms 内可对话）。

**步骤**：

1. 确认服务端可用：`Ayla/backend/apps/voice/` 的 WS 音频中继通道（`/ws/voice/` 或 audio_relay 端口），用 web 端 `wsRelayRoom.ts` 的连接握手顺序对照（token 鉴权 + slot 分配）
2. 依赖选型：录音（record / flutter_sound）、libopus FFI（opus_dart / flutter_libopus，先验证 ABI 覆盖 android arm64/iOS arm64/Windows x64）
3. 采集链路：48kHz 单声道 PCM → 按 wsRelayRoom 的帧长（FRAME_SAMPLES）切帧 → opus 编码 → WS binary 帧上行
4. 播放链路：WS binary 帧 → opus 解码 → PCM 环形缓冲 → 低延迟播放（flutter_soloud 流式 / 原生 AudioTrack，二选一先验证延迟）
5. 验收检查点：
   - [ ] Echo 语音清晰可辨识，端到端延迟 <300ms（含网络）
   - [ ] 双端（Android 模拟器 + Windows 桌面）互听成功
   - [ ] 断线重连后成员状态恢复正确（slot 重新分配）
   - [ ] 抖动缓冲不爆音、卡顿率低（连续说话 30s 无中断）

**失败预案**：opus FFI 不可行 → 服务端转码（后端增加 PCM/Opus 转换的代价评估，需用户拍板）；播放延迟不可接受 → 评估原生 AudioTrack 通道（Android）与 AVAudioEngine（iOS）。

### PoC-B HLS 三端播放（直播链路）

**目标**：三平台各放一段 SRS 样例流（或现有直播频道），验证播放器选型、延迟体感、跳边、黑屏恢复。

**步骤**：

1. 样例流：SRS 推流端（OBS/ffmpeg）推一段测试流，确认 hls 播放地址可用
2. Android：video_player（ExoPlayer）验证 HLS 播放 + 延迟体感；测试 seek 到 live edge（refreshToLiveEdge 等价物）
3. iOS：video_player（AVPlayer）验证原生 HLS + 全屏/旋转行为（对应 webkitEnterFullscreen）
4. Windows：media_kit（mpv）验证 HLS；记录分包体积（mpv 运行库）与延迟
5. 黑屏自愈状态机：web 端事件驱动检测（waiting/stalled 2s + 冷却 4s → 重建）在 Flutter 播放器封装层复刻
6. 验收检查点：
   - [ ] 三端播放同一流成功，延迟体感接近 web 端（<5s 可接受，直播场景）
   - [ ] 跳边功能三端可用（seek live edge / 重建）
   - [ ] 推流中断后恢复不黑屏（事件驱动重建）
   - [ ] 全屏/旋转行为三端符合 03 §1 矩阵（Android 锁横屏 / iOS 原生全屏）

**失败预案**：Windows HLS 不可用 → 03 §5 决策点（降级方案由用户拍板）。

## 3. M0 基座 —— 工程 + 主题 + 路由 + 壳

**目标**：三端空壳可启动，登录流程跑通，视觉基座（极光背景 + 玻璃材料）就位。

**目录结构（建议，feature-first）**：

```text
lib/
├── main.dart / app.dart          # 入口：ProviderScope + MaterialApp + go_router
├── core/
│   ├── theme/tokens.dart         # 色值/圆角/间距/阴影 Tokens 类（05 §1 直接照抄）
│   ├── theme/app_theme.dart      # ThemeData + ThemeExtension
│   ├── theme/glass.dart          # GlassCard/GlassButton/GlassInput 基类（05 §2）
│   ├── net/dio_client.dart       # dio + 401 刷新拦截（互斥锁 + 重放一次）
│   └── ws/ws_manager.dart        # 四通道连接管理器骨架
├── router/                       # go_router 24 路由 + 守卫
├── pages/                        # 空壳页面
└── state/                        # Riverpod providers
```

**步骤**：

1. `flutter create` 三平台工程；pubspec 加依赖：flutter_riverpod / go_router / dio / web_socket_channel / google_fonts（或手打包字体）
2. Tokens 类落盘（05 §1 全表）；打包 Fredoka/Nunito/Space Grotesk 字体 + CJK 回退链
3. GlassCard/GlassButton/GlassInput 基类（05 §2.1/2.4/2.5）：材料参数 + hover/press 动画 + reduced-motion 开关
4. 极光背景：静态 LinearGradient 打底（动态流体背景 M7 再加，先静态不阻塞）
5. dio 客户端：Bearer 注入、401 刷新互斥锁 + 重放、错误归一（对齐 `api/client.ts`）
6. go_router：24 条路由 + ProtectedRoute 守卫 + `/` → `/group` 重定向；未登录跳 `/login?next=`
7. 双形态壳：AppShell（窄屏 BottomTabs 骨架 / 宽屏 TopNav 骨架 + 断点切换）；全屏预加载门（appInit 等价物）
8. 四通道 WS 管理器骨架：连接/心跳/重连/令牌预刷新（先通 chat 通道一个事件）
9. 验收检查点：
   - [ ] 三端 `flutter run` 启动无崩溃，极光背景 + 玻璃卡显示
   - [ ] 断点 375/768/1024/1440 下双形态切换无重建异常
   - [ ] 登录接口调用成功（token 存取 + 401 拦截路径正确）
   - [ ] chat WS 连接成功，收到任一事件（如 presence.status）不报错

**阶段验收**：三端空壳登录流程跑通；M0 完。
