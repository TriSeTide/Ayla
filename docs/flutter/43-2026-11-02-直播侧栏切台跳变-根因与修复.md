# 2026-11-02 Flutter 直播界面「侧栏切换直播间跳变」—— 根因与修复

> 用户实报原话：「修复 Ayla Flutter 直播界面侧栏切换直播间跳变的问题。参考 Ayla web」。
>
> 本文件记录**根因、证据、修法、验收**。代码事实源在 `Ayla/flutter/lib`。
> 相邻但**不重叠**的历史记录：`40-2026-10-29-直播全屏与小窗脱离`、
> `41-2026-10-31-Windows直播小窗脱离`、`42-2026-11-01-直播全屏拉伸与状态栏与返回键`。

## 一、现象与定位

用户报的是「侧栏切换直播间**跳变**」。按项目纪律先对照 web 读完全链，再把 Flutter 与 web
**逐条对齐**，而不是先猜是哪个动画参数不对。

对照之后发现：**根本不是一个动效参数问题，而是页面被整页重建了**。

| | web | Flutter（修前） |
|---|---|---|
| 侧栏切台的调用 | `navigate(\`/live/${id}\`, { replace: true })`（`LiveRoomPage.tsx:52–55`） | `context.replace('/live/$id')`（`live_room_page.dart` 的 `_goTo`） |
| 页面的身份 | `resolvePageKey(pathname)` 把 `/live/:id` 归一成 **`/live/room`**（`PageTransition.tsx:62–63`） | Page key = **路径字符串**（`app_router.dart` 的 `aylaRoutePage`） |
| 结果 | React 按类型复用同一个 `LiveRoomPage` 实例，只换 `useParams().channelId` | `/live/1 → /live/2` 换了 `ValueKey` ⇒ `Page.canUpdate` 判假 ⇒ **整条 route 被替换** |

### 1.1 证据（探针实测，非推测）

用一个临时 widget test 直接量 `State` 的 identity（路由用**真实路由表**，不是手搓 Widget）：

```
PROBE before count=1
PROBE after  count=1
PROBE sameState=false sameElement=false      ← 修前：整页重建
PROBE sameState=true  sameElement=true       ← 只改 page key 之后
```

### 1.2 这一下重建具体坏了什么（= 用户看到的「跳变」）

| 被销毁重建的东西 | 用户可见后果 |
|---|---|
| `LiveRoomPage` / `LiveStudioPage` 的 `State` | 会话、侧栏分页 `AylaPagedList`、名单弹层缓存全部归零（重拉一页目录） |
| `AylaLiveChannelRail` 的 `State` | 选中高亮的 `_highlightRect` 丢失 ⇒ 高亮**先消失一帧再瞬现**在新项，而不是 300ms 迁移 |
| `AylaLivePlayer`（平台视图 / texture） | 销毁重建 ⇒ 黑屏、重新起播、自愈状态机复位 |
| `_LiveRoomHeaderSwap` + `AylaRevealScope(replayKey:)` | 切台编排动效（旧头退出 → 新头进入 / 三块面板重播）退化成「整页重建」 |

> ⚠️ 这里纠正一处**容易被误判**的方向：`live_room_body.dart` 里那套切台动效
> （`AylaRevealScope` / `_LiveRoomHeaderSwap`，2026-09-28 交付）本身是**对的**、且与 web
> 逐条对齐；它在修前**根本没机会生效** —— 页面先被路由层重建了，动效 owner 连 State 都没留住。
> 所以本轮**不动**这两个件，只把路由层的页面身份补齐。

## 二、修法

### 2.1 路由层：页面身份归一（web `resolvePageKey` 的等价物）

`app_router.dart` 新增两个固定 Page key（与既有的 `kAylaGroupShellPageKey` 同一纪律）：

```dart
const LocalKey kAylaLiveRoomPageKey   = ValueKey<String>('ayla-live-room-page');
const LocalKey kAylaLiveStudioPageKey = ValueKey<String>('ayla-live-studio-page');
```

判定走 `shell_config.dart` 新增的两个纯函数（可单测）：

- `aylaIsLiveRoomPagePath` —— 只认 `/live/:channelId`（对照 `LIVE_ROOM_PATTERN`）；
- `aylaIsLiveStudioPagePath` —— 只认 `/live/start/:channelId`（对照 `LIVE_STUDIO_PATTERN`）。

`aylaIsLiveRoomRoute`（壳层沉浸路由判定）保持原语义，改为这两个的**或**，不改变既有调用方。

> ⚠️ `/live/start/:channelId` **必须**同样归一。web tsx 46–50 写明了不归一的后果：
> 开播台切频道会「新旧两页并存 → 旧页 cleanup 的 `liveSessionRuntime.leave()` 清掉新页刚
> 建立的会话 ⇒ 控制台退化成普通直播间且弹幕断开」（2026-09-06 事故）。

### 2.2 页面层：`didUpdateWidget` 就地换会话

页面不再靠重挂载换状态，于是「web `useLiveRoom` effect 的职责」必须由页面自己承担：

```
didUpdateWidget(channelId 变了)
  └─ _switchChannel(newId)
       ├─ 旧会话：removeListener → scheduleMicrotask(stop() → dispose())
       ├─ 新会话：_createSession(newId) → addListener → _session = next
       ├─ 名单弹层缓存（属于上一频道）：dispose + 置 null，按新频道重建
       └─ next.start()
```

**为什么是「完整销毁 + 重建」而不是 `detachView`**：web `liveSessionRuntime.enter()`
（`:179–255`）在切频道分支先 `this.leave()` 完整销毁旧会话；`detachView`（`:319–337`）
是「离开页面」的语义（窄屏直播中 ⇒ 进小窗），切台用它会弹出小窗。

**为什么旧会话的销毁必须排进 microtask**（本轮实测踩到）：`stop()` 的同步段就会
`liveStateProvider.clearCurrent()`，而本方法由 `didUpdateWidget` 调用 —— 那时正在 build
⇒ Riverpod 抛「Tried to modify a provider while the widget tree was building」。
这与 `dispose` 里把 `detachView` 排进 microtask 是**同一个坑**（该文件既有注释已登记）。
`start()` 的第一个语句就是 `await Future.delayed(Duration.zero)`，所以它可以在
`didUpdateWidget` 里安全发起。

### 2.3 数据投影：切台窗口期必须按 id 门控

切台后存在一个「旧会话已 `clearCurrent`、新会话详情未回」的窗口。此时若直接读
`live.currentChannel` / `viewerCount` / `viewers`，会把**上一个直播间**的数据显示在新直播间上
（同一类「跳变」）。按 web `LiveRoomBody.tsx:125–130` 的口径改为按 id 校验：

- `LiveRoomPage`：新增 `_channelOf(live)`（按 id 取，current 必须同 id）与 `_viewerOwnerId(live)`；
  人数/头像条只在 `viewerOwnerId == channelId` 时用 store 读数，否则退到 descriptor 快照值。
- `LiveStudioPage`：同款门控。
- 分享 payload 也改为按 id 取（原来直接读 `currentChannel`，切台窗口期会分享出**上一个**直播间）。

另外修掉一处真缺陷：`LiveRoomPage._ordered()` 原来是
`channelOf(widget.channelId) ?? currentChannel` —— 切台时 `currentChannel` 可能仍是旧频道，
会把**旧频道**当成当前项插到侧栏首位。web `LiveRoomPage.tsx:32–33` 只认同 id，已改为只读
`channelOf(channelId)`。

#### ⚠️ 切台窗口期的事实与直觉相反（审计纠正 + 探针实证）
第一版把 `_channelOf()` 写成 `channelOf(id) ?? current`，理由是「切台窗口期 `currentChannel`
为 null，退到目录快照避免头部退化成『直播间』」。**这个前提是错的**：

- 旧会话的 `stop()` 被排进 microtask（§2.2）；
- 新会话 `start()` 的第一个语句就是 `await Future.delayed(Duration.zero)`，
  `clearCurrent()` 在那之后才执行（`live_support.dart:383–433`）。

⇒ **切台首帧里 store 躺的是上一个频道**，既不是 null、也不是已清空。写成
`?? current` 就会把旧快照递给头部/分享 ⇒ 标题、封面、主播、来源标签先显示旧频道再跳
成新的 —— 正是用户报的「跳一下」。正确写法是 `return live.channelOf(id)`（拿不到就 null，
让头部走「加载中…」档）。探针实测首帧：`loading=false srs=live channel=null`
（`channel` 为 null 说明新写法生效且没有回落旧值）。

**同一窗口期的连带缺陷（探针实证，比原报告更严重）**：
`AylaLiveRoomSession.danmakuEntries()` 的回落是 `_history?.items ?? _live.danmaku`。
切台首帧 `_history` 还是 null、`_live.danmaku` 还是**上一个频道**的队列 ⇒ 旧弹幕被挂到
新频道的列表与飘弹幕层上。探针：`overlay=1 channelKey=2 items=3 bodyLoading=false`。
web 不留这个窗口（`enter()` 切频道分支**同步**先 `leave()` 清空 danmaku）。
已改为 `_fallbackDanmaku()`：仅当 `live.currentChannel?.id == channelId` 时用实时队列，
否则返回空。修后同一探针：`items=0`。

### 2.4 飘弹幕层：`channelKey` 接线

`AylaDanmakuOverlay.channelKey` 早在组件里定义了（「变化 → 基线重建 + 画面清空，切台无残留」，
对照 `DanmakuOverlay.tsx:101–149` 的 `useEffect(..., [channelId])`），但**生产调用点从来没传**
（只有组件自己的样张传了）—— `didUpdateWidget` 里 `old.channelKey != widget.channelKey`
恒为 false。已在 `live_room_body.dart` 的播放器 `children` 处补 `channelKey: widget.channelId`。

> **审计纠错（2026-11-02）**：本报告起初写「页面不再重建后，这条接线变成唯一生效路径，
> 不接就会残留旧弹幕」。该因果**不成立**：切台后新会话 `start()` 的同步段会
> `setCurrentLoading(true)`（`live_support.dart:431`）⇒ `children` 变 null ⇒ 本层
> **整件卸载重建**、`_seen` 自然归零。真正把旧弹幕带过窗口期的是**数据投影**的回落
> （见 §2.3 末段的 `_fallbackDanmaku`）。本参数的正确职责是「同实例内换频道时主动清基线」，
> 属双保险，不是唯一防线。

### 2.5 审计发现的三处「当前不可达但会错帧/锁死」的死角（已一并修）

这两条不是本次实报的直接原因，但都是「一旦条件成立就永久卡住」的类型，且修法极小。

**① 头部换台零行程锁死** —— `live_room_body.dart` 的 `_LiveRoomHeaderSwap.didUpdateWidget`：
退出用 `_c.reverse()`，而 `AnimationController` 在 `value == 0` 时 `reverse()` 是**零行程**，
不会派发任何 status 回调 ⇒ `_onStatus` 永不触发 ⇒ `_leavingChild` 摘不掉、头部锁死在旧内容。
正常路径到不了（`_c` 停在 1 或停在退出中），但 reduced-motion 切回、以及「退出刚播完
`forward(from:0)` 还没起第一帧就又被切台」能到达。修法：`value == 0` 时同步跳终态
（等价 `duration: 0` 档）。

**② 侧栏高亮不重试** —— `live_rail.dart` 的 `didUpdateWidget`：切台时
`_highlightRect = _slotRect(newId) ?? _highlightRect`，新槽位若**尚未挂载**（列表仍在加载、
新频道刚被置顶进列表）就量不到矩形，旧实现会保留旧矩形且**不再重试** ⇒ 高亮停在上一个
频道的位置，直到下一次 `currentId`/长度变化才纠正。修法：量不到时排一次帧后补测
`_measureHighlight()`。

**③ 收起 → 展开的一帧错位** —— 同一文件：`collapsed` 时整件 `return SizedBox.shrink()`
（高亮子树被拆），但 `_highlightRect` 仍留在 State 里 ⇒ 展开首帧按**收起前**的矩形画，
帧后才被 `_measureHighlight` 纠正。修法：`old.collapsed && !widget.collapsed` 时先把
`_highlightRect` 置 null（不按失效几何画），帧后重测补真值。

> 另有一条**按 web 现状有意不改**：`live_studio_page.dart` 的 `channel = live.currentChannel ??
> live.channelOf(id)` 与 `LiveStudioPage.tsx:28–29` 完全一致（web 也不校验 id）。
> 单边收紧会偏离 web 且让 `showOwnerPanel` 多翻一次，故保留原样。

### 2.6 独立只读审计的确认结论（同为本次交付的证据）

本轮同时派了一个**只读审计**（不写 `lib/**`）独立核对「in-place prop 更新」契约。
其确认项（每条均有 `文件:行` 依据，原文已并入本节后删除临时文件）：

| 件 | 结论 |
|---|---|
| Page key 归一机制 | ✅ SDK 依据：`Page.canUpdate` = `runtimeType == runtimeType && key == key`（`widgets/navigator.dart:762–764`），命中后只 `route._updateSettings` → `_ModalScope` 的 `_page = null`（`widgets/routes.dart:1115`）⇒ `buildPage` 重跑、**State 保留** |
| `AylaLiveChannelRail` 高亮 | ✅ 切台**不跳**：`currentId` 变时当帧取新槽位矩形，`AnimatedPositioned` 300ms 迁移 = web `layoutId`（`LiveChannelRail.tsx:67–74`）。两处死角已修（§2.5） |
| `_LiveRoomHeaderSwap` | ✅ 串行退出→进入正确；快速连切停在最新 identity、`_onStatus` 分支可达。零行程死角已修（§2.5） |
| `AylaRevealScope(replayKey:)` | ✅ 只重播**不重挂**；tick 经 InheritedWidget 在 build 前生效（`reveal.dart:228–236/723`），不会「先按旧进度画一帧」。范围与 web `mediaPanels` 三条 target 一致 |
| `AylaLiveViewerStrip` 名单缓存 | ✅ 页面切台时已重建控制器；弹层打开期间遮罩本就挡住侧栏，**不可达** |

审计另指出一条**有意不改**的项：`_replay` 用的是 `AylaRevealItem(fadeGlass: false)` ⇒ 只有位移、
没有淡入，而 web 的 WAAPI 关键帧是 `opacity:0 → 1`（含淡入）。这是 `reveal.dart:25–53` 已登记的
玻璃档取舍（Impeller 下对玻璃件整层 `Opacity` 会被拒），**不属本轮范围**，保持原样。

## 四、未自证项（按纪律交用户验收）

- **真机肉眼**：按 skill「预览职责边界」，agent 不代起/代看预览实例、不截图；
  用户自己 `flutter run`（debug 热加载）后在直播间**点侧栏切台**看这一组现象是否都消失：
  ① 不再黑屏/重新起播；② 侧栏高亮 300ms 迁移而不是闪一下；③ 头部旧头退出→新头进入；
  ④ 切台后侧栏列表不重拉（滚动位置保留）。
- **窄屏上下滑切台**：同一条归一规则生效（也是 `/live/:id` 之间），但手势路径未单独加断言。
- **群内直播** `/group/:id/live/:cid`：本来就是同一个 `GroupPage` 实例（`aylaIsGroupScene`
  已归一），本轮未改动；其切台走 `GroupLivePage._enterRoom`（自有会话换法）。
