# 2026-10 直播全屏 / 小窗脱离 根因与修复

> 用户实报五项。本文件记录**根因、证据、修法**，避免同类问题被反复调查。
> 代码事实源在 `Ayla/flutter/lib`；本文件只写结论与依据。

## 一、手机端直播全屏：点全屏后横屏显示直播间页面，随后回竖屏

### 现象
点直播间的全屏键 ⇒ 手机横屏、但显示的是**直播间页面**而不是全屏画面 ⇒ 随即回竖屏。

### 根因（两个叠加，都在「widget 类型在运行期变化」这一族）

**① 页面层：`AylaFullScreenSwipeBack` 被写成条件包裹**

`lib/pages/live_room_page.dart` 旧写法：

```dart
return narrow
    ? AylaFullScreenSwipeBack(onBack: ..., child: body)
    : body;
```

失败链：
1. 点全屏 ⇒ `AylaLivePlayer` 插 root Overlay + `SystemChrome.setPreferredOrientations(landscape)`；
2. 系统旋转 ⇒ MediaQuery 宽 > 768 ⇒ `narrow` 翻成 false；
3. 三元表达式返回**类型不同的 Widget**（`AylaFullScreenSwipeBack` → `body`）
   ⇒ Flutter 无法复用 Element ⇒ **整棵 subtree 销毁重建**；
4. `_AylaLivePlayerState.dispose` ⇒ `_fsEntry.remove()` + `_unlockOrientation()`
   ⇒ 全屏层被摘掉、屏幕解锁回竖屏。

**② 组件层（更隐蔽，`lib/widgets/motion/gestures.dart`）**

```dart
if (!on) return content;      // Transform
return GestureDetector(...);  // 类型不同！
```

即使照抄 web 的「恒挂载 + `enabled` 开关」形状，只要 `enabled` 翻转时返回的
**widget 类型变了**，子树照样被销毁重建 —— 只修页面层**不足以修复本缺陷**。
（实测：只改页面层时 `identical(stateBefore, stateAfter) == false` 仍然成立。）

### web 为什么没有这个缺陷
`web/src/pages/LiveRoomPage.tsx:66–75`：

```tsx
<FullScreenSwipeBack onBack={() => navigate("/live")} enabled={isNarrow}>
  <LiveRoomBody ... />
</FullScreenSwipeBack>
```

`<motion.div>`（`FullScreenSwipeBack.tsx:36–43`）**恒在**，`enabled` 只进
`useEdgeSwipeBack` 决定 handlers 是否生效 ⇒ React 始终复用同一实例。

### 修法
1. `gestures.dart`：恒挂 `GestureDetector`，禁用时把四个手势回调置 null，
   `behavior` 退回 `deferToChild`（禁用时不该吞掉整块区域的命中）。
2. `live_room_page.dart`：改为恒包 `AylaFullScreenSwipeBack(enabled: narrow, …)`，
   与 web 形状逐字对齐。

### 验证证据
- 修前：旋转前后 `identical(state)` = false，`退出全屏` 键计数 1 → **0**（全屏层被销毁）。
- 修后：`identical(state)` = true，`退出全屏` 键计数 1 → **1**。

### 同类风险（未逐一修，登记）
其他页面也有 `narrow ? AylaFullScreenSwipeBack(...) : child` 的写法：
`favorites_page.dart` / `game_support.dart` / `live_studio_page.dart` /
`private_chat_page.dart` / `profile_page.dart` / `voice_support.dart`。
它们在**路由切换**时才翻转 `narrow`，不像直播全屏那样**在同一页面内因锁横屏而翻转**，
故未表现出可复现缺陷；但同一模式仍是隐患 —— 后续改动若引入页内 `narrow` 翻转需一并改成恒包。

## 二、电脑端直播全屏：要真·全屏 + ESC 退出

### 根因
`AylaLivePlayer._toggleFullscreen` 只做两件事：插 Flutter root Overlay（**App 窗口内**铺满）
+ 移动端锁横屏。**桌面端从未让窗口本身进入全屏** ⇒ 用户看到的是「App 窗口内黑一下」。

### 修法要点（详见 task-1）
- `window_manager` 0.5.2 的 `setFullScreen`：纯 HWND 变换（`SetWindowLongPtr` 去
  `WS_THICKFRAME|WS_MAXIMIZEBOX` + `SetWindowPos` 到 `rcMonitor`），**同一个 engine**，
  不会重建播放器。ESC 由 Dart 的 `Shortcuts` 处理（插件本身**不处理** ESC）。
- 已知坑：从**最大化**状态进全屏后退出会永久留在 frameless ⇒ 退出后补
  `setTitleBarStyle(TitleBarStyle.normal)`。
- 已知坑：Win11 圆角在全屏时露出桌面 ⇒ `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE)`。
- 已知坑：`windows/runner/win32_window.cpp` 的 `WM_DPICHANGED` 会无条件 `SetWindowPos`
  ⇒ 全屏到不同 DPI 显示器会被拽出全屏 ⇒ 加 `is_fullscreen_` 守卫。

## 三、手机端直播小窗脱离应用（App 在后台也能悬浮看直播）

### 平台事实（已核官方文档，勿凭印象改）
- Android **PiP** 是唯一能在离开 App 后继续显示直播画面的机制。
  `android:supportsPictureInPicture="true"`；本工程现有 `configChanges` 已含官方要求
  的全部 token，**不需要改**。
- **`enterPictureInPictureMode()` 要求 Activity 处于 RESUMED**，从
  `didChangeAppLifecycleState` 调用必抛 `IllegalStateException` ⇒ 只能由 UI 手势触发；
  「按 Home 自动进 PiP」走原生 `setAutoEnterEnabled`（12+）/ `onUserLeaveHint`（26–30）。
- **PiP 期间 Flutter 只收到 `inactive`，不会 `paused`**（引擎：`onPause → appIsInactive`、
  `onStop → appIsPaused`；PiP 不触发 onStop）⇒ 弹幕 WS / 在看登记天然不断。
  **这就是「PiP 里也算观看人」能成立的机制**，不需要额外保活服务。
- 仍需守卫：某些 OEM 的 stashed PiP 可能真走到 `paused` ⇒ 生命周期处理里要问
  `aylaIsInLivePip()` 再决定是否 `aylaPauseLiveViewingForBackground()`。

- **iOS 明确不支持**：iOS PiP 只能承载 `AVPlayerLayer` / `AVSampleBufferDisplayLayer` 的画面；
  本工程视频走 Flutter texture（`video_player` 默认 textureView）⇒ 帧进不了 iOS PiP；
  且 App 进后台后 Flutter 停止出帧，任何「截 Flutter 画面喂系统」的方案在后台都黑屏
  （`pip_kit` 自述 experimental、`fl_pip` 有公开黑屏 issue）。⇒ 如实降级为 App 内小窗。

## 四、电脑端直播小窗脱离应用（独立置顶窗口）

### 根因
Flutter 桌面端**没有**「把 Widget 拆到独立 OS 窗口」的能力：一个 Flutter view 只能
铺满自己的窗口。所以「脱离应用」必须开**第二个顶层窗口 + 第二个 Flutter engine**。

### 前置阻塞（必须同时修，否则主窗口直播黑屏）
`media_kit_video` 2.0.1 有进程级单例：

```cpp
// media_kit_video-2.0.1/windows/media_kit_video_plugin.h:52
static MediaKitVideoPlugin* instance_;
```

第二个 engine 注册插件时**覆盖**它 ⇒ 静态 `WindowProcDelegate` 把
`kMainThreadTaskMessage` 派给错误的引擎 ⇒ **主窗口**的 `VideoController.create()`
永久挂起（上游 media-kit#1383，OPEN）。修法：改成按 HWND 查的
`std::unordered_map<HWND, MediaKitVideoPlugin*>`。落地方式与 `third_party/flutter_webrtc` 同族。

### 已验证的选型结论
- `desktop_multi_window` **不适用**：无 always-on-top / frameless / size API，
  `Create` 硬编码 `WS_OVERLAPPEDWINDOW` 800×600@10,10，无自定义 Dart entrypoint，
  子窗口不热重载（#318 OPEN）。
- 自写 `live_window.cpp`：`WS_POPUP | WS_EX_TOPMOST | WS_EX_TOOLWINDOW`，
  每个 HWND 转发 `FlutterDesktopViewControllerHandleTopLevelWindowProc`（否则键盘/IME 全废）。

## 五、悬浮球脱离应用

- Android：`SYSTEM_ALERT_WINDOW`（特殊权限，**无运行时弹窗**，只能跳
  `ACTION_MANAGE_OVERLAY_PERMISSION`）+ `TYPE_APPLICATION_OVERLAY` + 前台服务
  （Android 14+ 必须 `foregroundServiceType`）。**不要**复用现有 `dataSync` 下载服务
  —— Android 15 对它限 6 小时/24 小时。未授权必须返回 `permissionRequired` 并给引导，
  **不允许静默失败**。
- Windows：复用第四节的双窗口基础设施，开一个小的置顶窗体。
- iOS：**无 API** 可让自绘窗口压在其他 App 之上（Live Activity 只在锁屏/灵动岛）⇒ 不支持。
