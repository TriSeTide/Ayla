**A2 交付后的补修（2026-09-21，用户逐条验收指出，已提交 `89458a5` + 后续一轮）**：

1. **三组独立共享胶囊**：web 的 `selectionId-scene` / `-subgroup` / `-live` 是**三个各自独立的
   layoutId、可同时存在**；此前做成「全组件单实例」⇒ 父级（场景组）永远没有胶囊、子项收起时
   旧矩形被误用（用户：「父级选项卡没有，二级选项卡还窜到父级去了」）。
2. **胶囊 z 序**移到内容**之下**（web `z-index:-1`）；画在内容之上会盖住图标与文字。
3. 子群 / 直播间胶囊各套一层与**各自下拉同参数**的裁剪层 —— web 里胶囊是按钮子元素，被
   `.channel-subgroups` 的 `overflow:hidden` 裁住；卡片级单画会**超出视口**（用户实报）。
4. **扫光「挂载即命中」统一**：抽出 `_jumpSweep(kind)`（**排到下一帧**——点击那刻胶囊可能刚挂载、
   `currentState` 还是 null）；底部两项（帖子/桌游）此前漏了该调用 ⇒ 点击后**从左往右重播一次**
   才反向（用户实报）。5 处（场景/子群/语音房/直播间/底部两项）行为现已一致。
5. **帖子/桌游不再渲染浮层钮**（tsx 511–522）：`hasSecondary` 由 `_ => open` 改为 `=> false`，
   此前 ＋/三角盖住按钮右端 ⇒ 该区域 hover 只点亮行级 ⇒ **扫光不触发**。
6. **语音房「高亮移动动画」照 web**：`sharedLayout={false}` ⇒ 不做跨行共享迁移；高亮是
   `motion.li layout="position"` 的**子元素** ⇒ **随行一起位移**（Flutter 侧由行的
   `AnimatedPositioned(top: i × pitch)` 驱动）。同时**去掉一切自造入场淡入**（web 用
   `initial={false}`）—— 见 §6.13。
7. **点「直播」默认选中第一个直播间**；**「语音」保持不默认选中**（用户裁决：语音房有独立页面，
   必须手动点）。「聊天」保持默认选中第一个子群（tsx 451）。
8. 样张：语音房列表自持**活跃排序**演示（点某房 → 视为「有人进入」→ 排到最前，行平滑位移）。
9. **三角展开键常态不亮**：`.is-open` **只旋转**（web `group.css 874–876` 只有 `transform`），
   底色/字色**只有 `:hover` 才给**（883–886）。此前把 `is-open` 当 `activeState` 传 ⇒ 只要下拉
   展开三角键就常驻亮底（用户实报「常态时这里不高亮的」）⇒ 拆出 `rotated` 参数专管旋转。
10. **同一行的多个浮层钮分开高亮**：web 每个钮有自己的 `:hover`（`-voice-add:hover` 852 /
    `-voice-toggle:hover` 883），但**两者都联动词条底色**（878–881）⇒ 拆成
    `_hoveredRow`（行底联动）+ `_hoveredOverlay`（钮自身，身份 = `overlay:kind:id:slot`，
    `slot ∈ edit/add/toggle`）。此前两钮共用行级身份 ⇒ 悬停一个两个一起亮（用户实报）。

## 六、关键决策存档（历次讨论的结论，避免重复推导）

### 6.1 媒体上传（B5-6，2026-09-20）

- **二进制上传走后端中转**：`PUT /api/v1/media/uploads/{upload_id}`（后端 `UploadBinaryView`：
  `request.stream` 流式分块写临时文件、边写边校验累计大小、超限 413、再 `put_stream` 到对象存储）。
  web 走的是 `presigned_url` 直打 MinIO + 把绝对 URL 换成 `/minio` 走 Vite 反代；
  **Flutter 侧没有这条反代**（后端 `apps/media/urls.py` 无 `/minio` 路由，也没有 Vite），
  故改用后端专门提供的直传端点（该端点**需要** Authorization，与预签名直传相反）。
- **ASGI 不解析 chunked**（本项目已知坑）：上传必须携带确定的 `Content-Length` → 实现以
  `Uint8List` 作请求体（dio 自动写入）；若要改流式，必须显式设置 `content-length` 头。
- **视频海报**：web 用 `<video>` + `<canvas>` 抓 0.1s 帧（宽边 640 / JPEG q85）。Flutter 没有
  等价物（抓帧依赖平台视频解码）→ `AylaMediaUploader.uploadPoster(mediaId, jpegBytes)` 已就位，
  抓帧由 `core/media/video_poster.dart`（`media_kit` 截帧）承担，失败静默。
- `AylaMediaKind` 从 `post.dart` 抽到 `core/models/media_kind.dart`（`post.dart` 继续 re-export，
  既有 import 不变），使 `core/media/*` 不再依赖帖子模型。

### 6.2 分享族（B5-5，2026-09-20）

- **复用边界**：`.share-sheet-card` 与 `.privacy-sheet-card` 规格同源（`--glass-bg-strong` /
  blur24 sat1.4 / radius-panel 20 / `--glass-shadow-modal` / 窄屏 60dvh 贴底），直接复用
  `AylaModalCard`（调用处传 `maxHeight: min(80vh,720)`、`narrowHeightFactor: 0.6`、
  `narrowRadius: 20`、`scrollable: false`）。宽屏入场（framer-motion `opacity 0→1 + scale .96→1
  + y 12→0`，250ms `--ease-out`）以新参数 `wideEntrance` 入库，默认关闭。

- **选项卡不是滑动胶囊**：`share.css` 顶部注释写「单一选中胶囊 300ms 滑动」，但实现是每个 tab 自带
  `.is-active` 底（`--nav-active-bg` + `--glass-shadow-compact`，无边框、无扫光），tsx 也没有
  `.auroraqua-nav-highlight` 元素 → **按实现复刻，不按注释**。
- **关闭语义**：web `closedRef` → Flutter `_closed` 守卫；重复关闭只回调一次（已锁测试）。
- **画布里的弹层要用 `MediaQuery` 覆写视口**：断点/`60dvh` 读的是 `MediaQuery`，只用 `SizedBox`

  + `.share-sheet-body { flex: 1; min-height: 0 }` → 条目少时下方留白**属于可滚动区**，不是多余容器；
  Flutter 侧用 `Expanded`（窄屏 fixed 高）/ `Flexible(loose)`（宽屏内容高）对齐 `flex: 1` 语义。

### 6.4 溢出父边界的子元素收不到指针 → 浮层必须走 Overlay（2026-09-21，A1 实测）

`AylaServerRail` 的悬停置顶面板在 web 里是 `position: absolute` **溢出 rail 右缘**
（`group.css` 594–612）。Flutter 侧照做成 `Stack(clipBehavior: Clip.none)` 后：
**面板画得出来、`tester.getRect` 位置也对，但点不动**（`tester.tap` 报
"would not hit test on the specified widget"）。

根因是 framework 语义、不是实现 bug：`RenderBox.hitTest` 先判断命中点是否落在
**自己 bounds 内**，父级 bounds 之外的点不会向下递归 → 溢出区的子元素永远收不到指针
（CSS 的溢出元素仍可接收事件，两者语义不同）。

结论与纪律：

- Flutter 侧**任何溢出宿主边界的交互内容都必须走 Overlay**：`aylaOverlayEntry` +
  `Overlay.of(context, rootOverlay: true).insert(entry)`；库内范本 `conversation_more_menu`、
  `top_nav` 的浮层。位置改用 `GlobalKey` + `localToGlobal(ancestor: overlayBox)` 实测；
- 只解决**绘制**不够（`clipBehavior: Clip.none` 只保证画得出来）；
- 定位类问题的验证口径：看 `tester.tap()` 的 hit-test 警告与
  `tester.hitTestOnBinding(offset).path`（**第一项即最深命中目标**），
  比"widget 在不在树上"可靠得多。

### 6.5 Flutter `BoxDecoration(border:)` 不占布局 ⇒ 需要 1px 内边距补位（2026-09-21，A1 实测）

CSS 的 `border` 参与盒模型（`box-sizing: border-box` 下 `.server-rail` 内容区 = 72 − 2×1 = 70），
Flutter 的 `BoxDecoration(border:)` **只画不占位** → 列表宽 72（多 2px）、行右缘 71→72，
浮层锚点整体偏 1px。修法：`GlassSurface(padding: EdgeInsets.all(railBorderWidth))`，
补位后行宽 70、行右缘 = 71（相对 rail 外框），与 web 逐值一致。
**凡"容器有 1px 边框且内部有按边距定位的内容"都要检查这一条。**

### 6.6 预览 cell 溢出：定位方法与两处既有样张修复（2026-09-21）

用户预览日志报 `A RenderFlex overflowed by 889 / 4 / 16 pixels`。**定位方法（可复用）**：
写一个**临时探针 testWidgets**，把每个 public `@Preview` 函数按它声明的 `size` 包进
`SizedBox(cell)` 渲染一次，再读 `tester.takeException()` —— 一次就能列出所有报错的 cell
（本次 28 个 cell 里 3 处异常、2 处根因：`imageViewer`、`topNavWide`；`serverRail` 与画布本身都 OK）。
跑完即删；别靠肉眼在预览器里找。

两处根因（**都是既有样张问题，与本轮 ServerRail 无关**）：

1. **`image_viewer` 样张的舞台按 MediaQuery 视口算**（`image_viewer.dart:304–306`：
   `stageMaxW = vw*0.92` 上限 1200、`stageMaxH = vh*0.82`），而样张把它放进固定 520×560 的盒子
   ⇒ 预览宿主/画布视口越大、舞台越高越宽 → 底部溢出 889px、右侧 4px×2。
   修法：盒子加大到 520×680，并用 `Builder + MediaQuery.copyWith(size: Size(520, 680))`
   **覆写局部视口**（与「画布里弹层必须覆写 MediaQuery」同一条纪律）。
2. **`top_nav` 宽屏 @Preview 的 cell 高 140 不够**（顶栏 64 + 上边距 12 + 说明行 + 按钮行 ≈ 155）

### 6.8 自建 CSS sticky + 动态裁剪（2026-09-21，A2a）

Flutter 没有 `position: sticky`（库内此前零 `CustomScrollView`/`SliverPersistentHeader` 用法）。
ChannelSidebar 需要「三个场景行依次吸顶 + 语音/直播同时吸底 + 下拉内容随列滚动」，
自建方案（已落地）：

1. **滚动内容里只放行占位**（`SizedBox(height: 40, key: slotKey)`），行本体画在顶层
   `Stack` 的 `Positioned` 上；
2. **位置公式**（等价 CSS 的 top/bottom 双约束，**top 优先**）：
   `y = max(top, min(natural − scroll, viewportH − 40 − bottom))`
   —— 内层 `min` 做底吸附、外层 `max` 保证视口不足时停在 top。
   ⚠️ 写成 `min(max(follow, top), maxY)` 是**错的**（视口不足时返回 maxY、越过 top）；
3. **几何靠实测**：`GlobalKey` + `localToGlobal(ancestor: 内容 Stack)` 取占位与下拉的
   自然坐标，postFrame 同步（值变化才 setState）；
4. **滚动偏移用 `ValueNotifier<double>` + `ValueListenableBuilder`** 驱动浮层重建，
   避免整树 setState；
5. **动态裁剪**（`useSidebarContentClip` 等价，paint-only 不改布局）：
   `start = max(0, headerBottom + gap, dropdownDrawnTop)`、
   `end = min(viewportH, nextHeaderTop − gap, dropdownDrawnBottom)`，
   再换算成 `ClipRect(clipper: 自定义 inset)` 的 top/bottom；
6. 点击场景项「滚到自身吸顶位」= `animateTo(natural − stickyTop)`（web 是 scrollTo smooth）。

### 6.9 Flutter 没有 CSS `overflow: hidden` 的静默裁剪（2026-09-21，A2a 两次踩到）

web 里「固定高度容器 + 超高内容」是**静默裁剪**；Flutter 的 `RenderFlex` 会直接报
`A RenderFlex overflowed by N pixels`（黄黑条纹、测试失败）。出现场景与修法：

- **语音房下拉折叠**：折叠高度 = `min(3, n) × 31 − 1`，内容仍是全部行
  → 必须 `SizedBox(height:) + ClipRect + OverflowBox(maxHeight: infinity)`
  （行的**禁用**语义同样要对齐 web 的 `disabled/tabIndex=-1/inert` → `IgnorePointer + ExcludeSemantics`）；
- **画布样张里的长文本**：不加宽度约束的 `Text` 会把 `Row` 撑出画布（实测 736 可用宽溢出 5.2px）
  → 样张说明文字一律包 `SizedBox(width: 组件宽 + margin)`。

### 6.10 依赖「实测几何」的布局必须给测量开**追踪窗口**（2026-09-21，A2a 用户报错位）

**现象**（用户报）：展开/收起、展开更多/收起时**父级选项卡不动、内容错位**。

**根因链**（用临时探针逐帧打印几何定位）：
1. 场景行位置依赖**实测**的占位坐标（[_stickyY] 的 natural）；
2. 测量只在 `build` 里排队 → 「点击 → build（此时布局仍是旧的、测得值没变）→ 不 setState
   → 不再 build → **不再测量**」；
3. 而高度动画由 `AnimatedSize` 自己的 ticker 驱动，**只重绘自身、不触发父级 build**
   ⇒ 整个动画期间的几何停留在旧值（实测：收起子群后语音行一直停在 178 不回收；
   展开更多 303→364 能生效纯属偶然，因为那次有别的 setState 带了一次重建）。

**修法**：`_scheduleMeasure({int ticks = 0})` + `_measureTicks` 追踪窗口 ——
在展开/收起与「展开更多/收起」的 onTap 里开 30 帧窗口，测量末尾若窗口未耗尽就继续排队；
动画每帧都测（值变就 setState），稳定后窗口耗尽自然收敛。

**推广**：任何「位置/尺寸靠 `GlobalKey` 实测、且依赖 `AnimatedSize`/`AnimatedContainer` 等
隐式动画结果」的组件，都要开追踪窗口；只靠 build 排队会在**缩小的方向**上失效。
调试手法：临时 `debugPrint` 在测量入口打印几何 + 探针 testWidgets 分阶段 dump 行位置 ——
一次就能看出「哪一帧开始没测」。

### 6.11 「同一帧」定位：把依赖布局结果的定位放进 `paint`（2026-09-21，A2a 用户报穿透）

**现象**（用户报，承接 §6.10）：会动了，但**响应比子列表慢** —— 子列表已到位、选项卡还在动，
出现穿透。要求「子列表和父级选项卡一块移动」。

**根因**：追踪窗口只保证「每帧都测」，但测量本身是 `postFrame`（layout **之后**）→ 行位置
永远用**上一帧**的几何；而 `AnimatedSize` 的本帧 layout 已经把子列表摆到位 ⇒ 恒定落后一帧。

**解法**：`_StickyRowLayer`（`SingleChildRenderObjectWidget` + `RenderProxyBox`）——
把行的定位从 build 搬到 **paint**：`paint` 里读占位相对视口的 `localToGlobal`（本帧 layout 已完成）
→ 算 clamp 后的 y → `context.paintChild(child, offset + y)`。**零滞后、与内容同帧。**

三个必须一起做的细节（每个都实测踩过）：

1. **`performLayout` 要自己写**：层用 `Positioned.fill` 铺满视口（命中测试要覆盖），
   但若沿用 ProxyBox 默认布局，tight 约束会把 40px 的行**拉伸到视口高**
   （实测 `child=Size(244,443)`）→ 位置与命中全错。正确：`size = constraints.biggest` +
   `child.layout(BoxConstraints.tightFor(width: size.width))`。
2. **必须覆盖 `applyPaintTransform`**（与 paint 用同一偏移）：否则 `localToGlobal`、
   命中测试、语义树、测试里的 `getRect`、可见性判断读到的还是**布局**坐标（y=0）。
3. **每次 widget 重建无条件 `markNeedsPaint()`**：层的位置取决于**外部**（滚动内容里的占位）
   的移动，占位移动不会让本层 markNeedsPaint（属性 setter 的 identical 比较会跳过）
   → 实测「内容在动、行不动」。

**验收判据**：动画每一帧「行 ↔ 其下拉首行」的距离恒定（实测全程 `gap=42`）。

### 6.12 预览宿主（Flutter web / CanvasKit）**不认系统字体** → 中文全方框（2026-09-21）

### 6.13 选中底**不许有过渡** + 零透明必须用**同色相**（2026-09-21，用户报「高亮块出现和消失有一段灰色过渡」）

**现象**：各种横向/纵向选项卡在选中态切换时，高亮块「出现/消失」拖着一层**灰**，拖沓且脏。

**两个机理叠加**：

1. **渐隐渐显**：web 里 `.has-auroraqua-highlight:is(.is-active, .active) { background: transparent }`
   是**瞬时**的 —— 选中瞬间底色直接交还给共享高亮块（挂载即出现、卸载即消失，
   `AuroraquaNavHighlight` 还带 `initial={false}`）；而组件库给这个底色变化套了
   `AnimatedContainer(200–300ms)` ⇒ 高亮块「渐显」出来 ⇒ 拖沓。
2. **透明黑插值**：`Colors.transparent` 是 `0x00000000`（**透明黑**）。Flutter 的 `Color.lerp`
   是**逐通道直插**（不按 alpha 加权），从 `.18 冰蓝` 插到透明黑的中途是 `rgb(118,120,121)`
   **中灰**；CSS 用 premultiplied alpha 插值（色相不变）故 web 无此现象。
   ⇒ 零透明一律写**同色相**透明（如 `ice500.withValues(alpha: 0)`）。

**统一口径**（已全库扫过一遍）：

- **选中态**（底色交还高亮块）⇒ `duration: active ? Duration.zero : <原时长>`；
- **hover 底色**保留 web 声明的过渡（导航组 300ms / 筛选 200ms / 图标钮 180ms）；
- **零透明**一律同色相（组件内可设常量，如 ChannelSidebar 的 `_SidebarZeroTint.hover`）。

**改动清单**：`AylaChannelSidebar`（场景项 + 子群/语音房/直播间行共 4 处 + 新增 `_SidebarZeroTint`）、
`AylaTopNav`（模块选项卡选中底 300ms→0；图标钮圆底零透明改同色相）、`AylaDirectoryFilters`
（选中态 200ms→0）。`AylaSegmentedTabs` / `AylaBottomTabs` / `AylaGroupTopTabs` 本来就无背景过渡
（不用改）；`AylaShareSheet` / `AylaPrivacySheet` / `AylaMenuItem` / 会话更多菜单早已用同色相。

### 6.14 同一行有多个浮层钮时，hover 必须**分成两层**（2026-09-21，A2 补修）

**现象**：聊天/语音/直播行右侧有 **＋ 与 三角**两个钮，悬停任一个**两个一起亮**（用户实报）。

**根因**：两个钮共用**行级** hover 身份（`_Selection('scene', 场景名)`）⇒ `hovered` 判定同时命中。

**web 的事实**（`group.css`）：
- 钮自身：`.channel-scene-voice-add:hover`（852）与 `.channel-scene-voice-toggle:hover`（883）
  —— **各自独立**；
- 行底色：`.channel-scene-row:has(.channel-scene-voice-add:hover) .channel-scene,
  .channel-scene-row:has(.channel-scene-voice-toggle:hover) .channel-scene { background: .18 }`（878–881）
  —— **任一钮 hover 都联动**。

⇒ 必须拆成**两个状态**：
- `_hoveredRow`（**行级** → 联动词条底色）；
- `_hoveredOverlay`（**钮自身** → 该钮底 `.3` + 主色图标），身份 = `overlay:<行kind>:<行id>:<slot>`，
  `slot ∈ { edit, add, toggle }`。

### 6.15 展开/打开态（`.is-open`）**不得**点亮底色（2026-09-21，A2 补修）

**现象**：三个场景行的三角展开键在**常态**下常驻灰蓝底 + 深色图标（用户实报「常态时这里不高亮的」）。

**根因**：`_buildOverlayButton` 的底色判定是 `hovered || activeState`，而三角键把**展开态**当成了
`activeState` 传进来 ⇒ 只要下拉展开就亮。

**web 的事实**：`.channel-scene-voice-toggle.is-open { transform: translateY(-50%) rotate(180deg) }`
（874–876）—— **只有 transform**；底色与字色**只有 `:hover` 才给**（883–886）。

⇒ 拆参数：`activeState`（`.is-active` → 点亮底色；**只有编辑笔**用）与
`rotated`（`.is-open` → **只旋转 180°**）。

> **通用教训**：CSS 里 `.is-open` / `.is-active` / `:hover` 是**三种不同状态**，
> 常被合并成一个 bool 传参 —— 迁移到 Flutter 时必须逐条对照选择器，
> 尤其「展开态只改 transform/几何、不改颜色」这一类。

### 6.16 Dart `List.sort` 不是稳定排序（2026-09-21，A2a）

web `sortSubgroupsByActivity` 依赖「并列保持列表原序」；Dart 的 `List.sort` 是**不稳定**的
→ 必须显式带原索引做二级比较（`return a - b`），否则 UI 顺序会漂移。

### 6.17 频道侧栏重做（A2）实现期新踩的 5 个坑（2026-09-21，供后续 agent 直接复用）

第一版失败点（坑 1–9）见 `15-重做频道侧栏-启动提示词.md`；**重做版新踩**的是下面这些：

1. **`localToGlobal` 不能在 `performLayout` 里调**：sticky 行的位置要读兄弟子树（占位）的坐标，
   而 layout 期间兄弟可能尚未布局 → `RenderBox.size accessed beyond the scope of resize`
   （实测：行层 `performLayout` 里算 y 直接崩）。**位置一律放 `paint`**（本帧 layout 已完成），
   `performLayout` 只负责 `size = constraints.biggest` + `child.layout(tightFor(...))`。
2. **裁剪层的坐标基准必须统一**：下拉裁剪层挂在滚动内容的 `Column` 里，`paint(offset)` 的
   `offset.dy` 是**相对 Column** 的坐标，而 `rowTop()`/视口 rect 是**相对卡片**的坐标 →
   混用会把 `topInset` 算成 63px（实测：下拉被裁到只剩 4px，点击全失效，`tester.tap` 报
   "would not hit test"）。修法：`localToGlobal(Offset.zero, ancestor: cardBox).dy` 统一基准。
3. **裁剪必须同时作用于命中**：web 的 `clip-path` 会裁掉指针命中区（被吸顶行盖住的内容点不到）；
   只做绘制裁剪会让「已被盖住」的按钮继续吃掉点击。`_DropdownClipRender.hitTestChildren`
   要按裁剪矩形过滤。**几何未就绪（`rowTop() == null`）时不裁剪** —— 按 `selfTop` 兜底会凭空
   裁掉顶部 44px，把首屏内容一起挡掉。
4. **GlobalKey 指向的行会在同帧失活**：收起子群会移除追加段里的行 → 该 key 的 element 变
   inactive/DEFUNCT，`findRenderObject()` 抛 "Cannot get renderObject of inactive element"
   （实测：胶囊层 paint 崩）。统一走 `_renderObjectOf(key)`（`mounted` + `try/catch` 双保险）。
5. **自绘浮层必须显式标脏**：自绘 RenderObject 的属性 setter 不会自动重绘/重排
   （`_StickyRowRender` / `_DropdownClipRender` 的位置与裁剪都依赖外部几何）→ 属性变化后
   要 `markNeedsPaint()`；另外首次 layout 完成后补一次（首帧 paint 可能早于兄弟子树 layout）。
6. **共享胶囊一律照范本，不要自研定位层**（用户 2026-09-21 点名）：第一版重做时我写了
   paint 定位 + 时间戳插值的自研层，被指出「应该参考组件库现有成功范例，或复用」。
   正解 = `AylaDirectoryFilters` 555–587 那套：**容器级单实例 `AylaNavHighlight`**
   + `GlobalKey` **实测选中按钮矩形**（`_measureCapsule()`，每次 build 排队 + 滚动/动画
   期间每帧重排）+ `AnimatedPositioned`（300ms `--auroraqua-ease-out`，等价 Framer `layoutId`
   的跨项迁移）+ 外层 `AnimatedScale(.98, 200ms)` 同步按压。**尺寸也来自实测**（不按组推算）。
7. **画布/预览样张必须可交互**（用户 2026-09-21 点名「没做交互」「父级/二级选项卡都要交互」）：
   组件是受控的（`activeScene`/`activeSubgroupId`/… 都是外部传入）→ 样张只摆固定参数就是
   **死的**。正确做法：样张内嵌一个 `StatefulWidget` 宿主自持选中状态并在回调里 `setState`
   （`_SidebarDemo`），这样预览/画布里点一级场景项、点子群/语音房/直播间行、点三角展开、
   点笔进编辑态都能真实响应（高亮迁移 / 扫光 / 按压全部可见）。

**测试侧**同样两条：`previewScope` 的 `Overlay(initialEntries:)` 只在首次创建生效 →
同一 `testWidgets` 里改参数必须用 `StatefulBuilder`（否则读到旧参数）；
`SemanticsHandle` 必须在测试体内 dispose（`addTearDown` 晚于框架校验）。

**回顶钮判定**（tsx:18–21 / 43–49）：滚动源必须是**主滚动容器**（`scrollHeight > clientHeight`
且 `clientHeight ≥ 40% window.innerHeight`）且 `scrollTop > window.innerHeight` 才浮入。
Flutter 等价：`viewportDimension` ↔ `clientHeight`、`MediaQuery.size.height` ↔ `window.innerHeight`；
滚动源取「注入 `controller` 优先，否则最近祖先 `Scrollable`」（web 用 document capture 监听任意容器，
Flutter 无全局 scroll 事件 → 两种装配都要覆盖）。`behavior: "smooth"` 浏览器无显式时长 →
与库内 ChannelSidebar 口径统一 **300ms ease-out**；reduced-motion → `jumpTo(0)`（= `"auto"`）。

**无回调 ≠ 禁用**：`RefreshFab` 的 `if (!fn) return` 是「点击无动作」，按钮外观 / hover 照常 →
**不能**传 `onPressed: null`（那会走 `.55` 禁用外观）。

#### 三个 Flutter 语义坑（本次实测，后续同类组件直接复用）

1. **`ScrollPosition.viewportDimension` / `.pixels` 在首帧 layout 之前是 null**——
   在 `didChangeDependencies`（或任何 layout 前）读会抛
   `Null check operator used on a null value`（栈指向 `scroll_position.dart` 的 getter）。
   → 用 `hasViewportDimension` / `hasPixels` 守卫，并把首轮计算排到 **postFrame**。
2. **`didChangeDependencies` 里 `setState` 会让 `_MediaQueryFromView` 的依赖断言失败**
   （实测 `'check that it really is our descendant'`）——首帧 `MediaQuery` 正在 `notifyClients`。
   → 首轮不要 setState，统一 `addPostFrameCallback`。
3. **`ScrollController.attach()` 不会 `notifyListeners`**（它只把 `notifyListeners` 挂到 position 上）
   → 首帧列表往往尚未 attach、`positions` 为空，滚动源绑不上 → build 里补一次 postFrame
   兜底绑定（`_bindSource` 幂等，绑上后不再排队）。

#### 测试侧三条

- `find.ancestor(of: X, matching: find.byType(Positioned))` **找不到** `StatelessWidget` build 返回的
  `Positioned`（build 结果是它的**子树** → 用 `descendant`）；而 `descendant` 又会连带命中
  `AylaCornerFab` 内部的 `Positioned.fill` → 用 `find.byWidgetPredicate` 锁「属性唯一」或
  「`child` 类型」最稳（`w is IgnorePointer && w.child is ExcludeSemantics`）。
- 同一个 `testWidgets` 里第二次 `pumpWidget` 改参数**不生效**（`previewScope` 的
  `Overlay(initialEntries:)` 只在首次创建生效）→ 换参数一律另开测试。
- 计时/半贴类断言用 `await tester.pump()`（**不带时长**）：既重建状态、又不推进时间；
  带时长会把短延时的计时器推进到再次触发（第一版就这么被坑）。

### 6.20 PostCard 头部折行修复：CSS flex 的 `min-width: auto` + `overflow` 语义差（2026-09-21）

**现象**：`post_card_test` 的「常规卡（360）+ 2 标签 → 时间与标签同排单行」长期失败
（`Wrap` 实测高 46，期望 < 30）。**不是新引入的回归**，是既有失败。

**探针实测**（卡片 360 / 内容区 328）：
- 时间 = `aylaPostCardTime(...)` = **「2026/9/20」108px**（>24h 走 `toLocaleDateString`，与 web 同源）；
- 标签「公开」38 +「深夜电台」60；
- ⇒ 右侧组自然宽 = 108 + sp3 12 + 38 + sp1 4 + 60 = **222**。

**根因**：`post_card.dart` 里 `nickReserve = 64`（注释写「昵称最少保留 4 个汉字」）把右侧组上限压到
`328 − 53(头像+halo+gap) − 12 − 64 = 199 < 222` ⇒ 标签折行。

**web 的真实语义**（本轮关键教训）：

```css
.post-card-nick { overflow: hidden; text-overflow: ellipsis; white-space: nowrap }
```

CSS flex 规范：**`overflow` 非 `visible` 的 flex item，其 `min-width: auto` 解析为 0**
⇒ 昵称可以被压缩到 0（ellipsis 兜底），而 `.post-card-tags`（无 `overflow:hidden`）的
`min-width: auto` = min-content = 最长标签宽 ⇒ **要保住完整宽度的是标签组，不是昵称**。
Flutter 没有这套自动最小尺寸，必须手工把「该保谁」写对。

**修法**：`nickReserve` 64 → **0**（昵称仍由 `Flexible` + `TextOverflow.ellipsis` 兜底 ⇒ 不会溢出）。
复验：`Wrap` 高 **21**（单行）、两标签 y 一致、右缘贴齐内容右缘；窄卡（220）时上限 123 ⇒
标签组内部兜底折行且不溢出（既有「极端窄卡 + 4 长标签」测试仍通过）。

**基线**：全量 `flutter test --concurrency 1` → **300 通过 / 0 失败（全绿）**。

> 同类排查提示：凡「CSS flex 一行里有一项带 `overflow:hidden` + 一项带 `flex-wrap`」的结构，
> 折行优先级都如上 —— 先压带 `overflow:hidden` 的（可到 0），最后才让可 wrap 的那组折行。
