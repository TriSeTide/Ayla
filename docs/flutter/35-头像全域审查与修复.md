## 二、三处根因与修复（「之前为什么不实时、现在为什么实时了」）

### A. 换头像不热更新

**之前为什么不更新**：
```
后端 PATCH /me/profile/ ──► _broadcast_user_updated() ──► WS 帧 user.updated
                                                              │
                                    presence_ws.dart:181-193 ──► AylaPresenceState.applyUserProfile()
                                                                          │
                                                                    _profiles[id] = patch  ✅ 存下来了
                                                                          │
                                                          profileOf(id) ──► ❌ 全仓零处调用
```
`AylaAvatarHalo` 只读构造参数 `resourceUrl`（REST 快照），所以整条链路**断在最后一米**。

**现在为什么实时**：组件在**已有身份**（`user` 或 `userId`）时，用同一个 `ListenableBuilder`
（原本只驱动光环颜色）同时驱动三样东西：
```dart
return ListenableBuilder(
  listenable: presence,                    // ← ChangeNotifier 本体，帧来即重建
  builder: (_, __) => _buildBody(
    context,
    _computeOnline(presence),              // ① 光环颜色
    patch: _profilePatch(presence),        // ②③ 资料覆盖（头像图 + 昵称）
  ),
);
```
**为什么改一处就覆盖 22 个点**：22 个点全部已传 `user:` 或 `userId:`（见上表），
覆盖层在组件内解析 ⇒ 无需逐点改 `resourceUrl` 实参。

**关键设计决策（3 条，均有回归锁）**：
1. **空串 = 权威「没头像」**，不回退旧 URL —— 否则用户删掉头像后别人仍看到旧图；
2. **无身份（群头像）完全不受影响** —— 用户资料帧不能改群头像；
3. **昵称也走覆盖层** —— 换昵称同样热更新（首字 / 语义标签 / tooltip 同步）。

### B. 群聊光环「状态错误」

**之前为什么错**：这不是颜色计算错，而是**头像整个不渲染**：
```dart
// 修复前 message_bubble.dart:571-573
final bool showSenderHalo = !recalled && !msg.isSystem &&
    (widget.senderAvatarLabel != null || widget.senderAvatarUrl != null);
```
`senderAvatarLabel` / `senderAvatarUrl` 都来自 `message_list.dart` 的 `_memberAvatars`
= `widget.conversation?.members`（**REST 快照**）。两种常见情形下双双为 null：
- ① 成员表**尚未加载**（冷启动直链进群 / 手机慢网）；
- ② 发送者**不在成员表**（历史消息里已退群的用户）。
⇒ 头像整块消失。用户看到的「光环状态错误」实际是「根本没有头像」。

**现在为什么对**：判据加 `senderId != null`（`senderUserId ?? senderUser?.id`）——
「只要知道发送者是谁就画头像」；文字回退链 `senderAvatarLabel → senderName → '发送者'`；
图片 URL 由 `resourceUrl` + 覆盖层决定。同时 `message_list` 改传**完整用户对象**
（新增 `_memberUsers`），让气泡头像同时具备 presence 订阅 + 资料覆盖。

### C. 直播标题栏没有头像图片

**之前为什么没有**：`GET /live/channels/` 的描述符只有 `owner_id` / `owner_nickname`，
**没有 `owner_avatar`**；web `LiveHostAvatar.tsx:24-48` 用 `ensureUser(ownerId)` 懒拉用户资料。
Flutter 侧把这件事「推给页面」，而**三个直播页面都没有做** ⇒ `avatarUrl` 恒为 null ⇒ 永远首字。

**现在为什么有**：新增 `AylaUserDirectory`（`core/api/users_api.dart`），与 web `ensureUser` 逐条对齐：
| 能力 | web | Flutter 本轮 |
|---|---|---|
| 缓存同步命中 | `getCachedUser` | `AylaUserDirectory.cached(id)` |
| 写入缓存 | `cacheUser` | `put(user)` |
| 单飞懒拉 | `pending` Map | `_pending` Map |
| 失败静默 | `.catch(() => null)` | `.catchError(... return null)` |
| 并发去重 | 同 id 只发一次 | 同 id 只发一次 |

`AylaLiveHostAvatar` 改为 `StatefulWidget`：`initState` 先查缓存（无闪烁）再懒拉；
`didUpdateWidget` 在 `userId` 变化时重置；拉到后 `setState` 填 `avatarUrl` + `hostNickname`。
并且因为传了 `userId`，**换头像 / 换昵称也会随 `user.updated` 覆盖**（与 A 共用同一机制）。
