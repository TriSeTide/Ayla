## 一、通用根因形态（本次复核口径）

| 形态 | 判定方法 | 本次命中 |
|---|---|---|
| ① 数据源错位 | 页面渲染的是**页面私有快照**（`AylaPagedList` / 局部 `setState` 数组），而 WS 帧只写**共享 store**（`chatState` / `messageState` / `socialStore` / `directoryStore` / `postsStore`） | R3 / R5 |
| ② 帧/事件订阅缺失 | 页面没有 `onFrame`，或只处理部分帧类型，或注册在页面生命周期上（切 tab / 卸载后失效） | R1 / R2 |
| ③ 副作用缺失（新增） | 写操作成功后**不做本地落库**，完全依赖 WS 回环；WS 未连/慢时界面不正确 | R6 |

> ⚠️ 形态 ② 在 Flutter 里有一层额外风险：页面级 `onFrame` 随 `dispose` 注销（`chat_ws.dart:592-594` 的 handler 集合是实例字段）。只要数据只在页面上有，卸载即丢最新状态。**凡是跨页需一致的数据必须落在模块级 store**。

**R1 完整根因链（好友列表不热更新）**

1. 对方同意好友申请 → 后端 `broadcast_group_request_resolved` / 好友模块发 `friend.request.resolved` 至 `chat_user_<id>`（后端 `apps/chat/consumers.py:495-506`）。
2. Flutter `chat_ws` 收到并 push notice + `badges.fetch()`（`chat_ws.dart:553-560`）→ **好友列表本身不刷新**。
3. 页级 `onFrame` 判 `aylaIsAuthRefreshFrame(type)` 为真 → 调 `_loadRequestsTab()`（`messages_page.dart:158`）。
4. `_loadRequestsTab()` 只 refresh `_friendRequests / _invites / _joinRequests / _leaveNotices`（`messages_page.dart:255-261`）—— **`_friends` 不在其中**。
5. 而 `_friends` 只在 `_ensureFriendsTab()` 里 `load()` 一次（`messages_page.dart:229-233`），该方法由 `_onTabChanged` 调（`messages_page.dart:263-267`），**只建不复取**。
6. ⇒ 用户停在「好友列表」tab 上，对方通过好友申请后，**列表永远不出现新好友**，除非退出重进消息中心或点页脚刷新。
7. web 侧 `loadFriendsTab` 的第 0 路就是 `friendsPage.refresh`（`MessagesPage.tsx:83,88-90`）⇒ 这是**移植遗漏**，非 web 同款缺口。

> 同一缺口在**宽屏左列**重复一次：`chat_support.dart:1042-1050` 的 `onFrame` 同样只 refresh 4 路，`_friends`（`chat_support.dart:1017,1108-1112`）不刷。web `WideMessagesSidebar.tsx:111-113` 的 `loadFriendsTab` 是 5 路。
> **修复方向**：把 `_friends` 纳入认证帧刷新（同 `_loadRequestsTab` 加 `unawaited(_friends?.refresh())`），或改读 `aylaSocialStore` 的 `friends` record（与 web 真正同构）。

**R2 完整根因链**

1. 用户在**帖子详情**（或直播卡/语音卡/桌游卡/消息气泡）点收藏 → REST 成功 → 后端 `favorite.changed` 广播到 `chat_user_<id>`（`apps/chat/consumers.py:385-393`）。
