> **为什么有这份**：用户指出「组件库视觉组件都没做完吧。搜索域和个人主页域群内各种独立页面什么的，
> 审一遍啊，虽然复用组件多，但也不能漏」。
> 之前两轮清点只对了 `web/src/components/**` 与 `web/src/layout/**` 的**导出名**（149 个）——
> **页面文件（`web/src/pages/**`）里内联的视觉件从未审过**，那部分正是这份文档补的。
>
> **审查方法**：逐页读 JSX 结构 → 抽出「本页自有类名」（排除 `btn`/`field`/`icon-btn-40`/`skeleton` 等基元）
> → 对照 Flutter 库（`18-组件库清册.md` + `grep lib/`）判定「已覆盖 / 缺 / 属页面装配」。
>
> **结论**：页面大多是「**Directory 目录页骨架**（`directory-*` 筛选 + 内容 + `home-load-more`）+ 域名自有件」；
> 骨架与筛选已覆盖（`AylaDirectoryFilters` / `AylaDirectoryLoadMore` / `AylaAsyncState`），

#### 11.9.1 用户第二轮反馈：**不是「下移上移」，要「自适应均匀分布」**（2026-09-28）

要**间隙本身按相邻组件均分**。

**改法**：卡片子项**改为平级**——`ProfilePage` 不再把 `identity + avatarActions` 打包成一个 Column
（打包会让 `space-between` 只能在那**一处**分配），而是三个平级子项

`UserProfilePage` 本来就是平级（identity / 签名 / relationActions）⇒ 天然一致。

**实测**（视口 1440×1000，测试打印）：
| 量 | 值 |
|---|---|

| 下半区间隙（avatar-actions ↔ form） | **233.5**（严格相等 ⇒ 均匀） |
| 操作区到卡底 | 18（沉底，首尾不留白） |

（`(upperGap - stretched).abs() < 2`）—— 若有人再把区块打包成一组（空隙集中成一处），这条会立刻红。

**⚠️ 口径说明（避免后人照抄 web 的打包写法）**：web 侧 `.profile-side .profile-card { flex: 1 0 auto }`

#### 11.9.2 用户第三轮反馈：**「我说这一整块上下均匀」**（2026-09-28）

第二轮只让**卡片级**两个间隙均分（各 233.5），用户随即指出：红框圈的是**整块** ——
头像行下方到卡片底（三按钮 / 在线状态 / 昵称 / 个性签名 / 向他人展示内容 / 保存+退出）
都要上下均匀。而 `AylaProfileForm` 是一个整体子件，`space-between` 在卡片级分配时
**拿不到份额** ⇒ 多余空间只会落在卡片级那两处。

**改法**：新增布局原语 `_EvenFillColumn`（`widgets/profile/profile_card.dart` 内的
`MultiChildRenderObjectWidget`，非公共视觉件）——
把「可用高 − 各子项自然高」的**多余高度**按**间隙总数**均分给两类间隙：
① 卡片级相邻子项之间的 `n − 1` 个；② **可伸展子项内部**的 `stretchChildInnerGaps` 个
（该项被撑高 `perGap × innerGaps`，再由它自己的 `space-between` 把这份份额均分掉）。

配套：
- `AylaProfileCard` 新增 `stretchChildIndex` / `stretchChildInnerGaps`（纯增量）；
- `AylaProfileForm` 新增 `fillHeight`（内部 `Column` 改 `space-between`）；
- ⚠️ 撑高时给子件的是 `minHeight` **而不是 tight 高** —— tight 会让子项内
  `Column(min, spaceBetween)` 的 `idealSize` 等于内容高 ⇒ 分配失效（实测踩过）；
- `extra < 0`（矮窗、内容超高）时 `extra = 0` ⇒ 退化为自然高 + 基准间隙，由侧栏滚动兜底，不溢出。

**实测**（视口 1440×1000，测试打印）：
| 量 | 值 |
|---|---|
| 卡片 / 卡内 Column | 976（铺满） |
| 卡片级间隙（两处） | **93.83 / 93.83** |
| 表单内部间隙（在线状态 ↔ 昵称） | **85.83** |
| 操作区到卡底 | 18 |

> 8px 的差来自**基准间隙不同**（卡片级 `gap: sp6` = 24 / 表单内 `spacing: sp4` = 16）——
> 两者都是 web 的语义值，额外份额相同（69.83）。若要求像素级完全一致，可把卡片级基准也改成 sp4
> （会偏离 `profile.css` 的 `gap: var(--sp-6)`）—— 未擅动，待用户拍板。
