# 36 · 群卡片轮播「切页回来不再滚动」根因与修复

> **任务**：用户实报 —— Ayla Flutter 主页群聊列表的轮播图，「刚进入 app 的时候是正常的，
> 但是切换其他页面再切换回主页群聊就不再滚动了」。
>
> **性质**：**缺陷修复**（已改 `lib/`）。纯 Flutter 侧可见性判定的可用性问题，
> 未触及数据层、协议层与主体语义。
>
> 基线：`6b0c834`（`docs(release): 1.0.21 发布说明`）+ 当时工作树（2026-10-26）。

---

## 零、结论摘要

| 项 | 内容 |
|---|---|
| **现象** | 首次进入主页：群卡片 4:3 状态轮播正常每 3s 切换。切到其它一级页（/voice /live /posts /games）再切回 /group：**轮播完全静止**，指示点停住不动 |
| **根因** | 可见性判定（「进视口才启动」，web `IntersectionObserver` 的等价物）**全程只有两次触发机会**：`initState` 的 post-frame 与祖先 `ScrollPosition` 的 notify。切页回来时子树被整棵卸载重建 ⇒ 新 State 的 `_visible = false`，而那一发 post-frame **量不到渲染盒**（`_viewportKey.currentContext == null`，它在 `LayoutBuilder` 的 builder 里、布局阶段才产生）⇒ 直接 return；此后既无滚动、也无路由参数变化 ⇒ `ScrollPosition` 不再 notify ⇒ **没有任何第二次机会** ⇒ `shouldRun` 恒 false ⇒ 节拍器 `AnimationController` 永不 `forward` |
| **为什么首次正常** | 首次进入时主页数据是**异步到达**的（`social_store.load` → `notifyListeners` → 页面 `setState`）⇒ 多渲染了一帧，恰好补上了第二发测量。而切页回来时命中 60 秒缓存（`social_store.dart:366–372`）⇒ **只渲染一帧** ⇒ 没有人再叫醒它 |
| **为什么 web 没有** | `GroupCarousel.tsx:104–118` 的 `IntersectionObserver` 是**全局观察**：元素重新插入文档即投递一次初始 entry，与「谁触发的布局」无关 |
| **修复** | ① 把测量抽成可排队的 [`_scheduleMeasure`]（post-frame 去重）；② 在 `build` 的 `hasItems` 分支里**每次渲染都排一发**（有变化才 `setState`，两帧内收敛、不自激）；③ 顺带修正视口的真实口径 |
| **状态** | ✅ 已修（`flutter/lib/widgets/group/group_card.dart`）+ 回归锁（`flutter/test/home_carousel_resume_test.dart`），修复前红、修复后绿，**并做过变异验证** |

## 一、根因链（逐条，含证据）

### 1.1 判定链的完整结构（修复前）

```dart
// flutter/lib/widgets/group/group_card.dart（HEAD 6b0c834）
initState() {                       // :244–250
  addPostFrameCallback((_) { _bindScrollPosition(); _checkVisible(); });   // ← 机会 ①
}
didChangeDependencies() { _bindScrollPosition(); }                        // :252–256（**不量**）
_bindScrollPosition() {                                                    // :258
  … _scrollPosition?.addListener(_checkVisible);                          // ← 机会 ②
}
build() { … final shouldRun = _visible && !reduceMotion && slides.length > 1; }
```

**机会 ①**（挂载那帧的 post-frame）在「切页回来」这条路径上必然落空：

```
// 实测日志（临时插桩，已移除）
DBG carousel initState
DBG check enter mounted=true          ← 走了
DBG early: ctx null                   ← _viewportKey.currentContext == null ⇒ 直接 return
DBG syncTimer shouldRun=false         ← 于是节拍器不启动
```

原因：`_viewportKey` 挂在 `LayoutBuilder` 的 `builder` 里（`build` 的下方），它的
`RenderBox` 是**布局阶段**才产生的；而路由重建那一帧的 post-frame 早于该子树布局（或
该帧根本没排到本子树）⇒ `currentContext` 为 null。

**机会 ②**（`ScrollPosition` 的 listener）在切页回来时**不触发**：没有滚动、列表没换
controller、路由参数也没变 ⇒ `ViewportOffset` 不 `notifyListeners`。

⇒ 两次机会都没了 ⇒ `_visible` 永远是 `false` ⇒ `shouldRun` 恒 `false` ⇒
`_SlidesViewport` 的 `_syncTimer` 走 `else` 分支 `_timer.stop()` ⇒ 指示点与滑轨一起冻住。

### 1.2 为什么「首次进入」却是好的（这条最容易被忽略）

首次进入主页时，四份目录与会话分页都是**异步**的：

```
HomePage.initState → _start() → pager.load() → social_store._patch → notifyListeners
                  → _onPagerChanged → setState → **第二帧渲染** → 再发一发测量（量得到）
```

而切页回来时：`social_store.load` 命中 60 秒 freshen 窗口**直接 return**、不发请求、
不 notify（`social_store.dart:366–372`）⇒ 页面只渲染**一帧** ⇒ 测量那发是量空的，
随后再无重建。**「首进正常 / 回来不动」这个不对称由此闭合。**

## 二、修复

### 2.1 三处改动（`flutter/lib/widgets/group/group_card.dart`）

| # | 改动 | 依据 |
|---|---|---|
| 1 | `_checkVisible` → **`_scheduleMeasure`（去重排队）+ `_measureVisible`（真正的测量）** 两段式 | 与库内既有的 IO 等价物同口径：`widgets/chat/message_visibility.dart` 的 `_schedule` / `_measure`（post-frame 量，帧内去重） |
| 2 | `build` 的 `hasItems` 分支里**每次渲染都排一发** `_scheduleMeasure()` | web `IntersectionObserver` 是全局观察、插入文档即投递初始 entry ⇒ Flutter 侧对等做法 = 「只要本体真的渲染出来了就量一次」。值不变时 `_measureVisible` 不 `setState` ⇒ 两帧内收敛，**不自激** |
| 3 | 视口改用 **`RenderAbstractViewport` 找到的真实 viewport 渲染盒**（原实现把 maybeOf 的结果丢掉了，两个分支字面相同 ⇒ 实际口径退化成 `MediaQuery.size`） | 与 `message_visibility.dart:166–172` 的既有规范一致；否则「卡片还在屏幕内、但已滚出列表视口」会被误判成可见（滚动容器里的轮播该暂停时没暂停） |

### 2.2 阈值常量化

新增 `kAylaCarouselVisibleRatio = 0.1`（web `GroupCarousel.tsx:114` 的 `{ threshold: 0.1 }`），
不再有散落的魔数。

### 2.3 顺带救回的两条同类路径（独立审计提出、本修复一并覆盖）

两者都是「卡已挂载但此刻不可见、恢复时没有滚动通知」⇒ 旧实现同样只有一次判定机会：

- `layout/app_gate.dart:59` 的 `Offstage`（启动引导期间整棵路由页 offstage）；
- `preview/component_gallery.dart:2289–2292` 的 `Offstage` + `TickerMode(false)` 保活
  （切回该分类时也没有滚动通知）。

### 2.4 不自激的前提（写进代码注释）

网格档的卡片高度由 `AylaGroupGrid` 用 `SizedBox(width: colW, height: cardH)` 按列宽
**精确钉死**（`group_card.dart:1413–1420`），列表档每行等高 ⇒ 可见比不会在 0.1 上下抖动
⇒ 不会变成「每帧 setState 的抖动环」。**将来若改成内容自适应高度，需要重新评估这条。**

## 三、回归锁

`flutter/test/home_carousel_resume_test.dart`

**为什么必须走真实路由 + 真壳层**：该缺陷只在「离开路由 → 回来」这条路径上出现。
组件单测自己 `pumpWidget` 一个 `AylaGroupCarousel` 永远量不到它 —— 这正是 skill 里
登记的「参数注入型组件必须查调用点」「验证必须走真实交互路径」同一类教训。

**判据**：轮播当前页 = 指示点里唯一那个颜色为 `--glow-500` 的点（`home.css 483–503`）。
断言链：

1. 首帧停在第 0 张；
2. 首次进入 3.1s 后 → 第 2 张；再过 3.1s → 第 1 张（**先证明它本来是会动的**，
   否则后面那条「回来也要动」可能是空断言）；
3. `router.go('/live')` → `router.go('/group')` → 记下当前张；
4. 再 3.1s ⇒ **必须换张**（这是用户实报的判据）。

**变异验证（已执行）**：把 `build` 里那行 `_scheduleMeasure()` 摘掉 ⇒ 用例**变红**并停在
第 171 行的断言上（`Expected: not <0>  Actual: <0>`）；恢复后**变绿**。
⇒ 这条锁是真锁，不是「写完就绿」。

## 五、遗留与建议

1. **同类风险扫描建议**：库内凡是「`ScrollPosition` listener 单通道驱动可见性」的件，
   都有同一类「重建后不再被叫醒」的风险。本轮已确认 `widgets/shell/fab.dart` 与
   `widgets/chat/message_visibility.dart` **不受影响**（前者的触发源是 `ScrollController`
   的 attach + 本件自身的 `didUpdateWidget`，后者是每行独立探针、行本身随列表重建）。
2. **组件库纪律提醒（写进 skill 摘要）**：给「可见性/生命周期敏感」的件实现
   IntersectionObserver 等价物时，**必须保证重建后有一次帧末测量**，不能只依赖
   「挂载那一刻」与「滚动通知」——前者在路由重建时可能量不到，后者在缓存命中时会缺席。
