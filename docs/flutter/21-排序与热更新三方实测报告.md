## 1. 三方对照（决定性证据）

同一个后端、同一个群 13「5」，同时打开 web 与 Flutter：

| | **web (Edge, `localhost:5173/group/13`)** | **Flutter (`ayla_flutter`)** |
|---|---|---|
| rail 顺序 | `5, 1, 分, 4, 6, 1, 1` | `5, 1, 6, A, 4, 2, 6, 3, 1` |
| **与后端顺序对比** | ✅ **逐项吻合** | ❌ **完全不同** |

| Lead 在 22:48 / 22:55 发的消息 | ✅ 立刻出现 | ❌ 完全没有 |
| 群「5」未读 | 11 | 3 |

**Flutter 多出来的 `A`/`2`/`3` 是什么？**
```
后端 不传 type    → 7 群 + 3 私聊（id=17「汐汐」/ 56 / 48）
后端 type=group  → 只有 7 群
```
⇒ **Flutter 的 rail 显示的正是「全部会话」= 群 + 私聊混合**。

## 2. 根因清单（按影响排序）

### 🔴 根因 #1：rail / 群列表**混入私聊**（「顺序怎么都不对」的直接原因）

| | 位置 | 行为 |
|---|---|---|
| **web 第一道** | `GroupPage.tsx:92` | `useSocialPage("conversations", { type: "group" })` —— **请求层就带 type 过滤** |
| **web 第二道** | `HomePage.tsx:65` | `conversations.filter(c => c.type === "group")` —— 再兜一层 |
| **web 补当前群** | `GroupPage.tsx:196–203` | `selected = conversations.find(c => c.id===id && c.type === "group")` |
| **Flutter 窄屏** | `home_page.dart:450–453` | `_groups()` **有** `if (c.isGroup)` ⇒ 窄屏正确 |
| **Flutter 宽屏** | `group_support.dart:390–400` | `groupsWith()` **只过滤「补进来的 selected」，对 `_pager.items` 不过滤** ⇒ **混入私聊** |

**修法**：`groupsWith` 对 `loaded` 也做 `isGroup` 过滤（对齐 web 的两道过滤）。

### 🔴 根因 #2：`loadSocial` 不回写 `chatState`（根因 A）

| | 位置 | 行为 |
|---|---|---|
| **web** | `stores/social.ts:170–181` | `loadSocial` 成功后**双写**：`useChatStore.upsertConversation(item)`（`:172`）+ `useSubGroupStore.upsertSubgroup(...)`（`:176/179`），带 `merging` 护栏（`:170/181`） |
| **Flutter** | `state/social_store.dart` 的 `load()` | **只写 social record**，无任何回写 |

**后果链**：
```
chat_ws._onMessageNew 的 if (conv != null)（chat_ws.dart:656，与 web ws/chat.ts:487 同形）
  ⇒ chatState 里查不到该群 ⇒ conv == null
  ⇒ setLastMessage 与 bumpGroupActivity 都不执行
  ⇒ ★收到消息后群卡片不往前排（用户实报「发条消息根本不排上去」）
```

**另有**：`chat_ws.dart:622–623` 只 `unawaited(reconcileConversation)`（**异步、当帧不生效**），
**不能**替代 web 的同帧同步回写。

## 4. 补充发现：Flutter rail 有**后端不存在的幽灵条目**

放大 rail 截图逐个读首字符：
```
Flutter rail  = 5, 1, 6, A, 4, 2, 6, 3, 1     （9 个）
web rail      = 5, 1, 分, 4, 6, 1, 1          （7 个）
```

**逐个扫描后端 id 1..70，全部群只有 7 个**：
```
id=12 title='44'   id=13 title='5'    id=26 title='123'   id=27 title='123'
id=42 title='6'    id=43 title='132'  id=58 title='分享测试群'
```
⇒ **`A` / `2` / `3` 开头的群在后端根本不存在** —— 它们是 **social record 里的过期缓存**
（历史上存在过、现在已删或已退的群）。

**为什么 web 不会出现？** `stores/social.ts:167` 的 `initial`/`refresh` 会**重建 items**：
```ts
const items = new Map((mode === "more" ? current.items
  : current.items.filter((item) => !atStart.has(itemId(item))))  // ← initial/refresh 剔除旧项
  .map((item) => [itemId(item), item]));
for (const item of results) items.set(itemId(item), item);
```
Flutter 的 `social_store.dart:417–424` **逐条照抄了同一逻辑** ⇒ 只要**再 load 一次**就会清掉幽灵条目。
⇒ **说明 Flutter 从启动后就没再刷新过 social**（与「没有任何热更新」的实报一致）。

**这条不是独立缺陷**，而是根因 #2（无回流 ⇒ 无触发源 ⇒ 永不重新取页）的**表征**。
修好 #2/#3 后应自然消失；**验收时请把它作为判据之一**：
`rail 数量 == 后端 type=group 的返回数量`（当前 web=7、Flutter=9）。
