# 26 · Flutter WS 热更新全面整改（2026-10-20）

> 用户需求：「全面检查 ws 热更新，包括但不限于群内/群外语音/直播/桌游/帖子列表等界面，新建内容后不自动刷新，
> 也监听不到别人发的内容，要一比一复刻 web 的 websocket 热更新」。
>
> **结论先说**：根因**不在 WS 协议层**（协议、帧解包、41 条 case 分发、subscribe/resume、
> 未读/已读算法全部与 web 等价；后端实测也正常下发）。缺陷集中在**装配生命周期**与
> **页面数据源**两层 —— 这正是「单测全绿但真机不热更新」的典型形态。
> 本轮修复 **8 条缺陷**，新增 **4 条回归锁**，全量 **2675 测试通过 / 0 失败**，
> `dart analyze lib` **零告警**。

## 二、修复清单（8 条）

### 🔴 R1 — 帧桥与目录订阅通路「拆了不装」（P0，跨三份报告）

**症状**：经历一次「登出 → 再登录」或「401 过期 → 再登录」后，**语音/直播/桌游/帖子的
全部 WS 帧从此不再被处理**，列表只能手动刷新，直到重启 App。

**根因**：
- 装配点**唯一**：`main.dart:255–262`（进程启动期）；
- 拆除点 4 处：`aylaStopRooms*` / `aylaStopPostsFrames*` 的 `detach()`、
  `aylaStopDirectoryTracking()`、`itemUpsertHooks.clear()`；
- **重装函数 `aylaStartRoomFramesForRef` / `aylaStartPostsFramesForRef` /
  `aylaStartSocialTrackingForRef` 全仓零调用点**（已验证）；
- 登录链 `auth_bootstrap.dart:95–129` 只连 chat/presence，**不重装**。

**web 为什么没这问题**：`ensureDirectoryTracking`（`directory.ts:205–259`）与
`ws/chat.ts` 的模块级监听在 `logout` 时**不注销**，只 `reset()` store 数据。

**修复**（[`auth_bootstrap.dart`](../flutter/lib/state/auth_bootstrap.dart)）：
新增 `_restartRealtimeBridges()` 并在 `aylaApplyLoginSession` 里调用 ——
登录/冷启动自动登录/会话恢复共用同一条链，补上三条通路的幂等重装。

---

### 🔴 R2 — 群内三场景页不读目录缓存（P0）

**症状**：群内语音/直播/桌游列表**结构性没有热更新**（与 WS 是否到达无关）。
宽屏侧栏能变、点进场景页就不变。

**根因**：三页用**页面私有 `AylaPagedList`**，完全不读 `AylaDirectoryStore`；
web 三页是 `useDirectoryPage("voice"/"live"/"game", {groupId})`。

| 页面 | 修复前 | 修复后 |
|---|---|---|
| `group_voice_page.dart:74/83` | 私有 PagedList | `AylaDirectoryController` |
| `group_live_page.dart:112/140` | 私有 PagedList | `AylaDirectoryController` |
| `group_games_page.dart:58/71` | 私有 PagedList | `AylaDirectoryController` |

⇒ 三页与群外大厅、宽屏侧栏走**同一条通路**（web 三处也是同一个 store 投影）。

---

### 🔴 D1 — 私信列表 / 宽屏左列读页面私有快照（P0，消息域头号根因）

**症状**：别人发消息时，**会话列表不动** —— 不显示新消息、不出预览、不涨未读、不重排。
（消息进入聊天详情页后能看见，因为那是另一个 store。）

**根因**：`messages_page.dart` 与 `chat_support.dart` 用页面私有 `AylaPagedList`，
且两页 `onFrame` **只处理认证帧、完全不理会 `message.new`**；
web 读的是 `useSocialPage("conversations", {type:"private"})`（共享 social store）。

**修复**：两处改为 `AylaSocialController`（共享 `aylaSocialStore`）。
链路变成：`message.new` → `chatState.setLastMessage/bumpUnread` →
`AylaSocialTracking` 回写 social record → store 通知 → 页面重建（**与 web 同构**）。

---

### 🔴 R3 — `boardgame.room.deleted` 帧形状不匹配（P1）

**根因**：后端删除帧是**顶层** `{"type","room_id"}`（`boardgame/services.py:113–127,195`，
不传 room）；Flutter `_roomId` 只读 `frame['room']['id']` 或 `frame['data']['room_id']`
⇒ 取到空串 ⇒ 在 `if (id.isEmpty) return` 处**整帧静默丢弃**（web `chat.ts:854` 读顶层）。

**单测为什么没抓到**：`room_live_test.dart:267–270` 喂的是带 `room` 键的**假帧形状**。

**修复**：`_roomId` 补顶层 `room_id` 分支（三种真实形状都认）+ 用**真实帧形状**的新回归锁。

---

### 🔴 D2 — `WsChannel.connect()` 无幂等（P1）

**根因**：登录链 `wsManager.connectAll()` 后紧跟 `client.connect()` ⇒ 同一通道
`connect()` 两次 ⇒ **开两条 socket**、旧 `_sub` 从不 cancel（泄漏一条活连接）。
presence 的同名方法有幂等判断，chat 没有。

**修复**：`connect()` 加「已 connecting/online 就不重开」守卫（与 presence 同口径）。
注：`connectWithToken`（真正的重连路径）**不加**守卫。

---

### 🔴 D3 — 注册路径完全不接 chat owner（P1）

**根因**：`register_page.dart:161` 只 `wsManager?.connectAll()`，**从不 attach**
chat owner ⇒ `onEvent/onOpen` 恒 null ⇒ 注册完进应用**收不到任何 chat 帧**。

**修复**：改为走统一的 `aylaApplyLoginSession`（登录/自动登录/会话恢复共用那一份），
顺带获得 R1 的重装修复。

---

### 🟠 R4 — 建桌游房后本地零写入（P1）

**根因**：`create_sheet_forms.dart:745–752` `await widget.createRoom(...)` **丢弃返回的
`AylaGameRoom`**，无 upsert、无 `noteCreated`。
web 靠 `boardgame.ts:60–63` 的 window 事件 + `GroupGames.tsx:49–56` 重取。

**修复**：typedef 改返回 `AylaGameRoom`，成功后 `aylaBoardgameStore.upsertRoom(room)` +
`aylaDirectoryStore.noteCreated(game, id)`。

## 三、回归锁（新增 4 条）

[`test/realtime_assembly_lock_test.dart`](../flutter/test/realtime_assembly_lock_test.dart)

| # | 锁什么 | 有效性验证 |
|---|---|---|
| ① | **R1**：`stop()` 后 `isTracking=false`、`start()` 后恢复 | 锁「可重装」这一契约 |
| ② | **R3**：只有 `{type, room_id}` 的真实删除帧必须能删掉条目 | **已实测**：临时回退 `_roomId` ⇒ 该测试立刻变红；恢复后变绿 |
| ③ | **D2**：第二次 `connect()` 不得再调 `connectFactory` | 锁「不重复建连」 |
| ④ | **D1**：`chatState.setLastMessage` ⇒ social record 的预览自动更新 | 锁「列表读共享 store」 |

> ②的有效性做了**反向验证**（回退→红→恢复→绿），不是「写完就绿」的假锁。

另修正 3 个既有测试的 setup（架构变了，测试跟着改才是对的）：
- `create_forms_test.dart`：桌游替身返回类型从 `void` → `AylaGameRoom`；
- `group_live_create_sheet_test.dart`：数据出口注入改走 store 的 `requestOverride`；
- `page_ws_scroll_share_test.dart`：测试数据补 `allowed_group_ids`（目录按群过滤）
  + 桌游 `id` 改数字（`AylaGameRoom.id` 是 `int`，字符串会全部解析成 0 撞键）。

## 六、给用户的自验路径

1. **R1（最重要）**：登录 → 登出 → 再登录 → 让另一个账号发消息 / 建语音房 →
   观察列表是否**自动**更新（修复前必须重启 App 才恢复）。
2. **R2**：进入群内语音/直播/桌游页 → 另一账号在该群建房间 → 列表应**自动**多一行。
3. **D1**：停在消息列表页 → 另一账号发私信 → 列表应**自动**出现新预览 + 未读 + 排到前面。
4. **R3/R4**：建一个桌游房 → 立即回列表应**马上**看见；另一账号删房 → 列表应**自动**少一行。
5. **D2/D3**：新注册一个账号直接进应用 → 应能正常收到消息（修复前完全收不到）。
