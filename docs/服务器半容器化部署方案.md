## 1. 部署形态总览

**半容器化**：Ayla 全栈（前端 + 后端）与基础设施（Redis/MinIO/SRS）容器化、单一 compose 编排；**MySQL 保持服务器本机现状**（frp 隧道 `frp-one.com:65429` 暴露的即本服务器上运行的 MySQL，非容器、不进 compose）；**Elysium 主进程保持宿主机手动启动**（AGENTS.md §10 铁律，见 §5）。

```text
                         ┌────────────────────────────────────┐
   用户 ──HTTPS──►       │  服务器（Docker Engine + Compose）  │
                         │                                    │
              ┌──────────▼──────────┐                         │
              │   web（nginx 容器）  │  80/443 唯一入口         │
              │ 静态文件 + 反代      │                         │
              └──────┬──────────┬───┘                         │
                     │ /api/ /ws/│                             │
              ┌──────▼───┐  ┌───▼──────────┐                  │
              │ayla-backend│  │ (同 compose) │                 │
              │ daphne 8100│  │  Redis       │                 │
              └──┬────┬────┘  │  MinIO       │                 │
                 │    │       │  SRS         │                 │
                 │    │       │  MySQL(已有)  │                 │
                 │    └──────►│              │                 │
              ┌──▼────────────┐              │                 │
              │ Elysium（宿主机进程）         │                 │
              │ 手动启动 · 本地模型 · 长连接   │                 │
              └────────────────┘              │                 │
                         └────────────────────────────────────┘
```

**关键裁决**：

1. **nginx 容器化**（`web` 服务）：同一 compose 托管前端静态文件 + 反代 `/api/` 与 `/ws/`，唯一对外端口 80/443；
2. **Ayla 后端容器化**：`python:3.12-slim` + daphne（ASGI，支持 Channels WS）；
3. **基础设施全容器**：Redis（生产加密码）、MinIO（卷持久化）、SRS（直播，M4-6 后启用）；
4. **MySQL 保持服务器本机现状**（非容器）：frp 隧道 `frp-one.com:65429` 暴露的即本服务器的 MySQL；Ayla 容器经 frp 地址连接（同机部署可直连内网绕开隧道，见 §6）；可选未来迁入 compose 管理（§9 决策点 1）；
5. **Elysium 例外**：宿主机进程 + 手动启动（AGENTS.md §10），不进入 compose。

## 2. 组件清单

| 服务             | 镜像/构建                    | 端口（映射）                 | 卷                                | 角色                            |
| -------------- | ------------------------ | ---------------------- | -------------------------------- | ----------------------------- |
| `web`          | 前端多阶段构建 → `nginx:alpine` | 80, 443                | 无（静态进镜像）                         | 静态托管 + 反代                     |
| `ayla-backend` | `python:3.12-slim` 构建    | 8100（仅内网，不映射公网）        | `ayla_static:/app/staticfiles`   | Django ASGI + WS              |
| `redis`        | `redis:7-alpine`         | 6379                   | `ayla_redis_data:/data`          | 缓存 + channel layer + presence |
| `minio`        | `minio/minio:latest`     | 9000/9001              | `ayla_minio_data:/data`          | 媒体对象存储                        |
| `srs`          | `ossrs/srs:5`            | 1935/8080/1985/8000udp | `ayla_srs_data:/usr/local/srs`   | 直播推拉流（M4-6 后）                 |
| MySQL（已有） | 服务器本机（frp 隧道暴露，非容器） | 65429（frp）| —（不进 compose） | 应用数据权威库，保持现状 |
| Elysium        | 宿主机进程                    | —                      | 本机 `data/` `runtime/`            | 意识/聊天/桥接                      |

> 端口原则：**只有 `web`（80/443）暴露公网**；Redis/MinIO/SRS 端口仅供宿主机 Elysium 与容器内服务使用；后端 8100 不映射公网（nginx 容器内 `ayla-backend:8100` 互访）。

### 3.1 Ayla 后端 Dockerfile（拟定）

```dockerfile
# Ayla/backend/Dockerfile —— 拟定
FROM python:3.12-slim
ENV PYTHONUNBUFFERED=1 PIP_NO_CACHE_DIR=1
WORKDIR /app
COPY pyproject.toml ./
RUN pip install --upgrade pip && pip install .
COPY . .
EXPOSE 8100
# daphne 承载 ASGI（Channels WS + lifespan 内嵌 bridge）
CMD ["daphne", "-b", "0.0.0.0", "-p", "8100", "config.asgi:application"]
```

> 说明：开发用 `launcher.py`（runserver）与 `run_bridge` 拆分便于调试；**生产用 daphne 单进程承载**（`ELYSIA_BRIDGE_INLINE` 默认 True 时内嵌 SSE 出站投影随 lifespan 起停，无需第二个进程）。静态文件：构建/启动时执行 `python manage.py collectstatic --noinput` 写入 `ayla_static` 卷，由 nginx 直接服务（或由 Django 服务，见 §4）。

### 3.2 前端 Dockerfile（拟定，多阶段）

```dockerfile
# Ayla/web/Dockerfile —— 拟定
FROM node:20-alpine AS build
```

## 4. nginx 配置（拟定）

```nginx
# Ayla/web/nginx.conf —— 拟定
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    client_max_body_size 60m;            # 媒体上传上限（voice 30M / file 50M 余量）

    # SPA 路由回退
    location / {
        try_files $uri /index.html;
    }

    # 静态资源长缓存（文件名带 hash）
    location /assets/ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # API 反代
    location /api/ {
        proxy_pass http://ayla-backend:8100;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket 反代（presence / chat / voice / live 弹幕）
    location /ws/ {
        proxy_pass http://ayla-backend:8100;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;        # WS 长连接
    }
}
```

> **HTTPS（实施时二选一）**：① 云厂商免费证书挂载到 `web` 容器（`/etc/nginx/conf.d` + 证书卷）；② `certbot` 独立容器签发续期（443 映射 `web`）。本文件仅声明位置，不落具体证书方案（§9 决策点）。

## 5. Elysium 例外（宿主机进程，铁律）

- **AGENTS.md §10 明确**：Elysium 必须由用户手动启动，禁止 systemd/cron/登录脚本/容器自启等自动拉起机制。**容器化 Elysium 需先修改该纪律**（用户决策，非技术问题），本方案默认保持宿主机进程。
- 部署方式：服务器上沿用与开发一致的手动/脚本启动（如 `start_elysium` 脚本 + 可见终端）；重启需人工确认。
- 连接关系：
  - MySQL（本服务器已有，frp 隧道暴露）：`DB_*` 指向 frp 地址；**Ayla 容器与 MySQL 同机部署时可直接用服务器内网地址**（如 `127.0.0.1:3306` 或内网 IP），绕开 frp 隧道（更低延迟、不依赖 frp 隧道可用性）；
  - Redis：宿主机 `127.0.0.1:6379`（compose 已映射）；
  - MinIO：宿主机 `127.0.0.1:9000`（映射端口）；
  - Ayla SSE 出站投影：`ELYSIA_CREDENTIAL_FILE`（一次性 secret 落盘，凭据最小权限 `ayla` stream）。

## 7. 部署步骤（拟定）

1. **服务器准备**：安装 Docker Engine + Compose v2；防火墙放行 80/443（及直播端口 1935/8080/8000udp 若公网直连 SRS）。
2. **代码与配置**：拉取仓库；生成 `.env.production`（§6）；`docker compose config` 校验。
3. **构建镜像**：`docker compose build`（本地构建，无需镜像仓库；或推私有仓）。
4. **迁移**：`docker compose run --rm ayla-backend python manage.py migrate`（MySQL 就绪后）。
5. **静态文件**：`docker compose run --rm ayla-backend python manage.py collectstatic --noinput`。
6. **启动**：`docker compose up -d`；`docker compose ps` 全部 healthy。
7. **验证**：
   - `curl http://<公网>/api/v1/health/` → `{"status":"ok"}`；
   - 浏览器 E2E 冒烟：注册 → 登录 → 建会话 → 发文本/图片/语音 → 媒体上传下载 → WS 实时回显；
   - 直播（M4-6 后）：创建频道 → OBS/ffmpeg 推流 → 拉流 → 弹幕。
8. **Elysium**：人工手动启动（连接本服务器 MySQL、写入凭据、SSE 投影验收）。

## 8. 备份与恢复（拟定）

| 数据         | 位置                  | 备份命令（定时任务或手动）                                                                                          |
| ---------- | ------------------- | ------------------------------------------------------------------------------------------------------ |
| MinIO 媒体   | 卷 `ayla_minio_data` | `docker run --rm -v ayla_minio_data:/data -v $PWD:/backup alpine tar czf /backup/minio.tgz -C /data .` |
| Redis      | 卷 `ayla_redis_data` | 同上（或 `redis-cli --rdb`；appendonly 卷备份即全量）                                                              |
| MySQL（本机已有，非容器） | 服务器本机 MySQL | `mysqldump --all-databases > dump.sql`（frp/内网均可连） |

## 9. 已知取舍与未决点（实施前逐项拍板）

1. **MySQL 形态**：**已定——保持服务器本机现状**（frp 隧道暴露，非容器，不进 compose）。可选优化：① Ayla 容器同机直连内网（绕 frp，推荐）；② 未来把 MySQL 迁入 compose 统一管理（需迁移数据卷与 frp 配置，属独立改造，不在本方案首期）。→ 首期执行：现状 + 同机直连。
2. **Elysium 纪律**：若未来要容器化 Elysium（自动拉起），必须先修改 AGENTS.md §10（用户决策）。本方案维持宿主机进程。
3. **HTTPS/域名**：域名与证书方案（云证书 / certbot / 自签内网）。本文件只预留 443 位置。
4. **SRS 公网暴露**：直播端口（1935/8080/8000udp）公网直连 vs 经 nginx 转发（HLS/FLV 可经 8080 反代；RTMP/WebRTC 需直连或专门反代）。M4-6 上线时定。
5. **内嵌 bridge**：生产 `ELYSIA_BRIDGE_INLINE=true`（daemon 线程随 daphne 起停）vs 独立 `run_bridge` 进程。默认前者，异常时切换后者（仅该服务重启用）。
6. **后端多 worker**：daphne 单进程满足初期；流量增长再上 `uvicorn/gunicorn` 多 worker + 前置负载均衡（channel layer 已走 Redis，可横向扩展）。
7. **媒体缓存**：MinIO 私密媒体 `Cache-Control: private, no-store`（M4-3 契约），nginx 不做媒体缓存。
