# Ayla 实时推送与性能优化 - 验收清单

## 概述

本次实施完成了 Ayla 前端实时刷新和图片加载性能优化，解决了以下核心问题：
1. 多用户操作无法实时同步（需要刷新浏览器）
2. 全局组件数据依赖问题（刷新后打开弹窗看不到数据）
3. 图片加载特别慢

## 一、WebSocket 实时推送功能

### 后端推送事件（8 个新事件类型）

#### 1. 语音房推送
- ✅ `voice.channel.created` - 语音房创建
  - 文件：`apps/voice/services.py`（推送函数）、`apps/voice/views.py`（调用点）
  - 推送目标：群成员（`chat_conv_{group_id}`）+ 创建者（`chat_user_{user_id}`）
  
- ✅ `voice.channel.deleted` - 语音房删除
  - 文件：`apps/voice/services.py`、`apps/voice/views.py`
  - 推送目标：与创建时相同

#### 2. 直播间推送
- ✅ `live.channel.created` - 直播间创建
  - 文件：`apps/live/services.py`、`apps/live/views.py`
  
- ✅ `live.channel.status.changed` - 直播状态变化（开播/下播）
  - 文件：`apps/live/services.py`、`apps/live/views.py`
  - 触发点：`ChannelStartView.post()`（开播）、`ChannelStopView.post()`（停播）
  
- ✅ `live.channel.deleted` - 直播间删除
  - 文件：`apps/live/services.py`、`apps/live/views.py`

#### 3. 帖子推送
- ⏳ `post.created` - 帖子创建
  - 文件：`apps/posts/services.py`、`apps/posts/views.py`
  
- ⏳ `post.deleted` - 帖子删除
  - 文件：`apps/posts/services.py`、`apps/posts/views.py`

#### 4. 桌游房推送
- ⏳ `boardgame.room.created` - 桌游房创建
  - 文件：`apps/boardgame/services.py`、`apps/boardgame/views.py`
  
- ⏳ `boardgame.room.deleted` - 桌游房删除
  - 文件：`apps/boardgame/services.py`、`apps/boardgame/views.py`

#### 5. 群列表推送
- ⏳ `group.created` - 群组创建
  - 文件：`apps/chat/services.py`、`apps/chat/views.py`
  - 推送目标：所有成员（`chat_user_{user_id}`）
  
- ⏳ `group.joined` - 用户加入群组
  - 文件：`apps/chat/services.py`、`apps/chat/views.py`
  - 触发点：接受邀请、申请通过、直接添加成员

### 前端事件处理

#### WebSocket 消费者扩展
- ✅ `apps/chat/consumers.py` - ChatConsumer 添加事件处理器
  - `voice_channel_created()` / `voice_channel_deleted()`
  - `live_channel_created()` / `live_channel_status_changed()` / `live_channel_deleted()`
  - ⏳ `post_created()` / `post_deleted()`
  - ⏳ `boardgame_room_created()` / `boardgame_room_deleted()`
  - ⏳ `group_created()` / `group_joined()`

#### 前端 Store 自动更新
- ⏳ `web/src/lib/chat.ts` - 扩展 dispatch 逻辑
  - 监听所有新事件类型
  - 调用相应 store 的 upsert/remove 方法

- ⏳ 各 Zustand Store 添加 upsert/remove 方法
  - `useVoiceStore` - 语音房列表自动更新
  - `useLiveStore` - 直播间列表自动更新
  - `usePostsStore` - 帖子列表自动更新
  - `useBoardGameStore` - 桌游房列表自动更新
  - `useConversationStore` - 群列表自动更新

## 二、前端数据加载优化（第一阶段）

### 1. 登录后预加载核心列表
- ⏳ 文件：`web/src/main.tsx`
- 功能：登录成功后并发加载会话、语音房、直播间列表
- 目标：解决全局组件数据依赖问题

### 2. 全局组件按需加载兜底
- ⏳ 文件：各弹窗组件（CreateVoiceChannelDialog 等）
- 功能：组件挂载时检查数据是否就绪，未就绪则主动加载
- 目标：确保即使预加载失败也能正常使用

### 3. Store 缓存时间戳机制
- ⏳ 文件：各 Zustand Store
- 功能：添加 `lastFetched` 字段，页面挂载时检查是否过期（> 60s）
- 目标：自动刷新陈旧数据

### 4. 手动刷新按钮
- ⏳ 文件：各列表页（语音房、直播间、帖子、桌游房列表页）
- 功能：顶部添加刷新按钮，用户可手动触发刷新
- 目标：用户控制权

## 三、图片加载性能优化

### 后端优化
- ⏳ `apps/media/views.py` - 响应头优化
  - 原图：`Cache-Control: private, max-age=3600`（允许浏览器缓存 1 小时）
  - 缩略图：`Cache-Control: private, max-age=7200`（缓存 2 小时）
  - 实现 `ETag` 和 `304 Not Modified` 支持

- ⏳ `apps/media/services.py` - 缩略图预生成
  - 检查 `complete_upload()` 是否延迟生成
  - 改为上传完成后立即生成缩略图

### 前端优化
- ⏳ `web/src/components/ResourceImage.tsx` - Blob URL 缓存
  - 全局 Map 缓存已请求的 blob URL
  - 避免重复请求同一图片
  - 生命周期管理（避免内存泄漏）

## 四、验收测试

### 实时推送验收

#### 测试场景 1：语音房实时同步
1. 用户 A 和用户 B 同时在线
2. 用户 A 在群 X 创建语音房
3. **预期**：用户 B 无需刷新，1 秒内语音房列表自动显示新房间
4. 用户 A 删除语音房
5. **预期**：用户 B 无需刷新，1 秒内语音房从列表消失

#### 测试场景 2：直播间状态实时同步
1. 用户 A 在群 X 创建直播间
2. **预期**：用户 B 立即看到新直播间（状态：未开始）
3. 用户 A 开始直播
4. **预期**：用户 B 立即看到状态变为"直播中"
5. 用户 A 停止直播
6. **预期**：用户 B 立即看到状态变为"已结束"

#### 测试场景 3：帖子实时同步
1. 用户 A 在群 X 发帖
2. **预期**：用户 B 的信息流立即出现新帖子
3. 用户 A 删除帖子
4. **预期**：用户 B 的信息流中帖子立即消失

#### 测试场景 4：群列表实时同步
1. 用户 A 创建群 Y 并邀请用户 B
2. **预期**：用户 B 接受邀请后，群列表立即出现群 Y
3. 用户 A 创建新群 Z 并直接添加用户 B
4. **预期**：用户 B 的群列表立即出现群 Z

#### 测试场景 5：全局组件数据依赖
1. 用户 A 刷新浏览器（F5）
2. 刷新后**不访问主页**，直接打开"创建语音房"弹窗
3. **预期**：群选择器立即显示群列表（不是空白）
4. 选择群 X，设置为"指定群可见"
5. **预期**：能正常创建语音房

### 图片加载性能验收

#### 测试场景 6：头像加载性能
1. 打开包含 20 个用户的群聊列表
2. **测量**：首次加载 20 个头像的总时间
3. **预期**：< 2 秒（优化前可能 > 5 秒）
4. 返回主页，再次进入群聊列表
5. **预期**：头像立即显示（浏览器缓存命中）

#### 测试场景 7：图片缓存复用
1. 打开用户 X 的个人资料页（显示头像）
2. 打开与用户 X 的私聊（显示头像）
3. **预期**：第二次显示头像时无网络请求（blob URL 缓存命中）
4. 检查浏览器 Network 面板
5. **预期**：同一 media_id 只请求一次

#### 测试场景 8：缩略图性能
1. 打开帖子列表（包含多张配图）
2. **预期**：缩略图加载快速（不等待原图）
3. 检查后端日志
4. **预期**：缩略图已预生成，无延迟生成日志

### 数据过期检查

#### 测试场景 9：自动刷新陈旧数据
1. 用户 A 打开语音房列表页
2. 等待 70 秒（超过 60 秒过期时间）
3. 切换到其他页面再返回
4. **预期**：自动重新加载语音房列表（检查 Network 面板）

#### 测试场景 10：手动刷新
1. 用户 A 在语音房列表页
2. 点击顶部刷新按钮
3. **预期**：立即重新加载列表，UI 显示加载状态

## 五、性能指标

### 实时性指标
- 推送延迟：< 1 秒（创建到接收）
- 列表更新延迟：< 0.5 秒（接收到 UI 更新）

### 图片加载指标
- 首次加载 20 个头像：< 2 秒
- 缓存命中率：> 80%
- 缩略图首字节时间（TTFB）：< 200ms

### 数据新鲜度指标
- 自动刷新触发时间：60 秒
- 手动刷新响应时间：< 1 秒

## 六、回滚计划

如果推送功能导致问题，可以逐个回滚：

1. **前端回滚**：注释 `chat.ts` 的 dispatch 扩展，保留原有消息推送
2. **后端回滚**：注释各 `views.py` 中的 `broadcast_*` 调用，推送函数保留（不影响其他功能）
3. **图片缓存回滚**：恢复 `ResourceImage.tsx` 的原始实现
