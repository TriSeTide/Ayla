1. **双重保障机制**
   - 登录时预加载（主路径）
   - 组件挂载时兜底加载（容错路径）

   - 向后兼容，无破坏性变更

   - 刷新按钮带加载状态，防止重复点击
   - 统一的视觉样式和交互反馈

## 第三阶段补充：多群可见性回归（群内页显示全部被选群内容）

**背景**：`visibility="group"` 的内容可被多个群选择（`allowed_group_ids` 白名单）。要求：voice/live/boardgame/post 的多群条目必须出现在**每个**被选群的群内页。此前 live/boardgame 群内页只按 `item.group` 过滤，白名单条目（`group=null` + `allowed_group_ids`）被漏掉。

**根因 1（前端过滤缺白名单）**：`GroupLive` / `GroupGames` 的投影只匹配 `group === groupId`，未包含 `allowed_group_ids`。已改为：

```ts
const items = allItems.filter((item) =>
  String(item.group) === String(groupId)
  || (item.allowed_group_ids ?? []).some((g) => String(g) === String(groupId)),
);
```

**根因 2（scoped 加载覆盖全局 store）**：群内页此前用 `listLiveChannels({ scope: "group:<id>" })` / `listGameRooms({ scope: "group:<id>" })` / `listVoiceChannels({ scope: "group:<id>" })` 并把结果 `setChannels`/`setRooms` **整体替换**全局 store。后果：

- 先进一个非目标群再切到白名单群时，store 被单群数据污染且未过期不重载，多群条目不出现；
- 返回 hub 页时全局列表只剩上次访问的群数据。

后端 `visible_queryset` 已含 `Q(group_id__in=my_groups) | Q(allowed_groups__id__in=my_groups)`，因此**无 scope 的「全部可见」查询天然包含白名单多群条目**。修复：群内页改为加载全量可见列表进 store，再前端按 `groupId` 投影当前群（与 hub 页共享同一全局 store，显示结果与 scoped 加载完全一致，且不再污染全局列表）。涉及：

- `web/src/pages/group/GroupLive.tsx`：`listLiveChannels()` 无 scope + 白名单过滤；
- `web/src/pages/group/GroupGames.tsx`：`listGameRooms()` 无 scope + 白名单过滤；
- `web/src/pages/group/GroupVoice.tsx`：`listVoiceChannels()` 无 scope + 新增群过滤（此前完全无前端过滤，依赖 scoped 加载兜底）；并修复房内视图 `currentChannel` 查找，使多群白名单频道在 `/group/:id/voice/:channelId` 下能进入房内视图（原来 `c.group === groupId` 对 `group=null` 的白名单频道恒为 false）。

**回归测试**（新增/修复）：

- `group-live.test.tsx`：7 项。新增「同一多群直播出现在每个被选群群内页」「不在白名单的群空态」「先看别的群再看白名单群，store 不被单群 scope 覆盖」（scope 感知 mock 复现覆盖 bug）；修复 `beforeEach` 未 reset `useLiveStore` 导致的空态用例失败。
- `group-games.test.tsx`：4 项。同上三组场景 + store reset。
