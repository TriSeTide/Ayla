# 实施记录-注册邮箱验证-2026-09-16

## 背景与决策

- 需求：Ayla 注册功能添加邮箱验证。
- 决策：**邮箱验证用表单内嵌 6 位数字验证码**（收件者回填=证明邮箱归属），保持现有「注册即登录」流程不打断。
- 决策：**人机验证不做**（用户拍板）。注册/发码接口的自动化滥用由**限流兜底**（冷却/每日/IP 配额），发码接口已留改造位，将来如需验证码可直接叠加。
- 部署：国内为主，SMTP 使用 QQ 邮箱（`smtp.qq.com:465/SSL` + 授权码，凭据只存 `.env`，Git 忽略）。

## 安全与限流（服务层强制，均有用例锁定）

- 60s 重发冷却（`cache.add` 原子，并发防重）
- 每邮箱每日 5 次发码上限；同 IP 每小时 30 次上限
- 验证码 6 位随机（`secrets.randbelow`）、比对用 `compare_digest`、TTL 5 分钟
- 错 5 次作废；注册成功后一次性消费（防重放）
- 发信失败：显式 `500/email_code_failed`，回滚验证码与冷却键，允许立即重试；daily/IP 配额计数保守保留（防 SMTP 故障期间持续轰炸）

## 遗留事项

- 真实 SMTP 发信需在部署环境做一次端到端验证（收信/垃圾箱）
- 「找回密码」是邮箱验证的自然延伸，未实施，可作二期
- 全 backend 全量回归异常（>300s 未完成；accounts 以外 app 存在失败）——与本功能无证据关联，疑似既有工作树状态（他人未提交改动区），另行核查；本功能定向验证范围（accounts 40 项 + 前端 tsc/smoke）全部通过

# 隐私设置（邮箱换绑 / 更改密码）- 2026-09-16

## 需求与设计

个人主页「更换头像」与「我的收藏」之间新增「隐私设置」按钮，弹窗内完成两项操作（全部走邮箱验证）：
- **更改密码**：验证码发至当前绑定邮箱 → 新密码两次确认 → 提交（Django 强度校验）
- **邮箱换绑**：两步验证——① 当前绑定邮箱验证码（未绑定则跳过）→ ② 新邮箱 + 发至新邮箱的验证码 → 提交；换绑后新旧码均失效
- 窄屏（≤768px）60% 下半屏弹窗；宽屏中央 modal（沿用 ShareSheet 弹层规格）
- 顺手修复：分享键移至身份区最右（margin-left:auto），头像块恢复与下方「更换头像」按钮对齐

## 接口契约（均 JWT 认证，复用 email_code 服务与 send-email-code 发送）

| 接口 | 入参 | 说明 |
|---|---|---|
| `POST /api/v1/auth/change-password/` | `{code, new_password}` | code 对应当前绑定邮箱；validate_password 强度校验；set_password |
| `POST /api/v1/auth/change-email/` | `{current_code, new_email, new_code}` | 双验证（当前邮箱码+新邮箱码）；未绑定邮箱用户仅验新码（首绑）；email 唯一（含并发 IntegrityError 兜底 400） |
| `GET /api/v1/me/` | - | 响应追加本人 `email` 字段（仅本人接口；UserPublic 不含 email 不泄露） |

## 改动清单

**后端**：`views.py`（ChangePasswordView/ChangeEmailView/MeView+email）、`urls.py`（两路由）、`tests/test_change_email_password.py`（10 用例）
**前端**：`components/PrivacySheet.tsx`（新建）、`pages/ProfilePage.tsx`（隐私设置按钮+分享键右移+弹窗接入）、`api/auth.ts`（changePassword/changeEmail）、`api/types.ts`（类型+email）、`styles/profile.css`（privacy-sheet 全套+布局修复）
