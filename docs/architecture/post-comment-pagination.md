# 帖子列表实时合并与评论分页

## 群内帖子刷新

`GroupPosts` 为当前账号和群持有分页 owner。首屏和续页仍使用 `/posts/?scope=group:<id>&limit=20`；刷新替换首页投影，续页沿原 cursor 追加。

开始读取时记录本地 mutation revision。请求期间收到的 WS 新帖、编辑、本地发布或可见范围变化先写入带版本的本地投影；较早的首页或续页响应不能覆盖这些新事实。删除标记阻止旧响应复活已删帖子。相同帖子的多次 `getPost` 对账另外具有请求 revision，较早请求迟到不能覆盖后来已成功返回的编辑。已有卡片 DOM 与单调的浏览/已读投影保留；新帖子只为新增 DOM 播放入场。

这修复了原先“刷新开始 → 实时新帖/编辑到达 → 旧首页返回”的结果丢失问题。它不把本地分页缓存当作完整目录，也不改服务器权限或事实内容。

## 评论的有界读取

旧 `GET /api/v1/posts/<id>/comments/` 保留数组契约。网页显式使用：

```text
GET /api/v1/posts/<id>/comments/?limit=20
GET /api/v1/posts/<id>/comments/?limit=20&cursor=<next_cursor>
```

响应为 `{results, next_cursor, has_more, total}`。`limit` 必须是 1–100 的整数，默认 20；仅序列化 SQL `limit + 1` 取得的当前页。排序为 `created_at ASC, id ASC`，相同时间戳按主键稳定遍历。签名 cursor 绑定读者、帖子和排序版本；空、损坏、重复参数、跨用户或跨帖子重放返回 400。每页先复查该用户对帖子的查看权限，再计数和分页；失去权限返回 403，不返回空列表冒充成功。

cursor 代表排序位置，不是跨请求冻结快照。先前位置删除不会位移后一页；后续新增评论按其实际排序位置进入续页或实时事件。回复目标仍使用明确的 `reply_to` 引用；目标未在已加载页时，界面显示评论编号及“未在当前列表中”，不会静默丢失回复关系。

## 网页 owner、实时事件与返回

`usePostComments` 为账号/登录会话/帖子隔离评论列表和 cursor。首屏 20 条，接近底部或点击“加载更多评论”才请求下一页；同一时刻一个请求，错误后停止滚动自动重试。首屏、续页错误分别提供“重试评论”和“重试加载更多评论”。失败保留已加载评论和原 cursor，未推进 cursor 或跨帖响应显式报错。

WS `comment.created`、本地发送成功和 `comment.deleted` 更新当前投影并按 id 去重。首屏/刷新返回时保留读取期间新出现的评论，删除标记使旧读取不能复活已删评论。旧账号、旧帖子和卸载后的响应不能落入当前视图。详情正文同时按账号/postId 创建独立组件 owner，并在后台读取结束时核对请求身份。

最多保留 12 个会话内评论快照，包含已加载页、cursor 和错误状态；退出登录或切换账号清空，未写入浏览器持久化存储。离开详情后不再接收该视图的实时事件，因此返回时保留已有页并提供明确的“刷新评论”入口，不冒充最新完整快照。返回前显式保存滚动位置，并在 Framer Presence 退出阶段停用旧详情的滚动监听，避免退出 DOM 的归零事件覆盖真实位置；`useScrollRestore` 在评论高度就绪后恢复。缓存返回的评论静止，之后续页或实时新增只为新 DOM 播放入场。减少动态效果时直接显示。

群外正文原有整体入场保持；群内首批评论跟随正文，不重复逐项进入，后续新评论独立进入。分页 footer 保持已占高度，避免加载/错误/结束状态切换使末尾跳动。

## 评论输入与删除

“我的帖子”目录同样保持每页 20 条及原 cursor。尾页失败保留已有卡片并提供显式重试，失败期间滚动不反复请求；同步忙锁阻止同一页的连续滚动重入，账号变化和卸载使旧请求失去写入资格。返回时保留已加载页和滚动位置，不重播旧卡片，后续只动画新增 DOM。

评论发送成功只清空本次提交的草稿；请求期间继续输入的新草稿和新回复目标保留。发送、上传和移除附件共用同步忙锁，不能在评论请求中途删除正在提交的附件。失败保留正文和成功上传的附件；失败图片保持显式的重试/移除入口，不能随一次纯文字发送静默消失。移除附件必须等服务器成功才从界面消失，失败保留原项与重试提示。预览使用已有媒体地址，不创建无人使用的 objectURL。

帖子删除确认具有同步忙锁和可见禁用态；失败保留正文，旧详情的删除回执不能让已经切换到别处的页面后退。每条评论的删除按钮在对应请求完成前独立禁用，其他评论仍可回复；删除失败保留该条评论和错误提示。

帖子编辑保存期间以原生 disabled fieldset 冻结标题、正文、可见范围和媒体控制，并禁用取消入口；同步忙锁拒绝重复保存，失败恢复原草稿与控制，卸载后的回执不再修改当前视图。这样不会出现保存请求已提交但表单仍接受新输入、成功后关闭并丢失新草稿的状态。

编辑层保留页面原背景。编辑期间原详情顶栏、滚动正文/评论和评论输入各自保留 DOM、分页、scrollTop 与草稿，同时通过 `post-detail-background` 标记的 visibility:hidden、inert 和 aria-hidden 从画面、指针/键盘及无障碍树隔离；编辑层自身不带该标记。打开编辑聚焦标题，取消或保存后解除原区域隔离，并等待编辑按钮实际的 visibility 过渡完成后恢复焦点；再次编辑或卸载会取消旧的焦点恢复。不重挂详情，也不叠加新的不透明背景来遮挡旧内容。

- `backend/apps/posts/tests/test_comment_pagination.py`：SQL 有界读取、同时间戳遍历、旧数组、用户/帖子绑定、每页权限、新增/删除边界和非法参数。
- `web/src/vitest/group-posts.test.tsx`：分页、详情返回、实时变更与旧首页、同帖逆序对账。
- `web/src/vitest/use-post-comments.test.tsx`：请求 owner、忙锁、失败重试、WS/本地/删除合并、缓存与账号边界。
- `web/src/vitest/comment-list-pagination.test.tsx`：旧 DOM 保留、新 DOM 入场、缓存恢复、群内首次入场和页外回复引用。
- `web/src/vitest/comment-composer.test.tsx`：请求期间新草稿、失败重试、回复目标、附件移除/上传互斥和部分失败。
- `web/src/vitest/post-detail-page.test.tsx` 与 `post-detail-back-navigation.test.tsx`：既有正文动效、编辑范围、删除状态和来源返回。

后端验证使用独立测试数据库；单元测试不替代真实浏览器控件状态验收，也不代表 Elysium 已经重启验收。
