# 资料页内容分页与草稿保存

`ProfilePage` 与 `UserProfilePage` 复用 `ProfileContentSections`，保留本人收藏入口、三分区折叠和桌面左右独立滚动布局。

## 数据与计数

本人发帖请求 `GET /posts/?scope=mine&limit=20`，本人直播请求 `GET /live/channels/?owner=<me>&limit=20`，本人正在玩的桌游请求 `GET /boardgame/rooms/?mine=1&limit=20`。他人三分区分别使用 `owner=<userId>`。这些过滤在后端 SQL 分页前完成，不能从已加载的全站目录筛选来推断完整个人内容。

三类接口均返回 `results`、`next_cursor`、`has_more`、`total`。帖子 `total` 在权限、scope、owner 过滤后、cursor 过滤前计算，因此尾页计数仍表示完整可见子集。旧服务若没有返回帖子总数，界面明确显示“已载入 N”，不能把当前页条数当作总数。

每区首次最多载入 20 条，展开并接近底部时继续请求下一页，也保留加载更多按钮。每区独立维护 loading、失败、游标和数据，单区失败不会阻断其他区。首屏失败显示重试；尾页失败保留已载入内容并重试原游标；只有成功获得空结果才显示暂无内容。折叠时不会挂载触底观察器。

列表请求以查看者、资料主人及内容类型为范围；切换账号、资料或卸载会使旧请求代次失效。对方未开启 `show_content` 时不挂载三分区，也不发送内容请求。好友与陌生人共享这一展示开关，可见数据仍由每类后端接口的现行权限过滤决定。好友申请或发起私聊失败保留资料及操作按钮，用户可直接重试；资料加载失败有单独重试入口。

## 保存与并发编辑

保存开始时记录昵称、签名、状态、内容展示开关、头像文件和预览的提交快照。文本按现有 PATCH 契约 trim 后提交；头像继续先上传、再 PATCH 内容 URL。失败保留本地草稿。

成功后更新账户资料，并仅同步仍与提交快照相同的编辑字段。例如用户提交“ 新昵称 ”后没有继续修改，回包将输入同步为“新昵称”，从而解除 dirty；若等待期间已改成下一版草稿，则保留该草稿。头像选择也按文件和预览身份判断，旧上传回包不能清除新选图片。界面只在没有新草稿时显示“已保存”。账号已经切换时，旧账号的回包不更新当前账号或错误状态。

契约测试位于 `web/src/vitest/profile-page.test.tsx`、`web/src/vitest/profile-content-pages.test.tsx` 与 `backend/apps/posts/tests/test_profile_post_total.py`。前者验证标准化同步及等待期间的文本/头像编辑；后两者验证分页、重试、范围切换、展示开关和完整权限计数。
