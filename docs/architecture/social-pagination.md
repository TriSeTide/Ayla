# 社交目录、成员选择与实时订阅的分页契约

会话、好友、认证消息、成员与子群使用服务端游标页。前端描述符缓存仅包含已加载页、按 ID 打开的对象和实时事件更新的对象，不代表当前账号的完整目录，也不能作为权限依据。

## 请求与响应

分页读取显式带 `pagination=cursor`。`limit` 默认 30，范围 1–100；`cursor` 只在继续读取时提供。响应为 `{results, total, has_more, next_cursor}`。旧的不带分页标识的数组接口保留兼容，但新的可见列表消费者均使用分页入口。

| 资源 | API（均挂 `/api/v1/`） | 附加范围 |
| --- | --- | --- |
| 群/私信目录 | `chat/conversations/` | `type=group/private/all`，可选 `q` |
| 群成员、转让候选、@候选 | `chat/conversations/<id>/members/` | 可选 `q`、`exclude_self=1` |
| 子群 | `chat/conversations/<id>/subgroups/` | 响应额外包含默认子群 `default` |
| 用户搜索、建群候选 | `users/search/` | `q` |
| 好友 | `friends/` | 无 |
| 好友申请 | `friends/requests/` | `direction=received`、`status=pending` 在分页前过滤 |
| 群邀请 | `chat/me/invites/` | 当前账号待处理邀请 |
| 入群申请 | `chat/me/join-requests/` | 对当前账号管理的全部群聚合后分页 |
| 单群审批 | `chat/conversations/<id>/join-requests/` | 每次验证管理权限 |
| 退群通知 | `chat/leave-notices/` | 当前账号未读通知 |

游标签名绑定账号、资源、过滤条件与排序。每次继续读取重新应用当前权限；签名不代表授权。空、篡改、跨账号、跨查询或跨资源游标以及重复参数被拒绝。SQL 在序列化前取 `limit + 1` 条；总数独立计算，不能用已加载数组长度冒充总数。相同排序值用主键稳定排序。

会话的置顶和活跃排序在 SQL 分页边界之前计算。私信使用最后消息时间；群使用现有 24 小时新内容窗口，合并消息、在播频道的开播时间、新建语音房/桌游房/帖子，并按明确的群可见白名单取值。子群先固定默认组，再按最后消息序号降序排列；同序号按主键升序。旧的无子群消息归默认组。前端不得先取创建顺序的首 30 项，再只对这部分模拟全量活跃排序。

## 有界目录与单项读取

会话目录行不嵌入增长中的群成员或未读序号数组。它保留完整 `member_count`、`my_role`、`my_muted`、未读计数，并显式返回 `members_complete=false` 与 `unread_seqs_complete=false`。私聊两名成员属于固定大小资料。

`GET chat/conversations/<id>/?metadata=directory` 返回同样的紧凑目录行，用于直接链接、最近访问群及未知实时对象。`metadata=1` 用于已打开聊天：群成员仍独立分页，但保留定位特殊未读所需的完整未读序号投影。完整成员旧详情入口仍兼容外部旧客户端；新页面不依赖它。`GET .../subgroups/<sid>/` 支持打开首批页之外的明确子群。

成员搜索与转让选择在服务端筛选；候选列表变化不清空已经明确选择的对象。可见性选择器独立保留已选群 ID，群内创建的锁定群即使不在当前页也保持勾选。私聊好友判断直接读取 `users/<peer_id>/` 的关系字段，不全量读取好友；用户头像补拉也只使用精确用户 ID，失败不进行模糊搜索替代。

## 前端页状态

`stores/social.ts` 按账号、资源、群 ID、查询词、类型和排除自己选项隔离页状态。初次请求与继续读取合并同键并发；刷新拥有独立 revision，旧请求不能覆盖更新的刷新。账号变化清空页记录，旧账号的迟到响应不得写入目录或描述符缓存。

继续读取时按稳定 ID 去重，保留已有对象与局部操作。重叠请求期间的删除/审批保留删除标记，避免迟到页重新插入已移除条目；新到达的描述符更新优先于旧页中的同一对象。失败保留已加载内容和原游标，重试读取同一页；只在成功返回空结果后显示空态。`has_more=true` 而没有新游标或重复游标是协议错误，不自动循环请求。

页面提供“加载更多”和失败“重试”，滚动到可见列表尾部时可继续读取。好友、好友申请、群邀请、入群申请与退群通知各自持有页状态，互不以失败覆盖其他列表。当前用户收到的审批不依赖已经加载的群目录，因此管理群在第 31 项之后时也不会丢失申请。

## 群订阅与角标

`GET chat/subscriptions/?pagination=cursor&limit=100` 是传输注册目录，每项只含 `{id, last_message_seq}`，包含当前账号有权访问的全部群，包括本人隐藏的群。连接后只有此紧凑注册目录会连续翻页完成注册；可见会话目录不为注册而自动读取全部。订阅帧按 100 个 ID 分批。

客户端单独保存传输序号基线。`chat.subscribed` 回执与已收到消息更新该基线，重连不要求曾经打开历史消息。未知基线先订阅，不把未打开页的空消息缓存当作 `resume(0)` 请求。注册失败显示错误并采用 5 秒起、最多 60 秒的退避；成功清除错误。登出取消注册、定时器和迟到写入。

`group_presence` 是 SQL 聚合的 `{live, voice, game}`，与房间可见页是否已加载无关；语音标志要求频道存在成员，直播标志对应频道在播状态，桌游对应可见房间存在。房间 WS 事件在 250ms 内合并，触发 `POST chat/group-presence/`，请求 `{conversation_ids:[...]}`，每批最多 100 个 ID，并串行处理当前已加载的群。响应 `{presences:{"id": flags|null}}`；无权限和已删除均为 `null`，不暴露二者区别。

角标对账只更新标志，保留当前完整未读投影、角色和成员资料；它不会因另一个房间页为空而清掉页外活动。失败保持已有角标并显示连接状态错误，下次房间变化或显式页面刷新重新对账。解除权限的群从本地目录移除。

## 定向验证位置

后端 `apps/accounts/tests/test_social_pages.py` 与 `apps/chat/tests/test_social_pages.py` 覆盖 SQL 边界、签名与权限、页外搜索、跨全部管理群审批、独立订阅、置顶/活跃顺序及页外房间角标。前端 `social-pages.test.ts`、`visibility-selector-lazy-load.test.tsx`、`ws-chat.test.ts` 和相应组件测试覆盖继续读取、失败重试、迟到响应、删除/审批竞态、默认子群、精确关系查询以及页面切换生命周期。一次性运行结果和浏览器验收范围记录在报告中，不能把静态类型检查等同于真实页面验收。

## 浮层、滚动与键盘边界

会话行的更多菜单通过 portal 挂载到 `body`，以触发按钮矩形和视口剩余空间选择向下或向上展开；左右及上下位置受到视口边界限制。它不再受会话行的玻璃 stacking context 或列表 overflow 裁剪，层级高于快捷消息抽屉。滚动和外点关闭菜单，方向键选择菜单项；Escape 在浮层自身的 React 事件边界停止传播，再关闭并返回触发按钮，不能顺带关闭下方的快捷消息抽屉。删除确认框也独占自己的 Escape，并将 Tab 保留在模态框内。

@ 成员浮层同样挂载到 `body`，以当前编辑器所属 composer 为位置和宽度锚点；最大高度 280px，视口不足时选择空间较大的方向并缩短滚动区。这样其 backdrop-filter 采样真实聊天背景，不受 composer 的 backdrop root 限制而出现正文穿透。编辑器保持输入焦点，方向键可进入/移动候选，鼠标按下保留原光标，选择后插入 @Token；Escape 回到编辑器，外点关闭。该变化不改变服务端成员搜索、排除自己和分页契约。

触底观察器必须位于实际的滚动列表尾部。转让群主候选的 footer 与候选同处受限列表，避免列表外常驻可见的观察器连续耗尽所有页。上述浮层的键盘、portal 与事件隔离回归位于 `floating-chat-popovers.test.tsx`。
