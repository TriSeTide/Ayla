# 聊天媒体失败与恢复

聊天气泡由 `web/src/components/chat/MediaContent.tsx` 按媒体 descriptor 分派，完整图片/视频由 `ImageViewer.tsx` 展示。恢复动作沿用原来的媒体身份、认证和 URL 构造入口，不换源、不降级到无鉴权地址。

- 文件初次签名期间下载控件禁用；签名失败显示“附件加载失败”和重试。重试失效该媒体的签名缓存并重新签发，成功后仍使用原生同源 `a[download]`。浏览器开始下载之后的网络/磁盘结果由浏览器负责，页面不将生成链接等同于下载完成。
- 无海报视频气泡在签名失败或原生 `error` 后显示错误和重试；重试重新签名、重新建立首帧元素。本地未上传预览失败时只重建原本地元素，不请求服务端签名。有海报的封面加载仍由 `ResourceImage` 承接。
- 查看器视频在签名或原生加载失败后保留查看器及保存/关闭入口，显示独立重试。每次重试清理旧视频监听、播放与元素，再按原媒体重建。浏览器阻止自动播放时仍保留原生 controls 供用户点击，不把自动播放策略拒绝误报为媒体损坏。
- 语音继续通过带认证的 blob 接口读取。读取失败、`audio.play()` 拒绝、原生音频 `error` 都提供可见错误和重试。重试释放旧播放所有权与 object URL，重新读取相同媒体；旧元素事件、卸载后的读取以及被其他语音抢占后的迟到播放结果不能恢复旧 UI 或启动新播放器。

正常语音互斥、暂停/继续、进度拖动，图片/视频查看器键盘和多图滑动、乐观媒体禁止保存等既有行为保持各自契约。错误不会自动发消息、写后端状态或无界重试。

## 图片控制与装饰头像

`ResourceImage` 的内容图片失败时显示明确重试。若已有原生按钮/链接包住图片，复用该控件重试，暂时覆盖其可访问名称并阻止同时打开查看器；成功或卸载后恢复原标签和动作，避免嵌套按钮。独立内容图片使用独立重试按钮。空 `alt` 表示装饰图片，失败仅呈现已有 fallback，不改写父控件：搜索结果行、头像资料入口和直播目录仍能执行各自主动作。媒体变体变化会重新签发对应原图或缩略图。

## 录音和语音发送所有权

`useVoiceRecorder` 以 idle/starting/recording/stopping 描述浏览器生命周期。同步状态锁阻止重复请求麦克风；每次录音只拥有自己的 stream、MediaRecorder、计时器、停止 Promise 和事件监听。权限拒绝、构造/start/stop 异常、原生 error 与意外停止进入可见错误；不抛出无人接收的 Promise rejection。停止共用一次 Promise 并有 5 秒截止，取消和卸载会释放所有已取得的 track；权限结果迟到时立即释放迟到 stream，不能恢复旧录音。

MessageInput 的语音上传与发送按账号、会话、子群和可写状态建立 owner。离开或切换 owner 会取消录音/上传，旧 Blob 或回执不能落入新会话。重复停止不产生双份上传；短录音仍按原产品条件丢弃。语音上传成功但发送失败时，重试保留该次 media_id、消息幂等键和原回复目标，直接重试消息发送；未完成上传才重传录音。成功只清除仍指向本次回复对象的引用，不清除用户后来选中的目标。

## 媒体上传取消

媒体乐观消息在创建上传会话前即具有 0% 上传状态和取消入口。创建会话、PUT、complete、视频封面解码/seek 与 poster 请求共享同一 AbortSignal。API 客户端传递信号到 fetch，401 刷新结束也必须核对取消，已取消请求不重放。PUT 开始前、每个上传阶段完成后和发送消息前均核对信号；迟到成功不能重新显示已删除的乐观气泡，也不能继续发消息。

取消只清理本次已知 upload_id 的临时会话；创建请求被取消且没有返回身份时，客户端不能猜测会话编号，后端按既有过期机制回收。二进制取消释放 XHR；视频首帧与 seek 均有取消监听和有界等待，清理监听/计时器/本地 URL；poster 请求同样可中止。上传全部结束后退出上传取消态，显示消息发送等待态，避免让用户在消息已经提交后误以为仍能取消上传。

契约检查见 `web/src/vitest/media-recovery.test.tsx`、`media-content.test.tsx`、`image-viewer-swipe.test.tsx`、`resource-image.test.tsx`、`use-voice-recorder.test.tsx`、`message-voice-owner.test.tsx`、`media-api.test.ts`、`client.test.ts` 与 `use-chat-optimistic.test.tsx`。隔离浏览器使用有效合成 WebM 和静音 WAV 验证原生解码，并注入签名/blob/播放策略/原生 error；它不证明真实麦克风、媒体服务器或浏览器下载完成。
