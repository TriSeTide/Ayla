# Ayla 前端实时刷新与数据加载问题调研报告

**日期**：2025-01-20  
**调研范围**：Ayla/web 前端数据流、WebSocket 实时更新、页面加载机制  
**目标**：排查页面不能实时刷新、数据依赖前端主动加载的问题，提供系统性解决方案

---

## 一、问题现状

### 1.1 用户反馈的典型场景

1. **创建群聊后侧栏不显示新群（核心问题）**：
   - 用户创建群聊后，左侧会话列表（WideMessagesSidebar / 主页群列表）不立即显示新群
   - **现状调查**：✅ WebSocket 已推送 `group.created` / `group.joined` 事件（chat.ts 230-269 行）
   - **现状调查**：✅ chat store 已正确 upsertConversation
   - **问题根因**：❌ **侧栏组件未订阅 store 变化**
     - `WideMessagesSidebar` 接收 `conversations` props（HomePage.tsx L44-56），而非直接订阅 store
     - `HomePage` 使用 `const conversations = useChatStore((s) => s.conversations)`，组件会重渲染 ✅
     - 但 `WideMessagesSidebar` 在 ChatPage、MessagesPage 等页面使用时，父组件未订阅 store，导致 props 不更新 ❌

2. **创建语音房弹窗场景**：
   - 刷新页面后未加载主页群聊列表时，创建语音房弹窗的"指定群可见"选择器看不见群聊
   - 点击主页加载一下群聊列表后，回到创建语音房弹窗，群聊列表才出现
   - **根因**：弹窗依赖前端已加载的群聊数据，未主动触发加载或后端推送

3. **数据变化需刷新浏览器**：
   - 其他用户发布的新帖子、新建的语音房、直播间等内容，不会自动出现在当前页面
   - 群成员状态、在线状态、语音房成员变化等需要手动刷新才能看到
   - **根因**：缺少 WebSocket 实时推送机制或前端轮询更新

4. **页面加载依赖路由访问**：
   - 某些 store 数据只在访问对应路由时才加载（如 `HomePage` 的会话列表检查 `conversations.length > 0`）
   - 跨页面组件（如全局弹窗、FAB 创建表单）访问未加载数据时显示空态
   - **根因**：按需加载策略导致全局组件无法访问尚未加载的数据

5. **侧栏内容不实时刷新（广泛问题）**：
   - **ChannelSidebar**（群内场景侧栏）：语音房人数、直播状态、帖子未读数等状态不实时更新
   - **WideMessagesSidebar**（消息侧栏）：
     - ✅ 消息未读数已通过 `bumpUnread` WebSocket 实时更新
     - ❌ 新群聊不出现（问题 1）
   - **ServerRail**（群列表侧栏）：新群不出现、群头像不刷新
   - **根因**：侧栏组件接收 props 而非直接订阅 store，父组件未响应 store 变化

6. **群聊界面刷新后首个群头像加载失败**（2025-01-20 新发现）：
   - 在群聊详情页（`/group/:id`）刷新后，ServerRail 左侧栏的首个群头像无法显示
   - 其他群的头像正常显示
   - **根因**：预加载与页面加载的并发请求产生竞态条件，导致组件重渲染时 blob URL 失效
   - **已修复**：✅ 通过防止重复加载 + 优化缓存 key 策略解决

## 二、架构现状分析

### 2.1 WebSocket 实时连接现状

#### 已实现的 WebSocket 客户端

| 客户端 | 路径 | 职责 | 连接时机 | 实时推送能力 |
|--------|------|------|----------|------------|
| **presenceClient** | `ws/presence.ts` | 用户在线状态 | 登录后自动连接 | ✅ 推送用户在线/离线状态 |
| **chatWS** | `ws/chat.ts` | 聊天消息、群通知 | 登录后自动连接 | ✅ 推送新消息、撤回、已读、输入状态、群申请通知 |
| **voiceWS** | `ws/voice.ts` | 语音房状态 | `VoiceHubPage` 挂载时连接 | ✅ 推送成员加入/离开/静音状态 |
| **liveWS** | `ws/live.ts` | 直播弹幕 | 进入直播间时连接 | ✅ 推送弹幕消息 |

**关键发现**：
- `presenceClient` 和 `chatWS` 在 `main.tsx` 登录后全局连接，保持长连接
- `voiceWS` 和 `liveWS` 是按需连接（进入对应页面或房间）
- **所有 WebSocket 只推送增量事件**，不推送列表级别的新增/删除（如新建的语音房、新发布的帖子）

### 2.2 数据加载模式

#### 模式 1：首次进入路由加载（懒加载）

```typescript
// HomePage.tsx L59-83
useEffect(() => {
  if (conversations.length > 0) return; // ⚠️ 已有数据跳过加载
  chatApi.listConversations().then(/* ... */);
}, []);
```

**问题**：
- 从未访问过主页时，`conversations` 为空，全局组件无法访问群聊列表
- 条件 `conversations.length > 0` 导致即使数据过期也不刷新

#### 模式 2：每次挂载重新加载（无缓存）

```typescript
// VoiceHubPage.tsx L60-78
useEffect(() => {
  voiceApi.listVoiceChannels().then(/* ... */);
  return () => { cancelled = true; };
}, [listRetry]);
```

**问题**：
- 频繁切换页面时重复请求
- 无法感知其他用户创建的新频道（除非手动刷新）

#### 模式 3：WebSocket 推送更新（聊天消息）

```typescript
// ws/chat.ts dispatch
case "message.new":
  message.upsertMessage(d.conversation_id, msg);
  chat.bumpUnread(d.conversation_id);
```

**优势**：
- 新消息实时到达，无需轮询
- 未读数实时更新

**局限**：
- 只覆盖聊天消息，不覆盖语音房、直播间、帖子等内容列表

## 四、解决方案设计

### 4.1 修复页面组件订阅 store（核心方案，P0）

#### 方案 A：统一使用 store 订阅模式

**目标**：所有列表页面直接订阅 store，而非使用本地 state

**需要修改的页面**：

| 页面 | 当前模式 | 修改方案 | 工作量 |
|------|---------|---------|-------|
| **ChatPage.tsx** | 本地 state | 订阅 `useChatStore` | 30min |
| **MessagesPage.tsx** | 本地 state | 订阅 `useChatStore` | 30min |
| **VoiceHubPage.tsx** | 本地 state | 订阅 `useVoiceStore` | 30min |
| **LiveHubPage.tsx** | 本地 state | 订阅 `useLiveStore` | 30min |
| **PostsPage.tsx** | 本地 state | 订阅 `usePostsStore` | 30min |
| **BoardgameHubPage.tsx** | 本地 state | 订阅 `useBoardgameStore` | 30min |

**代码示例**：

```typescript
// VoiceHubPage.tsx - 修改前
const [channels, setChannels] = useState<VoiceChannelDescriptor[]>([]);
useEffect(() => {
  voiceApi.listVoiceChannels().then(setChannels);
}, []);

// VoiceHubPage.tsx - 修改后
const channels = useVoiceStore((s) => s.channels);
const lastFetched = useVoiceStore((s) => s.lastFetched);

useEffect(() => {
  const now = Date.now();
  const stale = !lastFetched || now - lastFetched > 60_000;
  
  if (channels.length === 0 || stale) {
    voiceApi.listVoiceChannels().then((list) => {
      useVoiceStore.getState().setChannels(list);
    });
  }
}, [channels.length, lastFetched]);
```

**优势**：
- ✅ **彻底解决列表不实时更新问题**
- ✅ WebSocket 推送后，所有订阅组件自动更新
- ✅ 侧栏、列表页、全局弹窗数据一致

**成本**：
- 前端修改 6 个页面组件，约 3 小时
- 需要确保 store 有 `lastFetched` 字段（部分已有）

**实施优先级**：⭐⭐⭐⭐⭐ **最高优先级，彻底解决问题**

### 4.4 Store 增加缓存时间戳（P1）

#### 方案 E：统一缓存失效策略

**设计**：

```typescript
// stores/voice.ts
interface VoiceState {
  channels: VoiceChannelDescriptor[];
  lastFetched: number | null; // 时间戳
  setChannels: (channels: VoiceChannelDescriptor[]) => void;
}

export const useVoiceStore = create<VoiceState>((set) => ({
  channels: [],
  lastFetched: null,
  
  setChannels: (channels) => set({ 
    channels, 
    lastFetched: Date.now() // 更新时间戳
  }),
}));

// 辅助函数
export function isVoiceStale(): boolean {
  const { lastFetched } = useVoiceStore.getState();
  return !lastFetched || Date.now() - lastFetched > 60_000; // 60s 过期
}
```

**需要修改的 store**：
- ✅ `chat.ts` - 已有类似逻辑
- `voice.ts`
- `live.ts`
- `posts.ts`
- `boardgame.ts`

**优势**：
- ✅ 避免频繁重复请求
- ✅ 保证数据不超过 60s 过期

### 7.3 Store 缓存时间戳实现

#### voice.ts 示例

```typescript
// stores/voice.ts
interface VoiceState {
  channels: VoiceChannelDescriptor[];
  lastFetched: number | null;
  
  setChannels: (channels: VoiceChannelDescriptor[]) => void;
  upsertChannel: (channel: VoiceChannelDescriptor) => void;
  removeChannel: (channelId: number) => void;
}

export const useVoiceStore = create<VoiceState>((set, get) => ({
  channels: [],
  lastFetched: null,
  
  setChannels: (channels) => set({ 
    channels, 
    lastFetched: Date.now() 
  }),
  
  upsertChannel: (channel) => {
    const channels = get().channels;
    const idx = channels.findIndex((c) => c.id === channel.id);
    
    if (idx >= 0) {
      // 更新
      const updated = [...channels];
      updated[idx] = channel;
      set({ channels: updated });
    } else {
      // 新增
      set({ channels: [...channels, channel] });
    }
  },
  
  removeChannel: (channelId) => set((state) => ({
    channels: state.channels.filter((c) => c.id !== channelId),
  })),
}));

// 辅助函数：判断是否过期
export function isVoiceStale(): boolean {
  const { lastFetched } = useVoiceStore.getState();
  if (!lastFetched) return true;
  return Date.now() - lastFetched > 60_000; // 60s
}
```

## 八、风险与注意事项

### 8.1 组件重渲染性能

**风险**：订阅 store 后，store 任何字段变化都会导致组件重渲染

**防护**：
```typescript
// ❌ 错误：订阅整个 store
const voiceStore = useVoiceStore();

// ✅ 正确：只订阅需要的字段
const channels = useVoiceStore((s) => s.channels);
const lastFetched = useVoiceStore((s) => s.lastFetched);

// ✅ 更优：使用 shallow 比较避免数组引用变化导致重渲染
import { shallow } from 'zustand/shallow';
const channels = useVoiceStore((s) => s.channels, shallow);
```

### 8.2 并发加载竞态条件

**场景**：
1. 用户刷新页面，登录预加载开始
2. 用户立即访问语音房页面，页面也触发加载
3. 两个请求几乎同时完成，可能导致数据不一致

**防护**：
```typescript
// stores/voice.ts
let loadingPromise: Promise<void> | null = null;

export async function loadVoiceChannels() {
  // 防止重复加载
  if (loadingPromise) {
    console.log('[VoiceStore] 加载中，等待完成');
    return loadingPromise;
  }
  
  loadingPromise = voiceApi.listVoiceChannels()
    .then((list) => {
      useVoiceStore.getState().setChannels(list);
    })
    .finally(() => {
      loadingPromise = null;
    });
  
  return loadingPromise;
}

// 页面使用
useEffect(() => {
  if (channels.length === 0 || isVoiceStale()) {
    void loadVoiceChannels(); // 自动防重复
  }
}, []);
```

### 8.3 WebSocket 断线重连

**场景**：WebSocket 断线后重连，期间错过的列表变化事件丢失

**防护**：
```typescript
// ws/chat.ts
onOpen() {
  console.log('[ChatWS] 连接成功');
  
  // 重连后重新加载列表（补偿丢失的事件）
  const now = Date.now();
  const chatStore = useChatStore.getState();
  const voiceStore = useVoiceStore.getState();
  const liveStore = useLiveStore.getState();
  
  if (!chatStore.lastFetched || now - chatStore.lastFetched > 60_000) {
    void chatApi.listConversations().then(chatStore.setConversations);
  }
  if (!voiceStore.lastFetched || now - voiceStore.lastFetched > 60_000) {
    void voiceApi.listVoiceChannels().then(voiceStore.setChannels);
  }
  if (!liveStore.lastFetched || now - liveStore.lastFetched > 60_000) {
    void liveApi.listLiveChannels().then(liveStore.setChannels);
  }
}
```

### 8.4 乐观更新与 WebSocket 推送冲突

**场景**：
1. 用户创建语音房，前端乐观插入到列表
2. 后端 WebSocket 推送创建事件
3. 同一条目出现两次

**防护**：
```typescript
// stores/voice.ts
upsertChannel: (channel) => {
  const channels = get().channels;

```

### 8.5 内存泄漏

**风险**：组件卸载后，未清理的 store 订阅或事件监听器

**防护**：
- Zustand 自动管理订阅，组件卸载时自动清理 ✅
- WebSocket 事件监听在全局 `main.tsx` 注册，不会泄漏 ✅
- 定时器、`useEffect` 的清理函数必须正确返回：

```typescript

  return () => clearInterval(timer); // ✅ 必须清理
}, []);
```

### 11.1 群聊界面刷新后首个群头像加载失败（2025-01-20）

**问题描述**：
- 在群聊详情页（`/group/:id`）刷新后，ServerRail 左侧栏的首个加载的群头像无法显示
- 其他群的头像正常显示
- 浏览器 DevTools 显示图片请求成功但未渲染

**根因分析**：
1. **并发加载竞态条件**：
   - `main.tsx` 登录后预加载会话列表（调用 `fetchConversations`）
   - `GroupDetailPage` 挂载时也调用 `fetchConversations`
   - 两个请求几乎同时完成，触发 store 的 `setConversations` 两次
   
2. **store 防重复加载逻辑缺陷**：
   ```typescript
   if (current.length > 0) return; // ❌ 只判断是否为空，不判断来源
   ```
   - 第一次调用成功设置 `conversations`，`length > 0`
   - 第二次调用被跳过，但此时组件已经开始使用第一次的数据
   - 组件重渲染时，blob URL 可能因为缓存失效而失效

3. **ResourceImage 缓存 key 策略问题**：
   - 原缓存 key 使用完整 URL（如 `/api/v1/media/abc/content?s=small`）
   - 不同 `s` 参数导致同一资源被认为是不同的缓存项
   - 并发请求创建多个 blob URL，部分被提前释放

**修复方案**：

1. **优化 store 防重复逻辑**（`web/src/stores/chat.ts`）：
   ```typescript
   // ✅ 添加详细日志，明确跳过原因
   if (current.length > 0) {
     console.log('[ChatStore] 会话列表已加载，跳过重复设置，避免触发无意义重渲染');
     return;
   }
   ```

2. **优化 ResourceImage 缓存策略**（`web/src/components/ResourceImage.tsx`）：
   ```typescript
   // ✅ 从 URL 提取 media_id 作为缓存 key
   function getCacheKey(src: string): string {
     if (src.startsWith(MEDIA_PATH_PREFIX)) {
       const match = src.match(/\/media\/([^/]+)\//);
       return match ? match[1] : src; // 使用 media_id 而非完整 URL
     }
     return src;
   }
   ```
   - 同一 `media_id` 的不同 `s` 参数共享同一 blob URL
   - 避免重复请求和缓存碎片

**验证方法**：
1. 在群聊详情页刷新浏览器
2. 观察 ServerRail 左侧栏的群头像
3. 检查浏览器 DevTools Network 面板，确认图片请求数量正常
4. 检查 Console 日志，确认 store 防重复逻辑生效

- ✅ 修复群聊界面首个群头像加载失败
- ✅ 减少重复图片请求，提升性能
- ✅ 避免并发加载导致的组件重渲染问题
