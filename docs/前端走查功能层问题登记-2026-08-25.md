# Ayla 前端走查功能层问题登记（2026-08-25）

> 来源：2026-08-25 全站 UI 走查过程中顺带发现的功能层缺陷（与 UI/动画优化方案分离，另行排期）。
> 配套方案：`docs/plans/前端UI布局及动画优化实施方案-2026-08-25.md`（该方案明确排除本页内容）。
> 状态均为「已登记、未修」；修复后在本页对应条目标注结论。

## F1 会话列表预览泄漏 blob URL

- **现象**：消息中心会话「123」的预览行直接显示 `blob:http://localhost:5173/cb4ec772-...` 原始地址。
- **位置**：会话预览生成链（前端 `utils/segment.ts` / store last_message 兜底逻辑；宽窄屏均现）。
- **影响**：预览语义破坏（应显示 `[图片]/[视频]` 等占位）；blob URL 仅本机会话内有效，持久化后必然失效。
- **根因方向**：媒体消息的预览占位生成未覆盖「本地乐观消息的 content 恰为 blob URL」或历史消息 content 存量脏数据（该会话最后一条消息的 content 本身存了 blob URL，属发送链路把本地 URL 当文本落库的历史 bug）。排查先分「存量脏数据」与「生成逻辑缺口」两条线。
- **建议**：预览生成对 `blob:` 前缀内容按媒体占位处理（兜底）；存量数据评估是否清洗。

## F2 在线状态显示矛盾（列表 vs 私聊头部）

- **现象**：消息中心列表爱莉行显示「● 在线」，进入 `/chat/1` 头部同一时刻显示「离线」。
- **位置**：presence 状态消费链（`ws/presence.ts` → 各组件订阅）。
- **影响**：状态可信度；用户困惑。
- **根因方向**：两处订阅的 presence 数据源/更新时点不一致（列表可能用登录预加载快照，聊天头部用实时 WS；或 WS 断线后头部回退 offline 默认值而列表未回退）。
- **建议**：统一 presence 单一事实源（store），组件只读 store；WS 断线时两处同策略降级。

## F3 PostCard 内 button 嵌套 button（HTML 非法 + 可访问性）

- **现象**：console `validateDOMNesting` 警告：`<button> cannot appear as a descendant of <button>`，调用链 `PostCard.tsx:41 → header → Avatar`（Avatar 渲染为 button，外层「查看帖子」也是 button）。
- **影响**：HTML 非法；读屏器/键盘语义混乱（嵌套可点目标）；部分浏览器行为未定义。
- **建议**：外层「查看帖子」button 改为 div + onClick（补 role/tabIndex/键盘处理）或内层头像按钮改非交互元素；推荐前者保留头像独立可点语义。

## F4 favicon.ico 404

- **现象**：每次加载 `GET /favicon.ico` 404。
- **建议**：`web/` 提供 favicon（可用爱莉头像裁剪或品牌图形），`index.html` 显式声明 `<link rel="icon">`。

## F5 搜索历史重复未去重

- **现象**：搜索历史 chips 出现「Ayla 全流验收群」×2 及高度相似词条并存。
- **位置**：搜索历史写入逻辑（无去重/无归一化）。
- **建议**：写入时按精确匹配去重（命中则提到队首）；是否做相似归一化由用户定（涉及「验收群/验收验群」这类真实不同输入）。

## F6 无效重试循环（媒体加载失败态，低优先级登记）

- **现象**：封面/媒体「图片加载失败，点击重试」在对象已被删除（404）或越权（403）时，重试必然再失败，无失败次数上限。
- **说明**：走查样本中的 404/403 多为用户清理文件所致，非前端 bug；但「必失败的重试无上限」是交互层缺口。
- **建议**：同一媒体重试 ≥2 次仍失败后降级为静态占位（不再提供重试点击），或提示「资源不存在」。

## F7 未读跳转（聊天体验优化，2026-08-25 用户追加）

- **现状**：打开会话直接定位最新消息（或底部），未读多时不知道哪些没读过。
- **目标**：打开会话时定位到**第一条未读消息**，其上方插入「以下为新消息」分隔线（QQ 式）；无未读则定位最新。定位依据 = 会话已读游标（last_read_seq）之后的最早消息。
- **依赖**：消息窗口化（实施方案 U16/M6）——未读消息可能不在初始窗口内，需先向上加载至目标 seq 再定位。
- **建议**：与 M6 同期设计（定位逻辑同源：都是「按 seq 定位 + 必要时扩窗」）。

## F8 @功能

- **现状**：无 @ 能力。
- **目标**：输入框输入 @ 弹出本群成员选择器（玻璃浮层、搜索过滤、头像+昵称）；选中后在输入框生成不可拆分的 @Token（删除整体删除）；消息渲染中 @片段高亮（`--ice-500` 底胶囊或 `--glow-500` 描边，遵循 design.md token）；「@我」的消息在会话列表/红点聚合中有独立提醒语义（是否进 badges 聚合由后端契约定）。
- **边界**：私聊无 @ 需求（仅群聊）；@Token 需要消息 schema 支持（纯文本内嵌 `@<user_id>` 标记或 segments 扩展——与后端同轮定契约，涉及 schema 变更走迁移规范）。

## F9 @跳转

- **目标**：点击消息中的 @某人 → 打开该用户资料卡/个人页（复用现有用户页路由）。
- **依赖**：F8（先有 @ 数据才有跳转）；渲染层把 @Token 渲染为可点元素。

## F10 回复跳转

- **现状**：引用/回复块只展示摘要，点击无动作。
- **目标**：点击引用块 → 定位到被引用的原消息并短暂高亮（玻璃辉光一闪，§7 语言）；原消息在窗口内直接滚动定位；不在窗口内（更早）→ 自动向上加载至该 seq 再定位（依赖 U16 窗口化）；原消息已撤回 → 显示「该消息已撤回」态定位到位置。
- **依赖**：U16（M6）强相关，建议同期实施。

- F3（可访问性违规）建议最先修，改动小。
- F1/F2 需要先定位根因（存量数据 vs 逻辑缺口 / 数据源统一），建议各立小任务。
